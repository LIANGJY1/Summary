# 整体阅读优化 R1

## 目标与范围

用户要求在内核内容分层后先进行一轮整体优化。范围为根目录 18 篇，重点是 Android 开发者的阅读顺序、层间衔接、过程性内容收拢、术语和证据引用一致性。保留技术主体、代码、SQL、数值账目和证据状态。

## 阅读结构

1. 每篇先给出职责、数据流和阅读重点，再进入原有机制与证据章节。总纲提供输入主线、帧生产主线和按需查阅调度、SQL 的顺序。
2. 公共基准、时间口径、术语和引用规则集中到总纲。各篇的具体版本差异、时钟例外与样本限定继续保留。
3. 写作前行数盘点、study 批注工作及重复声明保存在 `整体优化-R1-原篇首存档.md`。部分批注审计、验收自查与归档计划收拢至 `整体优化-R1-过程性段落存档.md`，原章节保留追溯入口。

1. 总纲 §3.3 的新样本 RenderThread 从“未核对”更新为 tid 2079，依据 10 篇 H16 及已有查询留痕。

3. 总纲 §3.7、§3.9 不再沿用“input 队列计数不可见”“过滤路径仍全是候选”的初期状态，按 06、07、15 篇已完成的事件 ID、计数轨和时序分析更新。保留具体等待条件、主线程竞争致因、全程时钟校验与 host 行为盲区。
