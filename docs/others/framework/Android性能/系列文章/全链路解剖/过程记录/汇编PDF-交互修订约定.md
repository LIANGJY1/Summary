# 汇编 PDF 交互修订约定（2026-11-15 与用户定型）

> 用户需求："边看 PDF 边用 AI 进行修改"，定型为**直接引用文章内容修改**（用户原话："是否可以直接引用文章内容进行修改"）。
> 本约定供后续 agent 无缝接续；与 `汇编PDF-构建记录.md` 配套。

## 一、核心原则

PDF 是派生产物，**markdown 18 篇是唯一源**。一切修改落在 .md，PDF 按需重建。禁止直接改 PDF（重建即丢、源/PDF 不一致）。

## 二、修订流程（用户引文驱动）

1. **用户贴引文＋改法**：从 PDF 复制特征文字（几字到整句）＋修改指令；页码可选（给了更快）。
2. **定位**：grep 引文特征片段于 18 篇（PDF 提取文字丢 backtick/表格竖线/换行，用规范化片段匹配，勿整段逐字）；多处命中用上下文裁决或问用户。书签给各篇起始页（篇号→页映射见 PDF 一级书签），可辅助缩小范围。
3. **修改分类**：
   - 文字/表述/引文/行号类：直接改。
   - **机制结论类**：先对精树源码（/home/liang/Project/AAOS13、AAOS13_kernel/common，只读）或 trace 验证再落笔；验证结果随修改报用户。维持"断言必配证据"战役标准。
4. **报告**：每处报 `文件:行号`＋改前/改后；留痕入过程记录。
5. **重建按需**：修改先积累于源；用户说"重建"才跑 `python3 汇编/build_pdf.py`（约 3 分钟，覆盖 汇编/ 下 PDF 与 combined.html）。可批量引文一次改完一次重建。

## 三、重建后质检（快速门）

- `python3 汇编/qa_pdf.py`：目录 257 条页码与书签核对、四态逐篇计数、地址扫描、空白页。
- 技能 pdf_qa.py --skip-cover：已知 11 处行首标点 WARN 为 Pango 引擎限制（见构建记录§四），非缺陷。
- 若改动涉及表格/代码块：渲染改动页 PNG 目视或 pdf:visual-judge 验收。

## 四、纪律继承

只写不提交；两精树与 yadea_master 只读；设备离线；不打印设备标识/内部地址（vg-kit.err 序列号不得入任何产物）；不触碰 Summary 既有未提交删除项；专业严谨禁抽象词；全程留痕。

## 五、备选通道（用户未选，备查）

- ZCode PDF 面板：open_document 开 PDF，get_view 读用户选区/页位，show_in_viewer 指位。
- Evince（已装）批注批量：高亮＋笔记存于 PDF，PyMuPDF page.annots()＋get_textbox(rect) 提取→定位→批改；**须批注副本或先提取后重建**（重建覆盖会丢批注）。
