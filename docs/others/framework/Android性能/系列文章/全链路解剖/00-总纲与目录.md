# 00 · 总纲与目录：AppList 性能全链路解剖

本系列沿触摸输入 → 事件分发 → 应用消费 → 帧调度 → 渲染提交 → 显示合成与呈现的链路分析 AppList 性能。

## 0. 系列要回答的两个问题

1. **主线程等待**：Launcher 主线程处于 Sleeping 状态 50.928 ms（`00:00:06.779837–00:00:06.830765`）。
2. **输入分发延迟**：从 InputReader `notifyMotion` 到 InputDispatcher `prepareDispatchCycleLocked` 相差 34.738 ms（`00:00:06.795839→00:00:06.830577`）。

两个问题来自同一次采集（20261113-151358-vertical-1912967，见 §3）。时间数据见《战役计划与台账》第 7、69、72 行及会话记录；各段机制、结论及其证据边界见对应篇。

## 7. 词汇纪律声明

本系列执行契约硬性标准 2、4、5、7（战役计划与台账.md:34-40），口径如下：

1. 禁比喻。机制描述只允许代码实体（函数/结构体/队列/fd/socket）、trace 对象（slice/thread_state/counter/track）与可测量量（ms/μs/字节/次数）。不用"像……一样""相当于""管家""总管""流水线""旅程""接力"等词。契约作业单中的"预处理管道"一词在本系列正文统一写作"预处理层监听器链"（见 §1 [7]），避免使用"管道"。
2. 名词必须可指认。每个名词要么是代码符号（配 `文件路径:行号` 锚点），要么是 trace 对象（配 slice/事件名或查询口径），要么是 §4 术语表已定义的术语。既不是代码符号、也没有锚点、也不在术语表的概括词不得用于机制断言。
3. 三态标注。机制性与因果性结论一律标 已证（源码或 trace 明确支持）/未证（有候选无证据）/盲区（采集配置或源码缺失）；"没查到"不得写成"不存在"。
4. 术语全文只定义一次。定义集中在 §4；正文引用用编号或原词。
5. 时间口径。trace 数值一律 Perfetto 相对时间 `00:00:06.xxxxxx`；旧样本 BOOTTIME 口径须标注需换算。
6. 专有名词例外。契约中的篇名（如 05-触摸烹调段.md）与既有文档标题作为文件名引用时保留原样；正文散文不复用其中比喻词。
