## 二、硬性标准（每批验收门）

1. **源码引文**：每条断言必配 `文件路径:行号`＋关键代码摘抄（≤10 行）＋走读文字。引文行号以**精树**为准（见三、基准），写作时必须实际读取核对；行号错误的引文按缺陷处理。
2. **禁抽象词语**：全文机制描述只允许代码实体（函数/结构体/队列/fd/socket）、trace 对象（slice/thread_state/counter/track）与可测量量（ms/μs/字节/次数）。禁用"像……一样""相当于一个管家""流水线""总管"类比喻和未定义概括词。既有替换表口径（出版级深度标准）继续适用。
3. **机制四问**：讲机制必答——规则是什么/谁设置/谁执行/执行的后果（或违反的后果）。
4. **证据三态**：结论一律标注 已证（源码或 trace 明确支持）/未证（有候选无证据）/盲区（采集配置或源码缺失）。不得把未证写成已证；"没查到"不等于"不存在"。
5. **计数与定义**：数字精确到 trace 或统计的原始口径；概念全文只定义一次；主线先闭环再展开分支。
6. **全文通读**：交稿前全文通读一遍，禁补丁式写作。
7. **时间口径**：trace 数值一律 Perfetto 相对时间 `00:00:06.xxxxxx`；不得使用设备开机秒或其他 trace 口径解释新样本。
8. **过程留痕**：每批一份 `过程记录/批XX-过程记录.md`：实际读取的文件与行范围、逐断言的验证记录（断言→证据→行号）、运行的查询与输出摘要、结论、未证边界。过程记录必须真实，供复核 agent 独立复验。
9. **只写不提交**：全部产物写入文件，不执行任何 git commit；设备保持离线不连接。
