# 会话经验沉淀定位为知识条目，而非技能或交接

已有 session-to-skill（流程→SKILL.md）、handoff（上下文交接）、to-spec（讨论→spec）分别覆盖"方法、交接、需求"三类产物，但"会话中搞清楚的知识本身"没有归宿。决定：新 skill 只做知识沉淀——把会话结论写入 knowledge-base 的条目；可复用流程走 session-to-skill，交接走 handoff，互不越界。

## Considered Options

- 混合路由（一个入口按内容自动分流到技能/交接/知识）被否：触发与输出都会含糊，且与既有技能抢活。
- 纯日志式会话归档被否：按日期堆积的文档没有检索价值，知识只有按主题合并、持续修订才能复用。
