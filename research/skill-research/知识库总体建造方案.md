## 1. 设计原理（六条，全部有出处）

1. **按记忆类型分区**（alexop.dev 四类记忆框架）：semantic=knowledge-base+笔记；procedural=skills/tools/ai；episodic=issue/project；索引=path/AGENTS.md/索引文件。
2. **双循环 + 四桥**（费曼技术 + learning in public + SRE 复盘）：学习与工作不是两堆文件，是两条循环 + 四座桥（§3）。
3. **入口地图 + 渐进披露**（Claude memory 官方 + AGENTS.md 标准）：入口 <200 行指路，规则下沉到各子库自己的 CONTEXT/ROUTING，禁止复制。
4. **写入显式化**（Cline lockdown + 我们已有的确认门）：agent 永不自动写知识库；default-deny（ADR-0004）。
5. **单一事实源**：规则、条目、规则正文只存在一处，其余指路（writing-for-agents 的 pruning）。
6. **涌现优先于预设**（MOC，Obsidian 社区）：不预建大而全的索引；某主题被多处引用时才晋升为 MOC/总纲——防"先建结构后填内容"的反向失败。

## 3. 连接机制：学习 ⇌ 工作四座桥（本方案核心）

### 桥 1 工作 → 学习（缺口驱动学习）
- **触发点**：issue-review 复盘的"未竟事项/知识缺口"；工作任务的"看不懂的模块"（project-decoder 解码时发现的陌生领域）。
- **动作**：复盘 skill 在收尾时**提议**："这个缺口值得进学习队列吗？" 用户确认 → 写入 `path/` 对应总纲的**「缺口队列」节**（新增小节，格式：`- [ ] <主题>：为什么缺、从哪入手`）。
- **落点**：path/（学习路径是学习循环的输入端）。

### 桥 2 学习 → 工作（资产反哺）
- **触发点**：开始工作任务/设计/排查时。
- **动作**：已写进 AGENTS.md 动线——项目任务先读 `project-architecture/<项目>.md`；设计/写码前按主题查 knowledge-base（ROUTING 检索）。
- **强化**（阶段 3）：`ai/` 项目工作流手册中加一行"动手前查什么"。

### 桥 3 学习输出 → 工作影响力（费曼闭环）
- **触发点**：一个主题精读/解码完成后。
- **动作**：输出三选一——写文章（article-pipeline，learning in public）、`teach` skill 自测（"能教会 agent = 真懂了"，费曼第 2 步）、工作内分享文档。反馈/新问题 → 回流笔记或进 KB。
- **这是"学习必须连着工作"的关键设计**：每个学习循环的出口都对着一个公开或工作场景，防止"只进不出"的囤积式学习。

### 桥 4 素材 → 知识（验证升级）
- **触发点**：excerpts 确认（confirm）后回看；读书笔记转述完成时。
- **动作**：素材/洞见过**复习者测试** → 按 ROUTING 进 KB；不过 → 留在素材层。excerpts/reading/KB 三者互不写入，只单向升级。

## 4. 阶段路线图

### 阶段 1 ✅（已完成）
AGENTS.md 入口、knowledge-base+ROUTING、project-decoder、skills 镜像、source-annotator v1.24、my-skill-creator。

### 阶段 2 🚧（三摄入流，详见阶段 2 计划）
`issue-review` 复盘流 → `reading/`+`book-notes` → `writing/`+`article-pipeline`；7 步实施清单已列。

### 阶段 3（学习闭环补全 + 工作状态层）
1. **teach 接入**：学习循环的输出端标准化——精读/解码收尾时提议"用 teach 把它讲一遍？"（费曼自测），讲不清的地方就是笔记要补的洞。
2. **学习 backlog**：`path/` 各总纲加「缺口队列」节；桥 1 落地。
3. **项目 STATUS 层**：每项目一个 `STATUS.md`（当前状态/下一步/挂起），Cline activeContext 思想；挂进 AGENTS.md 地图与桥 2。

### 阶段 4（治理自动化与度量）
1. **季度整理**（checklist 脚本化）：死链扫描（check_kb 扩展）、ROUTING 与子库头部一致性、AGENTS.md 地图对账、MOC 晋升评审（某主题被 ≥3 处引用 → 考虑建总纲/MOC）。
2. **hooks 自动捕获候选**（memory-compiler 思想）：会话收口 hook 生成 session-to-knowledge 候选草稿（仍过确认门）。
3. **度量**：不建复杂指标——复习者测试本身就是度量（"六个月后翻到它能用"= 有效）；季度整理时抽查 5 条目做"当初的复习场景发生过吗"。

## 5. 治理规则（宪法，全库通用）

1. **写入三问**：基线会错吗/可迁移吗/放对地方了吗（技能资格三问的知识库版）；不过 → 不写。
2. **确认门**：agent 提议、用户裁决、然后落盘——全库无自动写。
3. **单一事实源**：规则在各子库头部；AGENTS.md/ROUTING 只指路；发现双写以子库为准修上游。
4. **新子库先登记**：AGENTS.md 地图没登记的目录，agent 不写不读（防野目录）。
5. **防沉积**：每次路过顺手修（四检思想）；季度大扫除删死链与过期缓存知识。
6. **防过度工程**：流程固化前过"资格三问"（不做会错吗/非一次性吗/可复用吗）——**不是所有习惯都要 skill 化**。
