# 阶段 2 详细计划：知识库三条摄入流

> 2026-09-06 制定。依据：H 调研（Claude memory / Cline Memory Bank / SRE postmortem）+ 本地事实（excerpts/CONTEXT.md、issue/ 活样本、juejin 索引、写作三件套原语）。
> 原则：每条流 = 一个轻量 skill（走 my-skill-creator 闭环建造）+ 落点子库登记进根 AGENTS.md。写入一律过用户确认门（lockdown 思想），agent 不自动写知识库。

## 总览

| 流 | skill（新建） | 落点 | 原语复用 | 状态 |
|---|---|---|---|---|
| A 复盘流 | `issue-review` | `issue/` + 桥接 knowledge-base | session-to-knowledge（价值门/分流） | 有活样本（Codex 403） |
| B 读书笔记流 | `book-notes` | 新子库 `reading/` + 桥接 knowledge-base | excerpts 边界、确认门模式 | 无库，需建骨架 |
| C 写作流 | `article-pipeline`（编排壳） | 新子库 `writing/` + `juejin-articles-index.md` 登记 | writing-fragments/shape/beats、markdown-typography-expert、diagram-guide | 素材侧已厚 |

实施顺序：**A → B → C**（A 有活样本可立即实测；C 素材最厚可按写作活跃度与 B 插队）。

## 流 A：复盘流（`issue-review`）

**现状缺口**：`issue/` 只有一篇 Codex 403 排查记录（事实上的复盘孤本，事件证据与可迁移结论混在一篇里）；排查完的知识没有归处。

**触发**（description 草案用词）："复盘一下这个问题 / 把这次排查记下来 / 记录问题复盘"；以及 agent 完成一次**非平凡**排查后主动提议（只提议不自动写）。

**资格门**（平凡问题不立复盘）：满足任一——根因非显而易见、排查耗时 >30 分钟、有复发可能、证据链有复用价值。

**产出双落点**（核心设计：事件与知识分家）：
1. `issue/YYYY-MM-DD-<slug>.md` —— 事件复盘，SRE 模板个人裁剪版：
   `现象与影响 → 时间线（可选，长排查才写）→ 根因与证据链（命令+关键输出，file:line 思想）→ 修复 → 预防 → 未竟事项`
   blameless 原则转为个人版：**对系统不对人**——写"什么机制让这个错误容易发生"，不写"我犯蠢了"。
2. 可迁移结论 → knowledge-base 候选清单（≤3 条，过复习者测试），按 `ROUTING.md` 路由，经 session-to-knowledge 的确认门写入。
   **分流判据一句话**："换个环境（换机器/换项目）还成立吗？" 成立 → KB；环境特定（IP/路径/版本号） → 留在 issue/ 复盘里。

**原语复用**：KB 写入部分 **REQUIRED SUB-SKILL 调 session-to-knowledge**（价值门、脱敏、并入规则不复制）。

**配套动作**：给 `issue/` 补 `CONTEXT.md`（词汇：复盘/挂起事项/证据链；两类文件名约定：复盘 `YYYY-MM-DD-<slug>.md`、挂起 `YYYY-MM-DD-handoff-<slug>.md`——现有 403 文件自然归入后者，改名一次）。

**验收用例**：把 Codex 403 按新模板重写一遍作为首篇（挂起部分保留、可迁移结论抽 1-2 条进 KB 走真实流程）。

## 流 B：读书笔记流（`book-notes`）

**现状缺口**：无读书笔记库。注意边界：`excerpts/` 是**手机捕获的原始素材**（原文保真、未验证、互不写入）——读书笔记是消化后的转述，**不能塞进 excerpts**（其 CONTEXT.md 边界明确）。

**触发**："读《X》记一下 / 整理这本书的笔记 / 这章讲了什么我记下来"。

**产出与落点**：新子库 `reading/`，**一书一文件** `reading/<书名>.md`：
- 书档：作者/版本/为什么读/状态（在读/读完）
- 按章小节：每条 = **引文（原文引用，标注页码/位置）** 与 **转述（自己的话）** 显式区分——转述处才允许提炼
- 章末"可迁移？"小节：通过复习者测试的洞见 → knowledge-base 候选（走 ROUTING；方法论/思想类通常进 design-principles）
- 与 excerpts 的桥：读书时想起某条摘录可引用（标来源路径），但互不写入

**方法论依据**：Zettelkasten 文献笔记（literature notes = 带源转述，永久笔记才入知识库）+ 渐进总结（分层高亮，转述分层）。

**skill 轻量设计**：`book-notes` 主要管三件事——①建书档与结构一致 ②强制引文/转述区分 ③读毕走一次 KB 分流建议。写作格式细节放 `reading/CONTEXT.md`（词汇：书档/引文/转述/可迁移）。

**验收用例**：拿一本在读的书真实记一章。

## 流 C：写作流（`article-pipeline`，编排壳）

**现状缺口**：素材侧厚（KB 条目/学习笔记/复盘/摘录），成文原语齐（writing-fragments/shape/beats 三件套 + markdown-typography-expert + diagram-guide），但**没有管线编排、没有成稿落库、索引靠手动**。

**触发**："写篇文章 / 续写 X 系列 / 把这个整理成博客 / 选题"。

**管线五步**（编排壳，同 my-skill-creator 模式）：
1. **选题**：三个来源——KB 高价值条目（"这条够写一篇吗"）、issue/ 复盘（403 类实战文）、`juejin-articles-index.md` 系列缺口（哪个系列可续）；列候选用户确认
2. **素材汇总**：把相关条目/笔记/复盘/摘录聚到工作稿
3. **成文**：按需 REQUIRED 调原语——素材散用 `writing-fragments` 挖、议论文用 `writing-shape` 逐段成形、教程/旅程文用 `writing-beats`；架构/流程图按 `project-decoder` 的 diagram-guide 画 Mermaid
4. **排版自查**：markdown-typography-expert 规范过一遍
5. **发布登记**：用户发布后 → 成稿落 `writing/<slug>/`（draft + 定稿）→ 登记索引（系列/标题/链接/日期），这步脚本化程度最高

**落点**：新子库 `writing/`，一文一目录：`writing/<slug>/draft.md`（+assets/）。**成稿必须落库**（推荐理由：线上是平台资产可能改动/丢失；本地成稿是下次写作的复用素材）。

**验收用例**：把 Codex 403 复盘（流 A 产物）写成一篇实战短文全流程跑通。
