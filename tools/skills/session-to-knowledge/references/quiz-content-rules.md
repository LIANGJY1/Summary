# 出题内容规则

本文件定义 session-to-knowledge 生成复盘题（同源题目）时的内容标准，适用于全部输入（会话、文章、网页、粘贴文本）。题目服务于记忆、复盘和面试表达，不追求固定配额；出到输入已没有新的可学习信息为止。

## 1. 先建立出题对象模型

生成前在内部整理一张模型——文章输入对应材料本身，会话输入对应用户问题与已核验结论：

- **主线**：要解决的问题、适用场景和最终结论。
- **概念**：术语定义、对象关系、前置知识和容易混淆的相邻概念。
- **机制**：现象背后的原因、执行链路、数据流、状态变化和关键不变量。
- **方法**：步骤、决策条件、配置、代码/API 用法和验证方式。
- **边界**：前提、限制、异常、反例、版本/平台差异和不适用场景。
- **迁移**：把原则应用到新案例时，哪些条件保持、哪些条件改变。
- **争议**：输入没有证明、可能过时、表述绝对或需要结合上下文才能成立的地方。

模型只用于决定覆盖范围，不写进文档。输入没有给出的结论可以作为"待核实/批判"题，但答案必须明确标注推导边界，不能把推测写成事实。

## 2. 题目覆盖与拆分

题目数量不限，但每道题都必须有独立的复习价值。持续生成，直到主线、核心概念、关键机制、实际方法和会改变结论的边界都至少有合适题目覆盖。

题型不限，按输入需要选择，例如：事实回忆、概念解释、机制推演、步骤复述、代码/API 分析、故障诊断、场景设计、方案取舍、边界判断、反例辨析、批判审查、跨主题迁移和模拟面试追问。题型名称是内部设计依据，不写入文档。

拆题遵循以下判断：

- 一个问题只考一个主要判断；"是什么、为什么、怎么做、边界是什么"只有在它们构成同一条不可拆的因果链时才合并。
- 题面包含回答所需的场景、前提、输入或代码，不要求学习者凭"原文第二节"寻找上下文。
- 先覆盖输入明确承诺的结论，再覆盖能够检验真正理解的机制、应用和边界；不要为了凑数量制造换词重复题。
- 题目语言跟随输入语言；术语保留材料和目标技术生态中稳定的写法。

## 3. 面试级答案

答案要能让面试官判断学习者是否真正理解，而不是只背出关键词。每个答案按需要组织为一条清晰的解释链：

1. **先直答**：第一段用一至三句话给出结论、直接原因和推荐做法。
2. **再解释**：按"前提 → 行为/机制 → 结果 → 做法"的依赖顺序展开；多方案先给选择依据，再说明条件对应的做法。
3. **补边界**：加入会改变正确结论的前提、异常、反例、版本、平台或性能/安全影响。
4. **给最小例子**：只有示例能证明语法、类型、运行结果或方案差异时才加入；示例必须完整到可解释结果，不能引入无关概念。
5. **收束判断**：结尾给出可执行的判断规则；短答案已经完整时不添加重复总结。

答案只解释题面承诺的范围。删除任何段落后如果不影响学习者正确理解和使用结论，就删除该段；不要堆历史背景、术语清单、泛化建议或"延伸阅读"，也不把来源说明或内部分析过程写进答案。

## 4. 逐题质量门

写入前逐题检查：

- 只看题面，能知道场景、核心困惑和回答目标。
- 题面只有一个主要问题，且不依赖未提供的上下文。
- 答案首段已经明确回答；后续每段都服务于题面。
- 机制和因果连续，事实、推导和不确定性没有混写。
- 关键边界、版本、平台和前提已经覆盖；没有无依据的绝对表述。
- 示例完整、最小、结果可解释；没有通过示例偷渡无关知识。
- 没有与本批其他题目、也与文档内既有题目重复；题型变化服务于覆盖，而不是换皮。
- 标记行为粗体形态 `**Qn: 题面**`，编号未与文档内既有题重复，答案到下一个 Q 标记或标题为止边界清晰。

整批验收：主线、概念、机制、方法和边界均有覆盖；所有题目都能支持后续口头复述或模拟面试；Q 块能被 atlas 同源解析器识别；文档不因出题新增章节标题、小节标题或目录（Q 序列即结构）。

## 5. 与知识库写作指南的对应

本规则是 `knowledge-base/WRITING-GUIDE.md`（问题式笔记写作指南）在出题场景的执行标准，生成前必须先读该指南：标题补足场景和目标，答案首段直答，正文沿因果链展开，列表保持单一维度，示例最小完整，版本和边界只在改变结论时出现，完成后执行删除测试。这里将"一个 Q 解决一个问题"落实为"一道题考一个主要判断"，并将答案标准提升为可复述、可追问、可评分的面试级回答。
