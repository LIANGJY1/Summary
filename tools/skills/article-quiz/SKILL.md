# 文档/网页出题 → Atlas 同步

用户给出文档、网页或粘贴文本后，先完整理解输入，再把可复习、可面试的题目与答案写入 Atlas 收件箱。题型和数量由内容覆盖需要决定，不使用固定配比或数量上限。

**出题只是入口，"学会"由 Atlas 闭环检验**：题目经 Atlas「工作台」待确认区确认后落入题库（questions.md），用户在题库或学习流程中复盘、模拟面试并持续补漏。

## 执行流程

1. **读取输入**：识别为本地文档、网页 URL 或粘贴文本。文档必须完整读取；网页先抓取正文及页面标题；无法访问的网页要求用户提供正文或可访问链接。
2. **深度分析**：读取 `CONTENT-RULES.md`，按其中规则梳理主题、概念、机制、因果、步骤、示例、边界、反例和可迁移场景；区分原文事实、合理推导与无法确认的内容。
3. **设计题目**：覆盖所有值得记忆和复盘的核心内容，题型不限、数量不限；每题只考一个核心问题，答案达到面试级完整度。
4. **确定文件名**：使用源文件名（去扩展名）或原网页标题，追加生成当天日期 `YYYY-MM-DD`，清理文件名中的路径分隔符和不适合文件名的字符，保存为 `.md`。同名文件已存在时追加 `-2`、`-3` 等序号，不能覆盖已有文件。
5. **写入固定目录**：确保 `/home/liang/Project/MyProject/Summary/atlas/inbox/` 存在，将本次全部题目写入一个 Markdown 文件。
6. **质量检查**：逐题检查题面自包含、答案可独立评分、覆盖完整、没有编造、标签有效、协议可被 Atlas 解析；检查目标目录内没有本次输入的重复未处理文件。

## 输入与输出

- 支持本地文档路径、网页 URL 和用户直接粘贴的文本。网页使用页面原始标题命名；没有可靠标题时使用 URL 最后一级名称。
- 固定输出目录：`/home/liang/Project/MyProject/Summary/atlas/inbox/`。不再根据当前工作目录推断库根，也不写入其他 inbox。
- 输出文件名：`<源文件名或原网页标题>-YYYY-MM-DD.md`；日期取实际生成当天的本地日期。
- 一个输出文件承载本次全部题目，候选块之间使用单独一行的 `---` 分隔。

## Atlas 收件箱协议

每个候选块使用以下字段；`tags` 是有明确主题依据时才写的可选字段：

```
kind: question
q: 题面（单行）
answer: 完整答案第一行
  答案续行（缩进两空格）——答案落库为题目正文，供复习与转闪卡
tags: 性能优化, Android系统启动
```

- 必填字段只有 `kind: question`、`q`、`answer`。
- `tags` 可选，使用逗号分隔；优先复用 Atlas 内置标签「Android系统启动」「性能优化」「Handler」「操作系统」，确有必要时再使用稳定、简短、可复用的自定义标签。
- 不写 `source`、`ref`、`deck`、原文链接、文件路径、参考要点或其他来源元数据；来源只用于生成时理解材料。
- `q` 为单行题面；`answer` 支持缩进两空格的续行。答案必须是直接面向学习者的完整内容，不把来源说明或内部分析过程写进答案。
- 写入前检查固定 inbox 中是否已有同一输入的未处理候选；有则提示用户并避免重复生成，除非用户明确要求重新生成。

## 内容规则

完整内容规则见同目录 [`CONTENT-RULES.md`](CONTENT-RULES.md)，生成前必须读取，生成后按其逐题验收。该文件参照知识库语言笔记的标题、直答、因果、边界、示例和压缩原则，但题目答案以面试级复盘为目标。

## 完成报告

向用户报告：输入名称、题目总数、题型覆盖概况、使用的标签，以及实际写入的绝对文件路径。提示用户打开 Atlas「工作台」确认题目；确认后在「题库」或「学习」中复盘。
