# 序列化

> Java 对象序列化学习资料（2026-10-05 重构，自 exceptions-io-and-files.md 拆出）：对象图编码与字节流的本质差别、Serializable 与 Externalizable 的控制粒度、序列化与持久化的概念边界。Android 侧 Parcelable/Serializable 选型与 Parcel 契约归 `../../01-android/02-app-framework/03-parcel.md`，本文只写 Java 标准库语义。结论按 Java 序列化规范口径（JDK 8+ 为基线）。Q 序列即结构，供 atlas 同源直读。

**Q1: [learning] 用 ObjectOutputStream 写对象和逐字节写文件差在哪里？反序列化不可信数据为什么危险？**

普通文件 I/O 传输字节或字符；对象序列化按特定格式编码整个对象图——流中除字段值外还携带类描述符与对象引用关系，反序列化时据此在内存里重建对象。两者编码目标不同，不能互相替代。

1. **编码内容**：序列化流是自描述的（类名、字段布局随数据走），字节流只是原始数据，如何解释完全由读写双方约定。
2. **重建语义**：反序列化不经构造器、按流中数据直接填充对象，可完整恢复对象图与共享引用。
3. **信任边界**：反序列化会按流内容执行目标类的读取逻辑，不可信输入可借既有类的行为构造攻击链（gadget），因此不可信数据一律不用 Java 原生反序列化；跨版本还须管理 serialVersionUID 与兼容策略。
4. **长期存储**：格式绑定 Java 序列化机制本身，跨语言或长期契约应选有明确 schema 的格式。

**Q2: [learning] Serializable 与 Externalizable 在控制粒度上有什么差别？各自付出什么代价？**

`Serializable` 是标记接口，序列化机制按默认规则保存对象状态，也允许通过特定回调（writeObject/readObject 等）或字段声明调整行为；`Externalizable` 继承 Serializable，要求类实现 `writeExternal()` 与 `readExternal()`，由类显式定义要写入和读取的内容。

1. **控制粒度**：默认机制+局部定制（Serializable）到完全自控格式（Externalizable），粒度递增。
2. **代价**：Externalizable 把读写顺序、构造要求与版本兼容全部交给实现者维护，出错无基础设施兜底。
3. **共同边界**：两者都不能作为不可信输入的安全反序列化边界；在 Android Binder IPC 中也不应替代 Parcelable（平台契约归 Android 侧文档）。

**Q3: [learning] 对象序列化完成等于数据已持久化吗？两者在“进程结束后可恢复”上差在哪？**

不等于。序列化把内存对象编码成可传输或存储的表示，持久化是让数据在进程结束后仍能从可靠存储恢复——序列化结果可以只在内存或 IPC 中临时使用。

1. **概念关系**：序列化是编码动作，持久化是存储目标；完成序列化不保证任何字节落盘，数据库也可以直接持久化字段而不保存 Java 序列化流。
2. **可靠恢复的条件**：要跨进程重启或应用版本保存数据，还需明确写入位置、事务与格式兼容策略，不能只因对象实现了 Serializable 就假设状态可靠落盘。
3. **Android 侧提醒**：Parcel 虽同为序列化容器，但编码绑定平台实现，不能当持久化格式（机制与选型见 Android 侧 Parcel 册）。
