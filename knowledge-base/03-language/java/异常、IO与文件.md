# Java 异常、I/O 与文件

> Java 语言与标准库学习资料。Q 序列即结构。

**Q1: Java 的受检异常与非受检异常有什么区别？**

受检异常要求调用方捕获或在方法签名中声明；非受检异常包括运行时异常和错误，不受这项编译期义务约束。异常类型应表达调用者可处理的失败条件，而不是把所有问题都包装成同一异常。

捕获后应恢复、转换为更合适的异常或记录后继续；如果无法处理，应保留原因并向上层传播，不能静默吞掉异常。

**Q2: Java 中 File 与输入输出流分别表示什么？**

`File` 表示路径名及相关文件系统操作入口，不承载文件内容；输入输出流才负责传输字节或字符。`File` 对象存在不代表对应路径一定存在，也不保证创建成功。

现代 Java 新代码常用 `Path` 与 `Files` 表达路径和文件操作；文件操作要显式检查异常与返回状态，并考虑权限、并发变化和平台路径差异。

**Q3: Java 字节流、字符流和缓冲流怎样选择？**

字节流处理原始字节，适合图片、压缩包等二进制内容；字符流按字符处理文本并涉及字符集编码；缓冲流减少底层读写次数。处理文本时应明确字符集，不能依赖平台默认编码获得跨平台一致结果。

1. **二进制数据**：使用 `InputStream`/`OutputStream` 类族。
2. **文本数据**：使用 `Reader`/`Writer`，或显式配置字符集的字节与字符转换器。
3. **大量小块访问**：在适合的流外包装缓冲层，并在结束时正确关闭资源。

**Q4: Java 流为什么应使用 try-with-resources？**

实现 `AutoCloseable` 的资源可由 try-with-resources 在退出作用域时自动关闭，包括发生异常的路径。这样比依赖调用者记住所有分支上的 `close()` 更可靠；若关闭也失败，Java 会保留主异常并把关闭异常作为 suppressed exception。

**Q5: Java 对象序列化和文件字节读写有什么区别？**

普通文件 I/O 传输字节或字符；对象序列化按特定格式编码对象图并在反序列化时重建对象。序列化格式、类版本变化和反序列化输入信任边界都需要显式考虑，不能把“写入对象”当作稳定的跨版本数据契约。

不可信输入不应直接使用 Java 原生对象反序列化；长期持久化或跨语言交换通常应选择有明确 schema 与兼容策略的格式。

**Q6: Serializable 与 Externalizable 在对象序列化控制上有什么区别？**

`Serializable` 是标记接口，Java 序列化机制按默认规则保存对象状态，也允许特定回调或字段声明调整行为；`Externalizable` 继承 Serializable，要求类实现 `writeExternal()` 和 `readExternal()`，由类显式定义要写入和读取的内容。

Externalizable 给实现者更多格式控制，但增加了维护读写顺序、构造要求与版本兼容的责任。两者都不适合作为不可信输入的安全反序列化边界，也不应在 Android Binder IPC 中替代 Parcelable。

**Q7: 序列化与持久化有什么区别？**

序列化把内存对象编码成可传输或存储的表示；持久化是让数据在进程结束后仍能从可靠存储中恢复。序列化结果可以只在内存或 IPC 中临时使用，因此完成序列化并不等于已经持久化；反过来，数据库也能直接持久化字段而不保存 Java 对象序列化流。

要跨进程重启或应用版本保存数据，还需明确写入位置、事务与格式兼容策略，不能只因对象实现了 Serializable 就假设其状态可靠落盘。
