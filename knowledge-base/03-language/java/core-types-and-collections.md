# Java 基础类型与集合

> Java 语言、数组与常用集合学习资料。Q 序列即结构。

**Q1: Java 中 this 表示什么？为什么静态方法不能使用 this？**

在实例方法或构造器中，`this` 引用当前接收调用的对象；静态方法属于类而非某个实例，因此没有当前对象，不能使用 `this`。它也可用于区分同名字段与参数、在构造器中委托另一个构造器。

同一构造器中的 `this(...)` 必须作为首条构造器调用语句；它不能与 `super(...)` 同时用于该构造器的首调度步骤。

**Q2: Java 的 final 修饰变量、方法和类时分别限制什么？**

`final` 变量只能完成一次赋值；`final` 方法不能被子类覆盖；`final` 类不能被继承。它限制重新赋值或扩展，不自动使被引用对象不可变。

若 `final` 修饰对象引用，引用不能改指另一个对象，但该对象可变状态仍可能被修改。编译期常量还要求符合常量变量的类型与初始化条件，不能把所有 final 字段都视为编译期常量。

**Q3: Java 数组与 ArrayList 在容量和类型检查上有什么区别？**

数组长度创建后固定，运行时保留组件类型并检查存储；`ArrayList` 是可调整容量的泛型集合，编译器提供泛型类型检查，内部容量可随元素数增长。数组更适合固定长度或与需要数组 API 的接口交互，集合更适合动态增删。

Java 数组支持引用类型协变，因此把子类型数组作为父类型数组使用时，写入不匹配的元素会在运行时抛出 `ArrayStoreException`；泛型集合则通常是不变的。

**Q4: 为什么 Java String 的 == 与 equals 得到的结果可能不同？**

对引用类型，`==` 比较两个引用是否指向同一对象；`String.equals` 比较字符序列内容。字符串字面量可能通过常量池共享对象，但 `new String(...)` 会创建新对象，因此不能用 `==` 判断内容相同。

**Q5: 循环中反复拼接字符串时，何时应使用 StringBuilder？**

`String` 不可变，每次拼接会产生新的结果对象；循环中大量累积时可用 `StringBuilder` 在可变缓冲区追加，最后再生成字符串。少量简单拼接由编译器优化即可，不需要为了每个 `+` 手动创建 Builder。

**Q6: ArrayList 与 LinkedList 的插入、查找成本为什么取决于操作位置？**

`ArrayList` 以连续索引访问元素，随机读取通常为常数时间，但中间插入删除需要移动后续元素；`LinkedList` 通过节点链接存储，已持有节点时改链接成本较低，但按索引查找需要遍历。遍历定位、内存局部性和额外节点开销也会影响实际性能。

因此“链表插入总是 O(1)”不成立：如果还要先按索引寻找插入点，定位成本仍是线性的。

**Q7: Java 设计中应怎样选择抽象类或接口？**

选择取决于是否需要共享状态，以及能力是否需要跨类型组合：

1. **抽象类：**适合相关子类需要共享实例状态或实现代码的场景。
2. **接口：**适合为不同类定义可组合的能力契约。Java 类只能继承一个类，却可以实现多个接口，因此接口可表达横跨不同继承层次的能力。

这不是“is-a 对 has-a”的机械判断：两者都能表达抽象关系。选择时检查是否确实需要共享状态/实现、是否需要多类型组合，以及接口契约是否应该独立于某个类层次。

**Q8: Java 接口的 default 方法解决什么问题，有哪些限制？**

Java 8 引入的 `default` 方法允许接口提供实例方法的默认实现，可在演进接口时为既有实现类提供兼容的默认行为。实现类可以直接继承该实现，也可以覆盖它；接口默认方法仍不能声明实例字段来保存每个实现对象的状态。

若实现类继承的多个接口提供同签名默认方法，类必须明确覆盖并消解冲突；类层次中已有的具体实现优先于接口默认实现。default 方法适合无状态或可基于接口既有方法实现的通用行为，不适合替代需要对象状态的抽象基类。
