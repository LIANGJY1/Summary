# C++ 语言基础

> 本文从编程方式、头文件、命名空间、入口函数和基础 I/O 说明 C++ 的入门概念。

**Q1: [learning] 编程范式是什么，C++ 支持哪些范式？**

编程范式是组织程序和表达解决问题方式的模型。C++ 是多范式语言，可以在同一程序中组合不同范式。

1. **过程式：**用函数组织步骤，适合表达清晰的处理流程。
2. **面向对象：**用类封装状态与操作，适合表达具有身份和行为的对象模型。
3. **泛型：**用模板编写适用于多种类型的算法与容器，减少重复并保留编译期类型检查。
4. **函数式风格：**把函数作为值传递或组合，常用于算法和回调。C++ 可组合多种风格，不局限于单一范式。

**Q2: [learning] C 程序为什么常能编译成原生机器码，什么是 Runtime？**

C 通常由编译器翻译为目标平台的机器码，再由操作系统装载执行。机器码不意味着 C 程序没有运行时支持，也不意味着它天然比其他语言快。理解这些差异可从三方面入手：

1. **Runtime：**程序运行所需的支持代码与环境，包括启动代码、语言运行库和操作系统服务等。C/C++ 程序也会依赖相应运行库，只是通常不需要托管虚拟机。
2. **运行速度：**取决于算法、编译器优化、运行库和执行环境，不能仅凭语言名称判断。
3. **硬件访问：**指针和位运算能表达底层操作，但访问端口、设备或物理内存仍受操作系统、处理器权限和平台 API 限制。

**Q3: [learning] C++ 程序的可移植性体现在哪里，与 Java 有什么区别？**

可移植性是程序迁移到不同硬件或操作系统后仍能正确运行的程度。C++ 和 Java 都能编写可移植源代码，但编译产物与运行条件不同。

1. **C++：**通常针对目标平台重新编译，生成该平台的机器码。源代码能否复用取决于是否使用标准语言特性及可移植库。
2. **Java：**通常编译为字节码，由目标平台上的 Java 虚拟机（JVM，Java Virtual Machine）执行。同一份字节码可在兼容的 JVM 上运行。
3. **共同限制：**使用平台专属应用程序编程接口（API，Application Programming Interface）、应用二进制接口（ABI，Application Binary Interface）或硬件功能时，两者都需要适配，不能仅靠语言本身保证可移植。

**Q4: [learning] 头文件与 `.cpp` 源文件分别负责什么，为什么通常不包含 `.cpp`？**

头文件通常提供声明，`.cpp` 通常放非模板实现并单独编译。`#include` 是预处理阶段的文本包含，不是导入已编译代码。

1. 包含头文件后，当前翻译单元能看到声明并检查调用。
2. 构建时，各 `.cpp` 分别编译成目标文件，再由链接器组合。
3. 多个翻译单元包含同一个 `.cpp`，可能产生重复定义并违反单一定义规则。模板和需要在实例化处可见的定义通常放在头文件中。

**Q5: [learning] 为什么 `<iostream>` 不带 `.h`，而 `<unistd.h>` 带 `.h`？**

这是接口来源和命名约定不同造成的，扩展名本身不决定文件是不是头文件。

1. `<iostream>` 是 ISO C++ 标准库头文件，标准名称不带扩展名，声明位于 `std` 命名空间。
2. `<unistd.h>` 是 POSIX 接口头文件，不属于 ISO C++ 标准库。只有提供相应 POSIX 接口的平台才能使用。

**Q6: [learning] 包含 `<iostream>` 后，为什么仍要写 `std::cout`？**

`#include` 让声明可见，但不移除声明所属的命名空间。`cout` 属于 `std`，因此可写 `std::cout`。

`using namespace std;` 会让当前作用域的非限定名称查找也搜索 `std`。它不能代替 `#include`，而且可能引入名称冲突。

**Q7: [learning] 为什么通常不在头文件或宽作用域中写 `using namespace std;`？**

它会把 `std` 中大量名称带入当前作用域，增加与项目名称冲突的机会。需要少数名称时，可使用限定名或精确引入。

1. **限定名：**直接写 `std::cout`，作用范围最明确。
2. **using 声明：**`using std::cout;` 只引入 `cout`。
3. **`using namespace` 的限制：**它后面必须是命名空间名，不能写 `using namespace std::cout;`。
4. **原因：**`cout` 是对象，不是命名空间。要精确引入它，应写 `using std::cout;`。

**Q8: [learning] C 头文件在 C++ 中有哪些对应写法？**

C++ 为多数 C 标准库头文件提供了去掉 `.h` 并加 `c` 前缀的形式，例如 `<stdio.h>` 对应 `<cstdio>`，`<math.h>` 对应 `<cmath>`。

使用 C++ 形式可通过 `std::` 使用标准库名称。旧式 `.h` 头文件在不少实现中仍可用，但名称暴露到全局命名空间的细节不应作为可移植保证。POSIX 头文件如 `<unistd.h>` 没有这种标准 C++ 对应形式。

**Q9: [learning] `int main()`、`int main(void)` 和 `void main()` 有什么区别？**

在 C++ 中，`int main()` 与 `int main(void)` 都表示不接收参数并返回 `int`。标准的 hosted 程序应使用 `int` 返回类型。

`void main()` 不是标准 C++ 程序入口的合法形式。某些编译器可能作为扩展接受，但不应依赖。

**Q10: [learning] `main()` 需要显式写 `return 0;` 吗？**

不需要。执行到 `main()` 的末尾等价于返回 `0`，表示正常结束。

1. 该规则只适用于 `main()`。
2. 普通的非 `void` 函数必须在所有可能的正常返回路径上提供返回值。

**Q11: [learning] 独立运行的 C++ 程序必须有 `main()` 吗，与 Java 有何不同？**

常见桌面和 Android 用户空间程序属于 hosted 实现，入口由实现规定为 `main()`。C++ 的 freestanding 实现可以采用实现定义的启动方式，因此不能把该结论推广到所有嵌入式环境。

Java 启动器会选择一个符合入口约定的类及其 `main` 方法。动态库是供其他程序加载的组件，本身通常不以 `main()` 作为入口。

**Q12: [learning] `_tmain()` 是什么，能否用于标准 C++ 程序？**

`_tmain` 是 Microsoft TCHAR 兼容层提供的宏式入口名，不属于 ISO C++ 标准。它会依据字符集配置映射到 `main` 或微软扩展 `wmain`。

跨平台程序使用标准 `main()`。只有在使用相应 Microsoft 工具链和 TCHAR 约定时，才考虑 `_tmain()`。

**Q13: [learning] `std::cout` 是对象吗？**

是。`std::cout` 是标准库提供的 `std::ostream` 对象，通常连接到标准输出。重定向后，它也可以写入文件或管道，不能简单等同于屏幕。

**Q14: [done] C++ 程序向 `std::cout` 输出后立即阻塞等待，未刷新流会造成什么问题？如何确保日志显示？**

对应代码是：

```cpp
std::cout << "Mini-Android init";
while (true) {
    pause();
}
```

输出语句没有刷新 `std::cout`，而 `pause()` 只等待信号，不会刷新流；因此缓冲区中的日志没有被送到终端显示。要立即显示，可用 `std::endl`（换行并刷新）或 `std::flush`（只刷新）；单独的 `\n` 不会主动刷新流。

例如：

```cpp
std::cout << "Mini-Android init" << std::endl;
```

**Q15: [learning] `std::cin.get()` 放在程序末尾有什么作用？**

无参数的 `get()` 从输入流读取一个字符并返回，因此常被用来等待一次输入。但它可能读走此前缓冲的字符，也不是通用的“暂停程序”机制。

调试时优先在 IDE 中设置断点。需要交互时应明确读取并处理用户输入，不要依赖控制台窗口行为。

**Q16: [learning] 什么是 Token，标识符和 Token 是什么关系？**

Token 是编译器词法分析阶段识别出的记号，例如关键字、标识符、字面量、运算符和标点符号。标识符只是 Token 的一种，用于命名变量、函数、类型等实体。

**Q17: [learning] 字符串字面量和注释分别会怎样处理？**

字符串字面量和注释的处理不同：

1. **字符串字面量：**双引号括起的内容会作为程序数据参与后续翻译。
2. **注释：**用于源码说明，不会作为程序语句执行。
    1. `//` 注释延续到当前行末。
    2. `/* ... */` 注释延续到结束标记，不能按普通注释形式嵌套。
    3. 翻译阶段会处理注释，但不能据此说注释必然以简单的“预处理器删除”方式工作。

**Q18: [learning] `int carrots;` 是声明还是定义，变量何时获得存储？**

在函数块内，`int carrots;` 定义一个具有自动存储期的 `int` 对象。对象的存储期由声明位置和存储期规则决定，不是所有变量都分配在栈上。

1. **定义：**提供实体并为对象建立存储。
2. **声明：**让名字及其类型对当前作用域可见。`extern int carrots;` 通常是对其他位置定义对象的声明。
3. **未初始化的局部标量：**不会自动变成零，读取不确定值可能导致未定义行为。
4. **静态存储期对象：**先进行零初始化。

**Q19: [learning] `carrots = 25;` 做了什么，赋值表达式还有什么结果？**

赋值把右侧值转换为左侧对象的类型，再更新该对象。内建赋值表达式的结果是指向左侧对象的左值，因此可写 `a = b = 25;`，其结合方式为 `a = (b = 25)`。

**Q20: [learning] `std::cout << "25"` 和 `std::cout << carrots` 输出方式有什么不同？**

两者调用的插入运算符重载不同：前者输出字符串字面量中的字符，后者把 `int` 按流的格式设置转换为文本。程序不需要手写 `printf` 风格的格式占位符。

**Q21: [learning] 为什么 `std::cout << "A" << "B" << carrots;` 可以连续输出？**

每次流插入都会返回流对象的引用，因此表达式按左结合继续在同一个流上调用插入运算符：`((std::cout << "A") << "B") << carrots`。

**Q22: [learning] C++ 中的类和对象分别是什么？**

类定义一种用户自定义类型及其成员。对象是该类型的一个实体，有自己的生命周期和状态。静态数据成员由类共享，不会在每个对象中各存一份。
