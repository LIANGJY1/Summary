# C++ 自定义类型

> 本文说明结构体、共同体和枚举的类型定义、对象布局与取值规则。

**Q1: [learning] 结构体和数组有什么区别，定义结构体何时会分配对象存储？**

数组和结构体组织数据的方式不同：

1. **数组：**包含多个同类型元素。
2. **结构体：**把不同成员组合成一个类型。

声明 `struct` 类型描述本身不创建该类型的对象，定义具体变量时才有对象及其存储。

```cpp
struct Inflatable {
    char name[20];
    float volume;
};

Inflatable balloon{};
```

此处 `Inflatable` 是类型，`balloon` 是对象。对象的成员可能因对齐要求而有填充，不能仅把成员大小相加作为对象总大小。

**Q2: [learning] 在函数内外定义结构体类型有什么区别，为什么谨慎使用全局变量？**

在函数内定义的类类型具有局部作用域，函数外定义的类型可在其可见范围内复用。类型声明本身不等同于创建全局对象。

全局变量具有静态存储期并可被多个函数访问，容易形成隐式耦合和共享状态。语言没有禁止全局变量，但应按设计需要使用，并优先缩小可变状态的可见范围。

**Q3: [learning] 结构体的列表初始化有什么规则，何时会拒绝初始化？**

满足聚合类型规则的结构体可以按成员顺序列表初始化：

1. 空列表会对成员进行值初始化。
2. 列表初始化会拒绝不允许的窄化转换。

```cpp
struct Point {
    int x;
    double y;
};

Point origin{};
Point p{2, 3.5};
```

类一旦包含特定构造函数或其他不满足条件的成员，是否属于聚合类型会改变。C++20 调整过聚合类型规则，需按目标标准版本判断。

**Q4: [learning] 能否在定义结构体时同时定义变量，匿名结构体和结构体数组是什么？**

可以在结构体定义的右花括号后声明对象，也可以先定义类型、再单独声明对象。单独的无名结构体类型可创建该处的对象，但之后不能通过类型名重复声明对象。

```cpp
struct Point {
    int x;
    int y;
} origin{};

Point points[2]{{1, 2}, {3, 4}};
```

标准 C++ 不支持把匿名结构体直接作为另一个结构体的成员并暴露其字段。某些编译器将这种写法作为扩展提供。

**Q5: [learning] 结构体位字段能保证成员精确占用指定比特吗？**

位字段适合紧凑表达小范围整数标志，但需要区分声明宽度和物理布局：

1. 位字段可限制成员的声明宽度。
2. 具体分配顺序、存储单元布局和对齐受实现影响，不保证可移植的物理布局。

1. 位字段的分配顺序、存储单元布局和对齐受实现影响。
2. 位字段类型和宽度受语言规则限制，无名位字段可用于填充。
3. 直接用位字段映射硬件寄存器或网络协议可能依赖编译器布局。需要可移植布局时，应按协议显式编码与解码。

**Q6: [learning] `union` 与 `struct` 的存储和使用方式有什么不同？**

结构体和共同体的存储方式不同：

1. 结构体为各成员分别提供存储。
2. 共同体的成员共享同一片存储，因此同一时刻通常只有一个活动成员。

共同体大小至少足以容纳其最大成员，但也受对齐和实现影响。读取非活动成员通常不合法，存在标准规定的特定例外。需要安全表达“多种类型之一”时，优先考虑 `std::variant`。

**Q7: [learning] 匿名共同体如何让成员直接出现在外层作用域？**

匿名共同体没有共同体类型名和成员对象名，其成员名直接注入包含作用域，因此可以用外层对象访问成员。

```cpp
struct Value {
    bool is_number;
    union {
        int number;
        char text[16];
    };
};
```

此例需要 `is_number` 这样的标签记录当前有效成员，并由程序维护一致性。共同体不会自动检查标签与活动成员是否一致。复杂场景可用 `std::variant`。

**Q8: [learning] 枚举值如何确定，枚举与 `const` 有什么关系？**

枚举定义一种枚举类型，并为其枚举项命名。枚举值按以下规则确定：

1. 未显式赋值时，第一个枚举项为 `0`，后续项依次递增。
2. 也可以显式指定底层值。

枚举项不是 `const` 变量的别名。两类枚举的名称和转换规则不同：

1. **无作用域枚举：**枚举项会在外层作用域引入名称，并可按规则隐式转换为整数类型。
2. **作用域枚举：**`enum class` 将名称限定在枚举类型中，不会隐式转换为整数。

**Q9: [learning] 枚举与整数之间有哪些隐式转换规则？**

隐式转换方向受枚举种类限制：

1. 无作用域枚举可以按标准规则提升为整数类型。
2. 作用域枚举不会隐式转为整数。
3. 整数不能隐式赋给枚举变量。

```cpp
enum Color { red, blue };
enum class State { ready, busy };

int value = red;
int state_value = static_cast<int>(State::ready);
```

枚举不保证只存显式列出的名称，不能靠“枚举变量只接受枚举常量”进行运行时校验。枚举自增也不是内建支持的操作。

**Q10: [learning] 能否把整数强制转换为枚举，枚举的取值范围是什么？**

可以显式转换，但“能写出强制转换”不等于转换结果一定是已命名枚举项或适合业务使用。

1. **有固定底层类型：**整数先按底层类型的转换规则转换，再成为枚举值。该值不一定对应已命名的枚举项。
2. **没有固定底层类型：**整数必须在枚举可表示范围内。按当前标准，范围外的 `static_cast` 会导致未定义行为。
3. **位标志：**应显式定义底层类型、允许的位组合和验证规则，不要把任意整数当成有效枚举值。

相关规则见 ISO C++ 工作草案的 `[dcl.enum]` 和 `[expr.static.cast]`。
