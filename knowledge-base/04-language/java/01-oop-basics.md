# 类、接口与关键字

> Java 面向对象基础学习资料（2026-10-05 重构，自 core-types-and-collections.md 拆出）：this 语义与内部类引用、final 的三层限制、抽象类与接口的选型、接口 default 方法及其冲突消解。结论按 Java 语言规范口径（JDK 8+ 为基线，涉及版本处单独标注）。Q 序列即结构，供 atlas 同源直读。

**Q1: [learning] 实例方法与构造器中的 this 指向什么？为什么静态方法里不能用 this？**

在实例方法或构造器中，`this` 引用当前接收调用的对象。静态方法属于类而非某个实例，没有“当前对象”，因此不能使用 `this`。它也可用于区分同名字段与参数、在构造器中委托另一个构造器。

1. **指向规则**：this 的值由调用点决定——谁接收这次方法调用，方法体内的 this 就指向谁。它不能被赋值，也不是可变的引用变量。
2. **构造器委托**：同一构造器中的 `this(...)` 必须作为首条语句，且不能与 `super(...)` 同时出现，因为创建过程只能有一次父类或兄弟构造器的首调度。
3. **lambda 边界**：lambda 体中的 this 沿用外围方法的词法作用域，仍指向外围实例。匿名内部类中的 this 则指向匿名类实例自身。从匿名类改写为 lambda 时，若方法体用到 this，行为可能随之改变。

**Q2: [learning] final 修饰变量、方法和类分别限制什么？为什么 final 引用指向的对象仍然可能被修改？**

`final` 变量只能完成一次赋值。`final` 方法不能被子类覆盖。`final` 类不能被继承。它限制的是重新赋值或扩展，不自动使被引用对象不可变。

1. **变量**：引用不能改指另一个对象，但该对象的可变状态（字段、元素）仍可修改。要真正不可变需对象自身不可变设计。
2. **方法**：禁止子类覆盖，锁定行为契约。但不影响重载。
3. **类**：禁止继承（如 String）。
4. **编译期常量**：final 字段只有同时满足常量类型与初始化条件才是编译期常量（可参与常量折叠），不能把所有 final 字段都当成常量。

**Q3: [learning] 需要共享实现或定义能力契约时，抽象类与接口应该怎样选择？**

选择取决于是否需要共享状态，以及能力是否需要跨类型组合：

1. **抽象类**：适合相关子类需要共享实例状态或实现代码的场景。
2. **接口**：适合为不同类定义可组合的能力契约。Java 类只能继承一个类，却可以实现多个接口，因此接口可表达横跨不同继承层次的能力。

这不是“is-a 对 has-a”的机械判断：两者都能表达抽象关系。选择时检查三件事——是否确实需要共享状态或实现、是否需要多类型组合、接口契约是否应该独立于某个类层次。

**Q4: [learning] 接口的 default 方法解决了什么演化问题？实现类继承到两个同签名默认方法时怎么办？**

Java 8 引入的 `default` 方法允许接口提供实例方法的默认实现，核心价值是接口演进：给既有实现类补新方法时不必破坏它们。实现类可以直接继承该实现，也可以覆盖它。接口默认方法仍不能声明实例字段保存状态。

1. **继承与冲突**：若实现类继承的多个接口提供同签名默认方法，类必须显式覆盖消解冲突。类层次中已有的具体实现优先于接口默认实现。
2. **显式引用**：类内沿用某个接口的默认实现可用 InterfaceName.super.method() 语法。
3. **具体性规则**：默认方法沿接口继承链传递，菱形冲突时“更具体的接口”胜出——子接口已覆盖该默认实现时优先采用。只有各分支同样具体、无法分出优劣时，编译器才强制类显式覆盖。
4. **适用边界**：default 方法适合无状态、可基于接口既有方法实现的通用行为，不适合替代需要对象状态的抽象基类。复杂逻辑放进来会污染接口职责。

**Q5: [learning] 非静态内部类为什么能访问外部实例的私有成员？this$0 与内存泄漏有什么关系？**

`this$0` 是编译器为非静态内部类（含匿名内部类）生成的合成字段，保存创建该实例时所用外部类实例的引用。内部类能直接访问外部实例成员，机制就是编译器把外部引用作为隐藏参数传入并保存在这个字段里。静态嵌套类没有该字段，也不持有外部实例。

这层隐式引用是经典泄漏源的机制基础：在 Activity 或其他长生命周期宿主里用匿名内部类实现 Handler、Runnable 或 Thread 时，只要这些对象活得比宿主久——排队的 Message 持有 Handler、未结束的线程持有 Runnable——宿主实例就会经 `this$0` 被连带持有而无法回收。处理方向是缩短内部类对象的寿命（销毁时移除回调、取消任务），或改用静态嵌套类并显式传入所需数据。判断某个类是否隐式持有外部实例，反编译后查看是否出现 `this$0` 字段即可。
