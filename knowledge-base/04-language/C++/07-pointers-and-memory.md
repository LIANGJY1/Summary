# C++ 指针与内存

> 本文说明指针、数组退化、动态存储期、`new`/`delete` 与标准容器的关系。

**Q1: [learning] 变量和指针分别表示什么？**

变量名指代对象，指针对象保存地址。基本操作如下：

1. `&object` 取得对象地址。
2. 对有效指针使用 `*ptr`，可访问其指向的对象。
3. 指针类型限制可访问的对象类型。空指针不指向对象，不能解引用。

**Q2: [learning] `int *ptr` 的声明如何理解，星号对多个变量声明有何影响？**

`int *ptr` 声明 `ptr` 为指向 `int` 的指针。声明符中的 `*` 作用于相邻的变量名，而不是让整行后续变量都成为指针。

```cpp
int* first, second;
```

此处 `first` 是 `int*`，`second` 是 `int`。为避免误读，多个指针分开声明，或在每个声明符前写 `*`。

**Q3: [learning] 为什么不能解引用未初始化的指针？**

未初始化的指针不保证保存有效地址。读取它本身就可能产生未定义行为，解引用则不能保证指向存活且类型适合的对象。

```cpp
int* ptr = nullptr;
```

先初始化为 `nullptr`，再在确认指针指向有效对象后解引用。不要把“垃圾地址”当成每次都会稳定出现的值。

**Q4: [learning] `int* ptr = &value;` 初始化了指针还是指针所指对象？**

它初始化的是指针对象 `ptr`，把 `value` 的地址存入 `ptr`。`value` 本身没有因此改变。

```cpp
int value = 5;
int* ptr = &value;
```

之后 `*ptr = 8;` 才会通过指针修改 `value`。

**Q5: [learning] 为什么不能直接把整数地址赋给对象指针？**

整数和指针是不同类型，普通赋值不会把任意整数解释为有效对象地址。整数到指针的显式转换依平台实现，结果未必指向可访问对象。

硬件寄存器访问、MMIO（Memory-Mapped I/O，内存映射 I/O）等必须遵循目标平台和编译器约定，不能把随意强制转换当作可移植做法。普通 C++ 代码应通过对象地址、容器或资源 API 获得指针。

**Q6: [learning] 指针和 `new` 有什么关系，C 的 `malloc()` 与 C++ 的 `new` 有何区别？**

指针可间接访问对象、表达可选对象和与 C API（Application Programming Interface，应用程序编程接口）交互。动态分配相关概念如下：

1. `new` 表达式创建具有动态存储期的对象并返回其地址。若程序之后需要访问或释放该对象，就必须保存或传递这个地址。
2. `malloc()` 只分配原始存储并返回 `void*`，不会调用 C++ 对象的构造过程。

```cpp
int* value = new int{5};
delete value;
```

动态存储期不等于语言规定的“堆”实现，也不要求直接使用裸指针。现代 C++ 通常优先使用 `std::vector`、`std::unique_ptr` 等自动管理资源的类型。`nullptr` 表示空指针值，不指向可解引用对象。

**Q7: [learning] `delete` 释放什么，`new`/`delete` 应如何配对？**

`delete ptr` 结束由匹配 `new` 表达式创建的对象生命周期，并调用相应释放函数。指针变量本身仍然存在，错误配对会导致未定义行为。

1. 单对象 `new T` 对应 `delete ptr`。
2. 数组 `new T[n]` 对应 `delete[] ptr`。
3. 不能删除栈对象、全局对象或已经删除的对象。
4. 不能重复释放同一资源。
5. `delete nullptr` 是安全操作，但删除后把其他别名置空并不能修复悬空引用。
6. 优先用 RAII 与智能指针管理所有权，避免手动配对遗漏。

**Q8: [learning] 数组名和指针能互换使用吗？**

不能把数组和指针当成同一种对象。数组在多数表达式中会转换为指向首元素的指针，但仍保留自己的数组类型和元素存储。

数组与指针需区分以下行为：

1. 在 `a[i]` 中，下标运算等价于 `*(a + i)`。
2. 数组名不能被重新赋值，独立指针可以改指向。
3. 数组在函数形参中会调整为指针，因此长度通常需要另行传递。

**Q9: [learning] 指针加一为什么不是地址数值简单加一？**

对指向数组元素的 `T*` 加一，会指向同一数组中的下一个 `T` 元素。实现按 `sizeof(T)` 所对应的步长处理。

指针算术只在同一数组范围内，或恰好计算到尾后位置时才有定义。尾后指针可用于结束判断，但不能解引用。

**Q10: [learning] 数组名和指针的关键差异有哪些？**

数组是一组连续元素，指针是保存地址的独立对象。数组表达式常退化为指针，但两者在赋值、大小和函数传参上的行为不同。

1. 数组不能整体赋值，指针变量可以改为指向别处。
2. 在数组仍是数组的作用域中，`sizeof(array)` 得到整个数组占用字节数。`sizeof(pointer)` 得到指针对象大小。
3. 数组传入函数时会调整为指针形参，函数无法仅凭该形参推导原数组长度。

**Q11: [learning] `tell` 和 `&tell` 起始地址相同，类型与指针步长为何不同？**

对 `short tell[10]`，`tell` 在多数表达式中转换为 `short*`，指向首元素。`&tell` 的类型是指向整个数组的指针 `short (*)[10]`。两者起始位置相同，但指针算术步长不同。

1. `tell + 1` 前进一个 `short` 元素。
2. `&tell + 1` 前进整个数组的大小，即 `sizeof(tell)`。

**Q12: [learning] 内建数组与动态数组的长度分别何时确定？**

内建数组的长度必须满足语言的数组界限要求。运行时才确定的长度通常使用动态分配或容器。C++ 标准不要求内建数组一定放在栈上，也不要求动态存储一定对应某种物理堆实现。

需要运行时长度时优先用 `std::vector<T>`，它同时保存元素数量并管理存储。

**Q13: [learning] `new int[n]` 如何创建动态数组，如何安全访问？**

数组 new 表达式创建 `n` 个连续的 `int` 对象并返回指向首元素的 `int*`。指针不保存数组长度，因此调用方必须另行保存长度。

```cpp
int main() {
    int n = 3;
    int* values = new int[n]{};
    values[0] = 1;
    delete[] values;
}
```

空花括号使元素值初始化为零。访问前要确保下标小于 `n`，并在所有退出路径上用匹配的 `delete[]` 释放。通常直接使用 `std::vector<int> values(n)` 更安全。

**Q14: [learning] 指针移动到数组中间后，为什么不能用它释放整个动态数组？**

数组释放必须传入数组 new 表达式返回的指针值。指向中间元素的指针不能作为 `delete[]` 操作数，否则行为未定义。

保留原始所有者指针并使用索引遍历数组。更好的做法是使用 `std::vector`，避免手动移动和释放所有权指针。

**Q15: [learning] `char*`、字符数组和字符串字面量在 `std::cout` 中如何输出？**

字符数组在表达式中通常转换为首字符指针。输出流对 `char*` 和 `const char*` 有字符串重载，会从该地址读取字符直到 `\0`，而不是显示地址。

其他对象指针通常按地址形式输出。需要打印字符缓冲区地址时，可显式转换为 `const void*`。只有缓冲区确实以 `\0` 结尾时，才能按 C 字符串输出。

**Q16: [learning] 为什么读取字符串时目标缓冲区必须有效且有足够容量？**

输入操作会向目标存储写字符，因此目标必须指向仍存活且容量足够的缓冲区。未初始化指针不能作为输入目标。

1. 对字符数组输入，限制最多写入的字符数并为 `\0` 留位置。
2. 对一般文本输入，优先读入 `std::string`，再按业务限制长度。
3. 复制字符数据才会形成独立字符串副本。复制指针只会让两个指针指向同一缓冲区。

**Q17: [learning] 为什么动态结构体指针用 `->` 访问成员？**

`ptr->member` 等价于 `(*ptr).member`。指针不是结构体对象，不能直接用 `ptr.member`。箭头运算符是更简洁的成员访问语法。

动态分配的对象仍是对象，只是没有由声明引入的变量名。`*ptr` 是指代该对象的表达式。“匿名内存”只是口语说法。

```cpp
struct Item { int price; };

int main() {
    Item* item = new Item{5};
    int price = item->price;
    delete item;
    return price == 5 ? 0 : 1;
}
```

**Q18: [learning] 自动、静态和动态存储期有什么区别？**

存储期决定对象存储可用的时间范围。“栈”和“堆”是常见实现说法，不是 C++ 对每个对象的物理布局保证。

1. **自动存储期：**通常对应块作用域局部对象，离开作用域时生命周期结束。
2. **静态存储期：**通常对应命名空间作用域对象和静态局部对象，程序执行期间一直存在。
3. **动态存储期：**由分配机制创建，生命周期由程序控制，宜用容器或智能指针管理。
4. 线程存储期对象在对应线程执行期间存在。

**Q19: [learning] `new` 一定必须赋给裸指针吗？**

不必须，但丢弃 `new` 返回值通常会失去管理对象的途径并造成资源泄漏。`new` 表达式返回指针，可赋给裸指针、智能指针或传给其他所有者。

现代 C++ 通常用 `std::make_unique<T>()` 创建独占对象，用 `std::vector<T>` 管理动态数组，而不是直接编写 `new` 和 `delete`。

**Q20: [learning] 结构体数组与指针数组的内存布局有什么区别，`const` 修饰谁？**

两种数组的内存内容不同：

1. 结构体数组连续存放结构体对象。
2. 指针数组连续存放指针值，指针所指对象可以分散在内存中。

```cpp
struct Item { int field; };

int main() {
    Item first{1};
    Item second{2};
    const Item* pointers[2] = {&first, &second};
    return pointers[0]->field + pointers[1]->field;
}
```

这里 `const` 修饰 `Item`，不能经由这些指针修改对象，但其他可写别名仍可能修改对象。指针数组适合重排较大的对象引用，但会增加间接访问。这不意味着整个操作“零拷贝”。

**Q21: [learning] `const T**`、数组退化与 `auto` 推导如何关联？**

若 `arp` 是 `const Item* arp[3]`，在一般表达式中数组会转换为指向首元素的指针，类型为 `const Item`。因此按值声明 `auto ppb = arp;` 通常也推导为 `const Item`。

1. `ppb + 1` 指向指针数组的下一个槽位。
2. `*(ppb + 1)` 取得该槽位中保存的 `const Item*`。
3. `(*(ppb + 1))->field` 再访问其指向对象的成员。

多级指针不代表动态分配。若函数需要遍历指针数组，还应传递长度。需要修改指针槽位时，参数的 `const` 层级也必须与调用方类型匹配。

**Q22: [learning] `std::vector` 和 `std::array` 与内建数组有什么区别？**

两种容器都提供标准接口，但长度、存储和边界检查方式不同：

1. `std::vector`：管理运行时可变长度的连续元素序列，保存元素数量和容量。扩容可能搬移元素并使指针、引用和迭代器失效。
2. `std::array<T, N>`：封装长度固定为编译期常量的数组，元素属于容器对象。对象本身的位置由其存储期决定。
3. **边界检查：**两者的 `operator[]` 都不检查边界，`.at()` 会检查并在越界时抛出异常。

默认优先使用标准容器。只有接口或布局要求时才直接管理原生数组和裸指针。
