# C++ 函数与类型

> 本文介绍函数声明与入口、基本类型、初始化、字符和浮点数的语言规则。

**Q1: [learning] 函数有返回值与 void 返回类型有什么区别？**

返回类型决定调用表达式是否产生可供程序使用的结果。结果通过寄存器还是内存传递属于调用约定和目标平台细节，不由 C++ 语言保证。

1. **非 `void`：**函数通过 `return` 提供符合返回类型的值。
2. **`void`：**函数不提供可供调用方使用的返回值，但仍可执行副作用。

**Q2: [learning] char **argv 与 char *argv[] 形参为何等价？**

`char **argv` 是指向 `char*` 的指针。`argv[i]` 指向第 `i` 个参数字符串，`argv[i][j]` 表示其中第 `j` 个字符。函数形参中的 `char *argv[]` 会调整为 `char **argv`，因此两种形参声明等价。

1. **参数结构：**`argv` 指向由 `char*` 组成的序列，每个元素指向一个以空字符结尾的字符串。`argv[0]` 按约定表示程序名。
2. **参数数量：**`argc` 单独提供元素个数，合法索引为 `0` 至 `argc - 1`。标准还保证 `argv[argc]` 为空指针。
3. **形参调整：**数组形参按元素类型调整为指针形参，因此 `char *argv[]` 调整为 `char **argv`。此规则仅适用于形参，独立数组仍是数组，`sizeof` 结果不同。
4. **元素类型边界：**`char argv[][16]` 调整为指向 `char[16]` 的指针，与 `char **` 不同。

例如：

```cpp
void parse_args(int argc, char *argv[]);

int FirstStageMain(int argc, char **argv) {
    parse_args(argc, argv);
    return 0;
}
```

形参写作 `char *argv[]` 的函数可直接接收 `char **argv` 实参，因为数组形参调整后类型相同。

**Q3: [learning] 为什么调用函数前必须让编译器看到它的声明？**

编译器需要先知道函数名、参数类型和返回类型，才能检查调用并生成代码。C++ 不支持对未声明函数的隐式声明。

1. 自定义函数可先声明，再在后文定义。
2. 多个源文件共享的声明通常放在头文件中，定义放在一个 `.cpp` 文件中。
3. 标准库声明由对应头文件提供，例如数学函数声明在 `<cmath>`。

**Q4: [learning] 为什么 C++ 函数链接名可能和源码函数名不同？**

C++ 支持函数重载和命名空间，编译器通常通过名字修饰（name mangling）将相关信息编码到链接名，以区分不同实体。

具体编码由编译器和应用二进制接口（ABI，Application Binary Interface）决定。前置下划线不是通用规则。跨 C/C++ 边界时，可按平台要求使用 `extern "C"`。

**Q5: [learning] C++ 为什么提供多种整型以及有符号、无符号类型？**

不同整型提供不同的最小取值范围，供程序表达数据约束或匹配接口。对象宽度受实现影响，不能假定某类型在所有平台都占固定字节数。

1. **有符号类型：**可表示负数、零和正数。
2. **无符号类型：**表示非负值，并按模运算规则处理溢出。仅在确实需要该语义时使用。与有符号数混合运算时需考虑转换规则。
3. **固定宽度需求：**优先检查 `<cstdint>` 提供的 `std::int32_t` 等类型是否由目标实现提供。

**Q6: [learning] short、int、long 为什么不是固定字节数？**

C++ 标准规定整型之间的最小范围和相对顺序，不规定它们在所有平台使用相同字节数。`sizeof(int)` 查询当前实现中的对象大小，单位是 C++ 字节。

标准为各整型规定最小范围，但具体位宽依实现而异。精确范围可用 `std::numeric_limits<T>` 或 `<climits>` 查询。类型宽度也不直接代表性能。

**Q7: [learning] 如何查询整型类型的取值范围？**

`<climits>` 提供整型取值范围宏，例如 `INT_MAX`。`std::numeric_limits<T>` 提供对应类型的边界信息。需要按类型编写通用代码时，优先使用 `std::numeric_limits<T>`。

**Q8: [learning] int a{7}、int b = {12} 和 int c{} 分别表示什么？**

这些是列表初始化语法，具体效果如下：

1. `int a{7}` 和 `int b = {12}` 分别初始化为 `7` 和 `12`。
2. `int c{}` 对 `int` 进行值初始化，结果为 `0`。

列表初始化会拒绝不允许的窄化转换，例如 `int value{3.14};` 会编译失败。Java 数组初始化中的花括号是另一种语法。

**Q9: [learning] 函数内的 int value; 未初始化就读取会怎样，Java 又如何处理？**

块作用域的内建标量变量若没有初始化，不会自动置零。读取其未确定值的规则随标准版本变化：

1. **C++17 至 C++23：**读取此类不确定值通常导致未定义行为。
2. **C++26 工作草案：**自动存储期对象的未初始化字节通常具有错误值（erroneous value），读取会导致错误行为（erroneous behavior）。
3. **Java：**局部变量必须在读取前明确赋值，否则编译器拒绝编译。

**Q10: [learning] C++ 如何确定整数字面量的类型？**

整数字面量的类型由进制、后缀和值共同决定。无后缀十进制字面量按标准规定的顺序尝试 `int`、`long`、`long long` 等候选类型。八进制和十六进制还会考虑无符号类型。

1. `42` 是十进制，前导 `0` 表示八进制，`0x2A` 表示十六进制。
2. `u`、`l`、`ll` 等后缀会影响候选类型，组合顺序须符合字面量语法。
3. 需要精确宽度时使用 `<cstdint>` 中可用的定宽类型，不依赖平台的 `long` 宽度。

**Q11: [learning] char 一定表示 ASCII 字符吗，为什么不用 int 存字符？**

`char` 是字符类型，大小为一个 C++ 字节，并足以表示基本执行字符集。它不保证使用 ASCII，也不保证默认具有符号性。

`int` 也可保存字符相关数值，例如字符输入接口用 `int` 区分字符值和 `EOF`。文本编码单元数不等于字符数。一个 UTF-8 字符可能由多个 `char` 代码单元组成。

**Q12: [learning] C++ 数字转义怎样书写？\0x8 为什么错误？**

转义序列在编译期表示字符或数值，符号写法和数值写法如下：

1. **符号转义：**`\b` 表示退格控制字符。
2. **数值转义：**八进制转义以 `\` 后接八进制数字，十六进制转义写作 `\x` 后接十六进制数字。`\x08` 表示数值为 `0x08` 的字符，具体解释仍取决于执行字符集和目标环境。
3. **错误写法：**`\0x8` 会解析为八进制转义 `\0`，后面再跟普通字符 `x8`，不是十六进制转义。

**Q13: [learning] 码点、编码与通用字符名有何关系？**

字符集规定字符及其抽象编号。Unicode 与 ISO 10646 当前在码点分配上保持一致。码点是字符集中的编号，例如 `U+4E2D` 表示“中”。

1. **码点不等于字节序列：**UTF-8、UTF-16 等编码用一个或多个代码单元表示码点。
2. **通用字符名：**C++ 源码可用 `\u` 加四位十六进制数，或 `\U` 加八位十六进制数表示字符，例如 `\u4E2D`。
3. 通用字符名能否用于标识符，以及运行时如何显示，还受 C++ 规则、源码编码和执行环境影响。

**Q14: [learning] wchar_t、char16_t、char32_t 有什么区别？**

这些类型用于不同的宽字符或 Unicode 代码单元表示，不保证一个对象对应一个完整 Unicode 字符。

1. `wchar_t`：宽字符类型，位宽和编码含义由实现决定。Windows 与 Linux 的常见配置不同。
2. `char16_t`：用于表示 UTF-16 代码单元。补充平面字符需要两个代码单元构成代理对。
3. `char32_t`：用于表示 UTF-32 代码单元，仍需区分码点与用户感知字符。

**Q15: [learning] 'M' 和 "MM" 的类型与内容有什么区别？**

两种写法的类型和存储形式不同：

1. `'M'` 是普通字符字面量，类型为 `char`。
2. `"MM"` 是字符串字面量，类型为含三个 `const char` 元素的数组，末尾包含空字符 `\0`。在多数表达式中会转换为指向首元素的指针。

字符串字面量的元素不可修改，普通字符的编码值也不保证等于 ASCII 数值。

**Q16: [learning] 为什么定义常量时通常用 const 或 constexpr，而不是 #define？**

`const` 和 `constexpr` 是有类型、有作用域的 C++ 声明，编译器可以检查其使用。`#define` 是预处理文本替换，不遵循 C++ 作用域和类型规则。

1. 需要编译期常量时使用 `constexpr`。
2. 只读但不要求编译期求值时使用 `const`。
3. 条件编译等预处理用途使用宏。

**Q17: [learning] 浮点数通常如何表示，为什么十进制小数可能不精确？**

常见浮点实现使用符号、指数和有效数字表示数值。二进制浮点的有效位有限，许多十进制小数无法精确表示，因此存储和运算结果可能是邻近值。

具体格式由实现决定，许多平台采用 IEEE 754。浮点数以较小固定存储空间覆盖很大数值范围，代价是精度有限，不能把它当作任意精度十进制数。

**Q18: [learning] float、double 和 long double 的精度有何区别？**

它们提供不同的最小范围和精度保证，实际大小与精度由实现决定。常见实现的 `float` 约有 6–7 位十进制有效数字，`double` 约有 15–17 位，`long double` 可能与 `double` 相同，也可能更精确。

需要跨平台保证时查 `std::numeric_limits<T>::digits10` 和 `max_digits10`，不要把常见实现的位数当作标准保证。

**Q19: [learning] 为什么 float 运算 11.17f + 50.25f 可能显示近似值？**

`float` 通常不能精确表示 `11.17`，因此字面量会先舍入为邻近二进制值。运算结果和十进制显示也受精度与格式设置影响。显示为 `61.42` 可能只是格式化舍入，不表示内部值精确。

金额计算可使用整数最小单位（如分）或明确的十进制定点方案。限制打印位数只改变显示，不会改变内部值。

**Q20: [learning] 运算符优先级和结合性分别决定什么？**

运算符规则决定表达式如何分组，不决定所有操作数的求值先后顺序：

1. **优先级：**决定不同优先级运算符的分组，例如 `3 + 4 * 5` 等价于 `3 + (4 * 5)`。
2. **结合性：**决定同优先级运算符的分组。减法左结合，`10 - 4 - 2` 按 `(10 - 4) - 2` 分组。赋值右结合，`x = y = 5` 按 `x = (y = 5)` 分组。

**Q21: [learning] 什么是窄化转换，列表初始化如何阻止它？**

窄化转换可能丢失数值范围或精度。列表初始化会拒绝不允许的窄化转换，因此 `int value{3.14};` 不合法。复制初始化 `int value = 3.14;` 则允许转换并丢弃小数部分。

即使变量当前值看似在目标范围内，运行期变量到较窄类型的列表初始化也可能因无法静态证明安全而被拒绝。

**Q22: [learning] static_cast 会执行什么转换检查？**

`static_cast<T>(expr)` 显式请求语言允许的转换，编译器检查转换是否合法，但不保证运行时没有信息损失。

```cpp
int a = 10;
int b = 3;
double quotient = static_cast<double>(a) / b;
```

将 `a` 转为 `double` 后执行浮点除法。转换合法不代表所有值都能无损表示。

**Q23: [learning] auto 如何根据初始化表达式推导类型？**

`auto` 根据初始化表达式推导变量类型，不会仅因使用 `auto` 而改变表达式类型。

```cpp
int a = 10;
int b = 3;
auto count = a / b;
```

`count` 推导为 `int`，保存整数除法结果。
