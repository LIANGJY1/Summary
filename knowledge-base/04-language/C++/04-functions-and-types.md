# C++ 函数与类型

> 本文介绍函数声明与入口、基本类型、初始化、字符和浮点数的语言规则。

**Q1: [learning] 函数有返回值与 `void` 返回类型有什么区别？**

返回类型决定调用表达式是否提供可供程序使用的结果。结果如何通过寄存器或内存传递由调用约定和目标平台决定，不能把某个寄存器当成 C++ 语言保证。

1. **有返回值：**函数通过 `return` 提供符合返回类型的值。
2. **`void`：**函数不提供可供调用方使用的返回值，但仍可执行副作用。

**Q2: [learning] 为什么调用函数前必须让编译器看到它的声明？**

编译器需要先知道函数名、参数类型和返回类型，才能检查调用并生成代码。C++ 不会像旧式 C 一样隐式声明未见过的函数。

1. 自定义函数可先写声明，再在后面定义。
2. 多个源文件共享的声明通常放在头文件中，定义放在一个 `.cpp` 文件中。
3. 标准库声明由相应头文件提供，例如数学函数使用 `<cmath>`。

**Q3: [learning] 为什么 C++ 函数链接名可能和源码函数名不同？**

C++ 支持重载和命名空间，链接器需要区分同名但签名不同的函数。编译器通常使用名字修饰（name mangling）把这些信息编码进链接名。

具体编码由编译器和 ABI（Application Binary Interface，应用二进制接口）决定。前置下划线并不是所有编译器都采用的通用规则。需要跨 C/C++ 边界时，可按平台要求使用 `extern "C"`。

**Q4: [learning] C++ 为什么提供多种整型以及有符号、无符号类型？**

不同整型提供不同的最小取值范围和存储需求，供程序表达数据约束或匹配接口。实际宽度受实现影响，不能笼统断定某类型固定占多少字节。

1. **有符号类型：**可表示负数、零和正数。
2. **无符号类型：**只表示非负值，可用于位域或模运算等明确需要其语义的场景。与有符号数混合运算时要注意转换规则。
3. **固定宽度需求：**优先检查 `<cstdint>` 提供的 `std::int32_t` 等类型是否由目标实现提供。

**Q5: [learning] `short`、`int`、`long` 为什么不是固定字节数？**

C++ 标准规定整型之间的最小范围和相对顺序，不规定它们在所有平台都使用同一字节数。`sizeof(int)` 可查询当前实现的对象大小，单位是 C++ 的字节。

典型实现中 `short` 至少 16 位、`int` 至少与 `short` 一样宽、`long` 至少 32 位、`long long` 至少 64 位。精确宽度和范围应使用 `std::numeric_limits<T>` 或 `<climits>` 查询，不应假设类型宽度对应某种固定性能。

**Q6: [learning] `<climits>`、`#define` 和 `constexpr` 分别适合做什么？**

`<climits>` 提供当前实现的整型极限宏，例如 `INT_MAX`。`#define` 在预处理阶段进行替换，`constexpr` 则声明受类型检查、可在编译期求值的实体。

1. 查询标准整型边界时可用 `<climits>` 或 `std::numeric_limits<T>`。
2. 新定义的具名常量通常优先使用 `constexpr` 或 `const`，以获得类型和作用域检查。
3. 预处理条件、头文件保护等必须在预处理阶段工作的场景仍需要宏，`constexpr` 不能替代这类宏。

**Q7: [learning] `int a{7}`、`int b = {12}` 和 `int c{}` 分别表示什么？**

这些是列表初始化语法，具体效果如下：

1. `int a{7}` 和 `int b = {12}` 分别把变量初始化为 `7` 和 `12`。
2. `int c{}` 将变量值初始化为 `0`。

列表初始化还会拒绝不允许的窄化转换，例如 `int value{3.14};` 会编译失败。Java 没有相同的基本类型列表初始化规则，Java 数组初始化中的花括号是另一种语法。

**Q8: [learning] 函数内的 `int value;` 未初始化就读取会怎样，Java 又如何处理？**

块作用域的内建标量变量若没有初始化，其值不确定，不能描述成稳定的“随机垃圾值”。读取这种值的规则随标准版本变化：

1. **C++17 至 C++23：**读取此类不确定值会导致未定义行为。
2. **C++26 工作草案：**自动存储期对象的未初始化字节通常具有错误值（erroneous value），读取会导致错误行为（erroneous behavior）。
3. **静态存储期：**对象会进行零初始化。
4. **Java：**局部变量必须在读取前明确赋值，否则编译器拒绝编译。

**Q9: [learning] C++ 如何确定整数字面量的类型？**

整数字面量的类型由其进制、后缀和数值共同决定。无后缀十进制字面量依次尝试 `int`、`long`、`long long` 等标准候选类型。八进制和十六进制还会考虑对应的无符号候选类型。

1. `42` 是十进制，前导 `0` 表示八进制，`0x2A` 表示十六进制。
2. `u`、`l`、`ll` 等后缀可指定无符号或更宽类型，组合顺序须符合字面量语法。
3. 需要精确类型时优先写清后缀或使用定宽类型，不依赖平台上 `long` 的宽度。

**Q10: [learning] `char` 一定表示 ASCII 字符吗，为什么不用 `int` 存字符？**

`char` 是独立的字符类型，大小为一个 C++ 字节，足以表示基本执行字符集。它不保证使用 ASCII，也不保证 `char` 默认有符号或无符号。

`int` 也可保存字符相关数值，例如某些字符处理接口用 `int` 表示字符或 EOF。文本编码和字符数不是一回事，UTF-8 文本通常由多个 `char` 代码单元组成。

**Q11: [learning] `\b` 与数字转义有什么区别，为什么 `\0x8` 不是正确写法？**

转义序列在编译期表示字符或数值，符号写法和数值写法如下：

1. **符号转义：**`\b` 表示退格控制字符，通常更容易读懂。
2. **数值转义：**八进制转义以 `\` 后接八进制数字，十六进制转义写作 `\x` 后接十六进制数字。`\x08` 表示数值为 `0x08` 的字符，具体解释仍取决于执行字符集和目标环境。
3. **错误写法：**`\0x8` 会解析为八进制转义 `\0`，后面再跟普通字符 `x8`，不是十六进制转义。

**Q12: [learning] 字符集、码点、ISO 10646 和通用字符名是什么？**

字符集规定字符及其抽象编号。Unicode 与 ISO 10646 当前在码点分配上保持一致。码点是字符集中的编号，例如 `U+4E2D` 表示“中”。

1. **码点不等于字节序列：**UTF-8、UTF-16 等编码用一个或多个代码单元表示码点。
2. **通用字符名：**C++ 源码可用 `\u` 加四位十六进制数，或 `\U` 加八位十六进制数表示字符，例如 `\u4E2D`。
3. 能否用于标识符及其运行时显示还受 C++ 规则、源码编码和执行环境影响。

**Q13: [learning] `wchar_t`、`char16_t`、`char32_t` 有什么区别？**

这些类型用于不同的宽字符或 Unicode 代码单元表示，不能简单理解为“一个类型存一个完整字符”。

1. **`wchar_t`：**宽字符类型，位宽和编码含义由实现决定，Windows 与 Linux 常见配置不同。
2. **`char16_t`：**至少 16 位，用于 UTF-16 代码单元。
3. **`char32_t`：**至少 32 位，适合表示 UTF-32 代码单元。
4. **代理对：**一个 Unicode 字符可能需要两个 UTF-16 代码单元表示。
5. **EBCDIC：**IBM 历史上使用的字符编码系列，与 ASCII 不同。它说明了编码生态的历史差异，但不是现代宽字符设计的唯一原因。

**Q14: [learning] `'M'` 和 `"MM"` 的类型与内容有什么区别？**

两种写法的类型和存储形式不同：

1. `'M'` 是普通字符字面量，类型为 `char`。
2. `"MM"` 是字符串字面量，类型为含三个 `const char` 元素的数组，末尾包含空字符 `\0`。在多数表达式中会转换为指向首元素的指针。

字符串字面量的元素不能修改。字符编码值不保证是 ASCII 数值。

**Q15: [learning] 为什么定义常量时通常用 `const` 或 `constexpr`，而不是 `#define`？**

`const` 和 `constexpr` 是有类型、有作用域的 C++ 声明，编译器可以检查其使用。`#define` 是预处理文本替换，不遵循 C++ 作用域和类型规则。

1. 需要编译期常量时用 `constexpr`。
2. 只读但不要求编译期求值时用 `const`。
3. 条件编译等预处理用途仍需要宏。

**Q16: [learning] 浮点数通常如何表示，为什么十进制小数可能不精确？**

常见浮点实现使用符号、指数和有效数字表示数值。二进制浮点的有效位有限，许多十进制小数无法精确表示，因此存储和运算结果可能是邻近值。

具体格式由实现决定，许多平台采用 IEEE 754。浮点数以较小固定存储空间覆盖很大数值范围，代价是精度有限，不能把它当作任意精度十进制数。

**Q17: [learning] `float`、`double` 和 `long double` 的精度有何区别？**

它们提供不同的最小范围和精度保证，实际大小与精度由实现决定。常见实现的 `float` 约有 6–7 位十进制有效数字，`double` 约有 15–17 位，`long double` 可能与 `double` 相同，也可能更精确。

需要跨平台保证时查 `std::numeric_limits<T>::digits10` 和 `max_digits10`，不要把常见实现的位数当作标准保证。

**Q18: [learning] 为什么 `11.17 + 50.25` 有时显示为 `61.419998`？**

如果参与运算的是 `float`，输入十进制小数通常先近似为二进制值，运算后再格式化为十进制时可能显示 `61.419998` 一类结果。`double` 或不同输出精度可能显示 `61.42`，具体文本取决于类型和格式设置。

金额计算可用整数最小单位（如分）或明确的十进制定点方案。单纯限制打印位数只改变显示，不会修复内部近似值。

**Q19: [learning] 运算符优先级和结合性分别决定什么？**

运算符规则决定表达式如何分组，不决定所有操作数的求值先后顺序：

1. **优先级：**决定不同优先级运算符的分组，例如 `3 + 4 * 5` 等价于 `3 + (4 * 5)`。
2. **结合性：**决定同优先级运算符的分组。减法左结合，`10 - 4 - 2` 按 `(10 - 4) - 2` 分组。赋值右结合，`x = y = 5` 按 `x = (y = 5)` 分组。

**Q20: [learning] 什么是窄化转换，列表初始化如何阻止它？**

窄化转换可能丢失数值范围或精度。列表初始化对不允许的窄化转换要求诊断，因此 `int value{3.14};` 会编译失败，而普通赋值初始化通常允许转换并丢弃小数部分。

即使变量当前值看似在目标范围内，运行期变量到较窄类型的列表初始化也可能因无法静态证明安全而被拒绝。

**Q21: [learning] `static_cast` 和 `auto` 分别做什么？**

两者用途不同：

1. `static_cast<T>(expr)` 明确请求一种编译期可检查的转换。
2. `auto` 根据初始化表达式推导变量类型，本身不执行类型转换。

```cpp
int a = 10;
int b = 3;
double quotient = static_cast<double>(a) / b;
auto count = a / b;
```

`quotient` 是浮点除法结果，`count` 推导为 `int` 并保存整数除法结果。`static_cast` 不能替代运行期类型检查，也不代表转换一定没有信息损失。
