# C++ 自定义类型

> 本文说明结构体、共同体和枚举的类型定义、对象布局与取值规则。

**Q1: [learning] 结构体与数组如何组织数据？定义结构体类型会创建对象吗？**

二者组织数据的方式不同：

1. **数组：**包含多个同类型元素。
2. **结构体：**把不同成员组合成一个类型。

声明结构体类型本身不会创建对象。定义具体变量时才创建对象并取得相应存储。

```cpp
struct Inflatable {
    char name[20];
    float volume;
};

Inflatable balloon{};
```

此处 `Inflatable` 是类型，`balloon` 是对象。对象的成员可能因对齐要求而有填充，不能仅把成员大小相加作为对象总大小。

**Q2: [learning] 函数内外定义结构体类型有何作用域差异？**

函数内定义的类类型具有局部作用域，只能在其可见范围内使用；函数外定义的类型可在后续声明中复用。定义类型本身不会创建对象。

**Q3: [learning] 结构体的列表初始化有什么规则，何时会拒绝初始化？**

满足聚合类型规则的结构体可按成员顺序列表初始化：

1. 空列表会对成员进行值初始化。
2. 列表初始化会拒绝不允许的窄化转换。

```cpp
struct Point {
    int x;
    double y;
};

Point origin{};
Point p{2, 3.5};
```

聚合类型资格取决于类成员和构造函数等条件。C++20 调整了相关规则，应按目标标准版本判断。

**Q4: [learning] 能否在定义结构体时同时定义对象？**

可以在结构体定义的右花括号后声明对象，也可以先定义类型，再单独声明对象。

```cpp
struct Point {
    int x;
    int y;
} origin{};
```

**Q5: [learning] 标准 C++ 支持匿名结构体吗？**

未命名结构体类型可用于定义当前位置的对象，但之后不能通过类型名再次声明对象。标准 C++ 不支持将匿名结构体作为另一结构体的成员并把成员提升到外层；部分编译器将其作为扩展支持。

**Q6: [learning] 结构体位字段能否保证成员按指定比特布局？**

不能。位字段宽度限制成员的取值位数，但不保证可移植的物理布局。

1. **实现差异：**分配顺序、存储单元和对齐受实现影响。
2. **适用边界：**位字段类型与宽度受语言规则限制；直接映射硬件寄存器或网络协议会依赖具体实现。需要稳定布局时应显式编码和解码。

**Q7: [learning] union 与 struct 的存储和使用方式有什么不同？**

两者的存储方式不同：

1. 结构体为各成员分别提供存储。
2. 共同体的成员共享同一片存储，因此同一时刻通常只有一个活动成员。

共同体大小至少足以容纳最大成员，并受对齐要求影响。读取非活动成员通常不合法，除标准规定的特例外。需要安全表示多种候选类型之一时，可使用 `std::variant`。

**Q8: [learning] 匿名共同体如何让成员直接出现在外层作用域？**

匿名共同体没有类型名和成员对象名，其成员名直接出现在包含作用域中，可由外层对象访问。

```cpp
struct Value {
    bool is_number;
    union {
        int number;
        char text[16];
    };
};
```

此例需要 `is_number` 这样的标签记录当前有效成员，并由程序维护标签与活动成员的一致性。复杂场景可用 `std::variant`。

**Q9: [learning] 枚举项的值如何确定？**

枚举定义一种类型，并为其候选值命名。枚举项的默认值和显式值规则如下：

1. 未显式赋值时，第一个枚举项为 `0`，后续项依次递增。
2. 也可以显式指定底层值。


**Q10: [learning] 枚举与整数之间有哪些隐式转换规则？**

名称作用域与隐式转换都取决于枚举种类：无作用域枚举会在外层作用域引入枚举项，作用域枚举（`enum class`）将名称限定在枚举类型中。隐式转换规则如下：

1. 无作用域枚举可按标准规则提升为整数类型。
2. 作用域枚举不会隐式转换为整数。
3. 整数不能隐式转换为枚举类型。

```cpp
enum Color { red, blue };
enum class State { ready, busy };

int value = red;
int state_value = static_cast<int>(State::ready);
```

枚举对象的值不一定对应已命名的枚举项，因此不能依靠枚举类型完成运行时输入校验。枚举自增也不是内建操作。

**Q11: [learning] 整数可以显式转换为枚举吗？**

可以显式转换，但“能写出强制转换”不等于转换结果一定是已命名枚举项或适合业务使用。

1. **有固定底层类型：**整数先按底层类型的转换规则转换，再成为枚举值。该值不一定对应已命名的枚举项。
2. **没有固定底层类型：**整数必须在枚举可表示范围内。按当前标准，范围外的 `static_cast` 会导致未定义行为。
3. **位标志：**应显式定义底层类型、允许的位组合和验证规则，不要把任意整数当成有效枚举值。

相关规则见 ISO C++ 工作草案的 `[dcl.enum]` 和 `[expr.static.cast]`。
