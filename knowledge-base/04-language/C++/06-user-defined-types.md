# C++ 自定义类型

> 本文说明结构体、共同体和枚举的类型定义、对象布局与取值规则。

**Q1: [done] 如何解析一个 C++ struct 定义？**

按语法把一个 struct 定义拆成四部分来读：struct 关键字、类型名、花括号内的成员声明列表、末尾的分号。定义引入一个新类型，随后用类型名声明的变量才是对象。

```cpp
struct Point {      // struct 关键字与类型名
    int x;          // 成员声明
    int y;
};                  // 成员列表结束，定义以分号结尾
```

四个部分的作用如下：

1. **struct 关键字：**它是类说明符，另外两个是 class 和 union。类说明符只决定默认访问控制是公有还是私有，不决定类型能拥有什么成员（`[class.pre]`）。
2. **Point 类型名：**它在定义所在作用域引入一个新类型名。右花括号之后类型即算定义完成，即使成员函数还未定义（`[class.pre]`）。
3. **成员声明列表：**每个成员声明给出类型和成员名，并以分号结尾。数据成员、成员函数、嵌套类型、枚举项和成员模板都可以作为成员（`[class.mem.general]`）。
4. **末尾分号：**struct 定义是一条声明，漏掉末尾分号是常见语法错误。

**Q2: [done] 结构体与数组如何组织数据？定义结构体类型会创建对象吗？**

二者组织数据的方式不同：

1. **数组：**包含多个同类型元素。
2. **结构体：**把不同成员组合成一个类型。

声明结构体类型本身不会创建对象。定义具体变量时才创建对象并取得相应存储。

```cpp
struct Inflatable {
    char name[20];
    float volume;
};

Inflatable balloon{};
```

此处 `Inflatable` 是类型，`balloon` 是对象。对象的成员可能因对齐要求而有填充，不能仅把成员大小相加作为对象总大小。

**Q3: [learning] 函数内外定义结构体类型有何作用域差异？**

定义位置决定结构体类型的作用域：

1. **函数内定义：**类型具有局部作用域，只能在其可见范围内使用。
2. **函数外定义：**类型可在后续声明中复用。

定义类型本身不会创建对象。

**Q4: [learning] C++ 的结构体可以定义成员函数和构造函数吗？**

可以。C++ 的结构体与 C 的结构体完全不同：struct 与 class、union 一样是类说明符，定义出来的类型就是类，可以包含成员函数、构造函数、析构函数和嵌套类型。C 的结构体只把数据成员组合在一起。

其依据是成员的分类规则。ISO C++ 工作草案 `[class.mem.general]` 规定，类的成员包括数据成员、成员函数、嵌套类型、枚举项和成员模板，且这一分类不取决于定义时使用 struct 还是 class。因此下面的写法合法：

```cpp
struct Counter {
    int value;
    void increase() { ++value; }
};

Counter c{0};
c.increase();
```

运行后 c.value 为 1。increase 是 Counter 的成员函数，在对象 c 上调用，函数体中的 value 就是 c 的成员。`Counter c{0}` 仍按成员顺序列表初始化。

声明构造函数会让结构体失去按成员顺序初始化的资格。C++20 草案 `[dcl.init.aggr]` 要求聚合类型没有用户声明的构造函数，所以给结构体手写构造函数后，`Counter c{1, 2}` 这样按成员位置对应多个成员的初始化不再成立，编译器改为寻找匹配的构造函数，找不到即 ill-formed。能匹配的 `Counter c{7}` 则按构造函数初始化。需要保持纯数据聚合的初始化形式时，不要给结构体手写构造函数。

**Q5: [learning] C++ 中 struct 与 class 有什么区别？**

语言层面两者没有本质区别，都定义类。差异只有默认访问控制两处：

1. **成员默认访问：**struct 的成员默认 public，class 的成员默认 private。ISO C++ 工作草案 `[class.access.general]` 对此有直接规定。
2. **基类默认访问：**继承时未写访问说明符的基类，在 struct 中默认 public，在 class 中默认 private（`[class.access.base]`）。

```cpp
struct S {
    int a;      // 默认 public
};

class C {
    int a;      // 默认 private
};

S s{1};
s.a = 2;       // 合法
```

同一段代码里把 C 的定义换成 struct，`c.a` 在类外即可访问。给 struct 写上 private: 分段后，行为与 class 相同。除此之外，成员函数、虚函数、构造函数、模板、友元等特性两者完全一样。`[class.pre]` 的说明也指出，类说明符只决定是否为联合以及默认访问是公有还是私有。

引用类型时两个关键字可以互换。`[dcl.type.elab]` 规定引用非联合类时 class 和 struct 均可，草案示例中 `struct S { } s; class S* p = &s;` 合法，即用 class 引用 struct 定义过的类型得到的是同一类型。惯例上把纯数据聚合写成 struct、把封装行为的类型写成 class，这只是风格约定，语言并不强制。

**Q6: [learning] 结构体的列表初始化有什么规则，何时会拒绝初始化？**

满足聚合类型规则的结构体按成员声明顺序列表初始化，元素是直接基类在前、非静态数据成员在后（`[dcl.init.aggr]`）。具体规则如下：

1. **元素顺序：**初始化器按元素顺序对应。静态数据成员和未命名位字段不占位置，不会被初始化器命中。
2. **空列表与短列表：**空列表或比成员少的初始化器会让剩余成员按空列表值初始化，标量成员得到 0。
3. **窄化转换：**列表初始化拒绝不允许的窄化转换（`[dcl.init.list]`）。

```cpp
struct Point {
    int x;
    double y;
};

Point origin{};      // x 为 0，y 为 0.0
Point p{2, 3.5};     // x 为 2，y 为 3.5
Point bad{3.5, 1};   // ill-formed：3.5 到 int 是窄化转换
```

能否列表初始化取决于类型是否为聚合类型。按 C++20 草案 `[dcl.init.aggr]`，聚合类型不能有用户声明的或继承的构造函数、不能有 private 或 protected 的直接非静态数据成员和直接基类、不能有虚函数或虚基类。聚合资格随标准版本变化过，例如默认成员初始器和公有基类是先后被允许的，以目标版本的 `[dcl.init.aggr]` 为准。给结构体加上构造函数后，按成员顺序的列表初始化不再可用，初始化只能调用构造函数。

**Q7: [learning] 能否在定义结构体时同时定义对象？**

可以在结构体定义的右花括号后声明对象，也可以先定义类型，再单独声明对象。

```cpp
struct Point {
    int x;
    int y;
} origin{};
```

**Q8: [learning] 标准 C++ 支持匿名结构体吗？**

未命名结构体类型可用于定义当前位置的对象，但之后不能通过类型名再次声明对象。标准 C++ 不支持将匿名结构体作为另一结构体的成员并把成员提升到外层。部分编译器将其作为扩展支持。

**Q9: [learning] 链表节点为什么用指针自引用，而不能直接包含同类型成员？**

因为定义进行到成员声明处时类型还没有完整。类在其类说明符的右花括号之后才算定义完成（`[class.pre]`），此刻 Node 仍是不完整类型，大小未知。非静态数据成员的类型不能是不完整类型，所以 `Node next` 非法。指向不完整类型的指针本身是完整类型，大小和对齐已知，所以 `Node*` 合法。

C++20 草案 `[class.mem.general]` 在规定成员类型不得为不完整类型的同时给出了明确边界：类不能包含自身的非静态数据成员，但可以包含指向自身对象的指针或引用。草案中紧邻的示例就是一棵二叉树的节点结构体，两个子节点成员均为指向自身的指针。

```cpp
struct Node {
    int value;
    Node* next;
};

Node a{1, nullptr};
Node b{2, &a};
```

这段代码合法：a.next 为空，b.next 指向 a，通过 `b.next->value` 可以读到 1。若把成员写成 `Node next;`，编译器会报告成员类型不完整，因为嵌入同类型成员要求对象包含自身，大小无法确定。

**Q10: [learning] 结构体前向声明之后、完整定义之前，能用这个类型做什么？**

此时类型是已声明未定义的不完整类型：可以声明指向或引用它的指针和引用，也可以只用它们声明函数。定义出现前不能定义对象、不能取大小、不能访问成员。定义出现后类型立即补全，前后是同一类型。

ISO C++ 工作草案 `[basic.types.general]` 把已声明未定义的类归为不完整类型，并明确对象不能有不完整类型。下面片段中每行的合法性如行尾注释所示，片段整体不是可编译程序：

```cpp
struct Node;              // Node 是不完整类型
Node* p;                  // 合法
void f(Node* q);          // 合法：函数声明的形参可以只含不完整类型
Node n;                   // ill-formed：不能定义不完整类型的对象
sizeof(Node);             // ill-formed：大小未知
struct Node { int value; Node* next; };  // 定义出现，Node 成为完整类型
Node m;                   // 合法
```

三条边界需要记住：

1. **可以用：**声明指向或引用不完整类型的指针、引用，以及只使用这些指针或引用作形参和返回类型的函数声明。函数定义则要求函数体内类型完整，被删除的函数除外（`[dcl.fct.def.general]`）。
2. **不可以用：**定义对象（包括作为非静态数据成员）、sizeof、成员访问，以及指向不完整类型的指针算术，这些操作都需要类型的大小或布局。
3. **补全规则：**类可以在一个翻译单元内先不完整、后完整，两个点是同一类型（`[basic.types.general]`）。

前向声明的典型用途是打断头文件循环依赖：两个结构体互相持有指针时，头文件中只写 `struct Node;`，把完整定义留在各自的实现里，修改定义不必重新编译只依赖声明的使用方。

**Q11: [learning] 结构体位字段能否保证成员按指定比特布局？**

不能。位字段宽度限制成员的取值位数，但不保证可移植的物理布局。

1. **实现差异：**分配顺序、存储单元和对齐受实现影响。
2. **适用边界：**位字段类型与宽度受语言规则限制。直接映射硬件寄存器或网络协议会依赖具体实现。需要稳定布局时应显式编码和解码。

**Q12: [learning] 结构体作为函数参数，应该按值传递还是按 const 引用传递？**

按值传递创建实参的副本，const 引用不创建副本。选择取决于函数是否需要本地可修改的副本：

1. **按值传递：**形参是实参拷贝初始化得到的副本（`[class.pre]` 说明类对象可以作为函数实参传递），隐式拷贝构造函数按成员逐个拷贝基类和成员（`[class.copy.ctor]`）。对形参赋值不影响调用方的对象，适合函数需要修改副本或保存一份数据的场景。
2. **const 引用：**不产生副本，函数内也不能通过形参修改调用方对象，适合结构体较大或含 std::string 等拷贝成本高的成员、且只读取的场景。
3. **指针参数：**const Node* 同样避免拷贝，但指针可以为空，引用不能为空也不能重新绑定。形参一定指向有效对象时，用引用表达意图更准确。

```cpp
struct Point {
    int x;
    int y;
};

void shift_by_value(Point p) { p.x += 1; }

Point origin{1, 2};
shift_by_value(origin);
```

运行后 origin.x 仍为 1：被修改的是形参 p 这份副本。改成 const Point& 后不再有副本，函数体中也无法通过形参改写 origin。

**Q13: [learning] 什么是标准布局结构体，它有什么实际用途？**

标准布局类是满足一组严格条件的类。满足时标准保证成员按声明顺序排列、对象地址等于第一个非静态数据成员的地址，并且可以与 C 等语言编写的代码互操作。混用访问控制或使用虚函数都会破坏资格。

C++20 草案 `[class.prop]` 对标准布局类的要求如下：

1. 没有非标准布局类类型或引用类型的非静态数据成员，也没有此类成员的数组。
2. 没有虚函数和虚基类。
3. 所有非静态数据成员的访问控制相同。
4. 没有非标准布局基类，且同一类型至多有一个基类子对象。
5. 所有非静态数据成员和位字段都在最派生类中首次声明。
6. 满足 M(S) 规则：不存在某个类型作为基类时，使同一最派生对象中两个同类子对象可能分配到同一地址。

满足条件后得到三组可依赖的保证：

1. **成员顺序：**同一类中后声明的非静态数据成员地址更高，相邻成员之间可能因对齐插入填充（`[class.mem.general]`）。
2. **首成员同址：**有非静态数据成员时，标准布局对象的地址等于第一个非位字段数据成员的地址，填充只能出现在对象内部、不能出现在开头（`[class.mem.general]`）。
3. **布局兼容：**两个标准布局结构体按声明顺序从头开始、对应成员布局兼容且对齐相同的最长成员序列（共同初始序列）覆盖双方全部成员和位字段时，二者布局兼容（`[class.mem.general]`、`[basic.types.general]`）。标准布局类的用途正是与其他语言编写的代码通信（`[class.prop]` 的说明）。

反例是混用访问控制：

```cpp
struct Mixed {
    int i;
private:
    int j;
};
```

这个类型可以平凡拷贝，但不是标准布局类，因为两个数据成员的访问控制不同（`[class.prop]` 示例）。需要与 C 交互时应让数据成员的访问控制保持一致。标准布局可以用 `<type_traits>` 的 std::is_standard_layout 在编译期查询。

标准布局保证的是成员顺序和首成员地址，不保证填充字节的数量，也不保证位字段的物理分配。直接映射硬件寄存器或网络协议时仍应显式编码解码。

**Q14: [learning] union 与 struct 的存储和使用方式有什么不同？**

两者的存储方式不同：

1. 结构体为各成员分别提供存储。
2. 共同体的成员共享同一片存储，因此同一时刻通常只有一个活动成员。

共同体大小至少足以容纳最大成员，并受对齐要求影响。读取非活动成员通常不合法，除标准规定的特例外。需要安全表示多种候选类型之一时，可使用 `std::variant`。

**Q15: [learning] 匿名共同体如何让成员直接出现在外层作用域？**

匿名共同体没有类型名和成员对象名，其成员名直接出现在包含作用域中，可由外层对象访问。

```cpp
struct Value {
    bool is_number;
    union {
        int number;
        char text[16];
    };
};
```

此例需要 `is_number` 这样的标签记录当前有效成员，并由程序维护标签与活动成员的一致性。复杂场景可用 `std::variant`。

**Q16: [learning] 枚举项的值如何确定？**

枚举定义一种类型，并为其候选值命名。枚举项的默认值和显式值规则如下：

1. 未显式赋值时，第一个枚举项为 `0`，后续项依次递增。
2. 也可以显式指定底层值。

**Q17: [learning] 枚举与整数之间有哪些隐式转换规则？**

名称作用域与隐式转换都取决于枚举种类：无作用域枚举会在外层作用域引入枚举项，作用域枚举（`enum class`）将名称限定在枚举类型中。隐式转换规则如下：

1. 无作用域枚举可按标准规则提升为整数类型。
2. 作用域枚举不会隐式转换为整数。
3. 整数不能隐式转换为枚举类型。

```cpp
enum Color { red, blue };
enum class State { ready, busy };

int value = red;
int state_value = static_cast<int>(State::ready);
```

枚举对象的值不一定对应已命名的枚举项，因此不能依靠枚举类型完成运行时输入校验。枚举自增也不是内建操作。

**Q18: [learning] 整数可以显式转换为枚举吗？**

可以显式转换，但“能写出强制转换”不等于转换结果一定是已命名枚举项或适合业务使用。

1. **有固定底层类型：**整数先按底层类型的转换规则转换，再成为枚举值。该值不一定对应已命名的枚举项。
2. **没有固定底层类型：**整数必须在枚举可表示范围内。按当前标准，范围外的 `static_cast` 会导致未定义行为。
3. **位标志：**应显式定义底层类型、允许的位组合和验证规则，不要把任意整数当成有效枚举值。

相关规则见 ISO C++ 工作草案的 `[dcl.enum]` 和 `[expr.static.cast]`。
