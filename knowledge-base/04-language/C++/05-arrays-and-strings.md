# C++ 数组与字符串

> 本文说明内建数组、C 风格字符串、流输入（含 `std::istringstream` 解析）、`std::atoi` 数值转换和 `std::string` 的基本规则。

**Q1: [learning] 内建数组有哪些基本特征？如何声明和初始化？**

内建数组由固定数量的同类型元素构成，长度属于类型的一部分。初始化列表可逐项提供初值，未显式提供的元素会进行值初始化。

```cpp
int main() {
    int values[5]{1, 2};
    return values[0] + values[1];
}
```

此例将前两个元素初始化为 `1` 和 `2`，其余元素值初始化为 `0`。内建数组创建后不能改变长度，也不能直接整体赋值。需要可变长度时通常使用 `std::vector`。

**Q2: [learning] 何时可以省略数组长度？字符串数组为什么常用这种写法？**

若数组由初始化列表初始化，可以省略长度，编译器按初始化项数量推导长度。这样并非不安全，但访问时仍必须保证下标在范围内，内建数组不会自动检查越界。

```cpp
char name[] = "Bob";
```

此数组长度为 `4`，因为字符串字面量包含结尾的空字符。对普通数组省略长度也合法，是否清晰取决于代码是否容易看出元素数量。

**Q3: [learning] 为什么 long values[] = {25, 92, 3.0}; 会编译失败？**

列表初始化会拒绝窄化转换，原因如下：

1. `3.0` 是浮点类型。列表初始化禁止这类浮点到整数的窄化转换，即使该值没有小数部分。
2. 普通赋值形式可能允许转换并截断，容易掩盖精度损失。

**Q4: [learning] std::vector 和 std::array 与内建数组有什么区别？**

两种容器都提供标准接口，但长度、存储和边界检查方式不同：

1. `std::vector`：管理运行时可变长度的连续元素序列，保存元素数量和容量。扩容可能搬移元素并使指针、引用和迭代器失效。
2. `std::array<T, N>`：封装长度固定为编译期常量的数组，元素属于容器对象。对象本身的位置由其存储期决定。
3. **边界检查：**两者的 `operator[]` 都不检查边界，`.at()` 会检查并在越界时抛出异常。

默认优先使用标准容器。只有接口或布局要求时才直接管理原生数组和裸指针。

**Q5: [learning] C 风格字符串如何区别于字符数组与字符串字面量？**

C 风格字符串是以空字符 `\0` 结尾的字符序列，通常存放在 `char` 数组中。普通字符数组不一定有结束符。字符字面量如 `'S'` 的类型为 `char`，字符串字面量如 `"S"` 是含结束符的常量字符数组。

缺少结束符的数组不能安全地传给要求 C 字符串的函数。字符串字面量也不能赋给单个 `char`。字符编码不保证是 ASCII。

**Q6: [done] 如何使用 std::strcmp() 比较 C 风格字符串？**

`strcmp` 是 string compare 的缩写，C 标准库的字符串比较函数：比较两个以空字符结尾的字符串内容，相等时返回 `0`，不相等时按字典序返回正值或负值，只保证符号、不保证数值。C 程序经 `<string.h>` 声明，C++ 程序经 `<cstring>` 使用 `std::strcmp`。

1. **返回值读法：**判断内容是否相同用 `== 0`，判断先后用 `< 0` 或 `> 0`。具体数值由实现决定，写成 `== 1` 或 `== -1` 不可移植。
2. **常见误用：**比较内容必须调用 `strcmp`。两个 `char*` 之间写 `==` 比较的是指针地址。内容相同的字符串也可以位于不同地址，此时 `==` 为假而 `strcmp` 为 `0`。
3. **使用前提：**两个参数都必须是空字符结尾的字符串，比较范围由空字符决定。缓冲区未正确终止时会越界读取。
4. **相关函数与替代：**`strncmp(lhs, rhs, n)` 只比较前 `n` 个字符，用于判断前缀。两端都是 `std::string` 时直接用 `==`、`<` 比较内容，不必退回 C 接口。

例如，按返回值符号判断两个启动参数的关系：

```cpp
#include <cstring>

int compare_mode(const char *input, const char *expected) {
    int result = std::strcmp(input, expected);
    if (result == 0) {
        return 0;                 // 内容相同
    }
    return result < 0 ? -1 : 1;   // 只按符号判断先后
}
```

`result == 0` 判内容相等，`result < 0` 判 `input` 字典序在前。这里没有依赖任何具体返回值。

**Q7: [learning] sizeof 与 std::strlen() 分别测量字符串的什么？**

两者衡量的内容不同：

1. `sizeof` 查询对象占用的字节数。
2. `std::strlen` 计算以 `\0` 结尾的 C 字符串在结束符之前有多少个字节。

```cpp
#include <cstring>
#include <iostream>

int main() {
    char name[20] = "Bob";
    std::cout << sizeof(name) << ' ' << std::strlen(name);
}
```

输出 `20 3`：`sizeof(name)` 统计整个数组的字节数，`std::strlen(name)` 统计结束符之前的字节数。若 `name` 已退化为指针，`sizeof(name)` 得到的是指针大小。`std::strlen()` 要求参数指向有效的空字符结尾字符串。

**Q8: [learning] char*、字符数组和字符串字面量在 std::cout 中如何输出？**

字符数组在表达式中通常转换为首字符指针。输出流对 `char*` 和 `const char*` 有字符串重载，会从该地址读取字符直到 `\0`，而不是输出地址。

其他对象指针通常按地址形式输出。需要打印字符缓冲区地址时，可显式转换为 `const void*`。只有缓冲区确实以 `\0` 结尾时，才能按 C 字符串输出。

**Q9: [learning] std::cin.getline() 和 std::cin.get() 读取一行时有何区别？**

两种成员函数都可以读取字符数组，但遇到分隔符后的处理不同。

1. `getline(buffer, size)`：读到换行或容量上限，若遇到换行会将其从输入流中取走，并在缓冲区中写入 `\0`。
2. `get(buffer, size)`：读到换行或容量上限，但会把换行留在输入流中，后续读取需自行处理。
3. 两者容量不足时都要检查流状态，并处理未读完的行，避免截断输入被误认为完整输入。

**Q10: [learning] std::cin.get(buffer, size) 为什么保留换行符？如何检查输入是否被截断？**

该重载在遇到换行时将其留在输入流中。读取后应区分行结束、缓冲区容量上限和文件结束：

1. 若流状态正常且 `peek()` 得到 `\n`，说明本行已读完。换行仍留在输入流中，可按需提取。
2. 若已存入 `size - 1` 个字符，且下一字符既不是换行也不是 EOF，说明缓冲区不足以容纳整行。应丢弃剩余字符或报告错误。达到容量上限本身不会设置 `failbit`。
3. 若 `eof()` 为真且缓冲区已有字符，说明读到文件末尾时得到一行不带换行符的尾行，应按应用逻辑处理。

这项检查避免把截断内容当作完整输入。`get()` 本身不是安全输入的保证。

读取字符数组时应检查容量和流状态。现代代码也可使用 `std::string` 版本的 `std::getline`，再按业务规则限制输入长度。

**Q11: [learning] 为什么读取字符串时目标缓冲区必须有效且有足够容量？**

输入操作会向目标存储写字符，因此目标必须指向仍存活且容量足够的缓冲区。未初始化指针不能作为输入目标。

1. 对字符数组输入，限制最多写入的字符数并为 `\0` 留位置。
2. 对一般文本输入，优先读入 `std::string`，再按业务限制长度。
3. 复制字符数据才会形成独立字符串副本。复制指针只会让两个指针指向同一缓冲区。

**Q12: [learning] 为什么先用 std::cin >> year 再用 getline，会读到空行？**

执行过程分两步：

1. 格式化提取 `std::cin >> year` 读取数字后会把换行留在输入流中。
2. 紧接着的 `getline` 遇到这个换行便结束，得到空行。

若要丢弃本行剩余输入，再读取下一行，可显式忽略到换行：

```cpp
#include <iostream>
#include <limits>
#include <string>

int main() {
    int year{};
    std::string name;

    std::cin >> year;
    std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n');
    std::getline(std::cin, name);
}
```

这会丢弃数字后直到行末的内容。仅调用一次 `get()` 只会丢弃一个字符，不适用于用户可能输入额外空格或字符的情况。

**Q13: [learning] 如何用 std::istringstream 解析字符串中空白分隔的多个值？**

把字符串交给 std::istringstream，再用提取运算符逐个提取，是解析空白分隔文本的常用方式：提取按空白切分并自动完成类型转换，"1024 768" 可以直接得到两个 int。std::istringstream 是标准库头文件 <sstream> 提供的输入字符串流类（std::basic_istringstream<char> 的别名），提取行为与 std::cin 一致，因为两者都是 std::istream，提取规则由基类定义，只是数据源从标准输入变为内存中的字符串。

基本用法分三步：

1. **构造：**用待解析的字符串构造流，构造后流持有独立的内容，之后修改原字符串不影响流。
2. **提取：**提取运算符跳过前导空白，读到下一个空白前停止，并按目标类型转换文本，int、double 等都可以直接提取。
3. **判断：**提取运算符返回流引用，因此可以链式书写。流在布尔上下文中表示未处于失败状态，可用来判断解析能否继续。

例如，从一行文本中取出宽和高：

```cpp
#include <sstream>

int main() {
    std::istringstream stream{"1024 768"};
    int width{};
    int height{};
    stream >> width >> height;
}
```

执行后 width == 1024、height == 768。第一个提取读到空格前的 1024 停止，空格留给流。第二个提取跳过这个空格，再读 768。链式写法等价于 (stream >> width) >> height，因为提取运算符返回流引用。

字段个数不定时，把提取写进 while 条件：

```cpp
#include <sstream>

int main() {
    std::istringstream stream{"3 1 4 1 5"};
    int value{};
    while (stream >> value) {
        // 依次得到 3、1、4、1、5
    }
}
```

循环对每个值恰好执行一次。提取最后一个值 5 时到达字符串末尾，只置表示结束的 eofbit，不置表示失败的 failbit，循环体照常执行。下一次提取时流已不处于无错误状态，提取不再读取字符，直接置 failbit 并返回，while 条件为假，循环结束。因此 5 个值全部进入循环体，结束后 eofbit 和 failbit 均已置位（GCC 11 实测），已得到的值不受影响。

解析失败与适用边界：

1. **转换失败：**内容无法转成目标类型（如把 abc 读入 int）时，该次提取置 failbit，并把目标值置 0（C++11 起的标准行为，本机 GCC 11 实测确认）。
2. **失败后不可继续：**failbit 一旦置位，后续提取立即失败，不再改写目标值。要继续解析必须先 clear() 清除状态位，导致失败的内容还会留在流中，需要再读走或忽略。
3. **无内容可提：**空字符串或纯空白字符串上第一次提取就失败，目标值保持原值。
4. **只按空白切分：**等号、逗号对提取运算符只是普通字符，"width=1024" 会被整体读入一个字段。按其他分隔符切分要使用 std::getline 并指定分隔符。

选择解析方式时：

1. **多个空白分隔字段：**用 std::istringstream 的提取运算符。
2. **只转换单个数字：**用 std::stoi 或 std::stod，它们不维护流状态，无法转换时抛异常。
3. **热路径逐字段转换：**用 std::from_chars（C++17 起，头文件 <charconv>）解析整数，它不分配内存、不抛异常。它也不跳过空白，不维护读取位置，需要自己给定字符范围并判断解析到的位置。

**Q14: [learning] 如何使用 std::atoi 把 C 风格字符串转换成 int？**

std::atoi 把以空字符结尾的字符序列解析成 int 并返回，C++ 程序经 <cstdlib> 使用 std::atoi。它不报告错误：无法转换时返回 0，数值超出 int 范围时标准规定为未定义行为。因此它只适合输入可信的场景，例如转换程序内部生成的数字文本。

基本用法：

```cpp
#include <cstdlib>
#include <string>

int main() {
    int port = std::atoi("8080");
    std::string text{"1024"};
    int size = std::atoi(text.c_str());
}
```

执行后 port == 8080、size == 1024。字符串字面量本身就是 const char*，可以直接传入。std::string 不是 C 风格字符串，必须显式调用 c_str() 取得空字符结尾的字符序列，直接传 std::string 不能编译。

解析规则按顺序生效：

1. **跳过前导空白：**`std::atoi("  42")` 返回 42。
2. **允许可选符号：**`std::atoi("+42")` 返回 42，`std::atoi("-42")` 返回 -42。
3. **读到第一个非数字字符停止：**`std::atoi("123abc")` 返回 123，后面的 abc 被忽略。遇到空格同样停止，`std::atoi("12 34")` 只得到 12。
4. **只按十进制解析：**`std::atoi("0x1a")` 只解析出 0，十六进制文本不会按预期转换。

失败与溢出是两条要分开记的边界：

1. **无法转换时返回 0：**`std::atoi("abc")` 和空字符串都返回 0，合法的 `std::atoi("0")` 同样返回 0。返回值无法区分本来是 0 和根本不是数字，所以不能用 `if (std::atoi(text) == 0)` 判断输入合法。
2. **超出 int 范围是未定义行为：**标准不保证任何结果。实测本机不报错也不抛异常，`std::atoi("99999999999")` 得到回绕值 1215752191，`std::atoi("2147483648")` 得到 -2147483648（GCC 11 实测）。换实现可能得到别的值，不能依赖。

需要错误处理时的选择：

1. **要区分失败且接受异常：**用 std::stoi（C++11 起，头文件 <string>）。无法转换时抛 std::invalid_argument，超出 int 范围抛 std::out_of_range。它直接接受 std::string，不需要 c_str()。
2. **不能抛异常：**用 std::from_chars（C++17 起，头文件 <charconv>）解析整数，用错误码报告失败，不分配内存、不抛异常。
3. **用 C 接口且需要失败位置：**用 strtol。它的 endptr 参数报告解析到哪个字符，实测 `std::strtol("123abc", &end, 10)` 返回 123 且 end 指向剩余的 "abc"。

**Q15: [learning] 为什么通常优先使用 std::string 而不是 C 风格字符串？**

`std::string` 管理字符存储和长度，支持赋值、比较及拼接，降低固定缓冲区溢出和手动内存管理的风险。

C 风格字符串仍用于兼容 C API 或明确要求空字符结尾缓冲区的接口。使用它们时必须同时保证容量、终止符和边界条件。

**Q16: [learning] std::string 如何支持赋值和拼接？**

`std::string` 重载了赋值与拼接运算符，使其可以按字符串值进行操作。实现会管理所需容量，但具体何时分配内存不是程序可依赖的接口保证。

```cpp
#include <string>

int main() {
    std::string first{"A"};
    std::string second{"B"};
    std::string third{"C"};
    std::string combined = first + second;
    combined += third;
}
```

`operator+` 会生成拼接结果。连续大量拼接时，可用 `append` 或 `+=` 逐步追加，避免不必要的临时结果。

**Q17: [learning] C++ 原始字符串的 R"(...)" 和自定义定界符有什么作用？**

原始字符串不把内容中的反斜杠序列当作普通转义序列，适合写路径、正则表达式等内容。其结束标记默认是 `)"`。

```cpp
int main() {
    auto path = R"(C:\new\text.txt)";
    auto text = R"tag(text containing )" here)tag";
}
```

自定义定界符用于避免内容提前包含结束标记。原始字符串解决转义问题，`L`、`u8`、`u`、`U` 等编码前缀则决定字符类型或编码，两者可以组合但含义不同。
