# 文件与目录

> 文件属性、目录结构、路径查找和文件数据布局。

**Q1: [done] UNIX 文件系统如何组织文件和目录？**

文件系统提供组织、命名和访问文件的机制。UNIX 将目录和文件组织成以根目录 `/` 为起点的层次结构，通过路径逐级找到文件。

以 `/home/user/note.txt` 为例，查找与文件信息的关系如下：

1. **目录层次**：从 `/` 进入 `home`，再进入 `user`，最后找到名为 `note.txt` 的文件。
2. **目录项**：目录包含名称与文件对象的关联。`user` 目录中的 `note.txt` 是一个目录项，供系统根据名称找到对应文件。
3. **文件属性**：文件有类型、大小、所有者、权限和修改时间等元数据。stat 根据路径查询属性，fstat 根据已打开的文件描述符查询属性。
4. **属性如何保存**：目录项是查找名称的逻辑入口，不代表属性都存放在目录项中。许多文件系统把属性保存在 inode（索引节点）中，多个硬链接可以通过不同名称指向同一文件并共享这些属性。实际存储布局取决于文件系统实现。

挂载可以把不同文件系统接入同一目录树，所以目录树不等同于一个磁盘分区。不同进程的根目录或挂载命名空间可能不同，看到的目录树也可能不同。

**Q2: [done] UNIX 文件名、路径名以及 . 和 .. 分别表示什么？**

文件名是目录中的一个名称，路径名则用一个或多个名称说明如何找到文件。`.` 和 `..` 是路径中的特殊名称，分别表示解析到的当前目录和它的父目录。

假设工作目录是 `/home/user`，要访问其中 `doc` 目录下的 `note.txt`：

1. **文件名**：`note.txt` 是文件在 `doc` 目录中的名称。
2. **绝对路径**：`/home/user/doc/note.txt` 以 `/` 开头，从进程的根目录开始查找。单独的 `/` 也是绝对路径，表示根目录。
3. **相对路径**：`doc/note.txt` 不以 `/` 开头，通常从工作目录开始查找，在此例中指向同一个文件。openat 等接口也可用指定的目录描述符作为起点。
4. **特殊名称**：`./doc/note.txt` 中的 `.` 表示工作目录。`../user/doc/note.txt` 中的 `..` 先指向工作目录的父目录 `/home`，再进入 `user/doc`。根目录的 `..` 仍指向根目录。

路径中的 `/` 用来分隔名称，空字符 NUL 用来终止路径字符串，两者不能出现在文件名组件中。文件系统、编码或工具还可能施加其他限制。文件名包含空格或 shell 特殊字符时，需要适当引用，避免被 shell 当作命令语法解释。

**Q3: [done] 当前目录、相对路径和绝对路径怎样减少路径解析工作？**

绝对路径从根目录开始解析。相对路径从进程当前目录开始解析。维护当前目录可让常用位置下的操作省去重复书写根路径，但目录查找仍需要沿路径组件逐段完成。进程通常从父进程继承工作目录，可通过 chdir 修改；执行新程序后工作目录仍保留。使用 openat 等接口时，相对路径也可从显式指定的目录描述符开始解析。

**Q4: [learning] 操作系统为什么要同时管理文件属性、逻辑结构、目录和物理存储？**

这些问题分别回答“文件是什么、内容怎样组织、文件怎样被找到、数据怎样落到外存”。把它们分开，应用可以通过统一文件名和逻辑地址使用数据，而不必直接处理磁盘布局。

1. **属性与保护**描述名称、标识、大小、位置及访问权限。
2. **逻辑结构**描述文件内部的数据组织方式。
3. **目录**组织多个文件并支持路径查找。
4. **物理结构与空间管理**决定数据块如何分配、定位和回收。

**Q5: [learning] 文件的逻辑结构和物理结构分别回答什么问题？**

逻辑结构描述文件内容如何组织，物理结构描述文件数据块如何存放在外存。二者相互独立：顺序记录、索引记录等逻辑组织可以使用不同的磁盘块分配方式。

1. **逻辑结构**关注记录、字段、顺序访问或按关键字查找。
2. **物理结构**关注逻辑块到物理块的映射，以及数据块是否连续。

**Q6: [learning] 连续、链接和索引分配分别怎样把文件逻辑块定位到物理块？**

连续分配用起始块和长度计算位置。链接分配在每个块中保存后继块号。索引分配通过索引块记录逻辑块到物理块的映射。选择会影响随机访问、空间利用和元数据开销。

1. **连续分配**便于顺序和随机访问，但文件扩展困难且容易出现外部碎片。
2. **链接分配**便于追加，但随机访问需要沿链遍历，链指针损坏也会影响后续定位。
3. **索引分配**支持按逻辑块定位，但需要额外索引空间。大文件可能需要多级索引。

**Q7: [learning] 单级、两级、树形和无环图目录结构分别缓解什么限制？**

目录结构逐步增加命名空间隔离、层次分类和文件共享能力。结构越灵活，路径遍历和共享对象的生命周期管理也越复杂。

1. **单级目录**实现简单，但所有文件共用命名空间，容易重名。
2. **两级目录**按用户分开命名空间，但分类能力有限。
3. **树形目录**通过多级路径分类，适合组织大量文件，但同一个文件通常只有一条目录路径。
4. **无环图目录**允许多个目录项指向共享对象，必须防止引用关系形成环，并在删除时正确处理共享计数或引用。

**Q8: [learning] 目录项为什么可能只保存文件名和索引节点号？**

在使用索引节点的文件系统中，目录项把名称关联到 inode 编号，文件的类型、权限和数据位置等元数据由 inode 管理。这样目录负责名称查找，inode 负责描述文件对象。

1. **名称与对象分离：**多个目录项可以关联同一个 inode，形成硬链接。删除一个名称时，其他名称仍可指向该文件。
2. **查找过程：**系统先在目录中查到名称对应的 inode 编号，再查找或复用缓存中的 inode，检查权限并定位数据。查找有额外步骤，但目录项无需重复保存整份文件元数据。
3. **实现边界：**具体目录项内容随文件系统变化，部分文件系统还会在目录项保存文件类型等信息，不能认为所有文件系统都只存名称和编号。
