# 文件与目录

> 通用操作系统文件管理学习资料。主线：文件属性与四种管理的分工、逻辑结构与物理结构的独立性与三种块分配方式、目录结构的演进与路径解析、目录项与索引节点的分离、文件类型、块设备与 loop 设备、sda 与 NVMe 及 /dev 节点命名、LBA 与扇区、读写六层链路、PCIe 与 NAND、设备节点与 inode、设备号表解读。Q 序列即结构，供 atlas 同源直读。

**Q1: [done] 块设备是什么？**

块设备是以“块”为单位读写的设备文件：数据按固定大小的块组织，每个块可寻址，支持跳到任意块直接访问。磁盘、固态盘、分区和 loop 设备都是块设备。字符设备则以字节流顺序访问，如键盘和串口。两者的区别集中在访问方式、内核路径和系统里的呈现。

1. **访问方式：**块设备按块寻址，读写以块为单位，可以从任意块开始，不必从头顺序读。字符设备是字节流，只能顺序读写，不能指定“读第 1000 字节”。
2. **内核路径：**块设备的 I/O 经过内核块层，带有缓存与 I/O 调度，请求可以合并和重排。字符设备的 I/O 直接交给驱动，没有这一层。
3. **文件系统落在块设备上：**文件系统把数据组织成块存放到块设备中，所以一块盘在被挂载前首先是块设备文件（如 /dev/vda、/dev/sda）。镜像挂载后也是以块设备身份被访问。
4. **系统里的呈现：**块设备在 /dev 下是类型为 b 的设备文件，`ls -l` 第一列显示 b，由主、次设备号找到对应驱动。字符设备同位置显示 c，两者用 `mknod` 创建时的类型参数分别是 b 和 c。
5. **边界：**块设备的“块大小”由设备决定（常见 512 字节或 4KB），文件系统可以另选自己的块大小，两者不是同一回事。块设备支持随机访问，也不保证顺序读比随机读快。

**Q2: [learning] sda 是什么？**

sda 是 Linux sd 驱动呈现的第一块盘的名字：sd 取自 SCSI disk 命名体系，尾部字母是发现顺序。它只回答“由哪类驱动、按什么顺序呈现”，不回答物理接口。

1. **sd 的来历：**SCSI（Small Computer System Interface）本是一套存储命令集与接口标准，Linux 存储栈把它收敛成通用磁盘设备模型，多种物理接口的盘都收敛到该模型下呈现。
2. **收敛到 sd* 的三类设备：**

    1. SCSI 盘：直接走 SCSI 命令。
    2. SATA 盘：SATA/ATA 命令经 libata 翻译成 SCSI 命令后呈现。
    3. USB 大容量存储：底层同样翻译成 SCSI 命令呈现。

3. **读名字：**sd 加序号字母，sda 是该驱动探测到的第 1 块盘，sdb 第 2 块；sda2 是其上的第 2 个分区。
4. **字母会漂移：**字母只代表发现顺序，插拔、启动顺序或加盘都会改变对应关系，重启后 /dev/sda 可能指向另一块盘；因此写进配置的应是 UUID 这类写在文件系统超级块里的稳定标识，而非 sd 字母名。
5. **边界：**sda 只说明呈现层，同机各盘物理接口可能完全不同（SATA、USB、SAS）；不能从名字推断接口、性能或用途。

依据：Linux 内核 sd 驱动命名惯例。

**Q3: [done] NVMe 是什么？/dev/nvme1n1p4 怎么理解？**

NVMe（Non-Volatile Memory Express，非易失性内存主机控制器接口规范）规定主机与存储控制器怎样交换命令和数据。**NVMe 存储**通常指采用 NVMe 规范供主机访问的存储设备或存储资源，例如通过 PCIe 连接的 NVMe 固态硬盘。NVMe 是接口规范，固态硬盘则是实际提供持久化存储的设备。

`/dev/nvme1n1p4` 是 Linux 提供的**块设备节点**，用于访问一个 NVMe 命名空间中的分区。

本机路径从左到右表示：

1. `/dev/`：设备节点所在的目录。
2. `nvme1`：Linux 分配的 NVMe 控制器名称。
3. `n1`：该控制器下的第 1 个命名空间，即一段可独立寻址的逻辑存储空间。
4. `p4`：该命名空间上的第 4 个分区，本机在其中存放 ext4 文件系统。

读取文件时，文件系统找到数据所在的逻辑块，内核再通过 NVMe 驱动向控制器提交读请求。直接打开 `/dev/nvme1n1p4` 则访问分区的原始字节，不会自动按文件名解析。

常见本地 NVMe 固态盘通过 PCIe（Peripheral Component Interconnect Express）连接，NVMe 也支持网络传输。控制器编号不代表固定物理插槽，设备名称也不能单独说明存储介质或性能。

**Q4: [done] PCIe 是什么？**

PCIe（Peripheral Component Interconnect Express，外围组件互连express）是主机与设备间的高速串行点对点总线：NVMe 固态盘、显卡、网卡等挂在它上面，经它与 CPU 和内存交换命令与数据。它决定运力，不决定设备语义。

1. **形态：**点对点链路，带宽由 lane 数与代数决定，每代单 lane 速率约翻倍；一个设备占用一条或多条 lane。
2. **与存储专用互联对照：**SATA 是上一代存储专用互联，命令路径为机械盘时代设计；NVMe 走 PCIe 并以队列化并行命令为闪存设计。同一块 NAND 介质，两条路径的上限完全不同。
3. **在读写链路中的位置：**六层链路里 PCIe 位于驱动与控制器之间，命令提交与数据搬运都经它完成。
4. **边界：**PCIe 只是运输；设备说什么语言由协议（如 NVMe）决定，操作系统怎么用它由驱动决定。插在同一条 PCIe 槽上的网卡和 SSD 共享总线形态，语义毫无共同点。

依据：PCIe 与 NVMe 协议分层惯例。

**Q5: [learning] /dev/sda 是什么？**

/dev/sda 是“sd 驱动呈现的第一块整盘”在目录树中的设备节点路径：/dev 是设备节点目录，sda 是节点名。它与普通文件路径同形不同质——节点 inode 不指向数据块，而是携带设备号，对它的读写被内核翻译成对相应磁盘的块请求。

1. **节点不是盘：**/dev/sda 只是 VFS 可解析的人类可读入口；内核靠设备号（sd 族 major 8）识别设备，不靠名字。删掉节点盘仍在，建出节点盘不在则访问失败。
2. **整盘与分区：**sda 是整盘节点，sda2 是其第 2 分区的节点，二者都是块设备节点，设备号不同（minor 区分）。
3. **节点从哪来：**/dev 下节点通常由 devtmpfs 创建、udev 管理命名与符号链接；手工 mknod 也能建同名节点，但没有对应设备与驱动就是空壳。
4. **使用场合：**人工临时操作可直接用 /dev/sda；写进 fstab 等配置应改用 UUID 稳定标识，避免字母漂移指错盘。

依据：Linux 设备节点惯例与本机 /dev 观察。

**Q6: [learning] LBA 是什么？**

LBA（Logical Block Address，逻辑块地址）是块设备的线性编址：设备对上层呈现为从 0 编号的一串块，每个编号就是一个 LBA，读某 LBA 即请求该位置的数据。它是接口层地址，分区与文件系统都在 LBA 上算位置；盘内真实物理位置对上层不可见。

1. **线性幻觉：**盘内可能是闪存页、磁道与磁头，接口只暴露一维块序列；读写某 LBA 不必知道、也无法知道物理位置。
2. **FTL 的隐藏：**SSD 的 FTL（Flash Translation Layer，闪存转换层）把 LBA 映射到闪存物理页并做磨损均衡与纠错；同一 LBA 在不同时刻可能落在不同颗粒上。
3. **分区以 LBA 划界：**分区是整盘上的一段连续 LBA 区间，分区表的起止与大小都按 LBA 计。实测 nvme0n1p1 起始 2048、大小 532480，即占据 LBA 2048 到 534527。
4. **对齐单位：**LBA 读写按逻辑扇区大小对齐与取整，本机逻辑扇区 512 B，请求即按 512 B 对齐。

依据：本机 sysfs 分区 start/size 实测。

**Q7: [learning] 扇区是什么？**

扇区是磁盘读写的单位；“扇区”与“块”在不同层指不同东西，混用会造成容量与对齐的数量级误判。

1. **逻辑扇区：**设备接口上一个 LBA 对应的字节数，读写必须按它对齐和取整。本机 nvme0n1 为 512 B（/sys/block/nvme0n1/queue/logical_block_size）。
2. **物理扇区：**设备内部写入对齐与纠错使用的单位，可能大于逻辑扇区（常见 4096 B 的 Advanced Format 盘）；本机物理扇区同为 512 B。只按逻辑扇区对齐而不对齐物理扇区，会让一次写入拆成读改写多个物理单位。
3. **文件系统块：**文件系统分配空间、组织元数据的单位，mkfs 时独立选定，通常是逻辑扇区的整数倍；本机根分区 ext4 为 4096 B（stat -f）。设备扇区与文件系统块是两个独立参数。
4. **/proc/partitions 的 #blocks 按 1 KiB 计数：**既不是 512 B 扇区数也不是文件系统块数。实测 nvme1n1 的 #blocks 为 1953514584，即约 1.8 TiB；误当扇区数会把容量算大一倍。

依据：本机 sysfs、stat -f 与 /proc/partitions 实测。

**Q8: [learning] 应用经文件系统、块层、驱动、控制器到存储介质的六层读写链路怎么理解？**

这条链按职责分层：上层说文件与逻辑地址，中层说请求与顺序，下层说控制器命令与介质物理。每层只替上层翻译，并隐藏自己的复杂度。

1. **应用到文件系统或块设备接口：**应用给出路径或偏移。文件系统把“读某文件的第 4096 到 8191 字节”翻译成“读某块设备的哪几个块”。应用也可以绕过文件系统，经设备节点直接发块请求。
2. **Linux 块设备层（block layer）：**接收块请求，做合并（相邻请求合成一个）与调度（重排顺序），并维护缓存；设备看到的是优化后的请求流，不是应用发出的原始序列。
3. **设备驱动：**把通用块请求翻译成具体控制器的命令（如 NVMe 的提交队列条目、SCSI 命令），并回收完成事件。
4. **存储控制器：**内部可能做缓存、地址映射与纠错。SSD 控制器用 FTL 把 LBA 映射到闪存物理页，主机看不到真实物理地址。
5. **存储介质：**数据真正落盘处，如 NAND 闪存、磁性盘片；介质的物理约束（按页写、按块擦、磨损）在这一层生效。
6. **层间运输：**控制器与主机之间由互联总线运输命令与数据，NVMe 走 PCIe，老式盘走 SATA；互联决定运力，协议决定语义。

排查用法：性能或错误问题先定位现象属于哪层——文件系统层看文件与块号，块层看请求合并与延迟，驱动层看控制器命令与超时，介质层看坏块与磨损；跨层归因是最常见的误判。

依据：Linux 内核块层与 NVMe/SCSI 驱动的分层结构（内核 Documentation）。

**Q9: [learning] NAND 是什么？**

NAND（NAND 闪存）是一种非易失性存储介质：以单元电荷状态存数据，断电不丢，是 SSD 与 eMMC/UFS 内部的存储颗粒。它的物理特性决定了存储栈为什么需要 FL 之上的翻译层。

1. **写擦不对称：**按页写、按块擦（一次擦除覆盖多个页）；不能原地覆盖，写已用页必须先擦整块。
2. **磨损：**单元擦写次数有限，控制器必须做磨损均衡把写摊开；这正是主机只看 LBA、看不到物理地址的原因之一。
3. **从介质到盘：**SSD 等于 NAND 颗粒加控制器（FTL、缓存、纠错）；主机看到的是控制器翻译后的块设备，NAND 的页块结构对外完全不可见。
4. **与易失存储对照：**DRAM 掉电丢内容、按字节寻址；NAND 非易失、按页块组织，二者在存储层次中位置不同，不能互换职责。

依据：NAND 闪存与 SSD 控制器惯例。

**Q10: [learning] 设备节点和 inode 怎么理解？**

设备节点是一种特殊文件：它在目录树里看似普通文件，但 inode 不指向数据块，而是在 i_rdev 字段保存设备号；读写节点被内核翻译成对相应设备的操作。inode 是文件系统描述对象的元数据结构（类型、权限、属主、时间戳），普通文件的 inode 关联内容数据块，设备节点的 inode 关联设备号——同一种结构，两种指向。

1. **inode 的两种指向：**普通文件：inode 指向数据块，读文件即读块内容；设备节点：inode 的 i_rdev 存 major 与 minor，读节点即向对应驱动发请求。
2. **mknod 只创建节点：**在目录树里创建携带指定设备号的节点，不创造磁盘也不能替代驱动；要真正可访问，还需设备存在、驱动加载且权限满足。
3. **谁创建节点：**/dev 下节点通常由 devtmpfs 创建，udev 管理命名、权限与符号链接；initramfs 早期场景的关键节点（如 /dev/console）需预置。
4. **类型位：**ls -l 第一列 b 为块设备、c 为字符设备，mknod 的类型参数对应 b 与 c；类型位加设备号共同决定内核把请求交给哪条路径。

依据：Linux 设备节点与 inode 惯例、本机 /dev 观察。

**Q11: [learning] 设备节点表里各行设备号（259:0、259:4、8:2 等）与含义怎么理解？**

设备号是 major:minor 两段：major 标识驱动类别，minor 标识该驱动下的具体实例；表里每行的含义就是“哪个驱动的哪个对象”。stat 的 %t:%T 输出十六进制，0x103 即十进制 259，与 /proc/partitions 对照要先换算。

1. `/dev/nvme1n1`，259:0：第 1 块盘（1.8T）；259 是 nvme 驱动的 major，0 为该驱动下整盘实例。
2. `/dev/nvme1n1p4`，259:4：其第 4 分区，ext4，挂载于 /；分区与整盘同用 major 259，靠 minor 区分。
3. `/dev/nvme0n1`，259:5：第 0 块盘（953.9G）；minor 接在前一块盘的分区之后继续编号，说明 minor 按发现顺序全局分配，不是每盘从 0 起。
4. `/dev/nvme0n1p1`，259:6：其第 1 分区，vfat，挂载于 /boot/efi。
5. `/dev/sda2`（示例），8:2：若有 sd 盘则 major 8 为 sd 驱动、minor 2 为其 2 号分区（本机无 sda）。

边界——名字在不等于能挂载：“分区存在”“设备节点存在”“其中有可挂载的文件系统”是三件独立的事。本机 nvme0n1p2（16 MiB）是正常注册的分区节点，但不含任何文件系统（Microsoft Reserved 保留分区）；另有分区含 BitLocker 内容，Linux 识别出类型却无原生挂载能力。不能凭名字在就推断能挂载。

依据：本机 /proc/partitions 与 stat 实测。

**Q12: [done] 什么是 loop 设备，它怎么把普通文件变成块设备？**

loop 设备是 Linux 提供的虚拟块设备：背后没有物理磁盘，而是把一个普通文件当作“盘体”，让这个文件以块设备的身份被访问。挂载镜像、把镜像交给虚拟机，都是先把镜像文件关联到某个 /dev/loopN，再按块设备使用。

1. **工作原理：**loop 驱动把针对块设备的读写转发给绑定的文件。使用方看到的是一块可按块寻址的磁盘，实际数据存放在文件里，文件的字节布局就是磁盘的块布局。
2. **典型用法：**挂载镜像最简写法是 `mount -o loop system.img /mnt`，mount 会自动挑选一个空闲 loop 设备并完成关联。需要手动控制时用 `losetup /dev/loop0 system.img` 关联、`losetup -d /dev/loop0` 解除关联。
3. **为什么需要它：**挂载和 mkfs 等操作只接受块设备，而镜像只是普通文件。loop 设备补上“文件到块设备”这一层，文件系统工具因此无需区分镜像与真实磁盘。
4. **边界：**loop 设备数量有上限，可用 `losetup -f` 查找空闲设备，现代内核也支持按需创建。一个 loop 设备同时只能关联一个文件。文件被关联后应只通过块设备访问，绕过块层直接改写文件可能破坏一致性。

**Q13: [learning] 操作系统为什么要同时管理文件属性、逻辑结构、目录和物理存储？**

这些问题分别回答“文件是什么、内容怎样组织、文件怎样被找到、数据怎样落到外存”。把它们分开，应用可以通过统一文件名和逻辑地址使用数据，而不必直接处理磁盘布局。

1. **属性与保护**描述名称、标识、大小、位置及访问权限。
2. **逻辑结构**描述文件内部的数据组织方式。
3. **目录**组织多个文件并支持路径查找。
4. **物理结构与空间管理**决定数据块如何分配、定位和回收。

**Q14: [learning] 文件的逻辑结构和物理结构分别回答什么问题？**

逻辑结构描述文件内容如何组织，物理结构描述文件数据块如何存放在外存。二者相互独立：顺序记录、索引记录等逻辑组织可以使用不同的磁盘块分配方式。

1. **逻辑结构**关注记录、字段、顺序访问或按关键字查找。
2. **物理结构**关注逻辑块到物理块的映射，以及数据块是否连续。

**Q15: [learning] 连续、链接和索引分配分别怎样把文件逻辑块定位到物理块？**

连续分配用起始块和长度计算位置。链接分配在每个块中保存后继块号。索引分配通过索引块记录逻辑块到物理块的映射。选择会影响随机访问、空间利用和元数据开销。

1. **连续分配**便于顺序和随机访问，但文件扩展困难且容易出现外部碎片。
2. **链接分配**便于追加，但随机访问需要沿链遍历，链指针损坏也会影响后续定位。
3. **索引分配**支持按逻辑块定位，但需要额外索引空间。大文件可能需要多级索引。

**Q16: [learning] 单级、两级、树形和无环图目录结构分别缓解什么限制？**

目录结构逐步增加命名空间隔离、层次分类和文件共享能力。结构越灵活，路径遍历和共享对象的生命周期管理也越复杂。

1. **单级目录**实现简单，但所有文件共用命名空间，容易重名。
2. **两级目录**按用户分开命名空间，但分类能力有限。
3. **树形目录**通过多级路径分类，适合组织大量文件，但同一个文件通常只有一条目录路径。
4. **无环图目录**允许多个目录项指向共享对象，必须防止引用关系形成环，并在删除时正确处理共享计数或引用。

**Q17: [learning] 当前目录、相对路径和绝对路径怎样减少路径解析工作？**

绝对路径从根目录开始解析。相对路径从进程当前目录开始解析。维护当前目录可让常用位置下的操作省去重复书写根路径，但目录查找仍需要沿路径组件逐段完成。

**Q18: [learning] 目录项为什么可能只保存文件名和索引节点号？**

把文件名与其余元数据分离后，目录项可以更紧凑，单个目录块能容纳更多名称映射。文件元数据集中放在索引节点中。代价是查找文件时需要再读取或缓存索引节点信息。

**Q19: [learning] eMMC 是什么？**

eMMC（embedded MultiMediaCard）是把 NAND 闪存、控制器和 MMC 接口集成在封装中的嵌入式非易失存储方案。设备断电后通常仍保留数据，操作系统一般通过块设备读写它，控制器负责介质管理。

它属于持久化存储，与运行程序时使用的 RAM 不同；文件系统、分区和挂载是建立在存储设备之上的不同层次。eMMC 型号、容量、寿命和实际速度取决于具体芯片及系统配置，不能只凭名称确定性能。

**Q20: [learning] UFS 是什么？**

UFS（Universal Flash Storage）是面向嵌入式设备的非易失闪存存储标准及设备方案，设备通过 UFS 控制器和协议向主机提供存储。它与 RAM 用途不同，断电后通常仍保存文件与系统镜像。

UFS 支持队列化命令处理等能力，但实际性能受标准版本、器件、控制器、软件和负载共同影响。看到 UFS 不等于能够推断某台设备的具体吞吐量。

**Q21: [learning] eMMC 和 UFS 如何区分，怎样查看设备使用哪一种？**

eMMC 和 UFS 都提供持久化存储，但使用不同的接口和主机控制器。确认设备类型应优先查硬件规格，再结合系统暴露的设备及驱动信息交叉核对。

1. **查看硬件资料**：产品物料表、芯片型号及平台设备树通常可指出存储器件与控制器。
2. **查看系统设备**：Linux 可从 `/sys/block/` 对应设备的 `device` 链接追踪所属总线与驱动，并结合 `/sys/class/mmc_host/` 或 SCSI/UFS 控制器信息查看；Android 设备能否读取和具体路径取决于权限和内核实现。
3. **识别限制**：`mmcblk` 常见于 MMC 子系统，`sdX` 也可能用于 UFS 等 SCSI 块设备，但名称并非硬件型号的充分证明。`dm-0` 是映射设备编号，F2FS 是文件系统类型，二者都不能独自证明底层为 eMMC 或 UFS。

比较性能应在相同负载下实测；UFS 的协议能力不保证任意 UFS 器件都比任意 eMMC 器件快。

**Q22: [learning] 分区中的文件系统未挂载时，如何通过设备节点读取分区？**

在 Linux 中，程序可以打开代表分区的块设备节点，按偏移读取分区的原始字节。读取经过内核的块设备层和驱动，不需要先把该分区上的文件系统挂载到目录树。

以设备节点 `/dev/sdb1` 为例，读取过程如下：

1. **找到入口**：`/dev/sdb1` 是当前系统中代表某个分区的块设备节点。该名称仅作示例，实际名称要在目标设备上确认。
2. **打开节点**：程序按路径打开设备节点。节点位于已经可访问的 `/dev` 目录中，节点记录的设备号让内核找到对应的块设备。能否打开还受节点权限和系统安全策略限制。
3. **读取字节**：程序指定设备内的偏移和长度发起读取。内核将请求交给块设备层和驱动，返回相应位置的原始数据。
4. **解释内容**：返回的数据可能包含文件系统元数据或文件内容，但块读取本身不知道文件名。若要在未挂载时找到 `report.txt`，工具需要自行解析该文件系统的目录、inode 和数据块。

设备节点可访问与分区上的文件系统已挂载是两回事：前者提供分区的块级入口，后者让内核按目录和文件名解析文件。直接写入块设备可能覆盖文件系统元数据或文件内容，尤其不能在文件系统正在使用时随意写入。

**Q23: [done] device-mapper 是什么？Android 如何用它访问动态分区？**

device-mapper（设备映射器，简称 dm）是 Linux 内核中的虚拟块设备框架。它根据映射表，在已有块设备之上提供新的块设备；上层读写新设备时，内核按映射规则处理请求，再访问对应的底层设备。

以 Android 动态分区中的 system 为例，可以这样理解：

1. **存储在哪里**：system 的数据占用 `super` 分区中的若干区域。`super` 的元数据记录这些区域属于哪个逻辑分区。
2. **怎样变成设备**：启动时，Android 读取元数据，为 system 创建 dm 设备并加载映射表。这个设备对上层表现为一块独立的块设备，但并不是新增加了一块物理硬盘。
3. **怎样读取文件**：system 文件系统挂载后，应用读取其中的文件。文件系统向 system 的映射设备发出块读取请求，device-mapper 按映射表找到 `super` 中对应的区域，再将请求交给底层设备。

映射规则由 target（映射目标）决定：Android 动态分区可使用 dm-linear 将逻辑地址映射到底层区域；dm-verity 则用于读取时的完整性校验。实际设备的映射可能多层叠加，布局也因版本和配置而异。

例如，看到 `/dev/block/dm-0` 只能说明它是一个运行时 dm 设备，不能仅凭编号断定它是 system、scratch 或某个物理分区。要确定其作用和后端，应查看设备名称、映射表并逐层追踪。
