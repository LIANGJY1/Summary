# 文件操作与打开模型

> 本册讨论文件描述符、打开文件对象、标准流和文件读写。initramfs 中的文件准备与启动验证见 [Linux 启动](../05-Linux构建与启动/03-Linux启动.md)。

**Q1: [done] 文件描述符 fd 是什么？**

文件描述符（file descriptor，fd）是进程用来引用已打开对象的非负整数，对象可以是普通文件、管道或套接字。内核维护按进程区分的 fd 表；进程把 fd 传给 `read()`、`write()`、`lseek()`、`close()` 等系统调用时，内核在发起调用的进程表中查找对应的打开文件描述。因此，fd 是进程上下文中的编号，不是文件名、文件内容或打开对象本身。

1. **编号与查表：**每个进程有自己的 fd 表。成功调用 `open()` 会取得该进程当前可用的最小非负编号，所以不同进程的 fd 3 可以映射到不同对象。Linux 中，同一进程的线程通常共享 fd 表；一个线程关闭某个 fd 后，其他线程看到的表项也随之关闭，编号还可能被复用。
2. **打开状态：**fd 表项指向内核的打开文件描述（open file description），其中保存文件偏移量、文件状态标志等状态。分别调用两次 `open()` 会创建不同的打开文件描述；`dup()` 创建的新 fd 和 `fork()` 后子进程继承的 fd，则可以指向同一个打开文件描述，因此共享文件偏移量。
3. **关闭与释放：**`close(fd)` 移除当前进程中的 fd 引用，该编号之后可以分配给新打开的对象。如果还有其他 fd 引用同一个打开文件描述，它仍保持有效；最后一个引用关闭后，相关打开状态才可释放。
4. **标准描述符：**POSIX 程序通常把 0、1、2 分别用作标准输入、标准输出和标准错误。它们是用途有约定的普通 fd，启动环境可以重定向它们，编号本身不代表特殊文件类型。

判断 fd 指向什么对象时，必须同时看 fd 编号和发起系统调用的进程。相关依据见 Linux man-pages 的 `open(2)`、`dup(2)`、`fork(2)`、`close(2)`、`pipe(7)` 和 `socket(7)`，以及 Android SDK 的 `ParcelFileDescriptor` 文档。

**Q2: [done] 标准输入、标准输出和标准错误是什么，怎样重定向？**

标准输入、标准输出和标准错误是程序约定使用的三个输入输出通道。在 POSIX 环境中，它们通常对应文件描述符 0、1、2，让程序通过统一接口读写终端、文件或管道。

三个通道按用途分工：

1. **标准输入（0）**：向程序提供数据，例如从终端读取用户输入或从文件读取内容。
2. **标准输出（1）**：输出程序的正常结果，例如文件列表。
3. **标准错误（2）**：输出错误和诊断信息。它与正常结果分开，便于把结果交给文件或另一个程序，同时单独查看错误。

**重定向**是由 shell 在运行程序前改变这些通道连接的位置。程序仍使用标准通道，无须为终端和文件分别编写一套输入输出逻辑。例如 `./a.out < infile > outfile`：`< infile` 把标准输入连接到文件 `infile`，`> outfile` 把标准输出连接到文件 `outfile`，标准错误保持原连接。通常 `>` 会创建文件或截断已有文件；用 `2> errors` 可将标准错误另写入 `errors`。

交互式终端通常让三个通道连接终端，但脚本、管道或服务可以连接其他对象。重定向时若文件打开失败，相关命令不会正常执行。

终端规范模式下，行首输入配置的 EOF 字符通常为 Ctrl+D，可使等待输入的读操作返回 0，它不是写进文件的普通结束字节。重定向到普通文件时，读到文件尾也会返回 0。

**Q3: [done] UNIX 不带缓冲的文件 I/O 是什么？**

“不带缓冲”指 read 和 write 使用文件描述符发出读写请求，不经过 C 标准 I/O 库的流缓冲区。这不意味着没有任何缓冲，也不等于直接 I/O 或数据已经持久化。

**缓冲区**是暂存数据的内存区域，读写普通文件时要区分三个位置：

1. **应用缓冲区**：由程序提供。read 将数据放入其中，write 从中取出数据。
2. **标准 I/O 流缓冲区**：由 C 标准 I/O 库管理。例如多次 putc 的输出可能先暂存，再合并写出，以减少系统调用。直接调用 read 和 write 不经过这一层。
3. **内核页缓存**：内核通常用它缓存普通文件的数据。write 返回后数据可能仍在缓存中，等待写入存储设备；设备也可能有自己的缓存。

文件操作通常依次使用 open、read 或 write、close。lseek 可改变支持定位的文件的读写位置，管道等对象则不可定位。读写时应检查返回值：

1. **read**：正数是实际读取的字节数，可能少于请求值。对非零长度的普通文件读取，文件尾返回 0，失败返回 -1 并设置 errno。
2. **write**：成功返回实际写入的字节数，可能短于请求值。程序需要继续写入剩余部分，并处理错误和中断。

应用缓冲区的大小会影响读写调用次数和性能，合适大小取决于负载。write 成功不保证数据已落到持久介质，需要持久性时还须按系统和文件系统的契约处理同步与错误。

**Q4: [done] C 标准 I/O 与文件描述符 I/O 有什么区别？**

C 标准 I/O 使用 `<stdio.h>` 提供的 FILE 流和函数，通常在用户空间缓冲数据，并提供格式化、字符与行处理。POSIX 的 read 和 write 使用文件描述符进行字节传输，不提供同一层自动流缓冲。

标准流 stdin、stdout 和 stderr 是 FILE 流，与底层标准描述符相关联，但不是描述符整数本身。printf、getc 和 putc 可经流缓冲减少底层调用，fgets 最多读取缓冲区容量减一的字符，遇换行或文件尾也停止，长行可能需要多次读取。getc 在文件尾或出错时返回 EOF，应以 int 保存结果，并用 feof 或 ferror 区分原因。

流可配置为全缓冲、行缓冲或无缓冲，setvbuf 须在打开流后、其他操作之前调用。fflush 将用户态输出缓冲交给底层写操作，不保证持久化。同一打开文件混用流操作与描述符操作时必须遵守 POSIX 活动句柄协调规则，否则缓冲与文件偏移可能使结果不可预期。

**Q5: [learning] 为什么文件操作通常要经过 open、read/write 和 close 等不同操作？**

文件系统把定位文件、建立打开状态、传输数据和结束访问分成不同操作。`open` 根据路径找到文件并建立进程可用的打开记录。后续 `read`/`write` 通过该记录访问数据。结束时 `close` 释放打开状态。

打开可能读取元数据或访问缓存，但不等于把全部文件内容读入内存。具体缓冲、缓存和持久化行为由操作系统与文件系统实现决定。

**Q6: [learning] 打开文件后，系统打开文件表和进程打开文件表分别解决什么问题？**

进程打开文件表把进程可见的文件描述符映射到内核打开对象。系统级打开对象可维护访问模式、当前偏移和底层文件引用等状态。不同操作系统的结构名称与共享细节不同。在 POSIX 模型中，共享文件偏移取决于多个描述符是否引用同一个 open file description，例如描述符复制或继承后通常共享偏移。两个独立的 `open()` 即使使用同一路径，也通常建立不同的打开描述。

**Q7: [learning] 复制文件为什么不是单一的“复制”原子操作？**

复制通常由创建目标、循环读取源数据、写入目标并关闭两侧文件等基本操作组成。失败处理还要决定是否删除不完整目标。并发修改源文件时，复制结果是否一致取决于文件系统和应用采用的快照或锁定策略。

**Q8: [done] fcntl() 函数是什么，如何使用？**

`fcntl()` 是 POSIX 文件控制接口，通过文件描述符查询或修改相关属性，也可复制描述符或管理文件锁。它声明在 `<fcntl.h>` 中，语法为 `fcntl(fd, cmd, ...)`：`fd` 是已打开的文件描述符，`cmd` 指定操作，是否需要第三个参数取决于命令。

常见命令包括：

1. **`F_GETFL` / `F_SETFL`：**读取或设置文件状态标志，例如 `O_NONBLOCK`。这些标志属于打开文件描述，多个引用同一打开文件描述的 fd 会共享。
2. **`F_GETFD` / `F_SETFD`：**读取或设置描述符标志，例如 `FD_CLOEXEC`，它让该 fd 在成功执行 `exec` 时关闭。
3. **`F_DUPFD`：**复制文件描述符，新旧 fd 引用同一打开文件描述。

例如，为已有的 fd 开启非阻塞模式，同时保留原有状态标志：

```cpp
#include <fcntl.h>

int set_nonblocking(int fd) {
    int flags = fcntl(fd, F_GETFL);
    if (flags == -1) return -1;
    return fcntl(fd, F_SETFL, flags | O_NONBLOCK);
}
```

先读取再按位或，避免覆盖其他可设置的状态标志。在 Linux 上，该函数返回 `0` 表示设置成功，`-1` 表示失败。一般来说，`fcntl()` 成功时的返回值取决于命令，失败时返回 `-1` 并设置 `errno`。

依据：[Linux fcntl(2)](https://man7.org/linux/man-pages/man2/fcntl.2.html)。
