**Q1: [learning] 文件系统为什么要分层实现？**

分层让上层负责文件名和访问语义，下层逐步处理目录、空间分配、块读写和设备交互。分工能隔离接口变化，但每层都要维护契约，额外跨层调用也会带来成本。

**Q2: [learning] 物理格式化、逻辑格式化和挂载分别改变什么？这些术语在现代存储上有什么边界？**

在经典磁盘模型中，物理格式化（低级格式化）建立可寻址扇区等介质结构。逻辑格式化（高级格式化）在分区或卷上初始化特定文件系统所需的元数据布局。挂载则把已识别的文件系统接入当前目录树，使路径访问能够进入该卷。

这三者改变的层次不同：物理格式化面向设备介质，逻辑格式化会重建卷内文件系统元数据，挂载通常只建立运行期的命名空间连接，不等于重新格式化。现代 HDD/SSD 的扇区组织和低级格式通常在制造或控制器层处理，桌面系统中的“格式化磁盘”多数指逻辑格式化。分区表变更、加密或快照也不是同一操作。

**Q3: [learning] 文件系统在磁盘和内存中分别保存哪些信息？**

磁盘保存可持久化的文件系统元数据与文件内容。内核内存中的目录缓存、打开文件对象和进程描述符记录则加速路径解析并维护当前访问状态。缓存是可重建的运行期状态，不能与持久化目录或 inode 混为一谈。

**Q4: [learning] ext4 是什么，它用哪些关键机制组织磁盘？**

ext4（fourth extended filesystem，第四代扩展文件系统）是 Linux 原生的通用磁盘文件系统，ext 家族第四代：数据落在块设备上、可读写、带日志，是多数发行版根文件系统和 Android 数据分区的常见选择。相对 ext2/ext3 的关键变化是用 extent 管理物理块、容量上限提高到 EiB 级；磁盘骨架仍沿用 ext 家族的超级块加块组结构。延迟分配把块分配推迟到回写时进行，以换取更连续的布局。

1. **磁盘骨架：**

    1. **超级块：**记录块大小、总块数、总 inode 数等全局信息，位于固定偏移 1024 字节处，并在部分块组留有备份；挂载时先读它确认“是不是 ext4、多大”。
    2. **块组：**全盘切组，每组自带块位图、inode 位图、inode 表和数据块；管理信息按组集中，减少跨盘寻道。
    3. **inode 与 extent：**每个文件一个 inode，记权限、大小、时间戳和物理块位置。与 ext2/ext3 的差别在物理块清单改用 extent：每条记“起始块号加连续块数”，不再每块一个编号，大文件的映射结构因此更小更连续。

2. **日志：**元数据修改先写入日志区、按事务提交；崩溃后下次挂载重放日志即可恢复一致性，不必全盘扫描。默认只把元数据记入日志，并要求数据先于对应元数据落盘（data=ordered）。日志的代价是额外写入，这是它与闪存取向文件系统对比的焦点之一。
3. **在格式化与挂载链条中的位置：**mkfs.ext4 是逻辑格式化，把上述骨架写上空盘；超级块、组描述符、inode 表、位图和日志等固定开销与内容多少无关，因此镜像容量要为之留余量。mount 把超级块和组描述符读进内存后，路径访问才经 VFS 进入 ext4 的代码。
4. **边界与位置：**ext4 兼容 ext2/ext3，旧分区可直接挂载；只读分发场景不如 erofs、squashfs（无日志开销、可压缩）；Android 的 userdata 上 ext4 与 f2fs 并存，选择取决于设备与版本，快慢结论必须来自同条件实测。Mini_Android 的 system.img 与多数发行版根文件系统都是 ext4。

**Q5: [learning] 伪文件系统是什么？**

伪文件系统是没有磁盘落盘的文件系统总称：目录与文件内容不由块设备读入，而由内核在内存中生成和维护，再借统一的文件接口呈现给用户态。它让“读内核状态”和“拿内存当盘”复用与普通文件相同的操作路径。

1. **内核接口族：**procfs 呈现进程与系统状态，sysfs 呈现设备与驱动结构，devtmpfs 呈现设备节点；内容在读时或设备注册时生成，卸载后通常不留任何东西。
2. **内存存储族：**tmpfs、ramfs 把内存当存储介质，写入真的保存内容，但掉电即失；/dev/shm、/run 等由它们承载。
3. **与磁盘文件系统的同与异：**挂载方式与路径访问完全相同（都要挂载后才可见，都经 VFS 分派）；差别只在内容来源与持久性。因此 mount、df 等工具把它们当普通挂载点看待，但容量与持久语义不同：接口族报的大小多是虚拟值，存储族受内存上限约束。

依据：Linux 内核伪文件系统惯例与本机 /proc/mounts 实测。

**Q6: [learning] proc 是什么？**

/proc 是 procfs 的挂载点：内核把进程与系统状态呈现为目录和文件，内容在读时临时生成，不占磁盘也不持久化。它把“向内核询问状态”变成所有工具都会的文件读取动作。

1. **进程视图：**每个 PID 一个目录（/proc/<pid>/），内有 cmdline、status、fd、maps 等文件；ps、top 的数据来源就是它们。
2. **系统视图：**/proc/mounts 呈现当前挂载表（第一列是各挂载的 source）；/proc/partitions 呈现块设备与分区登记表（#blocks 按 1 KiB 计数）；/proc/cpuinfo、/proc/meminfo 呈现硬件与内存概要。
3. **可写节点：**/proc/sys 下部分文件是内核运行时参数，写入即生效（网络、虚拟机内存等调参），sysctl 命令的后端就是它。
4. **边界：**内容是读时视图而非快照，两次读取结果可能不同；文件常报大小 0 却有内容，按普通文件复制 /proc 只会得到空壳。

依据：Linux 内核 procfs 惯例与本机 /proc 实读。

**Q7: [learning] procfs 是什么？它在编译、启动和挂载时分别发生什么？**

procfs 是 Linux 内核实现的伪文件系统：没有块设备后端，/proc 下的目录与文件由内核在内存里生成。它从编入内核到出现在 /proc 要经过三个时间点，缺一不可。

1. **编译时：**fs/proc/ 下的源文件被编进内核镜像，每个文件定义一类条目的名字和读取函数，例如 cmdline.c、cpuinfo.c、base.c 分别定义 /proc/cmdline、/proc/cpuinfo 与 /proc/<pid>/ 下的进程条目。配置项 CONFIG_PROC_FS 控制是否编入：默认开启（default y），不显式设置也编入。关闭（=n）后 proc 类型不存在，挂载会因未知文件系统类型而失败。
2. **启动时：**proc_root_init() 调用 register_filesystem()，把类型名 proc 登记进 VFS（Virtual File System）的文件系统注册表。此时它与目录树还没有关系：/proc 只是制作根文件系统时创建的空目录。即使永不挂载，这个类型也一直留在注册表里。
3. **挂载时：**挂载传入的类型名 proc 被内核拿去注册表里查，命中 proc_fs_type 后调用 proc_fill_super() 构造实例：准备超级块与根目录 inode，建立 self、thread-self 等自指条目，再把实例的根接到 /proc 这个挂载点上。此后访问 /proc 下的任何路径，都由这个实例应答。

“接到 /proc”的完整含义就是：让内核在内存里生成的视图树从此刻起接管 /proc 这个路径。编译和登记只是准备，挂载才让它真正出现在目录树上。

依据：Android Common Kernel 5.15.41（AAOS13 学习副本）fs/proc/ 源码与本机 /proc 挂载实读。
