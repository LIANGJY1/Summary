# 线程同步与死锁

**Q1: [learning] POSIX 线程为什么要把互斥锁与条件变量一起使用？**

互斥锁保护共享状态，条件变量让线程等待该状态满足条件。等待方应在持有互斥锁时检查条件，并在每次被唤醒后重新检查。

以消费者等待队列非空为例，双方使用同一把锁保护队列。

1. **检查与等待**。消费者持锁检查队列。若队列为空，pthread_cond_wait 以原子方式释放锁并进入等待，避免生产者把通知发在检查和进入等待之间。
2. **更新与通知**。生产者持锁加入元素，并通知等待者。队列本身记录是否有数据，条件变量不累计无人接收的通知。
3. **唤醒与重查**。消费者从等待返回时重新持有锁。它可能虚假唤醒，也可能遇到其他消费者已经取走数据，因此应循环检查队列，再决定消费或继续等待。

依据：POSIX pthread_cond_wait 的等待和谓词语义。

**Q2: [learning] 两个线程怎样因加锁顺序形成死锁，如何判断与预防？**

当两个线程各自持有对方需要的互斥锁，又都在等待下一把锁时，会形成循环等待。统一多把锁的获取顺序，可以消除这一类死锁。

1. **形成过程**。线程甲先锁 A 再等 B，线程乙先锁 B 再等 A。两者都到达等待点后，都无法执行到释放已持有锁的位置。
2. **判断依据**。从线程栈和锁信息核对每个线程正在等待的锁，以及锁由哪个线程持有。持续看到两个线程都在等锁，还需要确认等待关系是否闭合成环。
3. **预防边界**。为可能嵌套获取的锁定义一致的顺序，并覆盖错误处理和回调路径。这个方法针对锁顺序反转，等待线程退出或同步调用也可能形成其他类型的循环。

依据：Linux 内核文档 Runtime locking correctness validator 对锁依赖循环的说明。
