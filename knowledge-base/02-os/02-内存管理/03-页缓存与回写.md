# 页缓存与回写

**Q1: [learning] Linux 页缓存与匿名内存有什么区别，内存紧张时怎样回收？**

页缓存保存文件内容在内存中的副本，匿名内存通常承载进程的堆、栈等没有普通文件作为后备的数据。能否直接回收，取决于数据能否从其他位置重新取得。

1. **干净的文件页**。内容与后备文件一致，满足回收条件时可丢弃，之后需要时再读入。普通缓冲读和文件映射可以利用同一文件的页缓存。
2. **脏的文件页**。内容已改变，通常需要先回写再回收，避免丢掉尚未保存的修改。
3. **匿名页**。仍被使用且内容无法重建的匿名页，需要有可用的交换空间等后备机制才能换出。没有交换空间时，这类页面通常不能这样回收。

例如，读取大文件后缓存增长与进程不断分配并写入堆内存，都会消耗物理内存，但回收成本与条件不同。排查时应先区分文件页、匿名页和脏页，再结合回收活动判断内存压力。

依据：Linux 内核文档 Concepts overview 的 Page cache、Anonymous Memory 与 Reclaim。

**Q2: [learning] 普通文件 write 成功后，数据什么时候才算持久化？**

对采用缓冲写的普通磁盘文件，write 成功表示系统接收了返回值所示的字节数，数据可能还留在页缓存中。需要等待文件数据持久化时，应调用 fsync 并检查返回值。

1. **写入缓存**。内核修改页缓存中的数据并标记脏页，应用可能先于存储设备完成写入而继续执行。
2. **回写与同步**。内核可在后台提交写入。fsync 请求同步该文件的修改数据和元数据，并等待设备报告完成。回写错误可能在后续 fsync 时才报告。
3. **目录项的边界**。新文件的名称或重命名后的目录项属于目录元数据。如果还要求这些变更在断电后可恢复，需要按所在文件系统的保证同步相关目录。

以新建配置文件为例，要验证断电后仍能通过文件名读到内容，既要确认文件同步成功，也要检查目录项的持久化条件。

依据：Linux 内核文档 Overview of the Linux Virtual File System 与 Linux man-pages 的 fsync(2)。
