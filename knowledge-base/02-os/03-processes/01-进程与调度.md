# 进程与处理机调度

> 学习资料。问题覆盖进程实体、状态与控制、线程及调度策略；题序即文档结构。

**Q1: [done] 内核有“进程”这个概念吗？内核为什么能运行？**

进程是内核管理的任务，不是内核运行的前提。内核启动初期由 CPU 直接执行特权代码。完成基础初始化后，才创建并调度内核线程和用户进程。

1. Bootloader 将内核载入内存，并跳转到内核入口。
2. 内核入口建立运行环境，随后进入 `start_kernel()` 初始化内存、中断和调度器。
3. 内核创建 `kthreadd` 和 `kernel_init` 等内核线程，调度器开始运行它们。内核线程只执行内核代码。用户进程则在用户态运行程序。





**Q2: [learning] 程序、进程和进程映像有什么区别？**

程序是存储介质上的静态指令集合。进程是程序的一次执行活动。进程映像描述该进程在某一时刻的代码、数据、控制信息和资源状态。相同程序可以同时运行多个进程实例。

进程会创建、运行并终止，多个进程可以在一段时间内并发推进。各进程具有相对独立的资源和执行状态，但其推进速度受调度和等待事件影响；涉及共享数据时必须通过同步保证所需顺序。

进程控制块（PCB）保存操作系统管理进程所需的信息，例如进程标识、状态、资源和处理器现场。程序段与数据段分别承载指令和运行数据。进程创建和退出时，操作系统建立和回收相应的控制信息与资源。

系统可按状态将进程控制信息组织成就绪队列和等待队列，也可通过索引查找；具体数据结构取决于实现。进程标识符用于区分进程，但进程结束并被回收后，标识符可以被复用。





**Q3: [learning] 就绪、运行、阻塞和挂起状态分别说明进程缺少什么条件？**

就绪进程具备运行条件但在等待处理器。运行进程正在占用处理器。阻塞进程等待某个事件或资源。在经典换出模型中，挂起进程暂不具备驻留条件；阻塞说明“等事件”，挂起说明“暂不参与调度”，两者回答的是不同状态维度。

1. **就绪 → 运行**：调度器选中该进程。
2. **运行 → 就绪**：时间片用尽或发生抢占。
3. **运行 → 阻塞**：进程等待 I/O、资源或其他事件。
4. **阻塞 → 就绪**：等待事件完成，进程重新具备运行条件。
5. **挂起 → 就绪/阻塞**：进程重新调入主存后，按等待事件是否完成恢复相应状态。

经典七状态模型还包括创建、终止、就绪挂起和阻塞挂起。阻塞挂起期间事件可能完成，进程转为就绪挂起；只有解除挂起并具备其他运行条件后才可参与调度。创建完成可进入就绪，运行结束可进入终止。该模型用于解释换入换出，并不要求现代系统把整个进程映像一次性换出。

不同教材和操作系统会采用不同状态模型。不要把所有实现都限定为同一组状态名称。





**Q4: [learning] 进程控制为什么要求创建、阻塞、唤醒和切换具备原子性？**

这些操作会同时修改进程状态、控制块和多个队列。如果在中间状态被另一个处理器或中断路径观察或修改，进程可能出现在错误队列、丢失唤醒或让调度器运行不该运行的任务。操作系统必须把相关状态变更作为一个对并发观察者不可见的临界区，并保持队列和状态之间的不变量。

例如阻塞操作需要确认等待条件仍未满足，再原子地登记等待关系并让出处理器。若先检查条件、后入队，中间事件可能已经到达，造成永久睡眠。唤醒操作则在条件满足时更新等待状态并使任务重新具备调度资格。现代多核系统通常需要锁、原子操作和内存顺序约束共同维护这些状态，屏蔽本地中断只能处理特定竞争，不能单独保证跨核原子性。





**Q5: [learning] 进程和线程的资源边界有什么区别？**

进程提供资源隔离和地址空间等执行环境。线程是进程内可调度的执行流。一个进程可以包含多个线程，这些线程通常共享进程的地址空间和打开资源，但各自拥有独立的处理器执行现场和栈。

线程能降低同一进程内任务共享数据的成本，但也需要同步以避免竞态。独立进程的地址空间隔离更强，进程间共享数据通常需要显式 IPC 或共享内存机制。具体资源共享范围由操作系统和线程实现定义。





**Q6: [learning] 高级、中级和低级调度分别决定什么？**

在经典批处理调度模型中，高级调度决定哪些作业进入内存并建立进程，中级调度决定哪些挂起进程重新调入内存，低级调度从就绪队列选择下一个获得处理器的执行单位。低级调度通常最频繁，因为它直接参与处理器分配。现代通用操作系统未必以这三种独立调度器实现，术语描述的是决策层次。

中级调度可能通过换出、换入缓解内存压力。它与进程是否等待 I/O 的阻塞状态不同。具有内核线程的系统中，低级调度器实际选择的执行单位可能是线程。





**Q7: [learning] FCFS、SJF、HRRN 和 RR 分别优先解决什么调度目标？**

FCFS 重视到达顺序，SJF 偏向短作业，HRRN 将等待时间纳入优先级，RR 通过时间片轮转改善交互响应。策略优化目标和假设不同，没有一种策略能同时对所有工作负载实现最佳响应、公平和吞吐量。

1. **FCFS**：按进入队列的顺序服务。实现简单但长作业可能让后续短作业等待很久。
2. **SJF/SRTF**：SJF 选择预计运行时间最短的作业，SRTF 是其抢占式版本，会优先运行剩余时间最短的任务。若时长估算准确可降低平均等待，但持续到达的短作业可能使长作业饥饿。
3. **HRRN**：按响应比 `(等待时间 + 服务时间) / 服务时间` 选择任务，等待越久响应比越高。经典形式通常在调度点非抢占地选择任务，服务时间估计仍会影响选择。
4. **RR**：每个就绪任务轮流获得时间片。时间片太大时交互响应变差，太小时切换开销上升。





**Q8: [learning] 优先级调度和多级反馈队列怎样影响响应与饥饿？**

优先级调度按任务优先级分配处理器，可让紧急任务更快获得服务，但低优先级任务可能长期得不到服务。若高优先级任务持续到达，普通任务饥饿。优先级老化可通过等待时间逐步提高其优先级缓解这一问题。

多级反馈队列让新任务从较高优先级队列开始，耗尽时间片后逐步降级，以近似区分短交互任务和长 CPU 密集任务。交互任务若在时间片结束前阻塞，通常可留在较高队列，但实际规则由队列策略决定。队列数、各级时间片和提升机制共同影响响应、公平与吞吐。

算法效果不能脱离工作负载和优先级更新规则来判断。反馈队列并不会自动消除饥饿，必须检查是否有老化或周期性提升。





**Q9: [learning] 周转时间、等待时间和响应时间分别测量什么？**

三个指标衡量不同等待阶段：

1. **周转时间**：作业从提交到完成的总时长，包含等待、执行和 I/O 等阶段。
2. **等待时间**：累计处于就绪状态但未获处理器服务的时长。
3. **响应时间**：请求提交到首次得到响应的时长，交互系统通常更关注该指标。

等待 I/O 通常不算处理器就绪队列等待。统计作业时，有的口径还把进入系统后等待作业调度的时间计入等待时间。批处理系统常关注吞吐量和平均周转表现，交互系统则更关注响应时间。比较调度策略时应明确统计对象、负载和平均值或分位数口径。





**Q10: [learning] fork 的写时复制（COW）省掉什么？exec 之后进程为什么还是同一个进程？**

fork 复制出的子进程获得父进程地址空间、打开文件表与寄存器现场的副本，但现代内核并不立即复制物理内存页：父子页表最初都指向同一批物理页并标记只读，任何一方首次写入时触发缺页，内核才复制该页——这就是写时复制。fork 之后调用 exec 会丢弃原地址空间、装入新程序映像，但 PID、打开文件描述符（未设 close-on-exec 的）与进程身份延续，所以“换了程序”仍是同一个进程。

1. **COW 的收益**：fork 的成本从 O(全部内存) 降到 O(页表)。配合 exec，“fork+exec”路径上绝大多数页面从未被复制。
2. **代价与边界**：COW 依赖 MMU 的页级保护，颗粒度是页而非字节。大量随机小写入会退化为逐页复制。有 vfork 这类“共享地址空间、挂起父进程”的极端优化，语义危险，新代码不应依赖。
3. **内核视角**：Linux 的 `clone()` 用标志位细粒度选择共享什么（内存、文件表、信号处理），线程就是共享地址空间的 clone 产物——对应前面题组的线程资源边界。





**Q11: [learning] 僵尸进程和孤儿进程分别是怎么产生的？为什么说孤儿无害而僵尸要追责父进程？**

子进程退出后，内核保留它的退出状态供父进程查询，这个“已死但状态未收”的过渡态就是僵尸（zombie）：内核只保留 PID、退出码与账务信息，等父进程调用 wait/waitpid 领取后彻底释放。孤儿则是父进程先退出、子进程还在运行：内核把它的父进程改挂到 init（或容器里的对应收养者），由收养者负责 wait，因此孤儿能正常存活到自然退出。

1. **僵尸的成因**：父进程只 fork 不 wait，或 wait 时机晚于子进程退出。僵尸堆积会耗尽 PID，这是“进程泄漏”的实质。
2. **处置**：让父进程补 wait/waitpid，或注册 SIGCHLD 处理。父进程已无法修改时，重启或终止父进程，使僵尸被收养者回收。
3. **边界**：以 SIG_IGN 忽略 SIGCHLD 可让内核自动回收子进程（POSIX 语义）。僵尸本身不可被 kill——它已经死了，能 kill 的只有忘了 wait 的父进程。





**Q12: [learning] 一次上下文切换的成本由哪些部分构成？进程切换与线程切换差在哪？**

上下文切换是内核把 CPU 从一个执行流改派给另一个的过程，成本分直接与间接两部分：直接成本是保存旧上下文、恢复新上下文（寄存器、程序计数器、内核栈指针切换）与调度代码执行。间接成本来自新执行流的地址空间和工作集与缓存、TLB 的现状不匹配，切换后一段时间内命中率可能下降，其大小取决于负载和硬件。

1. **进程切换**：地址空间不同时需要切换地址空间上下文；TLB 中的旧映射是否需要失效取决于处理器、地址空间标识和内核实现。
2. **线程切换**：同一进程内的线程通常共享地址空间，因此无需切换到另一个进程的地址空间，仍需保存和恢复各自的执行现场。
3. **边界**：两种切换的实际成本受架构、缓存、工作集和调度路径影响，不能保证线程切换在所有负载下都更快。切换频繁也可能来自正常的 I/O 唤醒，不能单凭次数判断锁竞争。

**Q13: [learning] 用户级线程和内核级线程有什么区别？**

区别在于谁管理和调度线程：用户级线程由用户空间的线程库或运行时管理，内核级线程由内核识别并调度。用户级线程仍要借助内核提供的执行实体运行，不能脱离内核获得处理器时间。

1. **用户级线程**：运行时可在用户空间保存和恢复线程的执行现场，切换不一定需要进入内核。内核看到的是承载它们的内核线程，而不一定知道每个用户级线程。
2. **内核级线程**：内核维护调度所需的线程状态，并可把不同线程安排到不同处理器核心执行。线程进入阻塞等待时，其他可运行的内核线程仍可被调度。
3. **阻塞边界**：如果多个用户级线程只由一个内核线程承载，其中一个发起阻塞系统调用时，承载线程可能被阻塞，其他用户级线程也无法继续。若运行时使用非阻塞操作、异步机制或多个承载线程，影响范围会不同。

不能只凭“用户级线程”就断言整个进程必然阻塞，也不能只凭线程数量断定能在多个核心并行。要看它们映射到多少个可运行的内核线程。

**Q14: [learning] 用户级线程与内核线程的一对一、多对一和多对多模型有什么区别？**

这些模型描述用户级线程如何映射到内核可调度的执行实体。映射关系影响用户态切换成本、阻塞影响范围和可并行的程度，但具体性能还取决于运行时和工作负载。

1. **一对一**：每个用户线程对应一个内核调度实体。不同线程可以被安排到不同核心，一个线程阻塞通常不阻止其他线程运行，但线程管理需要内核参与。
2. **多对一**：多个用户级线程由一个内核线程承载。用户态切换可以较轻量，但同一时刻最多只能在一个核心执行。承载线程被阻塞时，该线程上的用户级线程都无法运行。
3. **多对多**：运行时把多个用户级线程调度到多个内核线程上。不同承载线程可以并行，一个承载线程阻塞时其他承载线程仍可运行，但运行时必须处理任务分配和阻塞等问题。可同时执行的数量还受可用核心和可运行承载线程数量限制。

例如，Linux 上 GNU C 库的 NPTL（Native POSIX Threads Library）采用一对一模型，每个 POSIX 线程对应一个内核调度实体。依据：Linux man-pages 的 pthreads(7)。

**Q15: [learning] 处理器利用率、吞吐量和周转时间分别衡量什么？**

处理器利用率衡量处理器有多忙，吞吐量衡量单位时间完成多少任务，周转时间衡量一个任务从提交到完成经过多久。三者关注点不同，不能仅凭一个指标判断调度策略好坏。

1. **处理器利用率**：观察期间处理器执行非空闲工作的时间占总时间的比例。高利用率不保证每个任务响应及时。
2. **吞吐量**：观察期间完成的任务数除以观察时间。比较时要保证任务类型和统计口径相近。
3. **周转时间**：任务完成时刻减去提交时刻，包含排队、执行和等待输入输出等时间。平均周转时间反映整体表现，但可能掩盖少数任务等待很久。
4. **带权周转时间**：周转时间除以该任务的服务时间。它可以比较等待对长短任务的相对影响，但必须明确服务时间的定义，且分母必须大于零。

例如，任务提交后经过 10 秒完成，实际需要的处理器服务时间为 2 秒，则周转时间为 10 秒，按处理器服务时间计算的带权周转时间为 5。

**Q16: [learning] 抢占式调度和非抢占式调度有什么区别？**

抢占式调度允许系统在当前任务尚未主动让出处理器时，将处理器分配给另一个就绪任务。非抢占式调度通常等当前任务结束、阻塞或主动让出处理器后，才选择下一个任务。

1. **抢占式**：时间片到期或更高优先级任务就绪时，系统可以在允许调度的位置切换。它有利于交互响应和紧急任务执行，但更频繁切换可能增加开销。
2. **非抢占式**：当前任务继续执行至让出处理器的调度点，决策和切换相对简单。长任务可能使后续任务等待较久。

是否抢占取决于系统的具体策略和当前执行上下文。即使采用抢占式调度，内核也可能在保护共享状态等特定区域暂时推迟调度。

**Q17: [learning] 线程控制块保存什么信息？**

线程控制块是操作系统或线程运行时用来管理一个线程的数据结构。它保存线程的身份、执行状态和调度信息，使线程暂停后能够继续执行，也使调度器能够决定何时运行它。

线程控制块通常涉及以下信息：

1. **线程标识**：区分同一系统或进程中的线程。标识的作用范围和复用规则取决于具体实现。
2. **执行现场**：保存恢复执行所需的程序计数器、栈指针和其他寄存器状态。程序计数器用于确定恢复后的执行位置，栈指针用于找到线程的调用栈。
3. **线程状态**：记录线程是否可以运行或正在等待事件，让调度器和唤醒路径正确处理线程。
4. **调度信息**：保存优先级等调度所需信息，具体字段由调度策略和实现决定。

例如，线程等待输入时暂停，系统保留其必要的执行现场。输入完成后线程变为可运行，调度器再次选中它时恢复现场，线程便能从暂停的执行位置继续。系统可以用线程表等结构组织多个线程的控制信息。线程库和内核未必使用同一个名为“线程控制块”的结构，各字段的实际位置也会随实现变化。

**Q18: [learning] 多级队列和多级反馈队列调度有什么区别？**

多级队列将任务按类型或规则分配到不同队列，各队列可以使用不同调度策略。多级反馈队列允许任务根据运行和等待行为在队列之间移动，以调整任务的优先级。

1. **多级队列**：例如交互任务队列采用时间片轮转，批处理队列采用先来先服务。队列之间可以按固定优先级或分配处理器时间的比例竞争。
2. **多级反馈队列**：新任务可先进入高优先级队列，持续用完时间片的任务逐级降到较低优先级。系统也可以提升等待过久的任务，缓解饥饿。

固定优先级队列中，如果高优先级任务持续到达，低优先级队列可能长时间无法运行。反馈队列的具体升降规则、时间片和抢占条件都由实现定义，并不保证天然公平。

**Q19: [learning] 创建和终止进程时，操作系统需要处理什么？**

创建进程需要建立管理信息和执行环境，并在准备就绪后使其可被调度；终止进程需要停止执行、释放资源，并按系统规则保留或回收退出状态。具体顺序和结构取决于操作系统。

1. **创建**：系统分配标识和控制信息，建立或继承地址空间、打开文件等资源，并初始化执行现场。创建可能来自用户启动程序、服务请求或进程主动创建子进程，也可能因资源不足失败。
2. **终止**：正常退出、未处理的致命异常或外部终止请求都可能结束进程。系统关闭或释放该进程持有的资源，并通知需要观察退出结果的进程。
3. **回收边界**：在 Linux 中，子进程退出后，其退出状态通常保留到父进程调用 wait 系列接口收取；父进程先退出时，子进程可被收养，并不必然随父进程终止。

依据：Linux man-pages 的 fork(2) 和 wait(2)。

**Q20: [learning] Linux 没有可运行任务时，处理器为什么运行 idle 任务？**

当某个逻辑处理器没有其他可运行任务时，Linux 执行该处理器的 idle 循环，等待新的工作。空闲循环可以请求处理器进入省电状态，但是否进入以及选择哪一种状态取决于硬件、预计空闲时间和延迟约束。

新的任务变为可运行后，调度器可以安排它执行；处理器也可能因中断等事件退出空闲状态。空闲循环并不总是执行固定指令，也不保证任何情况下都比有用工作更省电。

依据：Linux 内核文档《CPU Idle Time Management》。

**Q21: [learning] 线程的就绪、运行和阻塞状态怎样转换？**

线程具备运行条件时等待调度，获得处理器后运行；需要等待事件时阻塞，事件满足后重新成为可运行线程。状态反映的是线程能否继续执行，而不是整个进程是否存活。

1. **就绪到运行**：调度器选中线程并恢复其执行现场。
2. **运行到就绪**：时间片到期或调度策略允许更高优先级线程抢占，原线程仍具备运行条件。
3. **运行到阻塞**：线程等待尚未完成的 I/O 或同步条件，暂时不能继续。
4. **阻塞到就绪**：等待条件满足或发生允许唤醒的事件后，线程再次参与调度；唤醒不等于立即运行。

具体系统可能有更多状态，用户级线程的状态和内核承载线程的状态也可能不同。
