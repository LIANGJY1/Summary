# 进程与处理机调度

> 学习资料。问题覆盖进程实体、状态与控制、线程及调度策略；题序即文档结构。

**Q1: [learning] 程序、进程和进程映像有什么区别？**

程序是存储介质上的静态指令集合；进程是程序的一次执行活动；进程映像描述该进程在某一时刻的代码、数据、控制信息和资源状态。相同程序可以同时运行多个进程实例。

进程控制块（PCB）保存操作系统管理进程所需的信息，例如进程标识、状态、资源和处理器现场；程序段与数据段分别承载指令和运行数据。进程创建和退出时，操作系统建立和回收相应的控制信息与资源。

**Q2: [learning] 就绪、运行、阻塞和挂起状态分别说明进程缺少什么条件？**

就绪进程具备运行条件但在等待处理器；运行进程正在占用处理器；阻塞进程等待某个事件或资源；挂起进程暂时被换出主存。阻塞说明“等事件”，挂起说明“暂不在主存”，两者回答的是不同状态维度。

1. **就绪 → 运行**：调度器选中该进程。
2. **运行 → 就绪**：时间片用尽或发生抢占。
3. **运行 → 阻塞**：进程等待 I/O、资源或其他事件。
4. **阻塞 → 就绪**：等待事件完成，进程重新具备运行条件。
5. **挂起 → 就绪/阻塞**：进程重新调入主存后，按等待事件是否完成恢复相应状态。

不同教材和操作系统会采用不同状态模型；不要把所有实现都限定为同一组状态名称。

**Q3: [learning] 进程控制为什么要求创建、阻塞、唤醒和切换具备原子性？**

这些操作会同时修改进程状态、控制块和多个队列；如果在中间状态被另一个处理器或中断路径观察或修改，进程可能出现在错误队列、丢失唤醒或让调度器运行不该运行的任务。操作系统必须把相关状态变更作为一个对并发观察者不可见的临界区，并保持队列和状态之间的不变量。

例如阻塞操作需要确认等待条件仍未满足，再原子地登记等待关系并让出处理器；若先检查条件、后入队，中间事件可能已经到达，造成永久睡眠。唤醒操作则在条件满足时更新等待状态并使任务重新具备调度资格。现代多核系统通常需要锁、原子操作和内存顺序约束共同维护这些状态，屏蔽本地中断只能处理特定竞争，不能单独保证跨核原子性。

**Q4: [learning] 进程和线程的资源边界有什么区别？**

进程提供资源隔离和地址空间等执行环境；线程是进程内可调度的执行流。一个进程可以包含多个线程，这些线程通常共享进程的地址空间和打开资源，但各自拥有独立的处理器执行现场和栈。

线程能降低同一进程内任务共享数据的成本，但也需要同步以避免竞态；独立进程的地址空间隔离更强，进程间共享数据通常需要显式 IPC 或共享内存机制。具体资源共享范围由操作系统和线程实现定义。

**Q5: [learning] 高级、中级和低级调度分别决定什么？**

在经典批处理调度模型中，高级调度决定哪些作业进入内存并建立进程，中级调度决定哪些挂起进程重新调入内存，低级调度从就绪队列选择下一个获得处理器的执行单位。低级调度通常最频繁，因为它直接参与处理器分配。现代通用操作系统未必以这三种独立调度器实现，术语描述的是决策层次。

中级调度可能通过换出、换入缓解内存压力；它与进程是否等待 I/O 的阻塞状态不同。具有内核线程的系统中，低级调度器实际选择的执行单位可能是线程。

**Q6: [learning] FCFS、SJF、HRRN 和 RR 分别优先解决什么调度目标？**

FCFS 重视到达顺序，SJF 偏向短作业，HRRN 将等待时间纳入优先级，RR 通过时间片轮转改善交互响应。策略优化目标和假设不同，没有一种策略能同时对所有工作负载实现最佳响应、公平和吞吐量。

1. **FCFS**：按进入队列的顺序服务；实现简单但长作业可能让后续短作业等待很久。
2. **SJF/SRTF**：SJF 选择预计运行时间最短的作业，SRTF 是其抢占式版本，会优先运行剩余时间最短的任务；若时长估算准确可降低平均等待，但持续到达的短作业可能使长作业饥饿。
3. **HRRN**：按响应比 `(等待时间 + 服务时间) / 服务时间` 选择任务，等待越久响应比越高；经典形式通常在调度点非抢占地选择任务，服务时间估计仍会影响选择。
4. **RR**：每个就绪任务轮流获得时间片；时间片太大时交互响应变差，太小时切换开销上升。

**Q7: [learning] 优先级调度和多级反馈队列怎样影响响应与饥饿？**

优先级调度按任务优先级分配处理器，可让紧急任务更快获得服务，但低优先级任务可能长期得不到服务。若高优先级任务持续到达，普通任务饥饿；优先级老化可通过等待时间逐步提高其优先级缓解这一问题。

多级反馈队列让新任务从较高优先级队列开始，耗尽时间片后逐步降级，以近似区分短交互任务和长 CPU 密集任务。交互任务若在时间片结束前阻塞，通常可留在较高队列，但实际规则由队列策略决定。队列数、各级时间片和提升机制共同影响响应、公平与吞吐。

算法效果不能脱离工作负载和优先级更新规则来判断。反馈队列并不会自动消除饥饿，必须检查是否有老化或周期性提升。

**Q8: [learning] 周转时间、等待时间和响应时间分别测量什么？**

三个指标衡量不同等待阶段：

1. **周转时间**：作业从提交到完成的总时长，包含等待、执行和 I/O 等阶段。
2. **等待时间**：累计处于就绪状态但未获处理器服务的时长。
3. **响应时间**：请求提交到首次得到响应的时长，交互系统通常更关注该指标。

等待 I/O 通常不算处理器就绪队列等待。批处理系统常关注吞吐量和平均周转表现；交互系统则更关注响应时间。比较调度策略时应明确统计对象、负载和平均值或分位数口径。

**Q9: [done] 内核有“进程”这个概念吗？内核为什么能运行？**

进程是内核管理的任务，不是内核运行的前提。内核启动初期由 CPU 直接执行特权代码；完成基础初始化后，才创建并调度内核线程和用户进程。

1. Bootloader 将内核载入内存，并跳转到内核入口。
2. 内核入口建立运行环境，随后进入 `start_kernel()` 初始化内存、中断和调度器。
3. 内核创建 `kthreadd` 和 `kernel_init` 等内核线程，调度器开始运行它们。内核线程只执行内核代码；用户进程则在用户态运行程序。
