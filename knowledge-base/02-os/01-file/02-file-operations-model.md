# 文件操作与打开模型

> 通用操作系统文件操作学习资料。主线：open/read/close 的阶段划分、系统级与进程级打开文件表的职责、open 与 read 的语义边界、文件复制为何不是原子操作。内容自原 01、05 两册按主题合并（2026-10-06）；创建、权限与挂载等命令实操随 initramfs 语境移入 ../05-linux-boot/。Q 序列即结构，供 atlas 同源直读。

**Q1: [learning] 为什么文件操作通常要经过 open、read/write 和 close 等不同操作？**

文件系统把定位文件、建立打开状态、传输数据和结束访问分成不同操作。`open` 根据路径找到文件并建立进程可用的打开记录；后续 `read`/`write` 通过该记录访问数据；结束时 `close` 释放打开状态。

“打开文件”不等于“把全部文件内容读入内存”；具体缓冲、缓存和持久化行为由操作系统与文件系统实现决定。

**Q2: [learning] 打开文件后，系统打开文件表和进程打开文件表分别解决什么问题？**

进程打开文件表把进程可见的文件描述符映射到内核打开对象；系统级打开对象可维护访问模式、当前偏移和底层文件引用等状态。不同操作系统的结构名称与共享细节不同。在 POSIX 模型中，共享文件偏移取决于多个描述符是否引用同一个 open file description，例如描述符复制或继承后通常共享偏移；两个独立的 `open()` 即使使用同一路径，也通常建立不同的打开描述。











**Q3: [learning] 为什么 open 不等于 read？**

`open` 解析路径并建立后续访问需要的文件引用或描述符；`read` 才请求把指定范围的数据交给调用方。打开操作可能触发元数据读取或缓存访问，但不意味着文件内容整体已读入。











**Q4: [learning] 复制文件为什么不是单一的“复制”原子操作？**

复制通常由创建目标、循环读取源数据、写入目标并关闭两侧文件等基本操作组成。失败处理还要决定是否删除不完整目标；并发修改源文件时，复制结果是否一致取决于文件系统和应用采用的快照或锁定策略。
