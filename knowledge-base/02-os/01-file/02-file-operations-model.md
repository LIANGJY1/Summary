# 文件操作与打开模型

> 通用操作系统文件操作学习资料。主线：open/read/close 的阶段划分、系统级与进程级打开文件表的职责、open 与 read 的语义边界、文件复制为何不是原子操作。内容自原 01、05 两册按主题合并（2026-10-06）；创建、权限与挂载等命令实操随 initramfs 语境移入 ../05-linux-boot/。Q 序列即结构，供 atlas 同源直读。

**Q1: [done] 文件描述符 fd 是什么？**

文件描述符（file descriptor，fd）是进程用来引用已打开对象的非负整数，对象可以是普通文件、管道或套接字。内核维护按进程区分的 fd 表；进程把 fd 传给 `read()`、`write()`、`lseek()`、`close()` 等系统调用时，内核在发起调用的进程表中查找对应的打开文件描述。因此，fd 是进程上下文中的编号，不是文件名、文件内容或打开对象本身。

1. **编号与查表：**每个进程有自己的 fd 表。成功调用 `open()` 会取得该进程当前可用的最小非负编号，所以不同进程的 fd 3 可以映射到不同对象。Linux 中，同一进程的线程通常共享 fd 表；一个线程关闭某个 fd 后，其他线程看到的表项也随之关闭，编号还可能被复用。
2. **打开状态：**fd 表项指向内核的打开文件描述（open file description），其中保存文件偏移量、文件状态标志等状态。分别调用两次 `open()` 会创建不同的打开文件描述；`dup()` 创建的新 fd 和 `fork()` 后子进程继承的 fd，则可以指向同一个打开文件描述，因此共享文件偏移量。
3. **关闭与释放：**`close(fd)` 移除当前进程中的 fd 引用，该编号之后可以分配给新打开的对象。如果还有其他 fd 引用同一个打开文件描述，它仍保持有效；最后一个引用关闭后，相关打开状态才可释放。
4. **标准描述符：**POSIX 程序通常把 0、1、2 分别用作标准输入、标准输出和标准错误。它们是用途有约定的普通 fd，启动环境可以重定向它们，编号本身不代表特殊文件类型。

判断 fd 指向什么对象时，必须同时看 fd 编号和发起系统调用的进程。相关依据见 Linux man-pages 的 `open(2)`、`dup(2)`、`fork(2)`、`close(2)`、`pipe(7)` 和 `socket(7)`，以及 Android SDK 的 `ParcelFileDescriptor` 文档。

**Q2: [learning] 为什么文件操作通常要经过 open、read/write 和 close 等不同操作？**

文件系统把定位文件、建立打开状态、传输数据和结束访问分成不同操作。`open` 根据路径找到文件并建立进程可用的打开记录。后续 `read`/`write` 通过该记录访问数据。结束时 `close` 释放打开状态。

“打开文件”不等于“把全部文件内容读入内存”。具体缓冲、缓存和持久化行为由操作系统与文件系统实现决定。



**Q3: [learning] 打开文件后，系统打开文件表和进程打开文件表分别解决什么问题？**

进程打开文件表把进程可见的文件描述符映射到内核打开对象。系统级打开对象可维护访问模式、当前偏移和底层文件引用等状态。不同操作系统的结构名称与共享细节不同。在 POSIX 模型中，共享文件偏移取决于多个描述符是否引用同一个 open file description，例如描述符复制或继承后通常共享偏移。两个独立的 `open()` 即使使用同一路径，也通常建立不同的打开描述。













**Q4: [learning] 为什么 open 不等于 read？**

`open` 解析路径并建立后续访问需要的文件引用或描述符。`read` 才请求把指定范围的数据交给调用方。打开操作可能触发元数据读取或缓存访问，但不意味着文件内容整体已读入。













**Q5: [learning] 复制文件为什么不是单一的“复制”原子操作？**

复制通常由创建目标、循环读取源数据、写入目标并关闭两侧文件等基本操作组成。失败处理还要决定是否删除不完整目标。并发修改源文件时，复制结果是否一致取决于文件系统和应用采用的快照或锁定策略。
