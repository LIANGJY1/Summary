# 文件系统分层与格式化

> 通用操作系统文件系统结构学习资料。主线：分层实现的分工与代价、物理格式化/逻辑格式化/挂载改变的层次、磁盘与内存中各自保存的信息。原 08 册更名并补规范格式（2026-10-06）。镜像概念、ext4 镜像与镜像归档对比三题于 2026-10-08 迁往 ../06-linux-build/01-image.md（实测核验与 mke2fs 链路口径随题迁移）。题序即结构，供 atlas 同源直读。

**Q1: [learning] 文件系统为什么要分层实现？**

分层让上层负责文件名和访问语义，下层逐步处理目录、空间分配、块读写和设备交互。分工能隔离接口变化，但每层都要维护契约，额外跨层调用也会带来成本。

**Q2: [learning] 物理格式化、逻辑格式化和挂载分别改变什么？这些术语在现代存储上有什么边界？**

在经典磁盘模型中，物理格式化（低级格式化）建立可寻址扇区等介质结构。逻辑格式化（高级格式化）在分区或卷上初始化特定文件系统所需的元数据布局。挂载则把已识别的文件系统接入当前目录树，使路径访问能够进入该卷。

这三者改变的层次不同：物理格式化面向设备介质，逻辑格式化会重建卷内文件系统元数据，挂载通常只建立运行期的命名空间连接，不等于重新格式化。现代 HDD/SSD 的扇区组织和低级格式通常在制造或控制器层处理，桌面系统中的“格式化磁盘”多数指逻辑格式化。分区表变更、加密或快照也不是同一操作。

**Q3: [learning] 文件系统在磁盘和内存中分别保存哪些信息？**

磁盘保存可持久化的文件系统元数据与文件内容。内核内存中的目录缓存、打开文件对象和进程描述符记录则加速路径解析并维护当前访问状态。缓存是可重建的运行期状态，不能与持久化目录或 inode 混为一谈。

**Q4: [done] ext4 是什么，它用哪些关键机制组织磁盘？**

ext4（fourth extended filesystem，第四代扩展文件系统）是 Linux 原生的通用磁盘文件系统，ext 家族第四代：数据落在块设备上、可读写、带日志，是多数发行版根文件系统和 Android 数据分区的常见选择。相对 ext2/ext3 的关键变化是用 extent 管理物理块、容量上限提高到 EiB 级；磁盘骨架仍沿用 ext 家族的超级块加块组结构。延迟分配把块分配推迟到回写时进行，以换取更连续的布局。

1. **磁盘骨架：**

    1. **超级块：**记录块大小、总块数、总 inode 数等全局信息，位于固定偏移 1024 字节处，并在部分块组留有备份；挂载时先读它确认“是不是 ext4、多大”。
    2. **块组：**全盘切组，每组自带块位图、inode 位图、inode 表和数据块；管理信息按组集中，减少跨盘寻道。
    3. **inode 与 extent：**每个文件一个 inode，记权限、大小、时间戳和物理块位置。与 ext2/ext3 的差别在物理块清单改用 extent：每条记“起始块号加连续块数”，不再每块一个编号，大文件的映射结构因此更小更连续。

2. **日志：**元数据修改先写入日志区、按事务提交；崩溃后下次挂载重放日志即可恢复一致性，不必全盘扫描。默认只把元数据记入日志，并要求数据先于对应元数据落盘（data=ordered）。日志的代价是额外写入，这是它与闪存取向文件系统对比的焦点之一。
3. **在格式化与挂载链条中的位置：**mkfs.ext4 是逻辑格式化，把上述骨架写上空盘；超级块、组描述符、inode 表、位图和日志等固定开销与内容多少无关，因此镜像容量要为之留余量。mount 把超级块和组描述符读进内存后，路径访问才经 VFS 进入 ext4 的代码。
4. **边界与位置：**ext4 兼容 ext2/ext3，旧分区可直接挂载；只读分发场景不如 erofs、squashfs（无日志开销、可压缩）；Android 的 userdata 上 ext4 与 f2fs 并存，选择取决于设备与版本，快慢结论必须来自同条件实测。Mini_Android 的 system.img 与多数发行版根文件系统都是 ext4。
