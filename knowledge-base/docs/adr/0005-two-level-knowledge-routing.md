# 知识路由两级分层：ROUTING.md 管候选，大类头部管准入

沉淀类 skill（source-annotator、session-to-knowledge）各自内嵌 doc 级分流规则，第三个沉淀 skill 出现就要抄第三份并各自漂移；而每个大类的「边界」头部服务人类直读场景，整段搬走会失去共置。决定：在知识库根目录建 `ROUTING.md`，作为 doc 级**候选分流**的唯一事实源（主判据链 + 路由表，含各维护者）；**准入**细则、条目模板、归并规则仍以各大类头部「边界/规则」为准。两个粒度、两个问题——路由表答"候选是哪个大类"，头部答"这条够不够格进它"；粒度相同的句子禁止两处出现，发现重复以头部为准修表。被否的替代方案：① 把「边界」整体搬进路由文档——要重构 4 个既有文档、改 session-to-knowledge 的骨架契约，代价大于收益，且人类直读失去上下文；② 维持现状——两份规则已现重复，skill 数量只增不减，漂移只会更糟。

## Consequences

- 消费 skill 沉淀前多读一个文件（约 40 行），换来源单一；新立大类的完成判据新增"回填路由表"，靠 skill 流程绑定而非自觉。
- 路由表自身不许长厚：只收候选级判据，超过一屏先删后加——路由文档自己变成沉积层即本决策失败。
