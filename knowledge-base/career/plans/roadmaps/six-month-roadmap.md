# Six-Month Roadmap

> 本文件是总路线，只规定阶段和周主题；每日练习放在 [../../weekly/](../../weekly/)。

## 1. 执行规则

五条轨道并行推进：Java/Kotlin、Framework、AAOS、源码/实践、面试/复习。每周主题只是主攻点，不能暂停其他轨道。

每周最低产出：

- Java/Kotlin：2-4 个主题、1 道手写、1 次闭卷书面回答；
- Framework：1 条源码链、3-5 张问题卡、1 次源码复述；
- AAOS：1 个机制、1 张场景卡；
- 实践：1 个独立代码、已有 trace/日志或源码验证；
- 面试：3 次限时短答、1 次错题复习、1 次周复盘。

模块完成必须经过：概念 → 机制 → 源码 → 实践 → 表达 → 7/28 天复习。真实项目先读 YaDi，再用 `AAOS13_study` 对照和修改；Glide/Retrofit/androidx/JDK 等应用层库与 JDK 源码在 `AndroidLibs`（`/home/liang/Project/MyProject/AndroidLibs`）标注学习；面试时区分“实际参与”“代码观察”和“学习验证”。

每周日记录投入、卡壳题、源码链路、实践产出和面试反馈，写在当周 `weekly/<周>/record.md`；忙周可减数量，不删五条轨道。

## 2. 冲刺周计划（W1-W27）

### W1：基线与项目熟悉

- **输入**：岗位目标、现有能力、Java/Kotlin/Framework/AAOS 基线。
 - **源码**：浏览 AAOS 目录地图，确认本地 Android 13 源码、两个真实项目目录和检索工具可用。
 - **实践**：从 `CarService` 启动链或一个真实项目模块中找出入口、调用方和关键定制点。
 - **输出**：3 分钟自我介绍书面稿、能力雷达、目标城市/岗位清单、源码环境记录。
 - **复习/验收**：完成 30 题基线测评并逐题批改；完成一张项目模块关系图。

**按顺序执行，不要自行加任务：**

1. **第 1 次 90 分钟**：完成 30 题基线测试；不会的题只记“不会”，不要现场查答案。
2. **第 2 次 60 分钟**：确认源码环境。检查三个源码目录、`rg`、Git 历史和现有文档。
3. **第 3 次 30 分钟**：书写 3 分钟自我介绍，按“经历→当前能力→车机目标→短板”组织答案。
4. **第 4 次 60 分钟**：从本地源码只找一条入口链：`CarService` 启动后如何提供车机服务；只记录文件和函数，不做批注。
5. **第 5 次 30 分钟**：在 `../../weekly/W1-2026-0917/record.md` 写下目标城市、目标公司类型、目标岗位关键词和本周结果。

W1 完成条件：四项材料齐全（基线批改、环境记录、自我介绍书面稿、目标岗位），而不是“看了多少文章”。

### W2：Java 并发

- **输入**：线程池、锁、volatile、ThreadLocal、死锁、线程安全边界。
- **源码**：JDK 线程池和 Android Binder 线程池的差异。
- **实践**：完成 DCL、生产者消费者；用 `jstack` 或 ANR trace 识别阻塞链。
- **输出**：12 张面试卡，闭卷书面答清线程池参数和锁的适用边界。
- **复习/验收**：DCL 3 分钟写完；并发题抽 3 题各讲 3 分钟。

### W3：集合、JVM 与 ART

- **输入**：HashMap、ConcurrentHashMap、LruCache、内存区域、GC、类加载、OOM。
- **源码**：ART 类加载、GC 与 dex2oat 的关键链路。
- **实践**：限时完成 LRU；制造并区分 Java OOM、泄漏和 lmkd 杀进程。
- **输出**：12 张卡和一份“内存问题定位树”。
- **复习/验收**：闭卷解释 HashMap 线程不安全原因、GC 与 lmkd 的区别。

### W4：Kotlin、协程与 Flow

- **输入**：suspend/CPS、状态机、结构化并发、取消、Dispatcher、StateFlow/SharedFlow。
- **源码**：协程编译后 Continuation；Android 回调与 Binder 线程切换。
- **实践**：将车辆属性回调包装成 `callbackFlow`，再转为 `StateFlow`。
- **输出**：10 张卡和一段可运行或可编译的车况流代码。
- **复习/验收**：能用车机旋钮、车速和音源切换解释 debounce、conflate、flatMapLatest。

### W5：基础 Framework 与第一次书面模拟

- **输入**：事件分发、绘制流程、配置变化、冷启动。
- **源码**：InputDispatcher → ViewRootImpl → Choreographer → RenderThread 主链。
- **实践**：根据 AOSP 源码和已有日志/trace 复述输入与启动链；设备采集留到后续阶段。
- **输出**：简历初版、5 分钟启动讲解、基础错题本。
- **复习/验收**：G1：30 题第一、二部分全部能答出主链，无空白题；完成基础书面模拟。

### W6：CarService/VHAL 主链

- **输入**：AIDL VHAL、Vehicle Property、areaId、权限、采样率、错误事件。
- **源码**：VHAL → CarPropertyService → CarPropertyManager → 应用。
- **实践**：从真实项目和 AOSP 源码整理属性注册、订阅、错误和死亡清理流程；用独立代码表达订阅模型。
- **输出**：一张闭卷架构图、一张“CAN 到 UI”面试卡。
- **复习/验收**：限时书面答清推送、拉取、粘性初值、死亡清理和权限校验。

### W7：CabinDemo 车辆属性里程碑

- **输入**：车辆速度、档位、订阅生命周期和高频数据降采样。
- **源码**：`CarPropertyService` 和默认 VHAL 配置；核对属性 ID 与版本。
- **实践**：完成速度/档位订阅接口和 Flow 封装；用源码调用链、伪输入或单元级代码验证数据流。
- **输出**：代码、调用链图、接口说明和学习记录。
- **复习/验收**：限时书面答清“数据源 → Binder → CarService → Flow → UI”，并接住两层追问。

### W8：系统应用、权限与 SELinux

- **输入**：priv-app、平台签名、privapp-permissions、开机自启、sepolicy。
- **源码**：PMS 安装/权限链和 init 启动相关路径。
- **实践**：完成系统应用安装；主动制造 `avc: denied`，用日志、上下文、规则定位。
- **输出**：权限选型记录、SELinux 排查记录、开机自启取舍。
- **复习/验收**：能分三层解释“应用权限、平台签名、SELinux”各自解决什么问题。

### W9：多屏、Occupant Zone 与车载音频

- **输入**：DisplayArea、Task 落屏、Mirror、OccupantZone、音频焦点、多音区、Ducking。
- **源码**：WMS 多屏、`CarOccupantZoneService`、`CarZonesAudioFocus`、`CarDucking`。
- **实践**：根据真实项目和 AOSP 源码画多屏、音频焦点和 UxRestrictions 状态图；用独立代码或纸面推演复现仲裁逻辑。
- **输出**：多屏/音频状态图和第三场景卡。
- **复习/验收**：G2：三类车机场景各完成一次限时书面答题；完成车机书面模拟。

### W10：冷启动排查

- **输入**：启动阶段、主线程阻塞、绑定服务、I/O 和首帧。
- **源码**：`ActivityTaskManager`、`ActivityThread`、启动关键事件。
- **实践**：使用已有 trace/日志或代码级时间线分析启动阶段。
- **输出**：现象→测量→定位→修复→结果五段式案例。
- **复习/验收**：带毫秒数据讲 5 分钟，指出源码和 trace 对应关系。

### W11：一帧上屏与卡顿

- **输入**：Vsync、Choreographer、RenderThread、BufferQueue、SurfaceFlinger、HWC。
- **源码**：`doFrame`、`performTraversals`、`DrawFrame`、合成主链。
- **实践**：使用已有 trace 或源码时间线定位 input/animation/traversal、GPU 或合成瓶颈。
- **输出**：带 trace 截图的一帧排查案例。
- **复习/验收**：能解释主线程“录制”与 RenderThread/GPU“执行”的区别。

### W12：内存、ANR 与崩溃

- **输入**：泄漏、内存抖动、ANR、tombstone、debuggerd、lmkd。
- **源码**：消息队列阻塞、进程优先级和低内存回收相关路径。
- **实践**：结合已有日志、trace、源码和独立小代码分析泄漏、内存抖动、ANR 与 lmkd。
- **输出**：内存案例、ANR 定位清单、工具边界说明。
- **复习/验收**：三种问题各讲 3 分钟，明确证据和转交边界。

### W13：算法第一轮

- **输入**：数组、哈希、双指针、链表、栈队列、二叉树、二分。
- **源码/实践**：完成 20-30 道 Easy/Medium；手写题全部限时一次。
- **输出**：AC 记录、错题原因分类、算法书面解题模板。
- **复习/验收**：链表 15 分钟 AC；G3：三个性能案例闭卷带数字。

### W14：项目深挖与阶段书面模拟

- **输入**：CabinDemo 全链、源码学习方法、量产边界、项目追问。
- **源码**：挑一条最有区分度的 Binder/WMS/CarService 链做 Showcase。
- **实践**：整理 Demo、实验、trace 和源码的相互证据。
- **输出**：项目 8 连问答案、简历 v2、项目证据目录。
- **复习/验收**：完成项目+性能书面模拟；任何无法验证的表述必须降级措辞。

### W15：车机系统设计

- **输入**：多屏 Launcher、车辆信号订阅、多音区焦点、图片/资源加载。
- **源码**：为每题绑定至少 3 个 AOSP/AAOS 源码锚点。
- **实践**：每题完成一次纸面推演，补充容量、失败、权限、生命周期和降级策略。
- **输出**：四份可书面作答设计稿，均包含澄清问题、架构、权衡、边界、演进。
- **复习/验收**：每题 15 分钟完成，接住“规模扩大十倍”和“依赖失效”追问。

### W16：AAOS 版本演进与设计实战

- **输入**：AAOS 13→16 的 VHAL、音频、多屏、Scalable UI、Remote Access 等演进。
- **源码**：以官方 release notes 对照本地 Android 13 实现，区分事实和推断。

- **输出**：版本差异表、前沿话术和三条明确的“不确定边界”。

### W17：C/C++、JNI 与 HAL 边界

- **输入**：RAII、智能指针、虚函数、移动语义、JNI 生命周期、AIDL/HAL 边界。
- **源码**：选 Binder native、VHAL 或 AudioFlinger 主链 3-5 个文件。
- **实践**：完成 Java/C++ JNI 互调；解释 native 崩溃和内存所有权。
- **输出**：8 张卡、JNI Demo、native 问题定位案例。

- **输入**：STAR/五段式、项目数字、协作分工、HR 问题、谈薪原则。
- **简历原则**：每条经历能被追问两层；数字真实、可复述、能解释口径；源码学习写成工程化证据；CabinDemo 写成端到端平台能力，不冒充量产；按 OEM/Tier 1/方案商分别强调 Framework/AAOS/HAL/量产排查。

## 5. 优先级

- **P0**：Java 并发/JVM、Binder、Handler、启动链、AMS/ATMS/WMS/PMS、Input、图形与性能、CarService/VHAL、CarAudio、多屏、UxRestrictions、SELinux、调试、系统设计、项目表达。
- **P1**：C/C++、JNI、ART、SurfaceFlinger、Power、OTA、构建系统、量产问题闭环、AIDL/HAL 边界。
- **P2**：CAN/SOME-IP、QNX、ASPICE、Hypervisor、音视频专项，只做能应付追问的概念和场景。
- **P3**：短期不能转化为面试答案、实践或简历证据的深层源码扩展。

## 6. 时间基线

在职版每周 18-28 小时：工作日每天 2.5-3 小时，周末 5-7 小时。每周配额建议：Java/Kotlin 20%、Framework 25%、AAOS 20%、实践与性能 20%、面试/复习 15%（含每周 1 道手写、1 次闭卷书面回答、3 次限时短答、1 次错题复习、1 次周复盘）；临近真实面试时面试轨道可临时提高到 25%，但不取消基础和复习。低于 18 小时连续两周时，先砍 P2，不砍 P0、排查案例和投递节奏。
