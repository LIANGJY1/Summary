# 操作系统基础与运行机制

> 学习资料。问题覆盖操作系统职责、运行特征、处理器保护机制与内核组织；题序即文档结构。

**Q1: 操作系统在硬件、应用程序和用户之间承担什么职责？**

操作系统管理处理器、内存、设备和文件等资源，并向应用程序与用户提供受控、可复用的接口。它让应用通过命令接口、图形界面或系统调用使用硬件，而不必直接管理每种设备的细节。

1. **资源管理**：分配与回收内存和设备，调度处理器，管理文件及其访问权限。
2. **接口服务**：命令行和图形界面面向用户；系统调用面向程序，是请求内核服务的受控入口。
3. **资源保护**：把共享资源操作集中到受控的内核路径，隔离应用之间以及应用与内核之间的访问。

操作系统也是硬件之上的抽象层，但不同系统提供的接口、资源模型和实现范围并不相同。

**Q2: 操作系统中的并发、并行、共享和异步分别表示什么关系？**

并发表示多个任务在一段时间内交替推进；并行表示多个任务在同一时刻执行。共享表示并发任务使用共同资源，异步表示任务推进速度受调度和资源事件影响，无法保证连续或可预测。

1. **单核处理器**：多个可运行任务通过切换形成并发，不能在同一时刻执行多条任务指令。
2. **多核处理器**：任务既可以并发，也可以在不同核心上并行。
3. **互斥共享**：同一时刻只允许一个任务访问资源，例如需要独占的设备。
4. **并发共享**：多个任务在同一时间段使用资源，底层可能由分时交替完成，例如多个进程读取同一文件。

并发与共享使操作系统必须处理同步和互斥；任务被暂停后何时继续，取决于调度与事件完成情况。

**Q3: 用户态和内核态如何限制程序执行特权操作？**

处理器通过执行状态和特权级限制可执行的指令：普通应用运行在用户态，不能直接执行特权指令；内核在内核态执行资源管理与硬件操作。系统调用、异常或外部中断使控制权进入内核，内核处理完后再返回用户态。

1. **用户态**：应用可执行普通指令，但访问受保护资源时必须请求内核服务。
2. **内核态**：内核可执行特权指令，并按权限检查完成设备、内存和进程管理操作。
3. **系统调用**：应用通过指定入口请求服务；处理器切换到内核态，内核检查参数并执行操作。
4. **异常与中断**：异常由当前指令执行引起，例如非法访问；中断通常由外部事件引起，例如设备完成 I/O。处理器依据异常或中断类型转到对应处理逻辑。

应用不能通过普通函数调用绕过系统调用边界直接执行内核代码；具体指令和特权级规则由处理器架构定义。

**Q4: 系统调用与语言库函数有什么区别？**

系统调用是程序请求内核服务的接口；库函数是编程语言或运行库提供的函数，其中有些会进一步调用系统调用，有些完全在用户态完成。库函数可以封装系统调用的参数、错误处理和平台差异，但两者不是同一层接口。

一次典型请求依次经历参数准备、受控陷入、内核处理和结果返回。文件读写、进程控制、内存映射等操作可能需要系统调用；字符串处理等库函数则不一定进入内核。

**Q5: 大内核、微内核、分层内核和模块化内核分别在什么方面取舍？**

这些结构主要在内核态代码范围、模块边界、通信成本和可维护性之间取舍。大内核把较多服务放在内核态，调用路径短；微内核把更多服务移到用户态，缩小内核核心，但服务通信需要额外切换。

1. **大内核**：进程、内存和设备等服务多在内核态协作，通常减少跨边界通信；内核代码体量和模块耦合会增加维护难度。
2. **微内核**：内核只保留较小的核心服务，其他服务通过受控通信运行；隔离边界更清楚，但消息传递和状态切换可能增加成本。
3. **分层结构**：模块按层提供接口，便于逐层验证与替换；层次边界和跨层访问会影响设计与性能。
4. **模块化结构**：以内核模块扩展功能，模块接口清晰时有利于独立维护和动态扩展；模块依赖仍需治理，模块化本身不等于隔离。

具体操作系统可以组合这些结构特征；不能只凭“大内核”或“微内核”标签推断整个系统的性能或安全性。

**Q6: 第一类和第二类虚拟机监控程序的边界在哪里？**

第一类虚拟机监控程序直接运行在硬件之上并分配物理资源；第二类运行在宿主操作系统上，由宿主系统提供设备和资源接口。两类都隔离多个 Guest OS，但资源路径和管理层次不同。

1. **第一类**：Guest 的 CPU、内存和设备访问由 VMM 直接管理，少一层通用宿主系统路径，通常更适合服务器整合；设备驱动和虚拟化能力由 VMM 平台提供。
2. **第二类**：VMM 作为宿主系统上的程序运行，虚拟磁盘等资源可表现为宿主文件，易于在桌面环境安装和迁移；资源访问经过宿主系统，增加一层依赖。

“第一类总是更快”或“第二类一定更易迁移”都不是不带条件的保证；实际性能与功能取决于硬件辅助、驱动、工作负载和产品实现。
