
**Q1: 打开文件后，系统打开文件表和进程打开文件表分别解决什么问题？**

进程打开文件表把进程可见的文件描述符映射到内核打开对象；系统级打开对象可维护访问模式、当前偏移和底层文件引用等状态。不同操作系统的结构名称与共享细节不同。在 POSIX 模型中，共享文件偏移取决于多个描述符是否引用同一个 open file description，例如描述符复制或继承后通常共享偏移；两个独立的 `open()` 即使使用同一路径，也通常建立不同的打开描述。

**Q2: 为什么 open 不等于 read？**

`open` 解析路径并建立后续访问需要的文件引用或描述符；`read` 才请求把指定范围的数据交给调用方。打开操作可能触发元数据读取或缓存访问，但不意味着文件内容整体已读入。

**Q3: 复制文件为什么不是单一的“复制”原子操作？**

复制通常由创建目标、循环读取源数据、写入目标并关闭两侧文件等基本操作组成。失败处理还要决定是否删除不完整目标；并发修改源文件时，复制结果是否一致取决于文件系统和应用采用的快照或锁定策略。
