# 内存管理

> 学习资料。问题覆盖地址空间、分配策略、分页分段、虚拟内存、进程映像与内存映射；题序即文档结构。

**Q1: 操作系统的内存管理需要解决哪些问题？**

内存管理需要分配和回收物理空间、把程序使用的地址映射到物理地址、隔离进程的访问范围，并在物理内存不足时提供受控的扩展机制。程序通常使用逻辑或虚拟地址，硬件与操作系统协作完成地址转换和保护。

编译时绝对地址、装入时静态重定位和运行时动态重定位，分别在不同阶段完成地址绑定；需要进程运行期间可移动或隔离时，必须采用支持动态转换的机制。

**Q2: 单一连续、固定分区和动态分区分配有什么碎片取舍？**

连续分配要求进程占用一段连续物理空间；固定分区简单但容易产生内部碎片，动态分区按需创建空间但容易产生外部碎片。内存总空闲量足够并不代表一定存在足够大的连续区间。

1. **单一连续分配**：用户程序独占用户区，管理简单但无法充分利用多道程序并发。
2. **固定分区**：预先划分分区并限制每区运行一个进程；进程小于分区时产生内部碎片。
3. **动态分区**：按进程大小分配连续空闲区；分区回收后可能形成外部碎片，可通过合并相邻空闲区或紧凑缓解。

首次适应、最佳适应、最坏适应和邻近适应改变的是选择空闲区的策略，不会消除连续分配本身的外部碎片问题。

**Q3: 首次适应、最佳适应、最坏适应和邻近适应分别怎样选择空闲分区？**

这些算法在满足请求的空闲区中采用不同的搜索顺序或大小偏好，影响搜索开销和后续碎片形态。它们不存在对所有分配序列都最优的固定排名。

1. **首次适应**：从地址较低的一侧开始，取第一个足够大的分区。
2. **最佳适应**：取满足请求的最小分区，可能留下难以利用的小碎片。
3. **最坏适应**：取最大的可用分区，避免本次剩余区过小，但可能较快耗尽大区。
4. **邻近适应**：从上次搜索结束处继续，降低反复从头扫描的成本，也可能逐渐消耗高地址大区。

**Q4: 分页怎样把逻辑地址转换成物理地址？**

分页把逻辑地址空间切成固定大小的页，把物理内存切成同样大小的页框；页表记录页号到页框号的映射。逻辑地址拆为页号和页内偏移，查到页框号后与偏移组合得到物理地址。

若页面大小为 2 的幂，页内偏移对应地址低位，页号对应其余高位。基本分页允许页框离散放置，消除外部碎片，但可能有页内未使用空间；页表、TLB 和多级页表影响地址转换成本。

**Q5: TLB、页表和多级页表分别解决什么问题？**

页表保存地址映射，TLB 缓存近期使用的页表项以减少转换延迟，多级页表则把大型页表分级并按需分配。TLB 未命中时仍须通过页表结构完成查找；它不是页表本身。

连续页表空间和常驻内存会造成开销，因此多级页表可只为实际使用的地址范围保留下级页表。若页面不在内存中，页表的存在位等状态会使访问进入缺页处理路径。

**Q6: 分页和分段的划分依据及可见性有什么区别？**

分页按固定大小的物理管理单位拆分地址空间，通常由系统对程序透明；分段按代码、数据等逻辑模块划分，段长可变，逻辑地址包含段号与段内偏移。分段更自然地表达模块边界和共享保护，分页更适合离散物理分配。

分段需要检查段号和段内偏移是否越界；分段可能产生外部碎片。段页式先按逻辑模块分段，再把每段分页，以兼顾模块化和离散分配，但地址转换会经过段表和页表。

**Q7: 虚拟内存怎样让进程使用大于当前驻留物理内存的地址空间？**

虚拟内存把进程地址空间与当前驻留的物理页分开管理；只有访问到的部分才需要驻留内存。访问缺页时，操作系统装入所需数据并更新映射，若内存不足则按策略回收或换出其他页。

虚拟地址空间的大小不等于可用物理内存，也不意味着所有页面都能同时驻留。缺页可能是正常的按需调入，也可能因非法地址访问而失败；缺页处理和换页会带来 I/O 延迟。

**Q8: 覆盖、交换和虚拟内存分别怎样缓解内存不足？**

覆盖由程序设计者把互斥使用的模块复用同一内存区域；交换由操作系统把暂时不运行的进程映像换出和换入；虚拟内存则以页或段为单位按需驻留。它们粒度、自动化程度和适用场景不同。

交换整个进程会产生较大的磁盘 I/O；按需分页能减少初始装入量，但工作集超过可用内存时会出现频繁缺页和抖动。覆盖需要显式安排模块互斥关系，不能等同于硬件分页。

**Q9: 32 位 Linux 进程的内存映像能否当作所有系统的固定布局？**

不能。代码、数据、堆、映射区和栈等描述的是常见进程地址空间组成；精确地址范围、布局顺序和增长方向会受位数、ABI、内核配置、加载器和地址随机化影响。

讨论内存映像时应先标明体系结构与操作系统。一个进程看到的虚拟地址布局不等于物理内存排布，动态库和文件映射也会占用虚拟地址空间。

**Q10: 内存映射文件与 read/write 文件访问在编程模型上有什么区别？**

内存映射把文件的一段内容映射到进程虚拟地址空间，程序通过内存访问读写映射区域；传统 read/write 则通过系统调用显式传入缓冲区。映射可简化随机访问并支持共享映射，但不保证文件数据立即驻留或同步落盘。

1. **建立映射**：系统创建虚拟地址区间与文件偏移的关联，通常不会因此立刻把整个文件读入 RAM。
2. **首次访问**：页面未驻留时可能触发缺页，由内核按映射关系调入数据。
3. **共享与写回**：多个进程可映射同一文件区域；共享/私有映射、同步调用和关闭时的持久化语义由平台 API 决定。

内存映射仍需处理映射长度、文件截断、错误和同步语义；它不等于“没有 I/O”或“修改后必定立刻写盘”。
