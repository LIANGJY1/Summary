# 进程与处理机调度

> 学习资料。问题覆盖进程实体、状态与控制、线程及调度策略；题序即文档结构。

**Q1: 程序、进程和进程映像有什么区别？**

程序是存储介质上的静态指令集合；进程是程序的一次执行活动；进程映像描述该进程在某一时刻的代码、数据、控制信息和资源状态。相同程序可以同时运行多个进程实例。

进程控制块（PCB）保存操作系统管理进程所需的信息，例如进程标识、状态、资源和处理器现场；程序段与数据段分别承载指令和运行数据。进程创建和退出时，操作系统建立和回收相应的控制信息与资源。

**Q2: 就绪、运行、阻塞和挂起状态分别说明进程缺少什么条件？**

就绪进程具备运行条件但在等待处理器；运行进程正在占用处理器；阻塞进程等待某个事件或资源；挂起进程暂时被换出主存。阻塞说明“等事件”，挂起说明“暂不在主存”，两者回答的是不同状态维度。

1. **就绪 → 运行**：调度器选中该进程。
2. **运行 → 就绪**：时间片用尽或发生抢占。
3. **运行 → 阻塞**：进程等待 I/O、资源或其他事件。
4. **阻塞 → 就绪**：等待事件完成，进程重新具备运行条件。
5. **挂起 → 就绪/阻塞**：进程重新调入主存后，按等待事件是否完成恢复相应状态。

不同教材和操作系统会采用不同状态模型；不要把所有实现都限定为同一组状态名称。

**Q3: 进程控制为什么要求创建、阻塞、唤醒和切换具备原子性？**

这些操作会同时修改进程状态、控制块和多个队列；如果被并发操作打断，进程可能出现在错误队列或状态不一致。操作系统因此用受保护的内核代码完成状态变更，并在必要范围内禁止或屏蔽会破坏不变量的并发操作。

例如阻塞操作要保存处理器现场、设置阻塞状态并将 PCB 放入对应等待队列；唤醒操作则从等待队列移出 PCB，改为就绪并加入就绪队列。现代系统的具体同步机制依体系结构与内核实现而异，不应简化成所有原语都只靠“关中断”。

**Q4: 进程和线程的资源边界有什么区别？**

进程提供资源隔离和地址空间等执行环境；线程是进程内可调度的执行流。一个进程可以包含多个线程，这些线程通常共享进程的地址空间和打开资源，但各自拥有独立的处理器执行现场和栈。

线程能降低同一进程内任务共享数据的成本，但也需要同步以避免竞态；独立进程的地址空间隔离更强，进程间共享数据通常需要显式 IPC 或共享内存机制。具体资源共享范围由操作系统和线程实现定义。

**Q5: 高级、中级和低级调度分别决定什么？**

高级调度决定哪些作业进入内存并建立进程；中级调度决定哪些挂起进程重新调入内存；低级调度从就绪队列选择下一个获得处理器的执行单位。低级调度通常最频繁，因为它直接参与处理器分配。

中级调度可能通过换出、换入缓解内存压力；它与进程是否等待 I/O 的阻塞状态不同。具有内核线程的系统中，低级调度器实际选择的执行单位可能是线程。

**Q6: FCFS、SJF、HRRN 和 RR 分别优先解决什么调度目标？**

FCFS 重视到达顺序，SJF 偏向短作业，HRRN 将等待时间纳入优先级，RR 通过时间片轮转改善交互响应。没有一种策略能同时对所有工作负载实现最佳响应、公平和吞吐量。

1. **FCFS**：按进入队列的顺序服务；实现简单但长作业可能让后续短作业等待很久。
2. **SJF/SRTF**：优先服务预计运行时间短的任务；若估算准确可降低平均等待，但持续到达的短作业可能使长作业饥饿。
3. **HRRN**：以等待时间和服务时间共同计算响应比，等待越久优先级越高；经典形式通常在调度点非抢占地选择任务。
4. **RR**：每个就绪任务轮流获得时间片；时间片太大时交互响应变差，太小时切换开销上升。

**Q7: 优先级调度和多级反馈队列怎样影响响应与饥饿？**

优先级调度可让紧急任务更快获得处理器，但低优先级任务可能长期得不到服务。多级反馈队列让新任务从较高优先级队列开始，耗尽时间片后逐步降级，以近似区分短交互任务和长 CPU 密集任务。

反馈队列需要设计时间片、队列数和提升策略；若缺少老化或提升机制，低队列任务仍可能饥饿。算法效果不能脱离工作负载和优先级更新规则来判断。

**Q8: 周转时间、等待时间和响应时间分别测量什么？**

周转时间是作业从提交到完成的总时长；等待时间累计任务处于就绪但未获处理器服务的时长；响应时间是请求提交到首次得到响应的时长。它们衡量不同目标，调度策略的优劣要结合系统关注的指标。

周转时间包含排队、处理器执行和等待 I/O 等阶段；等待 I/O 通常不算处理器就绪队列等待。交互系统常重视响应时间，批处理系统则更关注吞吐量和平均周转表现。
