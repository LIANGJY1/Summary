# Android 设备驱动接入

> Android 设备驱动在系统栈中的位置、设备访问控制、调试与测试。通用 Linux 驱动机制归 `../../02-os/06-Linux内核与驱动/`。

**Q1: [done] 为什么 Android 启动早期能看到 UART 日志，却无法使用 ADB？**

UART 控制台可由 bootloader 或内核较早初始化。USB ADB 还依赖 USB 设备功能、`adbd` 启动和主机枚举，因此常在更晚阶段才可连接。具体可用时间取决于设备配置。

1. **UART：**板级接口及早期控制台配置完成后，可以输出启动日志。
2. **USB ADB：**设备须配置 USB ADB 功能并启动 `adbd`，主机还须完成设备枚举和连接。
3. **排查选择：**需要观察 ADB 尚不可用时的日志，或设备只提供 UART 调试口时，可使用串口。

**Q2: [learning] AAOS 中 Linux 内核驱动位于系统栈的什么位置，应用是否通常直接读写硬件？**

内核驱动位于 Linux 内核中，负责管理设备并向上层暴露受控接口。AAOS 的应用通常通过 Android Framework、HAL 或系统服务访问硬件，而不是直接访问寄存器或任意 `/dev` 节点。

典型路径是应用调用平台 API，Framework/系统服务经 HAL 与内核驱动交互，驱动再使用内核设备子系统和硬件总线接口。不同硬件可能通过字符/块设备、sysfs、网络接口、专用子系统或 HAL 通道暴露。“Linux 一切皆文件”是统一接口思想，不代表所有硬件都只通过一个 `/dev` 文件访问。设备权限、SELinux 策略和服务架构也决定了谁能访问接口。

**Q3: [learning] Android 字符设备节点无法访问时应检查什么？**

驱动注册成功不保证 Android 应用能访问设备节点。需同时检查节点是否创建、文件权限和 SELinux 策略。

1. **节点与设备号：**确认驱动注册的设备号、设备模型和节点创建机制匹配，实际节点存在。
2. **访问权限：**检查节点所有者、用户组和权限配置，确认调用进程有权打开。
3. **SELinux：**检查设备节点标签和调用进程域，结合拒绝日志核对策略。

**Q4: [learning] 用用户态小程序验证字符驱动时，测试程序的 ABI 与驱动读写协议要核对什么？**

测试程序应为目标 Android ABI 构建，并按照驱动定义的读写协议传递长度和数据。用宿主机原生 `gcc -static` 生成的程序仍可能依赖宿主 ABI/运行时，静态链接不等于自动兼容 Bionic。

驱动与测试程序的最小闭环包括：打开设备节点、写入受支持数据、读取结果、检查返回字节数和错误码、关闭文件，并检查内核日志。测试数据长度必须覆盖边界情况，如零长度、超过最大缓冲区、部分读写和无效命令。程序应使用 Soong/NDK 等目标 Android 构建方式，或确认预编译二进制确实为目标架构和 Android runtime 构建。
