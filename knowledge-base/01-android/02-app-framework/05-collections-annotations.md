# 集合与注解的框架契约

> 应用框架 API 契约。边界：本文回答"SparseArray 等平台集合的取舍与平台注解契约"，并说明 Android 资源和值域注解的静态检查边界。Q 序列即结构，供 atlas 同源直读。
> 合并来源：> 学习资料。问题聚焦 AndroidX 注解提供的静态检查契约；题序即结构。

**Q1: 小规模整数键映射为什么可以考虑 `SparseArray`，它的主要取舍是什么？**

`SparseArray` 以有序 `int[]` 保存键、以并行 `Object[]` 保存值，避免 `HashMap<Integer, …>` 的键装箱和哈希节点开销，适合条目较少且键为整数的场景。它用二分查找定位，查询为 O(log n)，但插入和删除可能需要移动数组元素，不能把它当成任意规模下比哈希表更快的通用替代品。

Android 实现会用删除标记延迟压缩数组；值本身允许为 null，因此内部需要能区分“合法 null 值”和“已删除槽位”的标记。选择时看条目规模、读写比例与内存开销，而不是只比较渐进复杂度。

**Q2: Android 的 @DrawableRes 等资源注解会在运行时验证资源类型吗？**

`@DrawableRes` 等资源注解主要供 IDE、Lint 和编译期工具检查调用方传入的资源 ID 类型；它们通常不会把底层整数改成新的运行时类型，也不能替代运行时校验。

工具能否检查出错误取决于注解位置、被检查的调用路径和相应分析配置。跨模块或动态数据边界仍需自行验证资源值。

**Q3: Android 的 @IntDef 怎样表达一组允许的整数值？**

`@IntDef` 可用注解描述一个整数参数允许的常量集合，让静态分析工具在 IDE 或构建检查中报告不匹配值。它适合需要保持整数 ABI 或避免枚举对象开销的 API 约定，但不像运行时枚举那样自动保证输入合法。

若非法值会导致安全或数据完整性问题，应在运行时验证；Lint 提示不能作为唯一防线。
