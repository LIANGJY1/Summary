# 集合与注解的框架契约

> 应用框架 API 契约。边界：本文回答 `SparseArray` 等平台集合的适用条件与取舍，以及 Android 资源和值域注解能提供的静态检查保证。Q 序列即结构，供 Atlas 同源直读。

**Q1: 小规模整数键映射为什么可以考虑 `SparseArray`，它的主要取舍是什么？**

当映射条目较少、键是 `int` 且内存占用比通用哈希表更重要时，可以考虑 `SparseArray`。它省去 `HashMap<Integer, …>` 中整数键的装箱和哈希表节点，但以有序数组和较慢的插入、删除换取较低的对象开销。

判断时看以下实现特征：

1. **存储：**键和值分别保存在有序 `int[]` 与并行的 `Object[]` 中，因此整数键不需要装箱，条目也不需要哈希节点对象。
2. **查找：**按键排序后用二分查找，查找复杂度为 O(log n)。这不代表它在所有规模和访问模式下都比 `HashMap` 快。
3. **插入与删除：**插入可能移动数组元素，删除通常先标记槽位，再在需要时压缩数组。因此写入频繁或映射很大时，移动成本可能抵消节省的内存。
4. **空值与删除标记：**值允许为 `null`，实现需要用内部删除标记区分合法的空值与已删除槽位。

因此，按条目规模、读写比例和内存预算实测选型。`SparseArray` 适合小型整数键映射，不是任意规模下对 `HashMap` 的通用性能替代品。

**Q2: Android 的 `@DrawableRes` 等资源注解会在运行时验证资源类型吗？**

不会。`@DrawableRes` 等资源注解主要为 IDE、Lint 和相关静态分析工具提供参数、字段或返回值的资源类型约定。它们不会把资源 ID 这个整数变成新的运行时类型，也不会自动在运行时检查实际资源。

使用时需要区分静态提示与运行时保证：

1. **静态检查：**例如 `@DrawableRes` 表示该整数预期是 drawable 资源 ID，工具可据此检查已知调用位置是否传入了其他资源类型。
2. **检查边界：**检查结果取决于注解是否保留、工具是否识别该调用路径，以及相应分析是否启用。动态数据、反射或工具无法追踪的跨模块输入可能无法在静态阶段确认。
3. **运行时边界：**需要处理外部输入或动态资源 ID 时，仍要通过实际加载结果、异常处理或业务校验处理非法值，不能把注解提示当作运行时防线。

**Q3: Android 的 `@IntDef` 怎样表达一组允许的整数值，它能否强制输入合法？**

`@IntDef` 用一个源代码级注解声明整数 API 的允许值集合，供 IDE、Lint 等静态分析工具发现不匹配的常量。它保留整数 API 的调用形式，但不是运行时枚举，也不会自行拒绝非法输入。

理解这份约定要看它声明的元数据：

1. **允许值集合：**`value` 列出允许使用的整型常量。静态工具可以据此提示调用方传入集合外的已知值。
2. **位标志模式：**`flag` 默认是 `false`，表示把值视作互斥选项。只有设为 `true`，这些常量才表示可以按位组合的标志。省略该属性时，不能把组合值当作已声明的合法值。
3. **开放值模式：**`open` 默认是 `false`，表示工具按封闭集合检查并提示集合外的值。设为 `true` 后，集合外值也可接受，已知值主要用于提示和补全。它仍不增加运行时检查。
4. **保留范围：**AndroidX `IntDef` 使用 `SOURCE` 保留策略，注解供源码分析使用，不会作为运行时契约保存在 class 文件供反射验证。

因此，`@IntDef` 提高的是源码调用阶段的可读性和静态诊断能力。若非法整数会影响安全、状态一致性或数据完整性，被调用方必须在运行时验证。Lint 报告既不是强制类型系统，也不等同于运行时拒绝。
