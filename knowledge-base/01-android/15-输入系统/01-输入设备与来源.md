# 输入设备与来源

> 以 Android 13 为主要参考。基础流程和职责在本册，详细配置、源码及排查见 [输入设备与来源进阶](进阶/01-输入设备与来源进阶.md)。

**Q1: [learning] Android 输入系统解决什么问题？**

输入系统把设备状态变化转换为 Android 事件，并将事件交给合适的窗口和应用。它还处理设备识别、目标选择、权限和异常情况。

一次触摸通常经过：触摸设备 → Linux 输入驱动 → input core / evdev → EventHub → InputReader → InputDispatcher → 目标窗口 → View。

**Q2: [learning] 一次车机输入一定经过 Linux evdev 吗？**

不一定。车机物理按键和旋钮可以通过 Linux 输入设备接入，也可以经车辆硬件抽象层 VHAL 进入 CarService。实际走哪条路径取决于设备和厂商集成，不能只凭输入外观判断。

1. **Linux 路径：**驱动报告 Linux 输入事件，经 EventHub 和 InputReader 转换。
2. **车辆路径：**VHAL 报告车辆输入属性，由 InputHalService 和 CarInputService 处理，后续去向取决于事件类型与路由策略。

**Q3: [learning] Android 输入可以来自哪些设备或来源？**

Android 输入既可来自物理设备，也可由系统或授权程序生成。常见来源按设备和路径区分：

1. **触摸和指针：**触摸屏、触控板、鼠标和触控笔。
2. **按键和方向：**内置或外接键盘、遥控器、游戏手柄及摇杆。
3. **车机设备：**旋钮、方向盘按键和厂商自定义输入，可走 Linux 输入路径或 VHAL 路径。
4. **软件输入：**输入法文本、无障碍操作、测试注入和虚拟设备，各自入口与权限不同。

传感器、音频和相机有独立子系统，不能因数据也称为“输入”就假定都经过 InputDispatcher。

**Q4: [learning] 触摸屏、触控板、鼠标和触控笔的输入有什么区别？**

它们都可能产生指针类事件，但作用方式和事件属性不同。

1. **触摸屏：**接触点通常直接对应显示区域中的位置。
2. **鼠标与触控板：**通常以间接指针移动、按键或滚轮操作界面。
3. **触控笔：**除位置和接触状态外，设备可能提供压力、倾斜及工具类型等信息。

实际能力由设备、驱动和系统配置共同决定，应用应检查事件来源和支持的轴，不能假定所有设备都具有相同能力。

**Q5: [learning] 游戏手柄、键盘和车机旋钮如何表达操作？**

它们可以组合使用按键、方向或轴变化，不能都当作触屏手势。

1. **键盘和遥控器：**通常以按键按下、释放与修饰键状态表达操作。
2. **游戏手柄与摇杆：**可同时产生按键和摇杆轴事件。
3. **车机旋钮：**可能经 Linux 旋转编码器或 VHAL 接入，转动、按压和方向操作的路由取决于实现。

**Q6: [learning] 真实设备、虚拟设备和输入注入有什么区别？**

区别在于事件从哪里进入系统，以及是否创建输入设备。

1. **真实设备：**由驱动向系统报告硬件状态变化。
2. **虚拟设备：**软件创建一个被系统识别的设备，再通过设备接口产生事件。
3. **输入注入：**授权调用方把事件送入系统的注入入口，不一定对应一个新建的 Linux 输入设备。

注入权限和事件到达目标的结果取决于调用入口与系统策略。

**Q7: [learning] 输入无响应应怎样确定排查范围？**

先判断事件在哪一层消失或延迟，再查该层原因。

1. **设备：**确认设备存在且产生预期事件。
2. **系统：**确认设备被识别，目标显示和窗口正确。
3. **应用：**确认窗口收到事件，应用没有拦截、丢弃或长时间阻塞。
4. **画面：**事件已处理但无反馈时，继续检查帧调度和呈现。
