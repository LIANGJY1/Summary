# 手势与返回

> 以 Android 13 为主要参考。基础流程和职责在本册，详细配置、源码及排查见 [手势与返回进阶](进阶/07-手势与返回进阶.md)。

**Q1: [learning] 手势与单个触摸事件是什么关系？**

手势是对一段相关输入事件的解释。例如按下、移动和抬起可组合为点击、拖动或滑动。应用需要维护手势状态，并在取消时清理状态。

**Q2: [learning] 父子 View 的滑动冲突怎样产生？**

当父容器和子 View 都希望处理同一段触摸时，需要由分发与拦截规则确定当前目标。父容器在合适条件下拦截后，原目标可能收到取消事件。

解决时应根据滑动方向、边界和交互需求决定谁处理，并考虑手势中途改变方向及取消的情况。

**Q3: [learning] 系统返回手势和应用手势如何共存？**

系统可能在屏幕边缘观察并接管返回手势，应用也可能需要处理边缘交互。系统策略与应用申请的手势排除区域共同影响结果，申请排除区域不代表一定全部生效。

预测性返回的可用 API 和行为随 Android 版本、目标 SDK 及配置变化，应按目标版本核对。

**Q4: [learning] 长按、双击和滑动阈值应怎样处理？**

应优先使用系统提供的手势识别器和设备相关配置，而不是固定假设一种时间或距离阈值适用于所有设备。识别时还要处理多指、事件取消及目标 View 状态变化。
