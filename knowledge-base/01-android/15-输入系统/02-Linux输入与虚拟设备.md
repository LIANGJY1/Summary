# Linux输入与虚拟设备

> 以 Android 13 为主要参考。基础流程和职责在本册，详细配置、源码及排查见 [Linux输入与虚拟设备进阶](进阶/02-Linux输入与虚拟设备进阶.md)。

**Q1: [learning] Linux 输入子系统在 Android 输入链路中做什么？**

Linux 输入子系统为输入驱动提供统一的事件表示与处理机制，让用户态不必分别解析每种硬件协议。驱动报告事件后，input core 将其交给相应处理器，evdev 向用户态提供读取接口。

**Q2: [learning] evdev 与 /dev/input/eventX 分别是什么？**

evdev 是 Linux 内核的通用输入事件处理器。`/dev/input/eventX` 表示访问某个事件设备的字符设备节点，其中 X 代表数字，例如 `event0`。

`/dev/input/event*` 中的星号是通配符写法，可在命令行匹配多个节点；它不是一个实际设备节点，也不会由 `open()` 自动展开。节点编号会变化，不应固定假设某个编号就是触摸屏。

**Q3: [learning] Linux input_event 表示什么？**

input_event 是用户态读取的输入事件记录，包含时间、类型、编码和值。类型表示事件类别，编码表示该类别中的具体项目，值表示状态或数值。

例如坐标变化和按键状态可用不同记录表达。一次触摸更新通常包含多条记录，并以同步事件划分一组更新，不能把单条记录直接等同于一个 Android MotionEvent。

**Q4: [learning] virtio-input 如何接入客体系统？**

virtio-input 是虚拟机中的虚拟输入设备。宿主侧提供输入，虚拟设备通过 virtio 队列向客体驱动传递事件，客体驱动再将事件报告给 Linux 输入子系统。

如果客体运行 Android，后续可经 evdev、EventHub 和 InputReader 进入 Android 输入链。virtio-input 记录本身不携带时间戳，不能仅凭它推断宿主产生输入的时刻。

**Q5: [learning] 如何区分设备未上报和 Android 未处理？**

先观察内核设备和事件，再检查 Android 识别与路由。

1. **内核侧：**查看设备能力及事件节点，确认操作时是否产生预期事件。
2. **Android 侧：**检查设备分类、关联显示和窗口分发。
3. **边界：**没有节点可能由硬件、驱动、权限或设备策略造成；单凭应用没有响应不能直接认定驱动故障。

**Q6: [learning] SYN_REPORT 是什么，是否等于一帧画面？**

SYN_REPORT 是 Linux 输入事件中的同步标记，表示一组输入状态更新结束。它不是显示帧标记。

1. 一次触摸更新可由坐标、按键状态和同步标记等多条记录组成。
2. input core 根据同步标记交付当前积累的变化，evdev 再向读取者提供事件。
3. 一个输入包不必对应一次 read、一个 MotionEvent 或一次画面呈现。

依据：Linux 输入子系统与《全链路解剖》02、03 篇。

**Q7: [learning] getevent 和 EventHub 同时读取设备，为什么通常不会互相抢走事件？**

evdev 为每次独立打开设备节点的读取者维护独立缓冲。getevent 和 EventHub 通常分别读取各自缓冲中的事件副本。

1. 两个读取者的读取速度和缓冲溢出状态分别判断。
2. getevent 能及时读取，不代表 EventHub 同期也已读取。
3. 设备被独占抓取等特殊配置会影响其他读取者，不能无条件认为所有打开者都能收到事件。

依据：Linux 5.15 evdev 与《全链路解剖》03 篇。

**Q8: [learning] 输入设备已经可读，为什么读取线程仍可能没有运行？**

设备就绪只表示已有数据可读取，等待该设备的线程还需要被调度到 CPU 才能执行。

1. 内核准备好数据并通知等待者。
2. 线程进入可运行状态后，仍可能等待 CPU。
3. 线程获得 CPU 后，EventHub 才能执行读取。

因此，就绪通知时间、开始运行时间和读取完成时间是不同的观察点。

**Q9: [learning] 为什么不能直接比较 getevent 和 Perfetto 中的时间？**

比较前必须确认两个工具使用的时钟域及其映射。时间单位相同，并不代表起点和计时规则相同。

1. CLOCK_MONOTONIC 和 CLOCK_BOOTTIME 对系统挂起时间的处理不同。
2. evdev 读取者可配置事件时钟；getevent 与 EventHub 的实际设置要分别核实，不能只看默认值。
3. trace 若使用不同时间域，需要核对时钟转换；单个时间点吻合不能证明整个采集期间已经完成逐点校验。

依据：Linux 5.15 evdev、Android 13 EventHub 和《全链路解剖》03 篇。
