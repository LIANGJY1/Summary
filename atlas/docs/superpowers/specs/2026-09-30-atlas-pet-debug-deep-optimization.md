# Atlas 萌宠调试深入优化设计

## 背景与目标

Atlas 已提供萌宠调试页面、单条命令和 98 个可执行场景。实装截图暴露出主要体验问题：场景列表以英文 case 名称为主，用户难以快速判断每条场景验证什么；展开后看到的 `fresh_on`、`pet play_done`、`ipc 14` 等内部命令也缺少面向用户的解释。执行器目前按序运行外部进程，但取消只取消协程，不能及时终止当前子进程；输出先整体读入内存，再截取少量行展示。场景定义另有 Atlas 内嵌副本，容易与命令清单或 JVM 场景表不一致。

本次目标：让用户先看懂“验证什么、会发生什么、应该看到什么”，再决定是否执行；执行期间能可靠停止并看到清楚的进度；场景信息保持可追溯且不静默漂移。

## 方案选择

1. **只翻译界面文案**：改动较小，能改善场景列表阅读；进程停止、输出内存占用和场景副本漂移仍然存在。
2. **整合优化（推荐）**：集中改造萌宠命令执行器，建立场景数据同步与校验，并把当前场景列表改为中文说明优先、原始命令可按需查看。保留“工具 → 萌宠调试”入口、目标设备上下文和一键执行方式。
3. **向导式重做**：将工具改成多步工作流，操作路径变化大，当前 98 case 目录的核心诉求并不需要整页重做。

采用方案 2。范围限定在萌宠调试分区及其 PRD/场景同步，不重构 Atlas 其他工具，也不改变 Pet 状态机行为或注入协议。

## 用户界面与操作

### 场景目录

- 每个 case 的主标题改为自然、简短的中文名称；英文 `PetScenarios` 原名保留为副标题或技术详情，避免丢失源码追踪线索。
- 列表摘要优先呈现“本场景验证什么”和预期现象。使用中文搜索标题、摘要、步骤和限制条件；编号与原英文名称继续可搜。
- 展开场景后，先显示前置条件、按序排列的可读步骤、预期现象和设备限制。每一步用“动作名称 + 简短解释”描述，例如“模拟动作完成回调：通知状态机当前动画已结束”。
- 原始序列（如 `fresh_on; pet ivi_ready; pet play_done`）和实际展开后的 adb argv 收在可折叠的“技术详情”区域。高级用户仍能核对底层命令。
- JVM 覆盖、真实媒体会话等无法在设备端精确复现的限制继续醒目显示，并在执行确认中再次说明。

### 快捷操作与执行反馈

- 快捷事件控件增加一句用途说明或明确分组，区分 Settings 调试注入、PetIpcTest 正式 IPC、发送失败模拟和媒体会话控制。
- 执行确认说明目标设备、将中断或覆盖的对象、预计步骤和场景限制；干净重启、安装等影响设备状态的操作保持确认。
- 进度区主要显示中文步骤状态、当前步骤/总数、耗时和结果。技术命令和 stderr 放入可展开详情；输出区只保留有界尾部并明确标注截断。
- 保留搜索、阶段筛选、实时日志、单 case 一键顺序执行和“停止”操作。停止后明确区分“当前命令已终止”与“后续步骤已取消”。

## 场景数据与权威关系

- `PetScenarios.ALL` 仍是 case 编号、顺序和原英文名称的唯一权威。
- `08-调试注入命令清单.md` 仍是设备可执行序列、预期表现与设备限制的权威。Atlas 增补的中文标题、操作说明属于展示元数据，不覆盖这两个权威源。
- Atlas 不再维护一份无校验的 Kotlin 多行字符串副本。受控同步步骤从 08 清单生成可提交的应用资源；资源携带 case 编号与原英文名称。同步校验 98 条数量、连续编号、顺序及名称均对应 `PetScenarios.ALL`。
- 同步时若源文件缺失、case 集合不一致或行格式无法解析，明确失败并指出编号；Atlas 构建校验已生成资源的结构和 DSL token。这样应用构建不依赖外部 YaDi 源码目录，运行期也不读取 Markdown 文件。
- 注入 DSL 继续保持小而明确的命令集合；每种事件、等待、媒体操作与正式 IPC 都由类型化步骤表示。未知步骤在同步阶段报错，不作为成功的“说明”执行。

## 命令执行器

新增仅供萌宠调试使用的 `PetCommandRunner`（或等价内部模块），从 `AppStore` 分离流程编排与进程生命周期：

1. 同一设备的调试命令串行执行；不同页面操作不能在同一萌宠流程中插入命令。
2. 每条命令由 runner 持有 `Process` 和输出读取任务。取消时先标记当前任务取消，终止当前子进程并回收输出流，再停止后续步骤；取消不会只停在协程标志上。
3. 超时复用相同清理路径：终止进程、关闭流、记录超时结果、跳过剩余步骤。进程已退出、设备断开、命令启动失败等结果分别映射成用户可读状态。
4. stdout/stderr 并发排空以避免管道缓冲区阻塞；界面状态只保留配置上限的行数和字符数，超出部分丢弃旧输出并记录“前文已截断”。
5. 每步检查取消状态；`Wait` 使用可取消挂起，不阻塞线程。运行状态始终以一个最终结果结束（成功、失败、超时、用户停止）。
6. 专用 logcat 流沿用独立的开始/停止入口，但复用进程清理规则；停止或页面关闭时终止 adb 子进程并释放 reader。

## 数据流

```text
PetScenarios.kt ──编号/顺序/原名校验──┐
                                      ├─同步或构建生成──> 打包场景资源 ──> 中文场景目录
08 命令清单 ──命令/预期/限制来源──────┘                                      │
                                                                             ▼
用户选择场景 ──> 类型化步骤计划 ──> PetCommandRunner ──> adb / Gradle 子进程
                                      │                         │
                                      └────进度/取消/有界输出───┘
```

## 失败处理与边界

- 无在线设备、目标设备掉线、缺少 adb、源清单校验失败、构建目录不存在、子进程非零退出、超时和用户停止均呈现独立错误状态与下一步建议。
- 运行中禁用会与当前流程冲突的启动操作；停止操作始终可用。
- 不自动重试注入事件，避免重复发送造成状态变化；只有后续用户选择重新运行才会重试整条 case。
- `DEBUG_INJECTION_ENABLED` 仍由 Launcher 调试构建配置控制；Atlas 清楚显示当前配置要求，不通过调试键自动开启生产开关。
- 不改变设备端注入语义、`PetIpcTest` Intent 协议、ADB 参数语义、98 条 case 预期及用户现有设备选择设置。

## 验收标准

- 98 条场景均显示中文标题和中文“验证什么”摘要；英文原名、编号、原始序列与来源 case 可追溯。
- 展开任一 case 后，用户能读懂每一步注入含义、预期现象和限制条件；原始 adb 命令可按需查看。
- 中文关键词、英文原名、编号均能找到对应场景；阶段筛选和当前一键运行路径保留。
- 用户在命令运行期间按停止后，当前子进程被终止，后续步骤不再发出，最终状态明确显示停止；超时执行同样完成进程清理。
- 高频输出下内存中的执行日志不超过配置上限；页面提示已截断，命令本身仍由管道完整排空。
- 受控同步检查能识别缺行、重复/跳号、乱序、名称偏差和未知 DSL token，并定位具体 case；普通 Atlas 构建只依赖已生成资源。
- 构建出的 Atlas 资源自包含场景数据，不要求运行中的 Atlas 打开源仓库文件。

## 实施边界与待决事项

- 预计修改 `atlas/app/src/main/kotlin/atlas/core/PetDebugTools.kt`、`atlas/AppStore.kt`、`atlas/ui/ToolsView.kt`，增加 runner 与场景资源生成/同步模块，并更新 `atlas/PRD.md`。
- 先实现可取消、有界输出的 runner 与进度模型，再接入场景目录可读模型，最后调整 UI 展示和确认流程。
- 本设计选择“受控同步生成可提交资源，构建校验已生成资源，运行时打包自包含”的方式，避免 Atlas 的日常构建和运行依赖外部 YaDi 源码路径。实现计划阶段再确定同步命令与校验脚本的具体接口。
