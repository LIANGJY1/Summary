# source-annotator — 术语表

本 skill 的共享语言：写/改 SKILL.md 与附属文件时用词以此为准；概念词与标签的映射在此裁决。

## Language

**十六标签体系**：
注释块【标签】的固定集合（设计思想/核心流程/…/TODO 共 16 个），同时是检索锚点（`grep "【"`）与校验脚本的判定基础。
_Avoid_: 扩充新标签、体系外【】词

**伤疤**（行类型，非标签）：
看似多余/怪异的防御代码，多为历史事故修复现场，值得注释指出"它防的是什么事故"。落笔时用【注意事项】标签承载，"伤疤"只描述行的性质。
_Avoid_: 【伤疤】标签、【边界】标签（边界类内容用【关键细节】）

**学习批注**：
本 skill 写入源码的中文行注释（带 16 标签前缀）；四检（准确/清楚/合并/删冗）的对象。
_Avoid_: 注释（泛指时会与上游注释混淆）

**上游注释**：
库作者的原始注释（文档注释与行注释，含英文），只读保护，发现可疑记汇报不改。
_Avoid_: 原注释（歧义：谁的原？）

**两面讲解**：
扩展点/配置点/回调契约处的注释形态：源码侧在做什么 + 应用侧怎么用（内嵌最小示例 + 场景 + 不用会怎样）。

**论断分级**：
注释中每条论断的四种档位：代码事实（免标）/ 考据（可引 #编号）/ 推断（标 `[inferred]`）/ 外部观点（过核实门禁）；混档必须逐条标注。

**死注释六类**：
复述型/翻译型/日记型/万金油型/漂移型/占位型，病例与处方在 `references/quality-rubric.md`。

**质量门**：
交付前的双层门——机械门（`scripts/check_annotations.py` 九项，FAIL 必修）+ 语义门（删除测试/专名回查/链条检查三问）；WARN 的处置口径见 SKILL.md §6。

**沉淀文档 / 知识库**：
前者是每库一份的 `<库名>.md`（宏观机制章）；后者是跨库累积的思想资产（ROUTING.md 路由）。互不复制。

**批次**：
大范围任务按机制拆的执行单元（约 >8 文件或 >3 机制时必拆），每批结束出完整四段汇报，用户说"继续"走下一批。

**权威源 / 副本**：
`~/.agents/skills/source-annotator/` 是唯一改动入口（CONTEXT.md、docs/ 也在此）；`Summary/skills/source-annotator/` 是发布副本，整目录单向同步（含维护文档，供 git 留史）。
_Avoid_: 双向编辑 Summary
