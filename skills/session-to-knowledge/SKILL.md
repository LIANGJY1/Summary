# 会话知识沉淀

## 目标与硬边界

把脱离原会话仍成立、六个月后仍能直接复用的结论，按知识主题写入唯一知识库。先判断产品 profile，再路由、脱敏、审读、授权、写入、验证；任何一步不能证明就暂停，不用“看起来合理”补齐。

- 固定知识库：`/home/liang/Project/MyProject/Summary/project/knowledge-base/`。路径不可读、缺失或出现第二个候选库时停止询问，不静默建替代库。校验脚本默认使用此路径；迁移机器或显式指定另一库时必须传 `--kb-root`，不得靠环境变量静默切换。
- 本 skill 只接收声明性知识：事实、机制、坑、边界、权衡、可迁移做法。工作流/提示词/代理协议走 `session-to-skill`；源码行注释与库级讲解走 `source-annotator`；续做上下文走 `handoff`。
- 仓库是用户的 git 工作树：保留已有未提交修改，禁止清理、回滚、覆盖或自动 commit。
- 凭据、token、密码、个人信息、内网地址、私有链接和可重建秘密永不入库；脱敏后仍不安全的候选拒收。
- 本 skill 不设候选数或落盘数上限。数量不降低质量门；候选多时按主题分组、分页展示并分批授权，不把“≤3”换成隐形上限。

## 两种 profile

先按知识内核选 profile，绝不按会话顺序建“会话总结.md”。

| profile | 落点 | 内容形态 | 入口门禁 |
|---|---|---|---|
| `knowledge-entry` | 根目录条目型大类 | 服从目标文档的局部段落契约，保持完整命题、复习场景和边界可读 | 换项目仍成立 + 复习者测试 + 可追溯依据 + 脱敏 |
| `language-note` | `language/` 及语言子目录 | 服从目标文件的章节/Q&A/散文形状，保持示例驱动、术语白话和版本边界 | 语言替换测试失败（确属该语言）+ 示例或可复现解释 + 脱敏 |

### 文档规范派生（先读，后成形）

格式定义只维护在目标知识文档，不在本 skill、`CONTEXT.md` 或其他 skill 中复制。`knowledge-entry` 没有全库统一的条目四段式；写入格式按以下优先级读取：

1. 目标文档的 `## 规则`；
2. 目标文档紧邻 `## 目录` 的 HTML 注释模板（若有）；
3. 同一文档已有条目的稳定形状；
4. `CONTEXT.md` / `ROUTING.md` 的术语与边界（只用于路由和词义，不定义条目格式）。

语言笔记同样只以 `language/README.md` 和目标文件自身为准：已有 Q&A、章节笔记或散文形状时原地延续；目标文件为空且没有局部模板时，先在目标文件建立格式，再写内容。不得因为 profile 自动创建统一标题、Q 编号或段落。

新建根级知识文档时，先获授权建立该文档自己的 `## 边界`、`## 规则`、`## 目录` 和条目模板，再写条目。`CONTEXT.md`、`ROUTING.md`、ADR 是体系文档，不按上述条目模板写入。

条目标题、冷可读、无日期和无会话叙事仍是跨文档质量要求；具体段名、顺序、示例上限和版本写法只能从目标文档读取，不能在本 skill 重述。

## 权威文件与共享契约

动笔前读取：

1. `project/knowledge-base/CONTEXT.md`：术语、profile、生命周期、`supersedes` 定义。
2. `project/knowledge-base/ROUTING.md`：主判据链、唯一候选大类、相邻边界和维护者标记。
3. 目标大类或 `language/README.md`：收/不收边界、格式、归并方式；目标是语言域时再核对语言目录注册表。

所有直接写入 knowledge-base 的 skill 共享本流程、脱敏门、冲突规则和 `check_kb.py`。维护者只是责任/复核标记，不是第二套权限或另立近义文档的理由。

## 流程

### 1. 预检：锁定范围与写保护

用一句话记录主旨、输入范围、允许触及的文件和用户是否授权持久化。没有可迁移内容时报告 `0 条` 并结束。

在读取候选前记录目标文件的路径、存在性和内容 hash（或等价快照），列出本轮允许修改的文件白名单。工作树已有改动不归因于本轮；写入前若目标 hash 变化，停止并重新审阅，不覆盖并发修改。

### 2. 证据盘点与脱敏（只在本轮上下文中保留）

建立临时证据表，不把证据等级、命令环境或来源清单强行写入知识正文：

| 候选 | 依据位置 | 等级 | 是否脱敏 | 缺口 |
|---|---|---|---|---|
| C1 | 文件/命令/复现步骤 | `observed` / `verified` / `inferred` / `external` | 是/否 | 未验证点 |

- `observed`：直接看到的代码、文档或输出；`verified`：两个独立证据或可重复命令交叉确认；`inferred`：有依据但未验证的推断；`external`：外部资料且已与本地事实核对。
- 外部或版本敏感结论必须在候选和汇报中给出来源、版本/日期与核对结果；无法稳定复现就降级为 `inferred` 或暂缓。
- 扫描候选、示例、补丁和最终 diff；疑似秘密不引用原文，替换为 `[已脱敏：类型]`。脱敏不是“删掉一行”后继续猜测。

### 3. 原子化、内容成形与唯一主题路由

把会话拆成最小独立命题，一条只回答一个可复习问题。每条按以下顺序：

1. 过 profile 门；`knowledge-entry` 通过“换项目仍成立”与“六个月后遇到什么问题会翻到它、翻到后能直接用”；`language-note` 通过语言替换测试和示例驱动要求。
2. 查 `ROUTING.md` 的主判据链。多路命中时依次用：知识内核 > 目标大类头部边界 > 复习者主要动作；仍无法唯一决定就问用户，不用维护者列或文件名猜。语言本身先进入 `language/`，业务/项目操作不因示例语言而进入语言域。
3. 查目标标题、同义命题和相邻条目；已有同一命题就并入，不复制。需要两个不同视角时才分别写，并互相链接。
4. 按上面的文档规范派生结果：先确定目标文档的段名、顺序、示例上限、版本写法和目录更新方式，再成形正文；示例必须最小、可运行或明确标注未验证。

候选清单必须完整而不限数量；用主题分组和批次号代替上限：

```text
批次 A / 主题：Android UI
C1 | profile=knowledge-entry | 目标=android-ui.md
命题：构造期消费的配置不会被运行期 setter 自动重新消费
复习场景：改了组件属性但 UI 不变时
动作：并入「构造期配置与运行期 API 存在断层」
格式来源：`<目标文档>#规则` 或 `<目标文档>#条目模板`
依据：<路径/命令> | 等级：verified | 拒收原因：无
```

### 4. 授权、冲突与 ADR 分流

候选状态只能沿 `提取 → 待授权 → 已授权 → 写入中 → 已验证` 前进；用户拒绝、证据不足、冲突未裁决分别记为 `拒收`、`暂缓`、`待裁决`。无上限不等于默认全选：用户可按批次、按条目授权，未回应的保持待授权。

普通条目写入由候选授权覆盖；修改 `CONTEXT.md`、`ROUTING.md`、语言注册表、维护者边界或 ADR 必须单独列出并获得明确授权。维护者提示是非阻断通知，不代替授权。

冲突规则：

- 补充或收窄条件：就地并入，保留旧证据，正文不写日期。
- 结论反转：明确裁决后新条目写 `**supersedes**：<旧条目链接>`；旧正文保留并标“已被替代”，新旧关系可被校验器检查。
- 无法判定：不写入，列开放问题。
- 难逆、影响多个消费者且存在真实取舍的系统决定：进 ADR；可迁移结论仍进 knowledge-base，并从条目链接 ADR。ADR 不代替普通知识条目，普通条目也不复制 ADR 的决策过程。

### 5. 安全写入与幂等更新

授权后重新读取权威文件和目标，复核 hash、白名单和敏感扫描。使用 `apply_patch` 做精确修改；脚本或批量工具写文件时使用临时文件 + 原子替换，失败保留原文件。每个候选携带稳定的 `目标 + 动作 + 内容指纹`，重复执行应变成“无变化/已存在”，而不是追加副本。

- 新大类：先写骨架、边界、规则、目录，再写条目，最后回填路由和注册表。
- 新条目：标题是完整命题；正文按目标文档的局部模板成形，不套全库统一段式；目录与正文同补。
- 并入：只更新原条目的结论/场景/机制/边界中必要部分，不另开同义节。
- 修订：只改变目标语义；反转用 `supersedes`，不要覆盖旧结论。
- 发现目标文档的规则与现有条目形状不一致时，优先保持既有规范并报告漂移；不要顺手重构整篇文档。
- 任一目标在写入期间发生外部变化，停止、报告冲突并让用户重新授权；不得用强制覆盖解决。

### 6. 验证与回归

先校验本轮触及文档，再按需跑路由或全库审计。命令示例：

```bash
python3 /home/liang/.agents/skills/session-to-knowledge/scripts/check_kb.py <本轮 entry 文档...> --profile entry
python3 /home/liang/.agents/skills/session-to-knowledge/scripts/check_kb.py <本轮 language 文档...> --profile language
python3 /home/liang/.agents/skills/session-to-knowledge/scripts/check_kb.py --routing-only --routing /home/liang/Project/MyProject/Summary/project/knowledge-base/ROUTING.md
```

校验器负责 UTF-8、文档骨架、目录↔正文、重复标题、相对链接、路由注册、profile/路径一致性和明确的敏感模式；它不替代按目标文档 `## 规则` 做格式审读、复习者测试或版本核对。失败就修复或报告阻塞；全库已有问题单列为基线，不冒充本轮回归结果。

### 7. 固定格式收尾

```text
结果：已验证 / 部分完成 / 阻塞
主旨：<一句话> | profile：knowledge-entry N 条，language-note M 条
候选：提取 / 收录 / 并入 / 修订 / supersedes / 拒收 / 暂缓（逐项数量）
文件动作：<文件> — <条目/章节> — <动作> — <证据等级（仅汇报，不落盘）>
格式契约来源：<目标文档>#规则 或 <目标文档>#条目模板；结果：<是否保持既有格式>
质量：<格式与语义审读结论>；校验命令：<命令> → <结果>
安全与冲突：<脱敏、hash 冲突、supersedes、ADR 分流、维护者提示>
未解决：<开放问题/存量基线/下一步>
提醒：Summary 是 git 仓库，本 skill 不自动 commit。
```

## 快速判定与红线

| 信号 | 动作 |
|---|---|
| “总结一下”但未要求持久化 | 只回复，不写文件 |
| 可重复流程、提示词、代理协议 | 转 `session-to-skill` |
| 源码注释、源码阅读产物 | 转 `source-annotator` |
| 语言语法/类型/并发机制 | `language-note` |
| 跨项目机制、事实、坑、权衡 | `knowledge-entry` |
| 相同命题已有条目 | 并入，不重复开节 |
| 来源不足、库路径不明、路由不唯一、冲突未裁决 | 暂停并报告 |

看到“先全部写、之后再脱敏/补证据”“维护者不同就另建文件”“未报错所以机制成立”“用户说直接写就可跳过冲突/安全门”“工作树变了但先覆盖”，立即停止并回到对应步骤。
