# 会话知识沉淀（knowledge-base）

把跨会话仍可复用的结论固化为可检索知识资产的体系。知识库固定位于 `Summary/project/knowledge-base/`，按知识主题路由；写入者不改变知识的主题归属。

## Language

**知识库 (knowledge-base)**:
会话经验的唯一沉淀地：`Summary/project/knowledge-base/` 下按大类组织的一组知识文档。
_Avoid_: 笔记库（指整个 Summary 仓库）、文档目录

**大类**:
知识库下的一个 Markdown 文档，收纳同一主题的全部条目（如 `android-ui.md`）。文件名英文 kebab-case，文档标题用中文；引言 blockquote 标注维护者。
_Avoid_: 分类、知识文档、目录（与文件系统目录混淆）

**profile**:
知识落盘的形态契约。`knowledge-entry` 是通过复习者测试的条目型大类；`language-note` 是 `language/` 下示例驱动的学习散文。先选 profile，再套其边界、规则和校验。
_Avoid_: 统一模板、文章类型

**条目**:
大类文档内的一个 `## 节`，一条独立成立的知识；同名条目并入既有条目，绝不重复开节。
_Avoid_: 知识点、段落

**边界**:
每个大类文档顶部的"收什么 / 不收什么 / 与兄弟文档如何分工"声明；新建大类必须先立边界。
_Avoid_: 说明、前言

**路由**:
沉淀前确定知识去哪个大类的动作：先查根目录 `ROUTING.md`（主判据链 + 路由表）定候选，准入以目标大类头部「边界」为准；新立大类后必须回填路由表。
_Avoid_: 分流（旧称）、索引、归类

**沉淀**:
把当前会话中非显而易见、脱离本会话语境仍成立的结论写入知识库的行为；流水账与过程记录不属于沉淀。
_Avoid_: 总结（泛指）、归档

**复习者测试**:
对 `knowledge-entry` 的准入问题：六个月后遇到什么问题会翻到它，翻到后能否直接使用。说不出具体场景或动作的候选不收；该测试不适用于 `language-note`。
_Avoid_: 阅读量、学习记录

**证据等级**:
对论断来源的标记：`observed`（直接观察）、`verified`（独立交叉确认）、`inferred`（有依据的未验证推断）、`external`（已与本地事实核对的外部资料）。
_Avoid_: 可信度百分比

证据等级只存在于沉淀过程的临时候选表和最终汇报，不强制写入 timeless 条目正文；版本敏感或外部结论仍须在候选阶段给出来源与核对结果。

**维护者**:
对大类的责任与复核标记，不是分类轴，也不是新建近义大类的理由。路由按知识主题决定唯一落点；所有写入者共用同一结构契约和校验器。
_Avoid_: 文件所有者、唯一写手

**修订注记**:
对同一结论的补充或适用条件收窄所做的就地语义更新；正文保持 timeless，时间线由 git 提供。结论反转不用它，改用 supersedes。
_Avoid_: 日期戳、替代关系

**supersedes**:
条目间的替代标记：结论反转时新条目用 `**supersedes**：<旧条目链接>` 指向旧条目，旧条目正文不删，并在标题后或紧邻状态行标明“已被替代”。
_Avoid_: 作废、删除

写入前必须确认目标链接存在；旧条目保留是为了可追溯，不表示两套结论同时适用。校验器发现链接断裂或只写单向关系时应阻塞复核。

**知识**:
可迁移的结论：换一个项目仍然成立，且能通过复习者测试（六个月后遇到什么问题会翻到它、翻到后能直接用）。
_Avoid_: 经验（泛指）、结论

**工作记录**:
只对本次任务/项目有意义的操作结论（怎么收编、怎么分工、改了什么）；不属于沉淀，归宿是项目文档或交接。
_Avoid_: 知识、踩坑总结

**技能沉淀**:
可复用的工作流程固化为 `SKILL.md`（由 session-to-skill 负责），不进知识库。
_Avoid_: 与"沉淀"混用

**交接**:
给下一个 agent 续做用的上下文文档（由 handoff 负责），不进知识库。
_Avoid_: 与"沉淀"混用
