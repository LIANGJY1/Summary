## 构造期配置与运行期 API 存在断层

**一句话**：组件的 XML 属性通常只在构造期被消费，运行期调用对应 setter 往往只写字段、静默无效；正确姿势是"写值 → 触发重建"两段式，且重建自带必须处理的副作用契约。

**复习场景**：给某个三方/自研 UI 组件调属性，编译通过、运行无报错，但界面纹丝不动；或者切一次配置后列表选中态莫名回到第一项——都翻这条。

**现象与原因**（来源：UIComponent 1.3.2 AAR 反编译，`HCTabBar.java`（车机项目的自定义标签栏组件））：

```java
public void setItemMarginLevel1(int px) {
    this.itemHorizontalMarginLevel1 = px;   // setter 只写字段，到此为止
}
// 字段的消费点在私有重建方法里：每次重建才把字段应用到每个条目
private void updateAllitems() { /* removeAllViews → 逐项创建 → setSelectIndex(0) */ }
```

构造期"先读 XML 属性再构建条目"，字段消费发生在构建路径；条目建好之后再写字段，没有任何代码会重新消费它。而重建方法本身有副作用契约：清空容器、选中态重置为 0、并以新状态回调监听器——若监听器在重建前已挂载，回调会改写外部待恢复的状态（如"记住用户停在第二个标签页"）。

**怎么用**：
- 运行期修改 = 写值 + 触发重建入口，两步缺一不可；重建后先恢复状态、再挂监听（或适配先于挂监听执行）
- 适用条件：组件存在单一重建入口且 setter 无副作用；无重建入口的组件放弃运行期修改，改走布局变体
- 组件设计者视角：构建期消费的配置必须同时提供内建运行期 API（含静默恢复选项），否则业务方只能各自反射

## 定制系统资源兜底回落不可信，锚资源探针验证

**一句话**：定制系统（车机/TV 等）对限定资源目录的回落可能不符合标准行为，跨档位资源必须在每个宽度桶显式定义，并用同名"锚资源探针"验证实际命中的桶。

**复习场景**：改了基准资源的值，某个分屏/窗口档位下没生效；或新增了覆盖却不生效——别急着查代码，先用探针确认资源解析到底命中了哪个桶。

**现象与原因**（来源：车机项目实测断言，机制为团队既有约定；根源未独立复现）：

```xml
<!-- 每个宽度桶的 dimens.xml 各放一条同名探针，值 = 桶宽 -->
<!-- values-w1920dp/dimens.xml -->
<dimen name="split_screen_resource_anchor">1920dp</dimen>
```

```java
// 运行时读取探针，即可断言当前窗口实际命中的资源桶
int bucket = getResources().getDimensionPixelSize(R.dimen.split_screen_resource_anchor);
```

标准 Android 行为是"限定桶未命中则回落 values/"，但定制系统可能不回落或窗口宽度与假设不符，导致"覆盖写了却命中基准"。

**怎么用**：
- 跨档位资源逐桶显式定义，不依赖 values/ 兜底——兜底失效时无害
- "改了不生效"类问题先用探针定位实际命中的桶再决定改哪个文件；探针值与预期不符说明设备窗口宽度和假设不一致，需要重新映射桶

## ViewBinding 跨变体联合字段缺失为 null

**一句话**：同一布局的多个宽度桶副本按 id 并集生成 ViewBinding 字段；仅存在于部分副本的控件，在其他副本下该字段为 null，解引用即 NPE。

**复习场景**：布局有多份宽度桶副本、某控件只在部分副本存在，切到某个档位就 NPE 或控件"消失"——先查该字段是否跨变体缺失。

**现象与原因**（来源：车机项目收编审计，生成的 `ActivityAppDetailBinding.java`）：

```java
// 基准副本有 barrierHeaderBottom（底部对齐 Barrier），窄分屏副本没有该节点
// 生成字段按 id 并集生成，窄分屏 inflate 后此字段为 null：
public final Barrier barrierHeaderBottom;
binding.barrierHeaderBottom.setVisibility(...); // 窄分屏下 NPE
```

同 id 在不同副本用了不同控件类时更糟：字段类型被降级为 View，运行时按具体类型使用会 ClassCastException。

**怎么用**：
- 收编/合并布局副本的审计必须包含"仅单变体存在的节点 × 代码引用"检查——代码未引用的缺失节点无害
- 收编后核对生成的 Binding 字段类型未降级；同 id 控件类冲突要在收编第一步统一
- 适用条件：布局存在多宽度/朝向副本且节点集合不一致；单副本布局无此问题
