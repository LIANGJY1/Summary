# 0006: project-decoder 证据锚点与定向管道强化

日期：2026-09-06｜状态：accepted｜来源：retrofit 全库分析复盘（grill-with-docs 六问全决）

## 背景

retrofit 架构解码实践中暴露六处摩擦：file:line 锚点在协作工作区随注释改造全部漂移（20 处重校）；git 历史全为 "add" 使动机考据管道空转而脚本无提示；枢纽引用计数无工具（手搓 grep 循环）；同构桥接类的"家族行"覆盖形态是临场发明、无规则约束；同一库双文档（source-annotator 沉淀 vs 架构解码）分工边界靠临场判断；定向阶段没有"先查先验"步骤。

## 决策

1. **锚点改 `类名#方法名`，禁用行号**（用户裁决：连次锚行号也不要）。理由：行号随任何代码演进腐化，方法锚 grep 可验证、IDE 可跳转；行号只在"精确到行才有意义"的场景口头说明，不入文档。
2. **repo_stats.sh 三项增强**：git 历史有效性探测（commit<10 或去重率<30% → 提示考据改走代码结构+测试名）；主/测试代码行数比（>60% 提示考据优先读测试名）；枢纽引用计数 Top15（python 单遍扫描主源码类定义与全文件引用，注：子串计数启发式，精确值需 grep -w 复核）。
3. **家族行入 class-card.md**：真正同构的类族允许一行覆盖（行内列全成员、文尾覆盖算式、核心类/状态机类不适用）。
4. **双文档分工入 SKILL.md**：仓库已有 `<Lib>.md` 沉淀时，架构文档链接其为机制详解，自身只做地图/表格/链路/矛盾。
5. **Orient 增设第 0 步先验盘点**：扫 `<Lib>.md` 沉淀、知识库条目、既有架构文档，产出已懂/待验证/空白清单。

## 被否方案

- 行号留作次锚（Q1 推荐 a 的原始形态）：用户升级为全禁——"其他按推荐"之外明确"不要行号了"，理由是校准成本在协作仓库必然反复发生。
- 独立 hub_stats.sh：并入 repo_stats.sh，一次跑完定向所需全部数字。
- 只记 ADR 不改 skill：改动力求即时生效，ADR 只记 why。

## 局限

枢纽计数的子串匹配会把 "Service"（49）这类高频词抬进榜单，作 Top-N 候选生成器用，精确引用数需复核；历史有效性探测的两个阈值（10 commits / 30%）是经验值，可随更多库的实践调整。

retrofit 三份架构文档的锚点已迁移为 Class#method（ARCHITECTURE.md 9+13 处、core.md 4+2 处，终验零残留行号锚）。
