## 第4章 类与对象

**Q1: 单例怎么选型？DCL 与 object + init 的语义差异是什么？**

Kotlin 里两条单例路线：

```kotlin
// 路线一：手写双重检查锁（DCL），Java 惯用法直译
class PetActionController private constructor(context: Context) {   // 展车版萌宠控制器
    companion object {
        @Volatile private var instance: PetActionController? = null
        @JvmStatic fun getInstance(context: Context): PetActionController =
            instance ?: synchronized(this) {
                instance ?: PetActionController(context.applicationContext).also { instance = it }
            }
    }
}

// 路线二：语言级单例 + init 注入
object PetCore {                          // 萌宠服务单例编排入口
    private lateinit var stateMachine: PetStateMachine
    fun init(context: Context) {
        if (this::stateMachine.isInitialized) return // 防重复 init
        // ...装配依赖
    }
}
```

- `object` 是单例语法糖：编译器生成静态 `INSTANCE`，线程安全由 JVM 类初始化保证；**不能有构造参数**，context 只能经 `init(context)` 注入，成员用 `lateinit` + `this::x.isInitialized` 防重复初始化。
- DCL 的两层 `?:` 判空 + `synchronized` 是双重检查：外层让已初始化后的调用不进锁，内层防并发重复创建；`@Volatile` 保可见性、禁重排序。
- **实质语义差异**：DCL 版实例与 context 绑死，**不存在"未初始化就被使用"的状态**（没调过 `getInstance` 就没有实例）；object 版对象第一次被访问就存在，未 init 就调其他方法抛 `UninitializedPropertyAccessException`——时序契约靠纪律维持，编译器只保证崩得早、崩得明显。
- **选型标准**：初始化点固定且唯一（如 Application 启动调用一次）→ `object` 更简洁且错误暴露早；希望实例不存在未初始化状态、或初始化时机分散（各处随手 `getInstance(ctx)` 兜底）→ DCL。初始化点固定时，构造参数往往是伪需求。

**Q2: `const val` 只能声明在哪些位置？为什么？**

`const` 是编译期常量，不能归属实例，只能声明在：**文件顶层、`object` 体内、`companion object` 体内**。普通类体直接写编译不过——所以 `class PetArbiter` 这类普通类里的 TAG 必须包进 companion；而 `object PetCore` 本身就是"单例 + 静态之家"，TAG 直接写 object 体即可，再嵌 companion 纯属冗余。两种位置编译产物相同：外层类的 `private static final` 字段，且所有使用处在编译期内联字面量，运行时连字段访问都没有。

## 第5章 代数数据类型与模式匹配

**Q3: sealed class 的封闭性与穷尽性指什么？子类有哪些形态？**

`sealed` 语义：所有子类必须与父类同包、同编译模块（**Kotlin 1.5 起放宽为同模块**，1.0/1.1 时代才要求同文件）。换来的核心能力：外部无法继承、`when` 作表达式时编译器**穷尽性检查**——漏子类直接编译报错；新增子类时所有消费它的 `when` 同时报错提醒补分支。消息协议（事件进、指令出）的可靠性就是这么交给编译器的。

子类两种形态（以车机萌宠事件协议为例）：

```kotlin
sealed class PetEvent {
    data class Init(val enabled: Boolean) : PetEvent() // 带载荷：data class
    data class TimerFired(val id: String) : PetEvent()
    object Clicked : PetEvent()                        // 无载荷：全进程单例变体
}
```

- 带载荷 → `data class`：构造参数即 `val` 属性，自动生成 `equals/hashCode/toString/copy/componentN`，对照 Java 16+ `record`。
- 无载荷 → `object`：该变体全进程一个实例，`==` 即引用相等；`: PetEvent()` 的括号是在调密封父类构造器（sealed 构造器默认 private、仅同包/同模块子类可调——"封闭"的实现机制）。
- 对照：enum 常量单例、结构固定，表达不了"同族但载荷各异"；Java 17 `sealed` 要求 `permits` 显式列全子类，Kotlin 同模块即封闭更省。
