## 第 11 章 Android 生态

**Q1: 使用 Kotlin 编写 Android 代码时，Android KTX 除了缩短调用形式，还可能提供哪些生命周期或默认行为？**

Android KTX（Kotlin Extensions）是 Android Jetpack 和其他 Android 库面向 Kotlin 提供的一组 API。它利用扩展函数、扩展属性、命名参数、默认参数和协程等 Kotlin 能力，让 Android API 更符合 Kotlin 的使用习惯。

```kotlin
// 原始 SharedPreferences API
val editor = preferences.edit()
editor.putInt(KEY_COUNT, 1)
editor.apply()

// core-ktx
preferences.edit {
    putInt(KEY_COUNT, 1)
}
```

KTX 不应一概称为“纯语法糖”。不同 API 提供的价值不同：

- `String.toUri()`、`bundleOf()`：封装常见的对象创建和参数处理。
- `SharedPreferences.edit { ... }`：管理 `Editor` 的获取与提交，并提供带接收者的 lambda 作用域。
- `lifecycleScope`、`viewModelScope`：提供与生命周期绑定的协程作用域，包含实际的取消语义。

```kotlin
viewLifecycleOwner.lifecycleScope.launch {
    viewModel.uiState.collect { state ->
        render(state)
    }
}
```

因此，理解一个 KTX API 时，不要只看调用是否更短，还要查看它是否管理了生命周期、线程、资源释放或默认行为。

KTX 不会修改原有 Java 类。扩展函数在 JVM 上通常表现为静态方法，Java 理论上可以调用其中一部分，但调用形式通常不如 Kotlin 自然。Java 代码仍可继续使用原始 Android API。

`SharedPreferences.edit { ... }` 涉及的尾随 lambda 与带接收者函数类型见 01 笔记 Q3～Q4；扩展函数的静态解析规则见 02 笔记 Q7。
