## 第8章 函数式编程

**Q1: `inline` 是什么？为什么高阶函数常用它修饰？**

```kotlin
inline fun <T> Iterable<T>.forEach(action: (T) -> Unit) { /* 标准库即此实现 */ }

list.forEach { println(it) }
// 编译后 ≈ for (x in list) println(x) —— 函数调用与 lambda 对象都消失了
```

`inline` 的承诺：**编译期把函数体和 lambda 实参整体拷贝进调用处**——运行时既不存在这个函数调用，也不存在 lambda 对象。三个收益：① **零开销**：lambda 不再编译成 `Function` 对象，无分配无间接调用；② **非局部返回**：lambda 里可以 `return` 直接退出外层函数（`forEach { return }` 能编译正因 `forEach` 是 inline）；③ **支持 reified 泛型**（运行时保留泛型实参，如 `list.filterIsInstance<String>()` 能拿到真实类型参数）。代价：字节码在每个调用点复制一份而膨胀，public inline 函数只能访问 public API。适用判断：**接收 lambda 且高频**的小工具函数（`forEach`、01 笔记 Q1 的 KTX `edit`）才值得 inline，不是越多越好。

收益②是高频坑：**lambda 里的裸 `return` 退出的不是 lambda，是外层函数**：

```kotlin
fun dispatch(commands: List<PetCommand>) {
    commands.forEach { command ->
        if (command is StopAction) return@forEach   // ✓ 想跳过本条：标签返回（语义＝continue）
        // if (command is StopAction) return        // ❌ 裸 return：整个 dispatch 提前结束
    }
}
```

`forEach` 没有 break——中途终止整个遍历老实用 `for`，或先 `takeWhile` 收窄。非 inline 高阶函数的 lambda 里裸 `return` 直接编译报错（只许 `return@label`），反而不会踩；坑恰恰集中在 `forEach`/`let`/`apply` 这类 inline 函数上。
