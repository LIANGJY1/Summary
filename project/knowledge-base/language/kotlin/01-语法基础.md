## 第2章 函数与集合

**Q1: 什么是尾随 lambda（trailing lambda）？为什么 `sp.edit { putInt(...) }` 能这样写？**

**规则**：函数的最后一个参数是函数类型时，实参 lambda 可移出圆括号，括号为空则连括号省略。纯语法糖，实不变：

```kotlin
sources.startSwitch(initial, { on -> onEvent(PetEvent.SwitchChanged(on)) })
sources.startSwitch(initial) { on -> onEvent(PetEvent.SwitchChanged(on)) } // 尾随形式
```

Android KTX 的 `sp.edit { putInt(KEY_SWITCH, global) }` 一行叠了四个语法点（来源：androidx.core.content）：

```kotlin
inline fun SharedPreferences.edit(               // ① 扩展函数：外挂在 SharedPreferences 上
    commit: Boolean = false,                     // ④ 默认参数：不传即 apply()
    action: SharedPreferences.Editor.() -> Unit  // ② 带接收者的 lambda
) {
    val editor = edit()
    action(editor)
    if (commit) editor.commit() else editor.apply()
}
sp.edit { putInt(KEY_SWITCH, global) }           // ③ 尾随 lambda
```

② 参数类型 `Editor.() -> Unit` 规定 lambda 体内 `this` 是 `Editor`，花括号里的 `putInt(...)` 实为 `editor.putInt(...)`；④ 要同步落盘写 `sp.edit(commit = true) { ... }`。Java 等价物是长链 `sp.edit().putInt(KEY, v).apply()`；一次写多个键时花括号作用域风格优势最明显。**辨别口诀**：读到 `xxx { }` 先找函数签名——花括号是某个函数类型形参的实参，是不是带接收者看参数类型里有没有 `.()`。

**Q2: Java 怎么调用 Kotlin 的函数类型参数？（Function1 与 fun interface）**

Kotlin 参数 `onEdge: (Boolean) -> Unit` 编译后是标准库接口 `kotlin.jvm.functions.Function1<P, R>`（按参数个数有 Function0~N），不是 Java 的 SAM。Java 调用方写 lambda 的两个别扭点：

```java
sources.startSwitch(initialSwitch, on -> {
    onEvent(PetEvent.SwitchChanged(on));
    return Unit.INSTANCE;   // Unit 返回值必须显式给，不能像 void 省略
});
```

一是回调类型是 `Function1` 而非业务接口；二是返回 `Unit` 的函数不能像 `void` 那样省略 return。Java 原生惯例是先声明回调接口再作参数类型，调用处 lambda 几乎一样，但多出一个只为回调形状存在的接口文件——Kotlin 函数类型省掉的正是这批接口。**折中**：`fun interface`（Kotlin 1.4+）声明函数式接口，Kotlin 内部按普通接口调用，Java 侧得到标准 SAM 可写 lambda。选型：纯 Kotlin 模块用函数类型（最简），公开 API 面向 Java 调用方多时用 `fun interface`（互操作友好）。

## 第3章 类型系统

**Q3: 安全调用 + Elvis 如何一次收口多重 null 来源？**

```kotlin
val initial = stores?.resolveSwitch() ?: true
// stores: PetStores?（var 成员），resolveSwitch(): Boolean?
```

`stores?.resolveSwitch()` 有**两条 null 路径**：`stores` 为 null 时整体短路成 null；`resolveSwitch()` 本身返回 null（首次上电无记录）。一个 `?:` 把全部 null 来源收口成 `true`。类型视角：`Boolean?` 经 Elvis 消除 null 得 `Boolean`，后续无需再判空。Java 等价物是"先声明可变变量 + if 判空逐条赋值"。Elvis 右侧除默认值外常接控制流：`val s = x ?: return`、`val s = x ?: error("未初始化")`。

注意：`stores` 在 `init()` 里刚赋过值仍要 `?.`——见 Q4，var 成员不能跨语句智能推断。

**Q4: smart cast 的边界在哪里？为什么 var 成员不豁免，单例也一样？**

智能转换（判空后自动收窄类型）要求编译器确信**检查后变量不再改变**。`object` 单例的 `var` 成员同样不豁免：`init()` 里刚给 `var stores: PetStores?` 赋值，紧接着一句 `stores?.resolveSwitch()` 仍必须安全调用——编译器无法跨语句断言这个 var 不被改（同文件其他方法、其他线程都可能动它）。此时 `?.` 是防御式写法而非冗余；把字段改成 `val`、或收窄成局部 `val` 再使用，智能转换与 Elvis 兜底即可恢复。
