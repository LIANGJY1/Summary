# Interview Practice

本文件只做三件事：抽题、书面作答、记录复习结果。通用知识引用父目录，不在这里重复抄写。

## 使用规则

- 第一次作答闭卷，不查资料。
- 每题限时 3 分钟：先写结论，再写机制、源码或证据，最后写边界。
- 连续两次低于 2 分，加入错题表。

## 答卷判分与纠正

答完后按题号提交原答案，不要先自行修改。每次批改只处理一组题，建议 5～10 题。

### 判分标准

| 分数 | 标准 | 处理 |
|---:|---|---|
| 0 | 不会、答非所问或核心结论错误 | 直接学习标准答案，次日重答 |
| 1 | 知道名词，但机制不完整或存在关键错误 | 标出错误，补机制和边界 |
| 2 | 主链基本正确，但缺源码、证据或追问 | 补 1 个源码锚点和 1 个实践证据 |
| 3 | 结论准确，机制完整，有源码/证据，能处理追问 | 进入 7 天、28 天复习 |

### 批改输出

每题必须返回以下 6 项：

```text
题号 / 得分：__/3
判定：通过 / 部分通过 / 不通过
问题：错误或缺失的具体内容
面试级正确答案：30 秒结论 + 3 分钟展开
源码与证据：文件、类、函数、版本；没有证据时明确写验证方法
下一步：重答日期和需要补的内容
```

“面试级正确答案”必须满足：

1. 先给直接结论，不绕背景。
2. 再按调用链或因果链解释机制。
3. 绑定 Android 13 源码锚点；版本差异单独标注。
4. 给出真实项目、`AAOS13_study`、独立代码或日志/trace 中的一项证据。
5. 最后说明适用边界、风险和一个高概率追问。

没有可靠依据的内容必须标记为“待验证”，不能补写成事实或量产经验。

### 纠正闭环

1. **当天**：看批改，整理错误原因：概念、源码、实践、表达四类之一。
2. **次日**：不看答案重写；仍低于 2 分，再看标准答案并补证据。
3. **第 7 天**：限时 3 分钟重答，目标至少 2 分。
4. **第 28 天**：结合源码和项目证据再次作答，连续两次 3 分才算掌握。

批改结果记入“单题复盘”和“模拟成绩”，不要只记录总分。
