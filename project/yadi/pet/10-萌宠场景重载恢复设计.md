# 萌宠场景重载恢复设计

## 背景

切换萌宠形象会触发 Kanzi 宠物预制体重载。2026-10-21 真机日志显示，团团切到哈士奇后没有新的全局 `KanziReady`，状态机仍保持 `MUSIC`，却只下发 `VPA_Style`；切回团团后出现听歌动作。已确认哈士奇在音乐重新起播时能进入听歌动作，说明形象切换后的哈士奇需要新的动作开始沿。

## 目标

全局 Kanzi 场景重载和实时形象切换后，恢复应呈现的萌宠状态：形象、当前有效节日皮肤、显隐意图和正在播放的动作。恢复动作时保持现有状态，不重新运行竞合裁决。

## 设计

- 首次 `KanziReady` 保留冷启动补发语义，包括挂起皮肤、显隐和出场/动作决策。
- 后续 `KanziReady` 表示场景重载：按形象、节日皮肤、显隐、动作的顺序重建场景。
- 实时形象切换不保证产生全局 `KanziReady`。切换形象后等待动态预制体创建，再按当时的 `festivalSkin` 与 `currentAction` 恢复；持续动作先写结束码，间隔 50 ms 再写开始码，确保动作属性发生变化。等待时间暂定 500 ms，依据日志中哈士奇节点在形象写入后约 79 ms 出现；设备侧仍需验证这个上界。
- 若形象切换期间收到全局 `KanziReady`，取消等待，在该就绪沿恢复皮肤与显隐，并触发持续动作的结束→开始沿；不再次写形象，避免二次替换预制体。
- 节日皮肤以 `festivalSkin`（当前期望值）为恢复依据，不能只看首次下发后会清空的 `pendingSkin`。重载恢复不重置原到期时间，也不重复报告推荐结果或播放节日音效。
- 恢复始终读取当时的当前动作，不调用 `decideNextAction()`，避免竞合优先级变化导致动作被替换。短时动作重发时重挂已有看门狗；音乐若在等待期间停止，不重启听歌动作。
- 若当前不应呈现（开关关闭或页面后台），不显示或恢复动作；场景默认隐藏态由 Kanzi 加载提供。
- 命令结果回调区分新节日事件应用与场景恢复，恢复结果不向外重复回报。

## 验收条件

1. 团团听歌时切换哈士奇，即使没有后续 `KanziReady`，哈士奇也会收到 `91→90` 的新动作沿；反向切换同样适用。
2. `VOICE`、`CHARGING`、`LOW_BATTERY` 和 `RESIDENT` 场景重载后分别恢复原动作。
3. 已成功应用且 `pendingSkin == null` 的节日皮肤仍会重发；恢复不重置时限、不重复节日音效或结果回报。
4. 恢复命令顺序固定为形象/皮肤、显隐、动作；不改变首次就绪与冷启动出场语义。

## 范围

修改萌宠状态机、皮肤命令结果语义、场景用例和 SRS_013 记录。竞合矩阵、媒体监听、皮肤时限策略及 Kanzi 协议码值保持原规则。
