## 天气 SDK 接入与映射

- 天气来源是天气 App 提供的 `WeatherApi.aar`。Launcher 萌宠侧作为客户端，通过 `WeatherApiClient.connect(listener)` 接收 `WeatherInfoBean.weatherCode`；SDK 内部完成天气服务的 `bindService()`。天气数据**不经过智能推荐，也不经过 LauncherLib / LauncherService**。
- SDK 连接时会回放当前缓存天气，首次网络返回及后续更新还会推送；Launcher 按 D004 的进程周期只对首个有效雨/雪天气触发一次动作。无数据或非雨雪时继续等待后续有效数据，不消耗单次机会；触发后忽略本周期后续天气更新。页面不在前台时按既有萌宠事件泵的待落位规则处理。
- `weatherCode` 是天气方的原始整数码，由 Launcher 的天气适配层映射为 `WeatherPushed(雨天/雪天)`，再交给 `PetCore` 仲裁。原始码不进入 pet 对外事件码表。

| 萌宠动作 | 天气现象码（整数，PDF 中的 `03` 在 SDK 中为 `3`） | 依据 |
|---|---|---|
| 雨天 | `3, 4, 5, 6, 7–12, 19, 21–25, 301` | 阵雨、雷阵雨、雨夹雪、各级降雨、冻雨与“雨” |
| 雪天 | `13–17, 26–28, 302` | 各级降雪与“雪” |
| 不触发 | 其他码及 `99`（无/未知） | SRS_011 QA3：其他天气不触发 |

码值来自天气方 `~/Documents/files/yadea/sdk/天气/06-维天信天气现象(1)(1).pdf`；接入时机来自同目录 `README.md`。分组按 SRS_011 的“雨/雨夹雪→雨天，雪→雪天”转换，真机联调时以天气方实际推送为准。使用结束调用 `WeatherApiClient.disconnect()`；断线后的重新连接由 Launcher 天气适配层管理。

## 问答

1. **数据流向**

   QA: 天气 App 通过 `WeatherApiClient` 提供缓存回放与后续更新；Launcher 负责将多次数据更新收敛为每进程周期至多一次萌宠动作。接口链路已明确，Launcher 接入待实施（TD-10）

2. **枚举映射**

   QA: 天气方已提供天气现象码表；Launcher 天气适配层按上表映射为雨/雪动作，真机联调时核对实际码值（DEP-9）

3. **其他天气**

   QA: 不触发，正常常驻待机

4. **上电多事件顺序**

   QA: 不设全局顺序表，按两两关系推算（TD-7 关闭，F37）
