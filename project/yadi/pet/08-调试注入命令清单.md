# 08 调试注入命令清单（adb）

> 唯一职责：调试期用 adb 命令复现萌宠场景表全部 case 的命令清单。
> 代码落点：仓库 `application/Launcher/.../pet/debug/`（PetDebugInjector）；总开关 `PetConfig.DEBUG_INJECTION_ENABLED`（交付前必须改回 false）。
> 结果观察：`adb logcat -s Launcher_PetDebugInject Launcher_PetStateMachine Launcher_PetSources`

## 通道原理

通道＝**Settings.Global 调试键 + ContentObserver**（复用萌宠开关 `ai_pet_switch` 的观察者模式）：
adb `settings put` 写入调试键 → 观察器读取并翻译为 PetEvent → PetCore 事件泵进状态机。
注入事件与真实信号源同构，**不绕过任何门控**——开关/前台/前置/竞合照常生效，因此场景表的每条 case 都能复现。

- **不新增任何组件**（无 Activity/Service/Receiver，manifest 零改动）；
- **不使用 adb 广播 / am start**——广播会卡死在系统 background ordered 队列不派发（真机实锤），
  `settings put` 走 SettingsProvider 事务，必达；
- 命令消费后通道自动把键清空，**同一条命令可原样重复发送**；
- 通道关着时 `settings put` 无任何效果。

## 总式样

```bash
adb shell settings put global pet_debug_event "<type> [value]"
```

引号内 `type` 与 `value` 以空格分隔；数值类命令带第二个词。

## 典型组合链路（场景表 case ↔ 命令序列）

```bash
pet() { adb shell settings put global pet_debug_event "$*"; }

# 音乐中点击打断→暂停恢复:音乐起播→点击→点击完成拍→观察恢复舞动
pet music_on; sleep 1; pet clicked; sleep 3; pet play_done

# 充电独占→拔枪不恢复(定版):音乐→插枪→拔枪→观察回常驻
pet music_on; sleep 1; pet plug; sleep 2; pet unplug

# 语音打断舞动→会话结束恢复(暂停语义):音乐→语音唤醒→会话结束
pet music_on; sleep 1; pet voice_on; sleep 2; pet voice_off

# 低电量→充电收舞→拔枪恢复:低电量→插枪→拔枪
pet battery_low; sleep 1; pet plug; sleep 2; pet unplug

# 延迟链:点击进行中音乐起播→点击完成补播舞动
pet clicked; sleep 1; pet music_on; sleep 3

# 长期未登录判定沿(SRS_007):任意状态下注入,观察判定/排队/竞合
pet long_idle

# 发送失败→重试穷尽→隐藏兜底:点击后连续三次注入看门狗
pet clicked; pet timer_watchdog; pet timer_watchdog; pet timer_watchdog
```

## 备注

- `pet` 别名建议加进 `~/.bashrc`（见上）；`pet festival 3` 经 `"$*"` 拼接为 `festival 3`。
- 若同值重复写入未触发观察器（个别系统版本行为差异），在命令后附加任意序号即可：
  `pet clicked 1`、`pet clicked 2`（附加词被解析器忽略，不影响注入类型）。
