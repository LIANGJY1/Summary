## 1. 使用前提

- Launcher 已安装包含 `PetDebugInjector` 的调试包。
- `PetConfig.DEBUG_INJECTION_ENABLED=true`；交付前必须改回 `false`。
- 当前临时配置仍为 `SWITCH_FORCE_ON=true`、`BATTERY_FORCE_HIGH=true`。它们只屏蔽真实来源，不屏蔽本清单的 Settings 直注事件。
- `PetIpcTest` 位于 `/home/liang/Project/Reachauto/YaDi/PetIpcTest`，用于按正式跨进程接口发送生日和节日事件。
- 每个 case 默认从独立、干净的 Launcher 进程开始。不要连续执行两行而省略 `fresh_on`，否则进程周期内的出场、天气和抑制标记会串 case。

观察日志：

```bash
adb logcat -c
adb logcat -v time -s Launcher_PetDebugInject Launcher_PetStateMachine Launcher_PetSources PetIpcTest
```

状态机主日志顺序为 `onEvent` → `arbitrate` → `commands`。拒绝类 case 重点观察 `request rejected`，并确认没有禁发动作。

## 2. 一次性命令别名

```bash
# Settings.Global 直注；短暂停顿避免前一条尚未消费清空时被下一条覆盖。
pet() {
  # 把引号字符传给设备端 shell；否则双词 payload 会只写入第一个词。
  adb shell settings put global pet_debug_event "\"$*\""
  sleep 0.3
}

# 正式 IPC 测试端：0=取消节日，1~5=节日，14=生日。
ipc() {
  adb shell am broadcast \
    -n com.yadea.petipctest/.AdbReceiver \
    -a com.yadea.petipctest.SEND \
    --ei event "$1" >/dev/null
  sleep 0.3
}

# 重新建立进程周期；清空残留调试键，再启动 HOME Launcher。
fresh_on() {
  adb shell settings delete global pet_debug_event
  adb shell am force-stop com.yadea.launcher
  adb shell am start -W \
    -a 01-android.intent.action.MAIN \
    -c 01-android.intent.category.HOME >/dev/null
  sleep 3
}

# 给真实目标音乐会话发播放/暂停键，仅用于兜底查询场景。
media_play()  { adb shell cmd media_session dispatch play;  sleep 1; }
media_pause() { adb shell cmd media_session dispatch pause; sleep 1; }
```

`fresh_on` 启动后若车辆环境自动上报了真实 `IviReady`、枪状态或音源状态，先看日志确认；自动沿会改变步骤顺序。需要完全确定性的逐步验证时，以同名 JVM 场景测试为准。

## 3. 注入类型总表

Settings 通道总式样：

```bash
adb shell settings put global pet_debug_event '"<type> [value]"'
```

外层单引号必须保留，它把内层双引号字符送到设备端 shell。若直接写成 `... "festival 3"`，主机 shell 会先吃掉引号，部分 `adb shell` 版本最终只把 `festival` 写入 Settings。

| 类别 | type | 翻译事件 / 说明 |
| :--- | :--- | :--- |
| 开关 | `switch_on` / `switch_off` | `SwitchChanged(true/false)` |
| 车机 | `ivi_ready` | `IviReady` |
| 前后台 | `render_on` / `render_off` | `Render(true/false)` |
| 点击 | `clicked` | `Clicked` |
| 音乐 | `music_on` / `music_off` | `AudioPlay(true/false)` |
| 语音 | `voice_on` / `voice_off` | `VoiceWake(true/false)` |
| 长期未登录 | `long_idle` | `LongIdleSignal` |
| 低电量 | `battery_low` / `battery_ok` | `BatteryLow(true/false)` |
| 充电 | `plug` / `unplug` | `PlugChanged(true/false)` |
| 生日备用直注 | `birthday` | `BirthdaySignal`；正式 IPC 主路径用 `ipc 14` |
| 节日备用直注 | `festival 0~5` | `FestivalSignal`；正式 IPC 主路径用 `ipc 0~5` |
| 天气 | `weather_none` / `weather_rain` / `weather_snow` | 无有效天气 / 雨 / 雪；`weather_none` 为本次补充 |
| Kanzi 回调 | `play_start` / `play_done` | 动作开始 / 完成回调 |
| 定时器 | `timer_idle` / `timer_watchdog` | 常驻间隔 / 动作看门狗到点 |
| 发送失败 | `send_failed <actionCode>` | `SendFailed(PlayAction(action))`；本次补充，未知码拒绝 |

`send_failed` 使用 Kanzi 动作协议码：`0` 常驻、`1` 出场、`2~4` 随机、`5~6` 点击、`11` 长期未登录、`12` 雨、`13` 雪、`14` 生日、`70` 低电量、`80` 充电、`90` 音乐、`100` 语音。

## 5. 特殊限制与精确验证

### 5.1 无法仅靠事件直注构造的 4 类条件

1. `Init(false)`：当前包的 `SWITCH_FORCE_ON=true` 会把真实初始开关强制为开。表中 case 2 已给出设备近似链；精确语义由 JVM case 锁定。
2. `fallbackMusicPlaying=true`：它是 `AudioSourceMonitor` 的实时平台查询结果，不是 `PetEvent`。case 33~34 必须让网易云或蓝牙目标会话真实保持播放；只发 `pet music_on` 不等于平台真值为真。
3. `rules` 覆盖：case 76 为测试内临时裁决表，故意与正式矩阵不同。禁止为设备调试开放“在线改矩阵”后门。
4. `FestivalApplied`：注入器不提供直注。真机由 Launcher 实际写皮肤后自动回泵（case 88 的回报与音效即来自回泵沿）；节日触发走 `ipc 0~5` 即可。

### 5.2 发送失败注入防误用

`send_failed` 只接受 `PetAction.code`，并仅构造 `SendFailed(PlayAction(...))`。未知码会记录 `inject ignored`，不会猜测命令。发送失败链必须填写当时正在下发的动作码，例如出场用 `1`、生日用 `14`。

### 5.3 同值重复写入

注入器消费后会主动清空 Settings 键，通常可原样重复。如果某系统版本仍丢观察沿，可附加第三个序号词；解析器只读取前两个词：

```bash
adb shell settings put global pet_debug_event '"clicked 0 1"'
adb shell settings put global pet_debug_event '"clicked 0 2"'
```

### 5.4 未实装机制（无设备链）

TD-5 音乐停播防抖＝0 未启用（case 28 即按停播立即收舞验证）；TD-8 生日撞节日音效规则待增。两者不在 100 行场景内，参数登记见 [04-代码方案](./04-代码方案.md)。
