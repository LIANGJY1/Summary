## 1. 概述

萌宠是车机主界面上的实时渲染虚拟宠物角色，由 **Kanzi 渲染绘制**，与 3D 车模**共处同一 3D 场景**（共享渲染画布，Launcher MainActivity 的 kanzi_surface），位于车模旁固定位置；**Launcher 侧萌宠服务**负责信号采集、动作仲裁与指令下发，是语音助手（VPA）的视觉反馈层。主界面为萌宠核心展示区域。

职责边界：**服务不关心萌宠显隐的渲染细节、不关心画面**；显隐仅由开关与发送失败兜底两处控制（G1/G7）。

## 3. 决策记录

### D001 — 需求全新起步，不以现有代码为依据（2026-08-27，已接受）
现有萌宠代码为 demo 废弃代码。讨论与设计一律不参考、不受限于现有实现（含协议号、类结构）；
例外见 2.1。替代方案“旧码渐进重构”否决：旧实现零散、产品范围将明显超出旧 demo。

### D002 — 动作中断恢复统一采用 setRenderStop / setRenderStart 记忆-恢复机制（2026-08-27，已接受）
所有动作在前台丢失或非 P 档时的中断与恢复统一由 setRenderStop / setRenderStart 驱动：
stop 记住当前动作；start 恢复该动作并重新计时。萌宠服务不感知显隐、不关心画面。
**补充（SRS_005-C1）**：状态型动作在 start 恢复时不机械还原记忆动作，须先按实时驱动状态校验后重建；
无状态动作仍按记忆直接恢复。替代方案“逐动作自定义中断行为”否决。

### 审查裁决补充（2026-08-27）
- 「允许打断」列仅作参考，冲突处理以单元格规则为唯一依据；
- 节日音效每次上电至多一次（皮肤应用时播放，重复信号去重）；
- 竞合矩阵整体完善课题（TD-17）挂起：状态重算点（拟议 D003 暂不立）、一次性彩蛋被拒、开关重开初始态等，修订前按现表执行。

## 4. 术语表

### 角色
**萌宠**：车机屏幕上由实时渲染呈现的虚拟宠物角色，具备自主动作与交互反馈。_避免_：宠物精灵、AI 狗。
**车模**：车辆的 3D 数字模型画面，Kanzi 渲染，主页既有视觉主体。_避免_：3D车、汽车模型。
**VPA**：车机语音助手（语音交互系统）；萌宠是其视觉反馈层。

### 画面与系统
**共享渲染画布**（kanzi_surface）：主界面唯一由 Kanzi 驱动的渲染区域。_避免_：双 surface、叠屏。
**Kanzi 侧**：负责萌宠与车模全部画面绘制的渲染一方。**Launcher 侧**：画面集成、数据与控制信号提供方。

### 服务与设置
**萌宠服务**：围绕萌宠形象提供的整体能力总称，启停跟随萌宠形象开关。
**萌宠形象开关**：决定萌宠显隐的单一设置项。_避免_：「萌宠开关」。
**萌宠形象**：设置页内可选择的具体宠物外观角色；只决定呈现内容，不参与启停判定。
**车控车设**：PPX 阶段设置数据来源，即本项目 Setting 应用（“AI 萌宠”页）。
**萌宠 App**：PPX 之后承接萌宠设置的独立应用（尚未存在）。
**PPX 阶段**：设置数据仍由车控车设提供、萌宠 App 未上线的时期（准确定义待补）。

### 动作与联动
**出场动作**：上电开机后的一次性迎接动画，播完转常驻待机。_避免_：开场动作、出场动画、开机动画。
**常驻待机（随机动作）**：默认持续状态——空闲 5~10 秒随机播放小动作，循环往复。_避免_：常驻态。
**随机动作**：循环中随机抽取的短微动作（无音效），出自 3 动作池（洗牌不重复）。
**常驻动作**：两次随机动作之间的基础待机动作，持续 5~10s（默认值 TBD-4）。
**驻车桌面**：Launcher 在 P 档驻车状态下的桌面形态（是否独立形态待澄清，占位）。
**萌宠音效**：服务自行播放的声音资源（占音频焦点），非 Kanzi 渲染内容。
**动作开始回调 / 动作终止信号**：Kanzi→服务的“已开始”事件 / 服务→Kanzi 的“立即停止”指令。
**音乐联动动作**：音乐播放期间持续执行的听歌/舞动循环（连续型、无音效；仅蓝牙音乐＋网易云）。_避免_：多媒体联动动作、舞动动作。
**语音交互动作**：语音会话期间的持续反馈动作（无音效），循环由 Kanzi 处理。
**长期未登录（动作）**：48h 未上电后再次上电的不高兴表情动作（短时、单次、无音效）。_避免_：长期未骑行、长时未登录。
**低电量动作**：电量＜20% 期间的无力/饥饿类持续动作（无音效）；≥20% 或充电解除。
**充电中动作**：插枪充电期间持续展示的专属动作（无音效）；拔枪停止。
**生日祝福动作**：生日当天上电播放的庆祝动作＋生日音效；判定外置智能推荐侧。
**天气动作**：上电时按当天天气播放的一次性动作（本期雨天/雪天，无音效）。
**节日皮肤**：五套节日外观（春节/元旦/端午/中秋/国庆），与动作“同时”叠加。_避免_：节日惊喜皮肤。
**点击动作 / 点击热区**：单/双击触发的互动短动作（2 选 1，有音效）/ 萌宠周围随屏幕位置动态变化的命中区域（Kanzi 判定）。

## 5. 全局规则

| # | 规则 |
|---|---|
| G1 | **显隐与启停**：单一开关（Settings.Global `ai_pet_switch`）决定启停。开→提供服务；关→调 Kanzi 隐藏接口。取值成功即本地持久缓存，上电通信不畅以缓存恢复。形象选择不参与启停 |
| G2 | **竞合**：以《音效动作冲突矩阵》（02 文件）为唯一权威（独占/延迟/拒绝/同时/暂停/X；最多连续 2 动作；动作前提 P 档；不在前台不做竞合；动作结束音效停止）。矩阵尚不完善（TD-17），修订前按现表执行 |
| G3 | **中断恢复**：HMI 切走 / 非 P 档 → setRenderStop 记住当前动作；setRenderStart → 重新计时并恢复。状态型动作恢复先按实时状态校验重建。竞合适用边界见 F38 |
| G4 | **归宿**：除皮肤叠加外，一切动作结束回常驻待机循环 |
| G5 | **上电多事件**：不设全局顺序表，按到达顺序＋矩阵两两关系推算排队；皮肤即达即叠加不排队 |
| G6 | **音效通用机制**：服务占音频焦点；时机＝动作开始回调；等待超时 1000ms 弃音效不取消动作（生日音效暂挂除外） |
| G7 | **保活不做**；发送失败→重试 1~2 次→仍失败调隐藏接口 |

## 7. 功能需求条目结论索引

> 完整原文与问答见 [04-需求条目档案](./04-需求条目档案.md)。

- **001 场景功能入口**：单一开关（C1）；Settings.Global 通路（C2）；缓存兜底（C3）；停止＝隐藏接口（C4）；一期读 Setting 预留替换（C5）；触摸为外部行为（C6）。开放：TBD-1 默认值。
- **002 出场动作**：IVI ready 一次性主事件（TD-1 课题）；D/R 任意时刻终止；音效超时 1000ms（TD-2）；失败重试后隐藏、无保活；节日叠加＋节日音效优先。
- **003 随机动作**：洗牌不重复；回调驱动闭环；参数合一可配（TBD-4）；动作池可配置；起点＝落位完成。
- **004 点击动作**：单/双击均触发；2 选 1 纯随机；>20% 才响应（TBD-5）；防连点不关心；音效复用 G6。
- **005 音乐联动**：回 P 档实时重建；≤20% 不触发；暂不防抖（TD-5 课题）；音源监听已实装。
- **006 语音交互**：aiLit 已实装；收到即触发＋幂等；挂死一期接受（TD-6）；VPA 零订阅。
- **007 长期未登录**：先出场后本动作；晚到按竞合排队；转动中延至回正；链路整体 TBD-6、服务零计算。
- **008 低电量**：阈值不加滞回；信号 TBD-5；点击源头拦截；未进场口径 F38。
- **009 充电中**：插枪口径 TD-9；无效维持、恢复按实际值；低电量→充电＝独占；拔枪回常驻待机。
- **010 生日祝福**：音效细节暂挂；撞节日动作叠加、音效暂节日优先（TD-8）；依 DEP-8。
- **011 天气动作**：推送每周期一次（TD-10）；枚举 DEP-9；其他天气不触发。
- **012 节日皮肤**：判定归智能推荐；即达即穿不排队；音效每上电一次；两处原文勘误已确认。
