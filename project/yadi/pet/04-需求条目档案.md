## SRS_001 — 场景功能入口

> ✅ 已定 2026-08-27

### 事实

- 前置：电源 ON、车机正常工作
- F5 服务生死由单一开关决定（形象不参与启停）
- F6 数据 PPX 阶段来自车控车设（Setting），后续换萌宠 App
- F7 取值成功即本地持久化，上电通信不畅以缓存兜底；**首次上电无任何记录时默认为开**

### 问答

1. **开关与形象的数据模型**

   QA: 单一开关控显隐与启停；形象只是呈现内容

2. **数据通路**

   QA: 代码核验——Settings.Global 键 `ai_pet_switch`(1/0)，写入方 Setting 应用 AIPetFragment；服务侧 ContentObserver 监听；`ai_pet_choose` 存形象选择

3. **上电取值时序**

   QA: 成功即缓存；上电取不到实时值→用缓存恢复

4. **服务停止的表现**

   QA: 调用 Kanzi 萌宠隐藏接口（F8）

5. **数据源迁移**

   QA: 一期硬编码读 Setting；未来换萌宠 App，留替换余地、不做运行期双活

6. **「输入：触摸」所指**

   QA: 设置页上的用户操作；服务不感知触摸，只听状态值

7. **开关默认值（TBD-1 裁决）**

   QA: 第一次上电未获取到开关状态时默认为开；成功获取即缓存，之后上电取不到实时值→用缓存恢复。⚠️ Setting 页读取缺省值（现 0＝关）需同步对齐为 1

### 开放点

- ~~TBD-1 开关产品默认值~~ → 已裁决：首次上电无记录默认开；Setting 页缺省需同步改为 1（开）

> ✅ 已定 2026-08-27

### 事实

- 前置：电源 ON、车机正常工作、萌宠开关开启（开关语义见 SRS_001）
- F10 每上电至多一次，播完转常驻待机，D/R 立即终止＋释放音频焦点
- F11 音效由服务播（开始回调时机，超时 1000ms 弃播）；音效遵循《音频策略_SRS》（DEP-1）

1. **触发组合模型**

   QA: IVI ready 一次性主事件＋P 档＋未插枪；错过不补播（课题 TD-1）

2. **中断源边界**

   QA: 任意时刻变 D/R（含经 N）即终止；N 与插枪不中断

3. **终止作用范围**

   QA: 仅开场进行期间发终止；已进常驻待机不发

4. **音效超时**

   QA: 发指令起算 1000ms；超时弃音效、动作照播（TD-2 暂定）

5. **失败与保活**

   QA: 保活不做；失败重试 1~2 次后调隐藏接口（显隐细节参考《3D萌宠SRS》DEP-2）；未收到播放反馈则不播音频

6. **节日联动**

   QA: 外部→Launcher 接口→Kanzi；细节 TD-3；撞节日音效播节日音效

7. **竞合策略**

   QA: ＝《音效动作冲突矩阵》，拷贝为 02 文档维护（DEP-3 关闭）

### 开放点

- TD-1 出场触发边界课题：A 模型暂定，补播等边界后续评估
- TD-2 音效超时语义暂定（发指令起算 1000ms），待确认
- TD-3 节日联动细节待定；通路已定：外部→Launcher 接口→Kanzi
- DEP-1 《音频策略_SRS》未提供

- DEP-5 插枪条件“&&XXX”未列全的信号

- DEP-7 IVI ready（CCU 内部信号）接入通路待确认
- ~~DEP-3 竞合策略附录~~ → 已解决：《音效动作冲突矩阵》拷贝为 02 文档

   QA: 常驻时长＝触发间隔，同一可配置参数（默认值 TBD-4）

4. **非理想状态行为**

   QA: 全局 setRenderStop/Start 记忆-恢复（立 D002，F20）；服务不关心显隐与画面

5. **动作池扩展**

   QA: 可配置动作编号列表，增减只改配置

   QA: 落位完成事件；位移动画由 Kanzi 内部消化
