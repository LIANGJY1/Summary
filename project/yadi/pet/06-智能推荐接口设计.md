# LauncherLib pet 接口设计：智能推荐 ↔ Launcher（DEP-8）

> 唯一职责：定义 `LauncherLib` 中 pet 能力域的对外接口规格（API 唯一权威）；全局宿主服务为 Launcher 进程内的 `LauncherService`（D006）。
> 覆盖条目：SRS_010（生日祝福）、SRS_012（节日惊喜皮肤）；天气状态动作属于 [SRS_011](./entries/SRS_011.md)，走天气方 SDK 输入链路。
> 状态：**Launcher 侧已编码（2026-09-18），新版入口尚未启用，待智能推荐方评审联签与真机联调**。
> 需求结论见 [entries/SRS_010](./entries/SRS_010.md)、[entries/SRS_012](./entries/SRS_012.md)；竞合见 [02](./02-音效动作冲突矩阵.md)。

## 1. 架构与选型

```text
智能推荐 App → LauncherLib pet 客户端 → bind(LauncherService)
                                     → ILauncherService.getPetService()
                                     → pet Binder → PetCore → Kanzi/音效
智能推荐 App ← onResult(event, status) ← pet Binder
```

**选型：全局 `LauncherService` ＋固定根 Binder＋pet 子 Binder＋注册回调**。Android 对同一 Service 的多个客户端复用首次 `onBind()` 返回的 Binder，因此根接口必须固定，不能按 action 返回不同业务 Binder。后续能力域在根接口增加获取独立子接口的方法，不把业务方法堆入根接口。责任分界（SRS_012 QA3）：农历换算与节日/生日判定全在推荐侧，Launcher 只消费信号并回传结果。

`LauncherLib` 是已在工程 `settings.gradle` 注册的 Android Library Gradle 模块，使用 `com.android.library` 插件生成 `.aar`；它不是 Java Library 或只存文件的目录。AAR 包含 AIDL 生成类、客户端、常量及合并权限声明，不包含 Launcher 进程内的 `LauncherService` 或 pet 业务实现。构建与交付步骤见代码仓库 `component/LauncherLib/README.md`。

## 2. 权限与组件声明

Launcher（服务方）：

```xml
<permission android:name="com.yadea.launcher.permission.ACCESS_LAUNCHER_SERVICE"
    android:protectionLevel="signature"/>

<service
    android:name="com.yadea.launcher.LauncherService"
    android:exported="true"
    android:permission="com.yadea.launcher.permission.ACCESS_LAUNCHER_SERVICE" />
```

智能推荐（调用方）：manifest 声明同名 `<uses-permission>`（AAR manifest 已包含）；SDK 使用显式组件名绑定，action 为 `com.yadea.launcher.action.BIND`。全局 Service 采用签名权限，非同签名应用无法绑定；根/子 Binder 方法也按调用 UID 与 Launcher 的签名匹配再次校验，防止子 Binder 被转交给未授权进程。未来若不同能力域需要不同授权，再在对应 Binder 入口增加更细的调用方校验。

`LauncherService` 位于 Launcher 根包 `com.yadea.launcher`，`onBind()` 始终返回 `ILauncherService`；`getPetService()` 返回 `IPetRecommendationService`。全局入口只负责子接口分发、生命周期及共同鉴权；pet 的事件校验、事件翻译和回调由 `pet/recommend/PetRecommendationManager` 处理，竞合规则仍由 `PetCore` 决定。

## 3. AIDL 定义

目录：`component/LauncherLib/src/main/aidl/com/yadea/launcher/api/`（pet 子接口位于 `api/pet/`）；Launcher 与智能推荐依赖同一份 AAR，Service 实现仍在 `application/Launcher`。

### 3.0 ILauncherService.aidl（全局根接口）

```aidl
package com.yadea.launcher.api;
import com.yadea.launcher.api.pet.IPetRecommendationService;
interface ILauncherService {
    IPetRecommendationService getPetService();
}
```

### 3.1 IPetRecommendationService.aidl（推荐 → Launcher）

```aidl
package com.yadea.launcher.api.pet;

import com.yadea.launcher.api.pet.IPetRecommendationCallback;

interface IPetRecommendationService {

    /** 注册结果回调（重复注册幂等）；Launcher 进程重启后需重新注册 */
    void registerCallback(IPetRecommendationCallback callback);

    /** 注销回调 */
    void unregisterCallback(IPetRecommendationCallback callback);

    /**
     * 上报彩蛋事件（码值见 §3.3，与回调 event 同一张码表）。
     * 各码语义：14＝生日触发（Launcher 每上电周期至多播一次，重复自动忽略）；
     * 1~5＝当日节日状态（同值重复自动忽略）；0＝无节日/撤销皮肤。
     * 跨天/上电请重推当前有效状态。
     */
    void onEvent(int event);
}
```

### 3.2 IPetRecommendationCallback.aidl（Launcher → 推荐）

```aidl
package com.yadea.launcher.api.pet;

interface IPetRecommendationCallback {

    /**
     * 推送结果（每条推送终态一拍）。
     * @event  14＝生日；1~5＝节日（码值同下方 festival）
     * @status 1＝已完成/已应用；2＝未播放（开关关闭或被竞合让位，原因见 Launcher 日志）
     */
    void onResult(int event, int status);
}
```

### 3.3 常量表（由 LauncherLib 统一提供）

| 类别 | 常量 | 值 | 说明 |
|---|---|---|---|
| event | `LauncherPetEvent.BIRTHDAY` | 14 | 对齐萌宠生日动作码，与节日码天然不冲突 |
| event | 节日码 | 1~5 | **直通 Kanzi VPA_Festival**：1 春节、2 端午、3 国庆、4 元旦、5 中秋 |
| event | `LauncherPetEvent.NONE` | 0 | 无节日/撤销皮肤（仅节日语义） |
| status | STATUS_OK | 1 | 已播放完成（生日）/Kanzi 皮肤属性写入成功（节日） |
| status | STATUS_SKIPPED | 2 | 未播放（开关关闭 / 被更高优先级动作让位 / 周期内已播过） |

### 3.4 LauncherLib 客户端入口

对外提供 `LauncherPetClient`，调用方只需连接、发事件、接结果和断开。SDK 内部使用上述根/子 AIDL 与 `LauncherService` 建立连接。

```kotlin
val client = LauncherPetClient(context)
client.connect(object : LauncherPetClient.Listener {
    override fun onConnected() {
        // 推荐侧重新计算当日生日/节日状态，并推送当前有效事件
    }

    override fun onResult(event: Int, status: Int) {
        // 接收 Launcher 的终态结果
    }
})

client.sendEvent(LauncherPetEvent.BIRTHDAY)
client.disconnect()
```

`connect()` 自动 bind 并注册 AIDL 回调；`disconnect()` 注销回调并解绑。`sendEvent()` 在未连接时暂存本进程内的事件，同一本地日期连接后发送；跨日丢弃旧暂存，避免过期生日/节日误触发。推荐侧仍须在连接回调中重算并推送当日状态，以覆盖进程重启和跨天后的旧缓存。SDK 不持久化生日/节日判定，也不代替推荐侧的业务判断。

## 4. 时序

```
生日： 推荐侧 onEvent(14) → Launcher 播动作
       ← onResult(14, STATUS_OK)            （未播则 status=STATUS_SKIPPED）

节日： 推荐侧 onEvent(2) → Launcher 穿皮肤（与任意动作叠加，不排队）
       ← onResult(2, STATUS_OK)             （跨天撤销推 onEvent(0)）
```

音效每上电周期至多一次、信号重复去重，均为 Launcher 内部规则，接口不感知。

当前 Kanzi 接口只提供 `setValue(VPA_Festival)` 的调用成功/异常结果；`STATUS_OK` 不能解释为画面已完成渲染。若需渲染完成态，须由 Kanzi 方提供明确回执信号后再收紧回调语义。节日专属音频资源尚未交付，当前暂用既有点击音效占位。

## 5. 对账与异常（关键契约）

- **推送时机**：调用方通过 `LauncherLib` 客户端发送；SDK 内部完成 `bindService`、`registerCallback` 和连接前事件暂存，仅在连接建立后调用 AIDL。
- **推荐侧重连后**：SDK 重新注册回调并发送连接前暂存事件；推荐侧在连接回调中重算当前有效状态，再推当日节日码或生日窗口内的 `14`。SDK 不能仅凭旧事件判断其跨天后是否仍有效；Launcher 对重复推送做幂等兜底。
- **Launcher 内部未就绪不丢**：事件早于车机就绪（IviReady 前）或撞上出场动画到达时，事件泵仅记忆不联动，待就绪/动作完成后落位（竞合"延迟"语义）
- 推荐侧进程死亡：Launcher 经 Binder 死亡通知自动清理，无需推荐侧动作
- Launcher 进程重启：桌面进程常驻，若发生则推荐侧重连重推即恢复
- 回调远程异常：Launcher 隔离该回调，不影响主流程

## 6. Launcher 侧集成点（阶段 7 实施）

- `component/LauncherLib` AAR 提供 pet 客户端、根＋pet 两个 AIDL 接口和 callback AIDL、常量；Launcher 根包 `LauncherService.kt` 固定返回根 Binder，再由 `pet/recommend/PetRecommendationManager` 提供 pet Binder。该业务适配层完成翻译：`onEvent(14) → PetCore.onEvent(BirthdaySignal)`、`onEvent(1~5) → FestivalSignal(PetSkin)`、`onEvent(0) → FestivalSignal(无)`（PetCore 主线程化，Binder 线程安全）。
- 回传：状态机 `PetCommand.ReportStatus` → platform 层翻译为 `onResult`（替代当前仅记日志的分支）
- 展车版零涉及（D003 双闸）；场景表阶段 7 增行（推送/去重/竞合让位回传/撤销）

## 7. 演进原则

新增 pet 彩蛋类型须双方确认后扩展 pet 事件码；新增其他 Launcher 对外业务则在 `LauncherLib` 中增加独立子接口和根接口 getter，由同一个 `LauncherService` 提供。天气状态动作按 SRS_011 直接消费 `WeatherApiClient`，不占用 pet 对外事件码。破坏性 AIDL 变更须双方联签并通过新接口版本过渡。
