# SRS_010/011/012 阶段 7 实现计划

> 007 因需求大变更暂缓。本计划依据 [SRS_010](./entries/SRS_010.md)、[SRS_011](./entries/SRS_011.md)、[SRS_012](./entries/SRS_012.md)、[竞合矩阵](./02-音效动作冲突矩阵.md)和 [pet API](./06-智能推荐接口设计.md)。

**目标：** 让生日、天气、节日三条需求从信号输入到 Kanzi 指令和结果回传形成可编译、可测试的闭环。

**架构：** `component:LauncherLib` 是 Android Library Gradle 模块，构建对外 AAR；`LauncherService` 是 Launcher 全局绑定入口，固定返回 `ILauncherService` 根 Binder，由其获取 pet 子 Binder。天气方 AAR 仅由 Launcher 的天气适配层消费。`PetStateMachine` 管理去重、竞合和一次性标志；`PetCore` 执行 Kanzi 与回传。

**技术栈：** Android Library、AIDL、Kotlin、Gradle、JUnit 场景表。

## 全局约束

- 保留现有工作区改动；展车版 `control/pet` 不改，新版入口开关仍遵循 D003。
- 007 不增加输入、状态机处理或测试。
- 生日/节日判定由智能推荐负责；天气码映射由 Launcher 负责。
- `LauncherLib` 仅交付协议与客户端，Launcher 内部状态机和 Kanzi 实现不进入 AAR。
- 每上电周期以 Launcher 进程生命周期为准；节日皮肤与动作可同时存在。
