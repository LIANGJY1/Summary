## 1. 链路总览

三方按原生 Notification 发消息（文本 + `Notification.actions[]`，每按钮一个 PendingIntent）→ SystemUI 在弹横幅前把整条消息**托付**给萌宠，一次调用、一个返回值：

- **收** → 不弹横幅。消息作为**新动作类型**进竞合仲裁，由 Kanzi 弹卡片；点按钮由萌宠直接触发操作。
- **不收** → SystemUI 原生横幅直显，消息不丢。

```text
三方 ──notify──▶ SystemUI ──onNotification(card)──▶ 萌宠
                     │                                 │ 受理判定（§2）
                     │ false(不收)                     │ true(收)
                     ▼                                 ▼
                 原生横幅直显                    消息动作入竞合仲裁（§3）
                                                       │ 02 矩阵调度（可排队）
                                                       ▼
                                                Kanzi 弹消息卡（文本+按钮）
                                                       │ 点按钮 → 回传 index
                                                       ▼
                                          萌宠 send() 对应 PendingIntent（§4）
                                          超时/打断/cancel → 收卡结束（§5）
```

## 2. 分流接口（SystemUI → 萌宠）

挂载：`ILauncherService` 根 Binder 下新子接口 `IPetNotificationService`（"新业务加独立子接口"惯例，复用 `ACCESS_LAUNCHER_SERVICE` 权限 + 同签名校验，SystemUI 以特权身份直连）。

```text
interface IPetNotificationService {
    boolean onNotification(NotificationCard card);      // 消费裁决语义，先例 Activity.onKeyDown（"handled→true；让下一接收者处理→false"）：true=萌宠处理（入仲裁队列，SystemUI 不弹横幅）/false=SystemUI 自己处理（原生横幅直显）
    boolean updateNotificationCard(NotificationCard card); // 同 key 更新：队列或显示中→替换；已结束→false
    void removeNotificationCard(String cardId);         // 三方 cancel：出队或收卡，不触发操作
}
NotificationCard {
    String cardId;                                   // = SystemUI 通知 key（pkg+tag+id）
    String title;  String text;
    List<NotificationButton> buttons;                // ≤3；不支持主体点击，contentIntent 不下发
    int negativeIndex;                               // 消极按钮 index（T2），超时收卡即触发它
}
NotificationButton { int index; String text; PendingIntent action; }  // action=actions[i].actionIntent
```

**职责分层（凭据流向）**：SystemUI 从 Notification 抽取字段填充 NotificationCard——凭据裁剪唯一关口（仅按钮 actionIntent 过界）；萌宠收到即存（存储结构＝NotificationCard，零解析），PendingIntent 只存萌宠存储层、**不下发 Kanzi**。

受理判定（接口内同步，三条件全过才收）：Launcher 前台 ／ 形象可渲染（renderStarted + petShown）／ 消息动作此刻竞合裁决非拒绝。false 不细分理由——横幅侧对 false 只有一种动作：原生横幅直显。

## 3. 消息＝动作，一切按竞合

- 消息卡是新动作类型（与雨雪/生日并列），显示卡片＝播放动作，受 02 矩阵统一调度；多消息到达＝多动作排队。
- 排队／打断／取消全按竞合裁决，链路层不另设规则；不支持暂停/恢复（短时效 UI）。
- 被打断 → 按取消处理（待定 T3）；"消息"列格值在 02 专项定稿，本文不复述。

## 4. 按钮点击＝萌宠直接触发

PendingIntent＝三方在系统预登记的操作凭据：任何进程持有并 `send()`，都以**三方应用身份**执行，萌宠无需持有三方权限。故：

- 下发即传对象：按钮文字 + index + PendingIntent 随卡过 binder（Parcelable），SystemUI 不留执行权；凭据只进萌宠存储层；
- 点击链：Kanzi 回传 index → 萌宠查存储层取该按钮 `PendingIntent.send()` → 收卡，**全程不回 SystemUI**；
- 安全：凭据交出后萌宠任意时刻可 send，故仅平台签名/白名单应用的消息可托付；建议要求三方 `FLAG_IMMUTABLE`。

## 5. 超时（暂定）与消极按钮

- 暂定 **5s** 自动收卡，萌宠侧自计时（状态单点，横幅侧断连不致卡片常驻）；是否改按 Kanzi 动画时长→T1。
- 收卡时**有按钮** → 视为点击**消极按钮**，触发其 PendingIntent（消极按钮暂定＝列表最后一个→T2）；
- **无按钮** → 仅收卡，不触发任何操作。

## 6. Kanzi 对接点（待内容侧接口文档，键名/动作码后补）

- Kanzi 特殊接口只收显示数据（文本+按钮文字），不接触 PendingIntent；不支持 index=0 主体点击；
- 下发：新动作码 + 文本/按钮文字属性 put（String 值先例＝座椅名）；
- 回传：点击按钮回传 index，路由走既有 `VPA.* → PetCore` 通道；
- 消极按钮视觉标识、卡片动画时长 → 与内容侧联审。
