## 1. 一页结论

- **这是约 85 天（2026-06-25 ~ 2026-09-18）的密集开发+修复期**：1010 条非 merge 提交中 **761 条（75.3%）是缺陷修复**，涉及 **543 个去重缺陷单**；修复强度逐月上升（6月 34 → 7月 189 → 8月 219 → 9月上半月 319），符合"功能开发在前、提测放量在后"的节奏。
- **被修复缺陷中 79.2% 是"必现"**，89.5% 已闭环——大部分问题常规冒烟即可发现，修复吞吐跟得上流入。
- **根因第一大类是 UI 还原/主题适配（264/761，34.7%）**；其后是信号与协议（88）、状态管理与缓存（77）、蓝牙机制（73）、异步时序与竞态（57）。逐 commit 精读后又提炼出五类**跨模块系统性模式**：信号"状态域/命令域"双编码混用、内部哨兵值落入协议值域、主线程同步 Binder、防御性补丁叠加成死锁、多模块资源遮蔽（见第 5 节）。
- **11 个 A 级缺陷**全部与"偶现+并发/状态机"、"系统级（dsp/HAL）"或"启动时序"相关（SIR-8227 卡开机即单例 init 块过早落盘所致）。
- **追溯性损耗明显**：27.9% 的修复提交自带完整 [why]/[how]；85 条修复提交无缺陷单号（大量 `SIR-XXXX` 占位）；102 条引用缺陷库外单号；还存在**同 diff 重复提交对、Change-Id 串号、单号交叉错标**等污染（逐commit详析中已逐条标注）。

## 5. 根因模式与防回归清单（逐 commit 精读后的系统归纳）

### 模式一：UI 还原/主题适配（264 条，34.7%）
颜色/字号/字重/间距偏差、黑夜资源缺失或用错、设计稿版本混淆、`getIdentifier` 动态取资源绕过 `-night` 限定符（3ba0d479）、多模块同名资源遮蔽（39e4afc4：app 同名 drawable 劫持库 selector）、fwk 不支持非 100 整数字重。
**清单**：新增颜色必配 night 值；样式走 token；动态资源名改静态引用；UI 提测跑"日夜×分辨率"矩阵。

### 模式二：车控信号语义（88 条）
1. **超时 ≠ 清零**：超时保持旧值/显示"--"，绝不 set 0 或默认值（SIR-1486/1490/1494/1496 一整串）；
2. **信号恢复后重读关联信号**（独立 CAN 帧差 92ms，SIR-2084）；
3. **状态域(0/1)与命令域(1/2)双编码不得混用**（湿滑模式置灰恒假 e0903b2f、车外灯 `PCU_VEHICLE_SPEED_VALID` 0x0=有效被写反 fa797195、[`无单号_统一修改驾驶和主动安全相关信号下发值和回弹逻辑`](逐commit详析/Setting_无单号_统一修改驾驶和主动安全相关信号下发值和回弹逻辑.md) 完成三套值域总收口）；
4. **内部哨兵值避开协议值域**（SIR-1493、45a6d668 的 -1f 方案）；
5. **UI 值↔协议值显式换算**（SIR-5734 ×100 倍偏差）；
6. **下发前校验关联状态**（SIR-4569）。

### 模式三：Android ↔ Kanzi 双端状态同步（Launcher/3D车模）
组合状态成对复位（Gear/D_Desktop）；重复上报去重（386ms 双报）；反馈校验只向事实源对齐、不得回滚到点击前值（座椅加热/记忆三连）；跨端字体能力差异显式约定（Emoji）；进入某状态的副作用收敛到状态 entry 而非散在事件路径（19103951）；"动作播完必须补发 Action=0"类协议怪癖钉进配置表。

### 模式四：主线程与异步时序（57 条 + 崩溃 24 条）
1. **主线程同步 Binder 是本仓库最大性能病灶**：`getProperty`（1332cfe0 事件缓存直读+异步补拉）、`Car.createCar`（ac3b8da8 专用线程池+代数守卫）、写属性（56ed4a64 专用串行 HandlerThread）、`getCarLinkAppList`（ac3d9bd3 IO 线程+@Volatile 旧值先显）；
2. 延迟任务必须可取消；Fragment 销毁后回调要失效；并发容器 CopyOnWriteArrayList（SIR-2104）；
3. **回调里禁反查外部缓存**（SIR-5737 热点开关用滞后缓存致反复横跳，应使用回调参数）；
4. 防抖不得吞真实请求、终态分支才准取消超时（SIR-6525）。

### 模式五：蓝牙机制（73 条）
连接/回连状态机互斥（自动回连占栈终止 inquiry → AIDL 打断+150ms 延迟扫描）；跨进程单例陷阱（`BtAnwManager.getInstance()` 在 BTMusic 进程拿到空副本，改经 Settings.Global+ContentObserver 中转，aa9f9d8d）；PBAP 全家桶（未授权 iPhone 假 100%、5000 条上限差 1、多号码只匹配第一个、RTL 排版、双仓库漂移 → `ContactsRepository` 单仓库重构 7b7efe27）；"事件触发 + 状态回查"替代单设备广播当全局状态（781a6000）。

### 模式六：需求变更与流程（55 条 + 流程问题）
- mistag 40+（feature/bugfix 互标）、`SIR-XXXX` 占位 85 条、模块名拼写三套（Energymanagement/Energymanangement/EnergyManagement）；
- **同一 diff 两个单号重复入库且交叉错标**（b6771acc≡5b443500）；**Change-Id 串号**（一 ID 多单）；cherry-pick 错分支 5 小时内回退（b1bf5cfd/346f3de1）；
- 复制"pending 暂存+回显"模板自带逻辑反转 bug，3 天内两次修复才收敛（e2ee6731→11d164b8→c6c5e902）——**模板代码必须逐分支核对**；
- 搭车修改普遍（弹窗修复夹带通话逻辑、日志提交夹带真修复），回归范围与单号不匹配。
**清单**：pre-commit 校验类型枚举+单号格式（禁 XXXX）+模块白名单；CI 用 patch-id 查重；单号与提交 1:1 核对纳入 MR 模板。
