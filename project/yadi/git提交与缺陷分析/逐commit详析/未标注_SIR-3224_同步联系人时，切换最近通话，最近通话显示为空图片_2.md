# SIR-3224 · 同步联系人时切换最近通话页显示空图片
- **提交**：`dea49db5` | 2026-07-31 | liujinfeng | BTPhone | bugfix
- **缺陷库**：等级 C · 频次 必现-80%~100% · 状态 关闭 · 域 蓝牙电话

## 问题
联系人同步进行中切换到"最近通话"tab，页面显示空态图片，而不是加载中/已有数据。

## 根因分析
缺陷库根因"同步状态管理异常"。`CallLogFragment.onResume()` 的状态机分支存在三处漏洞叠加：
1. `mSyncInProgress` 判断里 `loading()` 之后本应 `return`，但 `return` 被注释掉了（`//                return;`），loading 渲染后被后续空态渲染覆盖，最终显示空图片；
2. 跳过刷新的"稳定态"白名单把 `SyncFailed`、`BluetoothDisconnected` 也算作稳定态，同步失败/未同步状态下再次进入页面直接跳过 PBAP 重查，停留在旧空态；
3. 触发补同步的条件只覆盖 `Empty`，`SyncFailed`/`SyncRequired` 不在内。
另外 loading 动画用 `binding.imageLoading.post(...)` 内联启动、多处散落 `clearAnimation()`，View 销毁后回调仍可能触达旧 binding，时序脆弱。本提交同时大规模精简了 `FavoritesViewModel`（-414 行）等同类同步状态逻辑，属同一根因家族的集中整改。

## 为什么能修复
Loading 态补上 `return` 后不再被空态渲染覆盖；`SyncFailed/SyncRequired` 从"稳定态"白名单移除并纳入补同步条件，再次进入页面会重查 PBAP/重触发同步而不是停留空态；进入 Empty/失败态先 `loading()` 占位，消除检查期间的空页闪烁；loading 动画用 `loadingUiRequested` 标志+统一启停方法管理，`onDestroyView` 先 `stopLoadingAnimation()`，回调不再触达已销毁的 View。隐患：本提交改动面很大（-808/+185，含 FavoritesViewModel 大重构与 FloatCallWindow 搭车的 `onCirculationAccepted()`），回归范围远超单据描述；`super.onStart()` 被顺带移除，需确认无基类副作用。

## 复盘经验
- 空态/加载态/失败态的渲染互斥必须显式短路（return），注释掉 return 这类"看似无害"的调整会直接破坏状态机互斥性。
- "稳定态跳过刷新"白名单要从严：只有真正数据就绪的状态（Success）可跳过，失败/未同步态都应允许重试，否则失败被固化。
- 状态页大重构应独立成 refactor 提交，与单点 bugfix 分开，否则缺陷复盘无法定位关键 hunk。
