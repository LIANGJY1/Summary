# 无单号 · 移除无用依赖（整个 ihuadapter 组件下线）

- **提交**：`23957a5f` | 2026-07-03 | dufan | IHuadapter | feature
- **关联单**：无

## 需求/目标
从仓库中整体删除 `component/ihuadapter` 组件（创维 skyworthauto SDK 的蓝牙/CAN/网络/设备选项适配层），属于架构瘦身与依赖治理。

## 实现结构
纯删除提交（-535 行左右）：移除 `component/ihuadapter/` 下的 `.gitignore`、`build.gradle`、`project.config`、`AndroidManifest.xml`，以及 `com.skyworthauto.sdk` 包内 13 个适配类/接口（`BluetoothAdapter`、`CanAdapter`、`NetAdapter`、`DevOptsAdapter` 及对应 `I*Interface`/`I*OnReceive` 回调接口）。

无数据流变化：该组件已被上层引用摘除，本次是残骸清理。`build.gradle` 中保留了它历史上作为独立 aar/jar 产出（`ihuadapter_V1.0.17`）的打包脚本，也一并消失。

实现讲解：`com.skyworthauto` 命名空间暴露了该工程源自创维车机 SDK 的移植代码，yadea 项目切换到 `ts.car.service.*` 中间件体系后，这层旧适配彻底失去调用方。删除范围一次到底（构建脚本 + 清单 + 源码），避免了"半删"状态造成的编译配置漂移。

## 复盘与要点
- 删除整个组件前应确认 `settings.gradle`/其他模块 `build.gradle` 已无引用；从同日多个"优化项目依赖"提交看，这是一轮系统性的依赖清理动作的收尾。
- 旧供应商 SDK（skyworthauto）与新一代中间件（ts.car.service）并存期的适配层，最终以整目录删除收场——识别"无调用方的移植层"是大型车机项目瘦身的重要课题。
- 无行为影响的删除也建议跑一次全量编译验证，防止 `compileOnly` 类残留引用。
