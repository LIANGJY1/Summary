# SIR-4602 · 触发"流转"后所有拨打电话都会触发"流转"
- **提交**：`cec821ce` | 2026-07-31 | liujinfeng | BTPhone | bugfix
- **缺陷库**：等级 B · 频次 必现-80%~100% · 状态 关闭 · 域 蓝牙电话

## 问题
触发一次"流转"（通话流转到车机/手机的悬浮提示）后，之后拨打的每一通电话都会再次弹出"流转"。

## 根因分析
缺陷库根因"流转状态判断有问题"。`FloatCallWindowPresenter` 用两组状态判断是否弹流转窗：标志位 `mHasActiveCallBeforeBluetoothConnect` 和时间戳 `mLastBluetoothConnectTime`。旧代码有两个持续性缺陷：
1. `mHasActiveCallBeforeBluetoothConnect` 置 true 后**没有任何复位路径**——用户确认流转、通话结束都不会清标志，后续每通电话进 `onCallAdded` 时都命中"标志已设置，keep circulation float window flag"分支，弹窗复现；
2. `detectCallDuringBluetoothConnect()` 用 10 秒窗口（`timeDiff < 10000`）比较"通话开始时间 - 蓝牙连接时间"，且命中后 `mLastBluetoothConnectTime` 不清零，加上 `checkCallStateOnBluetoothConnect()` 在**每次蓝牙状态回调**（含已连接状态的重复回调）都刷新连接时间戳，窗口被不断续期，后续通话持续误命中。
缺陷库方案"app 暂时使用连接时间来判断是否需要流转"即指这套时间窗口机制在本提交的收敛版本。

## 为什么能修复
三层收敛：① 新增 `onCirculationAccepted()` 在用户确认流转后一次性清空全部流转标志与时间戳，切断"标志常驻"的传播链；② 检测命中后立即消费 `mLastBluetoothConnectTime`（置 0），窗口只允许第一通电话命中；③ 连接时间戳只在真实连接沿记录、断开即清零，重复状态回调不再续期窗口；窗口也从 10s 收紧到 5s。副作用评估：若用户触发流转提示但未点确认（如直接挂断），状态改由通话结束路径清理，需覆盖测试；注释明说"暂时使用连接时间判断"，方案本身仍是启发式。

## 复盘经验
- 一次性提示/弹窗类功能必须有"消费即复位"的生命周期管理：标志位置 true 的同时就要写好所有 false 路径（用户确认、取消、通话结束、断连），否则必然复现。
- "时间戳窗口"检测要区分"可复用的基准"与"一次性凭证"：事件触发型判断应在命中后立即消费时间戳，防后续事件搭车。
- 布尔标志 + 时间戳双条件判断容易互相续命，收敛为单一状态机（如 CirculationState 枚举）可根治此类粘滞。
