# VIR-193 · iOS 联系人权限关闭时车机无授权引导文案
- **提交**：`dea6080b` | 2026-07-30 | liujinfeng | BTPhone | bugfix
- **缺陷库**：未关联单号（缺陷库 defs 为空）

## 问题
手机联系人权限关闭时，安卓设备车机会显示"请授权"引导文案，但苹果（iOS）设备没有引导文案，两端交互不一致。

## 根因分析
`ContactsFragment` 的状态渲染把 `ContactsUiState.SyncRequired`（未同步/未授权）与 `ContactsUiState.Empty`（空列表）分成了两条路径：`SyncRequired` 走 `showWaitAuthorized()` 显示授权引导；`Empty` 单独渲染"暂无通讯录"（`icon_no_contact` + `no_contacts`），且按钮/文案全部 GONE，没有任何引导。关键差异在于 iOS 的 PBAP 行为：权限关闭时手机端不返回"未授权"错误，而是同步出 0 条联系人，于是状态机落到 `Empty`，引导文案被吞掉——同一用户意图（未授权）被映射到了两个不同 UI 状态。

## 为什么能修复
把 `Empty` 并入 `SyncRequired` 的渲染分支后，无论平台把"权限关闭"表现为同步失败还是空列表，UI 都统一落到 `showWaitAuthorized()` 的授权引导，安卓/iOS 表现一致；文案改为同时覆盖"未授权/无数据"两种成因，避免真正无联系人的用户被误导。隐患：真正"确实没有联系人"的正常场景现在也显示授权引导，属于牺牲语义精度换一致性，文案里补了"/无数据"来兜底。

## 复盘经验
- 跨平台（安卓/iOS）蓝牙行为差异要在状态机入口归一化：同一用户意图映射到同一 UI 状态，而不是让底层差异泄漏到界面。
- "空列表"与"未授权"是两个语义，但 iOS 权限关闭会伪装成空列表；处理空态时要想清楚它的多种成因。
- 文案状态分支删除时同步清理其专属布局逻辑（image/btn 设置），本提交删分支删得干净，无残留引用。
