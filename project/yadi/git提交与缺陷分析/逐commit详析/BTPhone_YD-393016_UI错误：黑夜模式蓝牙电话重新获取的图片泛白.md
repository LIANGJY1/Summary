# YD-393016 · 黑夜模式蓝牙电话"重新获取"图片泛白
- **提交**：`38211575` | 2026-07-31 | hedeyuan | BTPhone | bugfix
- **缺陷库**：未关联单号（缺陷库 defs 为空）

## 问题
黑夜模式下蓝牙电话联系人"未授权→重新获取"状态页的提示图片泛白，与 UI 稿不符。

## 根因分析
该状态页使用的空态图片 `empty.png` 只有白天版本（`res/drawable/`），缺少 `drawable-night` 夜间变体。黑夜模式下系统资源回退机制加载白天浅色图，在深色背景上表现为"泛白"。属资源限定符缺失的典型模式，与 YD-392973（BTMusic 夜间图标）、YD-393001（SystemUI 夜间 seekbar）同一根因家族。

## 关键代码修改
改动文件：新增 `application/BTPhone/src/main/res/drawable-night/empty.png`（二进制图片资源，唯一改动）
```diff
+++ application/BTPhone/src/main/res/drawable-night/empty.png  (二进制更新)
```

## 为什么能修复
提供与白天 `empty.png` 同名的夜间限定符资源后，黑夜模式下系统自动选用深色版图片，无需任何代码/布局改动即完成修复。前提约束：夜间图与白天图的显示尺寸/内容语义必须一致，只换配色；`empty.png` 是高度泛化的资源名，其他引用该图的界面也会一并变为夜间深色版，需确认所有引用方期望一致。

## 复盘经验
- 空态/引导图（empty、no_contact、icon_no_connect 等）是夜间资源缺失的重灾区，UI 交付清单应按"白天/黑夜 × 资源名"二维核对。
- 纯资源限定符修复是零风险修法：不改代码、不触碰逻辑，代价只是包体积；前提是资源名语义清晰（empty.png 过于泛化，建议前缀化命名）。
- 车机项目昼/夜双主题是硬性需求，可建立 CI 检查：扫描 `drawable/` 下图片资源，对缺失 `-night` 变体的关键界面资源输出告警。
