# 无单号 · 基础库弹窗增强 + 蓝牙设备日志补全

- **提交**：`456d0002` | 2026-06-26 | dufan | CommonTools/Hardwarelibs | feature
- **关联单**：无（手车互联需求配套改造）

## 需求/目标
为手车互联的连接提示弹窗做准备：CommonTools 基础弹窗组件增加运行时定制能力，并补全蓝牙设备对象的调试日志字段。

## 实现结构
改动文件：BaseDialogFragment.kt、TextDialog.kt、dialog_text.xml、CachedBluetoothDevice.java、（顺带清理 .gradle/.idea 残留）。
- `BaseDialogFragment` 新增 `setCancelText(content)`：暴露取消按钮文案的运行时修改入口；
- `TextDialog` 标题支持为空：`title` 为空时隐藏标题控件，支持"只有正文"的弹窗形态；
- `CachedBluetoothDevice.toString()` 追加 `mPhoneCarConnectionType/mConnectionType/mIsPhoneCarConnect` 三个互联字段的输出。

## 关键代码
```kotlin
// BaseDialogFragment.kt
+ fun setCancelText(content: String) {
+     mTvCancel?.text = content
+ }

// TextDialog.kt — 标题空值不再显示空行
- mBinding.tvTitle.text = title
+ if (!TextUtils.isEmpty(title)) {
+     mBinding.tvTitle.visibility = View.VISIBLE
+     mBinding.tvTitle.text = title
+ }
```

## 复盘与要点
- 给公共组件加"运行时改文案"入口是为了配合倒计时弹窗（见 f536d005 的 CountDownTimer 每秒 setCancelText），组件能力与业务需求同步演进，节奏正确。
- 顺带把 toString() 补字段看似小事，但互联排障后续大量依赖这几行日志输出——日志字段是排障基础设施，新增状态字段时同步更新 toString 应成习惯。
- 遗留：`setCancelText` 无非空校验，传入空串会清空按钮文案。
