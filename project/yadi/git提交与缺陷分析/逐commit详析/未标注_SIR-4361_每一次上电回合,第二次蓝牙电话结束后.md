# SIR-4361 · 第二次蓝牙电话结束后 HUD 图层残留
- **提交**：`650618b7` | 2026-07-30 | liujinfeng | Launcher | bugfix
- **缺陷库**：等级 B · 频次 必现-80%~100% · 状态 关闭 · 域 蓝牙电话

## 问题
每次上电回合后，第二次蓝牙电话结束（挂断）时，蓝牙电话画面图层仍残留在 HUD 屏上不消失。

## 根因分析
缺陷库根因："Display4 图层不自动刷新"。HUD 对应 display 4，其合成图层在内容移除后不主动刷新，导致旧帧滞留。此前 `Myapplication.addTransparentPlaceholderWindow()` 只给 display 2 加了透明占位窗口（`dm.getDisplay(2)` 硬编码单屏），display 4 上没有任何常驻窗口驱动 SurfaceFlinger 持续合成，电话图层移除后 HUD 停在旧帧。修复思路即缺陷库方案"给 Display4 增加透明遮罩占位"：把占位窗口铺到 display 4，强制该屏保持合成刷新。

## 关键代码修改
改动文件：`application/Launcher/src/main/java/com/yadea/launcher/Myapplication.kt`、`application/Launcher/src/main/java/com/yadea/launcher/function/applist/AppListActivity.kt`、`application/Launcher/src/main/res/values/styles.xml`

## 为什么能修复
在 display 4 上常驻一个全屏、透明、不聚焦不触摸（`FLAG_NOT_FOCUSABLE|FLAG_NOT_TOUCHABLE`）的 `TYPE_APPLICATION_OVERLAY` 窗口，使 HUD 屏始终有活跃图层参与合成，电话应用图层移除后合成器输出随之更新，残留消失。风险：常驻 overlay 窗口长期占用一层 Surface，且循环加 try/catch 后单屏失败不影响另一屏；若未来屏幕编号变化（displayIds 硬编码 2/4）需同步维护。

## 复盘经验
- 多屏车机上"屏幕不刷新/图层残留"类问题，优先怀疑该 display 缺少常驻合成驱动，透明占位窗口是常见 workaround，但要集中管理屏幕 ID，避免散落硬编码。
- 硬件不自动刷新是根因时，软件侧补占位只是掩盖，应同步推动显示侧排查；此类 workaround 务必加注释说明存在原因（本提交已补注释）。
- 一个 commit 混入多个不相关改动（HUD 占位 + AppList scrim 动效 + styles）会降低可回溯性，应拆分提交。
