# SIR-4057 · 通知右滑时移除按钮与通知内容重叠显示

- **提交**：`a5f82d7d` | 2026-07-29 | liujinfeng | SystemUI | bugfix
- **缺陷库**：等级 B · 频次 必现-80%~100% · 状态 关闭 · 域 主交互

## 问题
通知中心里右滑应用通知时，"移除"按钮与通知卡片内容重叠显示，动效错乱。

## 根因分析
两层问题：
1. **移除按钮是"静止背景层"**：原实现中 `mDismissButtonContainer` 固定在卡片下层，卡片滑走时靠"露出"显示按钮。卡片位移量与按钮宽度没有对齐关系，滑动过程中按钮与卡片内容在视觉上叠在一起；`CarNotificationBaseViewHolder.setSwipeTranslationX` 只平移卡片、不管按钮位置。
2. **动效管理混乱**：`DismissAnimationHelper` 用 `viewHolder.itemView.animate()` 设值后以 `viewPropertyAnimator.getDuration()` 作 `postDelayed` 延时来回调 `onDismiss`——时长为 0 或动画被打断时回调时机完全失真；且新旧动画互相不取消（`setSwipeTranslationX` 直接跳变、`setSwipeAlpha(0)` 立即置 0），中途反向滑动时卡片与按钮处于半完成状态，重叠残留。缺陷库根因"动效错误"即此。

## 为什么能修复
移除按钮从"静止待露出"改为"贴着卡片前缘随动"（`translationX - actionWidth`），卡片滑多少按钮跟多少，两者永远相接不相叠，几何上消除了重叠；滑动目标距离改为 `viewWidth + actionWidth`，保证按钮完全入画。动画统一收口到 `animateTo`：同一条目的旧动画先 cancel、插值驱动、只有自然结束才回调 dismiss，半完成残留不复存在。分组 ViewType 合并消除了展开/收起时 ViewHolder 重建导致的动画对象失效（重叠的另一诱因）。隐患：随动模式依赖 `isStagedSwipeDeleteEnabled()` 开关，非 staged 模式仍走旧静止背景行为，两种模式的视觉表现需分别验收。

## 复盘与经验
- **滑动操作按钮应"随动"而非"静态露出"**：按钮与卡片的位移必须绑定为同一条插值曲线（translation 差一个 actionWidth），静态背景层方案在任意位移处都可能叠字。
- **动画要集中管理、可取消、有唯一完成回调**：`animate()` 链 + `postDelayed(getDuration())` 的组合在动画被打断时回调完全失真；ValueAnimator + 注册表（WeakHashMap）+ cancel 是滑动列表动画的标准治理。
- **展开态不要用两个 ViewType 表达**：展开/收起共用 ViewHolder、内容用 payload 局部刷新，才能保住动画连续性，这是 RecyclerView 分组动画的成熟模式。
- **动画中途状态（半透明、半位移）是重叠类视觉 bug 的高发区**，review 时优先检查"动画被打断后从哪个状态恢复"。
