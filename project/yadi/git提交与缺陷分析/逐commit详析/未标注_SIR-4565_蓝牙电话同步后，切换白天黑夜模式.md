# SIR-4565 · 蓝牙电话同步后切换白天黑夜模式最近通话显示空白

- **提交**：`194b8517` | 2026-08-03 | liujinfeng | BTPhone | bugfix
- **缺陷库**：等级 B · 频次 必现-80%~100% · 状态 关闭 · 域 蓝牙电话

## 问题
蓝牙电话同步完成后切换白天/黑夜模式，最近通话页面显示空白。

## 根因分析
此前为"首页蓝牙卡片跳转"需求在 `CallLogFragment` 引入了两套拦截逻辑：① `isFromBlueCard`/`isFirstLoad` 标记 + `onStart` 中"非卡片跳转+首次加载"时 `callLogAdapter.updateCallLogList(new ArrayList<>())` 清空数据；② `setupViewModel()` 里 UI 状态观察者加 `isFragmentVisible()` 门禁，不可见就 skip render。切换昼夜模式会重建 Activity/Fragment：重建后 `isFirstLoad=true` 且非卡片跳转，`onStart` 先把适配器清空，随后 uiState 派发时 Fragment 处于不可见瞬间被 `isFragmentVisible()` 拦截不渲染——数据被清又不再刷新，页面定格空白。

## 为什么能修复
移除"重建即清空"与"不可见不渲染"两道拦截后，昼夜切换重建的 Fragment 在 `onStart → observe → render` 链路上总能拿到 ViewModel 中的完整 uiState 并渲染，最近通话不再空白。副作用：首页卡片跳转场景的"强制显示缓存"逻辑一并删除，需确认该场景由 ViewModel 缓存兜底（本次提交即以此为准）。

## 复盘与经验
- 用静态/成员布尔标记控制"是否清数据/是否渲染"非常脆弱：Activity 重建、昼夜切换、分屏都会重置生命周期路径，标记语义随之失效。
- ViewModel 是配置变更后唯一可靠的数据源，Fragment 重建时应无条件从 uiState 恢复，而不是靠 onStart 清空来"避免旧数据"。
- "仅可见时渲染"类优化要考虑首帧可见性回调时序（onStart 时可能仍判为不可见），否则会吞掉关键渲染导致白屏。
