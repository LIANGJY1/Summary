# YD-392743 · Vlog 黑夜模式适配

- **提交**：`fac0a806` | 2026-06-27 | daizhecheng | Vlog | bugfix（黑夜模式适配，挂 YD-392743 单号，与该单 Toast 颜色修复同单不同主题）
- **缺陷库**：未关联单号（仅 YD 工单单号，无缺陷库记录）

## 问题
Vlog 应用在黑夜模式下弹窗、按钮仍是白底/红底日间配色，首页底图也是日间图，与黑夜模式设计稿不符。

## 根因分析
Vlog 模块此前没有任何 `values-night`/`drawable-night` 资源限定目录，且 drawable 里大量直接引用绝对色（`@color/white`、`@color/btn_bg_red_color`、`@color/bg_dialog_color`、`@color/gray_950_60`）——这些颜色没有夜间变体，系统切到夜间模式后资源选择器无从替换。修复思路是"引用换令牌 + 补夜间限定资源"：把 drawable/布局里的写死颜色换成 `bg_dialog`、`bg_button_default`、`setting_warning`、`text_default_press` 等语义令牌（由公共库带夜间变体），再为 Vlog 私有资源补 `values-night/colors.xml`（`main_bg_color` → `#131314`）与 `drawable-night/main_bg2.png` 夜间底图。

## 关键代码修改
改动文件：application/Vlog/src/main/res/values-night/colors.xml（新增）、res/drawable-night/main_bg2.png（新增，二进制图片）、res/drawable/{bg_dialog,btn_bg_radio16_white,btn_bg_radio18_red,btn_bg_radio18_white}.xml、res/layout/{activity_home,dialog_hint_ext,dialog_list_content,dialog_success}.xml

```diff
--- application/Vlog/src/main/res/values-night/colors.xml（新增）
+<resources>
+    <color name="main_bg_color">#131314</color>
+</resources>
```

```diff
--- application/Vlog/src/main/res/drawable/btn_bg_radio18_red.xml
@@ 绝对色 → 带夜间变体的语义令牌
-            <solid android:color="@color/btn_bg_red_color" />
+            <solid android:color="@color/setting_warning" />
--- application/Vlog/src/main/res/drawable/btn_bg_radio18_white.xml
-            <solid android:color="@color/white" />
+            <solid android:color="@color/bg_button_default" />
--- application/Vlog/src/main/res/layout/activity_home.xml
-                android:textColor="@color/gray_950_60"
+                android:textColor="@color/text_default_press"
```

## 为什么能修复
夜间适配的本质是"资源选择器换挡"：引用一旦走带 `-night` 变体的令牌，系统 `UI_MODE_NIGHT_YES` 时自动取夜间值，代码零分支；Vlog 私有的主背景色与底图通过新增 `values-night`/`drawable-night` 目录获得夜间版本。改动全为资源层，无逻辑副作用。隐患：`values-night` 里只覆盖了 `main_bg_color` 一个颜色，其余令牌依赖公共库的夜间定义是否齐全；且 `text_default_press`（按压态语义）被用来表达正文次要色，令牌语义错位，后续维护易误解。

## 复盘与经验
- **夜间模式是资源问题不是代码问题**：优先补 `-night` 限定资源 + 换引用令牌，避免在代码里按 `uiMode` 写 if（对比 3ba0d479 的 `getIdentifier` 场景，那是资源名动态拼接被迫手动适配的例外）。
- **令牌按语义选、按语义用**：`text_default_press` 顶替 `gray_950_60` 能跑，但语义错位是下一次走查的新 bug 源。
- **同一单号不同主题**（YD-392743 同时挂着 Toast 颜色修复 838a8309 和本黑夜模式提交）会让缺陷回归验证范围不清，单号宜一事一挂。
