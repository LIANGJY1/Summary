# SIR-2089 · 3D驻车桌面切行车仪表桌面后状态栏/Dock栏动效残留

- **提交**：`e5ba4570` | 2026-08-03 | liujinfeng | SystemUI | bugfix
- **缺陷库**：等级 B · 频次 必现-80%~100% · 状态 关闭 · 域 仪表信息

## 问题
3D 驻车桌面切换到行车仪表桌面后，顶部状态栏残留光圈动效、底部 Dock 栏残留两条线，界面"脏"。

## 根因分析
驻车（P 档）桌面为配合 3D 动效，状态栏与 Dock 栏背景是透明（`Color.TRANSPARENT`），切到 D/R 档仪表桌面后没有任何代码恢复背景，透明的状态栏/Dock 让下层桌面的动效元素（光圈、线条）透了出来，视觉上就是"残留"。缺陷库标注根因为需求变更——仪表界面显示时需要新增状态栏和 Dock 的背景。

## 关键代码修改
改动文件：application/SystemUI/src/main/java/com/android/systemui/navbar/ui/NavBarFragment.java、application/SystemUI/src/main/java/com/android/systemui/statusbar/ui/StatusBarFragment.java、application/SystemUI/src/main/res/values-night/colors.xml、application/SystemUI/src/main/res/values/colors.xml
```diff
// application/SystemUI/src/main/java/com/android/systemui/navbar/ui/NavBarFragment.java（StatusBarFragment.updateGearState 同构）
     public void updateGearState(int gear) {
+        if (mCurrentGear == 0 && (gear == 1 || gear == 2)) {
+            if (!handler.hasCallbacks(mPostActionRunnable)) {
+                handler.postDelayed(mPostActionRunnable, 600);
+            }
+        } else if ((mCurrentGear == 1 || mCurrentGear == 2) && gear == 0) {
+            handler.removeCallbacks(mPostActionRunnable);
+            setBackGround(false);
+        }
         this.mCurrentGear = gear;
```
```diff
// NavBarFragment.java
+    public void setBackGround(boolean needBg) {
+        LogUtils.d(TAG, "setBackGround: " + needBg);
+        if (needBg) {
+            clRoot.setBackgroundResource(R.color.bg_status_and_dock);
+        } else {
+            clRoot.setBackgroundColor(Color.TRANSPARENT);
+        }
+    }
```
```diff
// application/SystemUI/src/main/res/values/colors.xml（夜色 values-night 为 #0E0C15）
+    <color name="bg_status_and_dock">#F0F6FA</color>
```
状态栏侧 `setBackGround(true)` 由硬编码 `Color.parseColor("#1A000000")` 改为同一资源 `R.color.bg_status_and_dock`，昼/夜模式颜色一致。

## 为什么能修复
在 `updateGearState()` 里按档位沿 P→D/R、D/R→P 的边沿触发背景切换：进入行车档延迟 600ms（等 3D 动效播完）后铺上 `bg_status_and_dock` 背景挡住桌面残留；回 P 档时先 `removeCallbacks` 再恢复透明，保证驻车动效不被遮挡且不会出现回调错序。副作用：600ms 是按动效时长定的经验值，动效调整时需同步。

## 复盘与经验
- 透明 SystemUI 栏与桌面动效强耦合：任何"透明化"需求都要同步定义"什么时候恢复不透明"，否则切场景必出残留。
- 档位驱动的 UI 状态切换应基于"前一档→当前档"的边沿判断（保存 `mCurrentGear` 再比较），只看当前值无法区分进入/退出。
- 延迟恢复背景（600ms）是给前序动效留窗口的常用手段，配套 `hasCallbacks`/`removeCallbacks` 防重与撤销，避免快速来回切档时状态错乱。
