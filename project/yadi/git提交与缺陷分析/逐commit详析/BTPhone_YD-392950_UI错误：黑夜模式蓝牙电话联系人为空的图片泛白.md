# YD-392950 · 黑夜模式"联系人为空"占位图泛白

- **提交**：`b07dca37` | 2026-07-29 | hedeyuan | BTPhone | bugfix
- **缺陷库**：未关联缺陷库记录（单号 YD-392950，defs 无条目）

## 问题
黑夜模式下蓝牙电话联系人列表为空时的占位插图（icon_no_contact）显示泛白，与暗色背景格格不入。

## 根因分析
项目只有 `drawable/icon_no_contact.png` 一个白天版本资源，黑夜模式没有 `-night` 限定符变体，系统在夜间模式下仍复用亮色调插图；插图本身含大面积浅色元素，放在暗背景上观感"泛白"。这类问题不是颜色值写错，而是**位图资源缺少昼夜双版本**，代码/布局层无法修复，只能补资源。

## 关键代码修改
改动文件：application/BTPhone/src/main/res/drawable-night/icon_no_contact.png（**二进制新增**，218180 字节）

```diff
--- /dev/null
+++ b/application/BTPhone/src/main/res/drawable-night/icon_no_contact.png
（二进制文件：新增黑夜模式专属的"联系人为空"占位插图）
```

## 为什么能修复
利用 Android 资源限定符机制：`drawable-night/` 下的同名资源会在夜间模式（`uiMode=night`）被自动选中，白天仍用 `drawable/` 原图。布局与代码零改动，插图色调随模式自动切换，泛白问题消除。风险：新增 PNG 体积 218KB，需注意两套图片长期同步维护（设计更新时容易只更其一）；后续若引入 drawable-night 目录规范，同类占位图应一并补齐，避免零散适配。

## 复盘与经验
- **位图资源天生不分昼夜，必须用 -night 限定符成对提供**：颜色可以靠 values-night，PNG 只能靠资源目录限定，设计交付清单应把"暗色版切图"列为必交付项。
- **"泛白/泛黑"类 UI 问题先判断资源类型**：矢量/颜色走主题令牌，位图走限定符目录；用代码 setTint 硬救位图是脆弱方案。
- **双份资源的维护成本要有意识**：同名资源两目录并存，更新时遗漏单边会造成昼夜不一致的新 bug，建议在资源命名/评审清单中固化。
