## 需求/目标
从整体编译工程中临时剔除 Weather（天气）与 DebugTools（调试工具）两个 application 模块，缩短全量编译时间 / 规避无关模块编译问题。

## 实现结构
仅改动根 `settings.gradle`（2 增 2 删）：把 `include ':application:Weather'` 与 `include ':application:DebugTools'` 两行注释掉，其余模块（Launcher、Setting、SystemUI、Vlog、AccountCenter 等）保持不变。

## 关键代码
```diff
--- a/settings.gradle
@@ include ':application:Vlog'
-include ':application:Weather'
-include ':application:DebugTools'
+//include ':application:Weather'
+//include ':application:DebugTools'
 include ':application:AccountCenter'
```
实现讲解：Gradle 通过 `settings.gradle` 的 include 决定参与构建的模块；注释即从构建图摘除模块，代码仍保留在仓库中，随时可恢复。这是多模块车机项目里常见的"瘦身编译"手法。

## 复盘与要点
- 用注释而非删除，恢复成本低；但这类临时改动容易长期滞留主干，导致"代码在库里却不参与编译"的隐性漂移，建议用 Gradle 属性（如 `-PincludeWeather`）做条件 include。
- 影响 D 级合理：不改变任何运行时行为，只影响构建产物范围。
