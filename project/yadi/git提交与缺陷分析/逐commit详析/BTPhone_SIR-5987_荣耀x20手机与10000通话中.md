# SIR-5987 · 三方通话场景点击当前通话挂断键无法挂断

- **提交**：`3553dc00` | 2026-08-19 | liujinfeng | BTPhone | bugfix
- **缺陷库**：等级 B · 频次 必现-80%~100% · 状态 关闭 · 域 蓝牙电话

## 问题
荣耀x20与10000通话中、华为pro80来电呼入（三方场景）时，点击浮窗上"与10000通话中"的挂断键，当前通话挂不断。

## 根因分析
缺陷库根因："挂断事件处理错误，操作到来电响铃的通话上了"。`FloatCallWindow` 中第一个通话的挂断按钮 `ivFirstHangUp` 原来直接调用 `mPresenter.declineCall()`。`declineCall` 语义是"拒接来电"——在三方场景（一路 `STATE_ACTIVE` 通话 + 一路响铃来电）下，它作用在来电响铃的通话上而不是当前活跃通话上，于是点击挂断实际执行的是对来电的操作，当前通话保持不动，表现为"挂不断"。修复改为显式定位目标：`uiCallManager.getCallWithState(Call.STATE_ACTIVE)` 拿到活跃通话后调用 `uiCallManager.disconnectCall(activeCall)` 按对象挂断；取不到活跃通话则告警返回。本 diff 同时顺手修了两处 `getContactName().strip()` 在联系人名为空时的 NPE 隐患（把取值移进非空分支、用 `normalizedName` 判空）。

## 关键代码修改
改动文件：application/BTPhone/src/main/java/com/yadea/btphone/floatview/FloatCallWindow.java（+15/-9）
```diff
@@ application/BTPhone/src/main/java/com/yadea/btphone/floatview/FloatCallWindow.java @@
             ivFirstHangUp.setOnClickListener(v -> {
                 LogUtils.d(TAG, LOG_HANGUP_FIRST);
-                mPresenter.declineCall();
+                UiCall activeCall = uiCallManager.getCallWithState(Call.STATE_ACTIVE);
+                if (activeCall == null) {
+                    LogUtils.w(TAG, "Hang up current call ignored: no active call");
+                    return;
+                }
+                uiCallManager.disconnectCall(activeCall);
             });
```

## 为什么能修复
挂断动作从"按语义隐式选中某路通话"（declineCall 默认作用于来电）改为"按通话状态显式选中目标对象"（`STATE_ACTIVE` 的 `UiCall`），三方场景下无论是否存在并发来电，挂断都精确作用于当前活跃通话，且无活跃通话时安全忽略。隐患：若场景中存在多路活跃通话，`getCallWithState` 只返回其中一路，挂断的可能不是用户点的那一路；更彻底的做法是按钮直接绑定其对应的 `UiCall` 对象。

## 复盘与经验
- 多路通话 UI 上，按钮回调里用 `decline/reject/answer` 这类"面向场景"的语义接口时，实际操作的通话由框架内部状态决定，极易在并发场景错位；应持有并操作按钮对应的 `UiCall` 对象本身。
- "点击没反应"类 bug 要先确认事件被消费到了哪个对象上——本例事件没丢，只是打错了目标。
- 顺手修复的 `getContactName().strip()` 空名 NPE 提醒：蓝牙联系人姓名字段随时可能为空/null，所有字符串加工都要先判空。
