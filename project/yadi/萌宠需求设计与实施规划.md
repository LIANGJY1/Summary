## 一、需求定稿

### 背景
- 萌宠由 Kanzi 渲染绘制，Launcher 提供画面集成。
- 萌宠与车模共用同一画面（`MainActivity` 的 `kanzi_surface`）。
- Kanzi 状态改变通过 `KanziDataSourceManager.notifyDataChanged` 回调至 Launcher。
- Launcher 职责：信号采集 → 业务仲裁 → 下发 `VPA_Action` 动作码。动画状态机在 Kanzi 侧。

### 5 条需求

| # | 需求 | 动作码 | 信号源 |
|---|------|--------|--------|
| R1 | 空闲吃爆米花：未触发动作时长落在 [5,10]s 区间 | 3 | `VPA_Out_Action_PlayStatus`（Kanzi→Launcher） |
| R2 | 点击放屁：收到点击事件（不区分单击/双击，边沿触发） | 5 | `VPA_Clicked`（Kanzi→Launcher） |
| R3 | 音乐舞动：音源播放开始/暂停结束 | 90/91 | `AudioSourceMonitor`（已就绪） |
| R4 | 语音唤醒：VPA 可用 + 语音唤醒/退出 | 100/101 | aiLit SDK（方案 A，Launcher 直接集成） |
| R5 | 开关确认/中断：开关状态以 Kanzi 回传为准，关闭中断 | 复位 | `VPA_Switch` 回传 |

### 关键决策
1. R1 语义：空闲时长落在 [5,10]s 区间才触发，超 10s 不触发。
2. 动作码：吃爆米花 = 3，放屁 = 5。
3. 优先级框架：`语音 > 音乐 > 点击 > 吃爆米花 > 随机循环`，默认可打断，本期不启用（备用）。
4. 常驻态 = 随机动作循环（Kanzi 自动轮播），Launcher 不发「随机动作」码；音乐/语音结束发对应**结束码 91/101**，Kanzi 自动回常驻。
5. 开关以 Kanzi 回传 `VPA_Switch` 为准，关闭时中断当前循环动作。
6. 音源信号源：`AudioSourceMonitor`（已存在）。
7. 语音信号源：aiLit SDK 方案 A（`AiLitContext`，无需 aiLitBiz）。
8. 点击检测：Kanzi 侧检测（`VPA_Clicked` 回调）。
9. R1 的「任意动作」暂只考虑吃爆米花自身，其它竞合交给优先级框架。

## 三、架构设计

### 包结构（对齐 `control/audiosource` 扁平风格）
```
com.yadea.launcher.control.pet/
├── PetActionCode.kt        # 完整动作码常量表（19 个）
├── PetAction.kt            # 活跃动作枚举（code/priority/isLoop/isEnd）
├── PetConfig.kt            # 空闲阈值等配置
├── PetActionArbiter.kt     # 仲裁策略（PassThrough + Priority，可插拔）
├── PetAudioSource.kt       # 音频适配器（R3）
├── PetVoiceSource.kt       # 语音抽象接口（R4）
├── AiLitPetVoiceSource.kt  # aiLit 实现（R4）
└── PetActionController.kt  # 仲裁中枢（单例）
```

### 数据流
```
AudioSourceMonitor ──(MEDIA 播放状态)──┐
Kanzi notifyDataChanged                │
  ├ VPA_Clicked (R2)                   ├─► PetActionController ──► sendVpaAction(code)
  ├ VPA_Out_Action_PlayStatus (R1)     │       │ 采集→仲裁→下发
  └ VPA_Switch (R5)                    │       └─ 唯一下发出口
aiLit SDK ──(交互开始/结束) (R4)───────┘
```

### 核心类：PetActionController

状态：
- `isPetEnabled`：萌宠总开关（默认开）
- `isVoiceReady`：语音服务就绪（默认否）
- `currentAction: PetAction?`：当前动作，**null 表示常驻态（随机循环）**
- `arbiter`：仲裁策略（默认透传）

关键逻辑：
- **空闲计时**：`restartIdleTimer()` 在 init / PlayStatus「0」/ 结束码下发后启动；`stopIdle()` 在触发动作/PlayStatus「1」时停止。5 秒到且 `currentAction == null` → 下发吃爆米花(3)。
- **去重**：仅循环动作（`action == currentAction && action.isLoop`）去重，避免重复下发 90/100；非循环动作允许重复触发。
- **结束码**：音乐/语音结束下发 `MUSIC_END(91)`/`VOICE_END(101)`，随后 `currentAction = null` 回到常驻。
- **开关中断**：`VPA_Switch` 回传「0」时，若当前是 MUSIC/VOICE 循环则下发对应结束码。

### 动作枚举（`PetAction`）
```kotlin
enum class PetAction(val code: Int, val priority: Int, val isLoop: Boolean, val isEnd: Boolean) {
    POPCORN(PetActionCode.RANDOM_ACTION_3, 3, false, false),
    FART(PetActionCode.CLICK_1, 2, false, false),
    MUSIC(PetActionCode.MUSIC_START, 1, true, false),
    MUSIC_END(PetActionCode.MUSIC_END, 4, false, true),
    VOICE(PetActionCode.VOICE_WAKE_START, 0, true, false),
    VOICE_END(PetActionCode.VOICE_WAKE_END, 4, false, true)
}
```

## 五、R4 语音唤醒（aiLit 方案 A）关键 API

| 需求概念 | SDK API |
|---------|---------|
| 初始化 | `AiLitContext.initialize(Application, OnSpeechReadyListener)` |
