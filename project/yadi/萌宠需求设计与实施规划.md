# 萌宠（VPA Pet）需求设计与实施规划

> 项目：YaDi Launcher
> 日期：2026-08-14
> 状态：设计定稿（部分实现 / 部分待外部依赖）

---

## 一、需求定稿（含决策回执）

### 背景
- 萌宠由 **Kanzi 渲染绘制**，Launcher 提供画面集成。
- 萌宠与车模**共用同一画面**渲染，均为 Launcher MainActivity 中的 `kanzi_surface`。
- Kanzi 状态改变通过 `KanziDataSourceManager.notifyDataChanged` 回调至 Launcher。
- Launcher 职责：**信号采集 → 业务仲裁 → 下发 `VPA_Action`**。动画状态机在 Kanzi 侧。

### 4 条需求 + 1 条开关联动的定稿

| # | 需求 | 触发条件 | 动作码 | 信号源 | 实现状态 |
|---|------|---------|--------|--------|---------|
| R1 | 空闲吃爆米花 | 非随机循环的空闲时长落在 **[5,10]s** 区间 | **3**（随机动作-3 = 吃爆米花） | `VPA_Out_Action_PlayStatus`（Kanzi→Launcher） | 待 Kanzi 回调，逻辑可实现 |
| R2 | 点击放屁 | 收到 Kanzi 回调的屏幕点击（单击/双击） | **5**（点击-1 = 放屁） | Kanzi 侧点击 dataSource（待定） | ⏸ 等 Kanzi，先 stub |
| R3 | 音乐舞动 | 音源播放开始 / 暂停·结束 | **90 / 91**（多媒体音乐开始/结束） | `AudioSourceMonitor`（已就绪） | ✅ 可立即实现 |
| R4 | 语音唤醒 | VPA 可用 + 语音唤醒/退出 | **100 / 101**（语音唤醒开始/结束） | 语音 SDK（待接入） | ⏸ 等 SDK，先 stub |
| R5 | 开关确认/中断 | 开关状态变化（Kanzi 回调为准） | 关闭→中断动画 | Kanzi 回传 `VPA_Switch`（待定） | ⏸ 等 Kanzi，先设计 |

### 决策回执（用户确认）
1. **R1 语义**：空闲时长落在 **[5,10]s** 区间才触发吃爆米花；超 10s 不触发。
2. **动作码**：吃爆米花 = **3**（随机动作-3），放屁 = **5**（点击-1）。
3. **优先级框架**：默认 `语音唤醒 > 音乐舞动 > 点击 > 空闲吃爆米花 > 随机循环`；**默认都可打断**；提供开关决定是否启用框架；**本期不启用，先设计备用**。
4. **常驻态**：R3/R4 退出后需**显式下发随机动作 code** 恢复（具体值 0 或 2 待 Kanzi 确认）。
5. **开关**：萌宠开关状态**从 Kanzi 回调确认**（非仅 Settings 值）；开关关闭时**中断**当前动画。
6. **音源信号源**：已在项目中新增 `AudioSourceMonitor` 等（已确认存在）。
7. **语音信号源**：等待接入语音 SDK，暂未提供，**先设计接口**。
8. **点击检测方**：**Kanzi 侧检测**（a 方案），等待 Kanzi 提供点击事件回调，**先设计**。
9. **R1 前置**：暂设计为「任意动作」只考虑吃爆米花自身；其它动作竞合交给（后续启用的）优先级框架。

## 二、代码现状调研摘要

### 数据流向
- **Kanzi → Launcher**：`IKanziDataListener.notifyDataChanged(dataSourceName, type, value)`，入口 `KanziDataSourceManager.java:282`。现有特殊分支：`CarModel.KanziLoadingComplete`、`Button.PreviewReturnBack`；其余走 `KanziSignalMapping.handleKanziToCar`（车模按钮点击 → 车辆属性）。
- **Launcher → Kanzi**：`kanziManager.setValue("", key, value)`。

### 已打通的萌宠链路（仅 2 条）
- `KanziDataSourceManager.registerAiPetSettings()`（`KanziDataSourceManager.java:656-680`）：
  - Settings.Global `ai_pet_switch` → `VPA.VPA_Switch`
  - Settings.Global `ai_pet_choose` → `VPA.VPA_Style`
- 由 Setting 模块 `AIPetFragment.kt` 写入。

### KanziType.VPA 常量现状（`KanziType.java:199-214`）
| 常量 | 字符串 | 状态 |
|------|--------|------|
| VPA_SWITCH / VPA_STYLE | VPA.VPA_Switch / VPA.VPA_Style | ✅ 已用 |
| VPA_STATE / VPA_FESTIVAL / VPA_BIRTHDAY / VPA_ACTION | 同名字符串 | ❌ 定义未用 |
| **VPA_Out_Action_PlayStatus** | 缺失 | ⚠️ 需求有、代码无，**需新增** |

### 画面与触摸
- `activity_main.xml`：根 FrameLayout → `kanzi_surface`（FrameLayout）+ `kanzi_cover`（加载遮盖，加载完 GONE）。
- `MainActivity.kt:41`：`mKzManager.init(mBinding.kanziSurface)`，Kanzi SDK 注入 `KanziSurfaceView`（SurfaceView），**消费全部触摸事件**。
- MainActivity **无** onTouchEvent / dispatchTouchEvent / GestureDetector。
- 现有点击回调仅车模 `Button.*`（`KanziSignalMapping.handleKanziToCar`），**无通用屏幕点击回调**。

### AudioSourceMonitor（用户已新增，R3 信号源已就绪）
路径：`application/Launcher/src/main/java/com/yadea/launcher/audiosource/`
- **双层监听**：
  1. `CarAudioManager.CarFocusCallback` —— 判断哪个音源持有音频焦点（音源身份 + 会话存活）。
  2. `AudioManager.AudioPlaybackCallback` —— 判断是否真实出声。
- **状态聚合**：
  - 焦点持有 + 出声 → `PLAYING`
  - 焦点持有 + 不出声 → `PAUSED`
  - 焦点被更高优先级抢占 → `INTERRUPTED`
  - 焦点释放正常退出 → `STOPPED`
- `AudioSourceType`：CALL / NAVIGATION / **ASSISTANT(语音)** / MEDIA / RINGTONE / NOTIFICATION / ALARM / UNKNOWN。
- `AudioSourceListener` 接口：`onPlaybackStateChanged(AudioSourceEvent)`、`onActiveSourceChanged(source)`，均主线程派发。
- 已在 `Myapplication.onCreate()`（第 42 行）`start()`。

### 语音唤醒现状（R4 上游）
- Launcher 无任何语音信号接收（manifest 仅 `ExitWithAnimatorReceiver`）。
- 语音助手 = AISpeech「Lyra」（`com.aispeech.lyra.assistant` / `.daemon`），仅 Setting 模块集成 aiLit SDK。
- 可用状态：`SettingKeys.SPEECH_RECORDER_USABLE`、`AiLitContext.isSpeechReady()`。
- SystemUI VPA 图标点击 `launchVoice()` 为空实现。
- **注意**：`AudioSourceMonitor` 已跟踪 `USAGE_ASSISTANT`，可作语音活动的临时/辅助信号（可选增强）。

## 三、总体架构设计

新增单例 **`PetActionController`**（建议 `com.yadea.launcher.control`），作为萌宠动作**唯一仲裁中枢**。

```
                    ┌─────────────────────────────────────────┐
 AudioSourceMonitor │  onPlaybackStateChanged(MEDIA)          │
 (R3 已就绪)        └───────────────►┌──────────────────────┐ │
                                     │   PetActionController │ │
 Kanzi notifyDataChanged             │  ┌─────────────────┐  │ │
  ├ VPA_Out_Action_PlayStatus (R1)   │  │ 动作仲裁 + 状态机 │  │ │
  ├ 点击回调 dataSource (R2 待定)    │  │ 优先级框架(可开关)│  │ │
  ├ VPA_Switch 回传 (R5)             │  │ 空闲计时器(R1)   │  │ │
  └ ...                              │  └─────────────────┘  │ │
 语音 SDK 回调 (R4 待定)             └──────────┬───────────┘ │
                                                 │ sendVpaAction│
                                     ┌───────────▼───────────┐ │
                                     │ KanziDataSourceManager │ │
                                     │ kanziManager.setValue   │ │
                                     │ ("", VPA_Action, code)  │ │
                                     └─────────────────────────┘ │
                                                               │
```

**职责边界**：
- `PetActionController`：只做「采集 → 仲裁 → 下发」，不碰车辆信号、不碰 UI。
- `KanziDataSourceManager`：新增公开 `sendVpaAction(code)`；在 `notifyDataChanged` 中把 VPA 相关 dataSource 转发给 `PetActionController`。
- Kanzi 侧：动画状态机、命中检测、`VPA_Out_Action_PlayStatus`、开关/点击回传。

## 四、分模块设计

### M1 动作码常量（Phase 0）
- 补 `KanziType.VPA.VPA_Out_Action_PlayStatus = "VPA.VPA_Out_Action_PlayStatus"`。
- 新增 `PetActionCode` 常量类集中管理：
  - `POPCORN = 3`、`FART = 5`、`MUSIC_START = 90`、`MUSIC_END = 91`
  - `VOICE_START = 100`、`VOICE_END = 101`
  - `RANDOM_RESIDENT = 0`（常驻态恢复，具体值待 Kanzi 确认）

### M2 R3 音乐舞动（可立即实现）
- `PetActionController` 实现 `AudioSourceListener`，关注 `AudioSourceType.MEDIA`：
  - `PLAYING` → 下发 90
  - `PAUSED / STOPPED / INTERRUPTED` → 下发 91（恢复常驻）
- 已具备条件：`AudioSourceMonitor` 已启动、接口清晰。

### M3 R1 空闲吃爆米花（逻辑可实现，依赖 Kanzi PlayStatus 回调）
- 监听 `VPA_Out_Action_PlayStatus == 0`（上一个非循环动画播完）→ 启动 5s 计时器。
- 5s 到：若仍空闲且空闲时长 ∈ [5,10] → 下发 3；随后等下一次 `PlayStatus==0` 才重启计时。
- 兜底：计时器回调若超过 10s（延迟/被阻塞）→ 不触发，回到随机循环。

### M4 优先级框架（备用，本期不启用）
- 抽象 `PetAction`（`id`、`priority`、`canInterrupt`）。
- 仲裁器：新动作比较优先级，高优先级且可打断 → 切换；否则忽略。
- 开关 `usePriorityFramework`（默认 false：不启用则所有动作直接触发、不考虑竞合）。
- 默认优先级：`VOICE(0) > MUSIC(1) > CLICK(2) > POPCORN(3) > RANDOM(4)`。

### M5 R2 点击放屁（等 Kanzi，先 stub）
- 预留 `onMascotClick(clickType)` 接口；Kanzi 新增点击 dataSource（对齐现有 `Button.*` 模式）回传后接入。
- 单击 → 5（放屁）；双击 → 6（点击-2）**待 Kanzi 确认**（或双击也 → 5）。

### M6 R4 语音唤醒（等 SDK，先 stub）
- 预留 `VoiceWakeListener { onWakeStart(); onWakeEnd() }` 接口。
- 下发 100 / 101。
- 可选增强：`AudioSourceMonitor` 的 `USAGE_ASSISTANT` 作临时/辅助信号。

### M7 R5 开关确认/中断
- `notifyDataChanged` 收到 Kanzi 回传的 `VPA_Switch`（dataSource 名待 Kanzi 定）→ 更新权威开关状态。
- 开关 = 0 → 中断当前动作（下发对应结束动作 + 复位常驻）。
