# 雅迪车机音源播放状态监听方案总结

> 项目路径：`/home/liang/Project/Reachauto/YaDi/yadea_master`
> 落地模块：`application/Launcher`
> 新增包：`com.yadea.launcher.audiosource`

---

## 一、需求

在 Android 车机中监听**音源的播放开始、暂停、结束**状态，用于驱动媒体卡片等 UI 联动。要求不侵入既有代码。

---

## 二、源码现状（各应用已有方案）

| 应用 | 使用的方案 | 解决的问题 |
|---|---|---|
| **SystemUI** | `CarAudioManager` 三回调（`CarFocusCallback`/`CarVolumeCallback`/`CarOutputDeviceCallback`）+ `activePlaybackConfigurations` 主动检测 | 音量条显示当前音源、三指滑动调对音量组 |
| **BTMusic** | `MediaBrowser` → `MediaController.Callback`（`onPlaybackStateChanged`/`onMetadataChanged`）+ A2DP 广播 + `AudioFocusManager` | 蓝牙音乐播放/暂停态、歌名进度、切歌、电话打断 |
| **BTPhone** | `CarAudioManager`(group mute) + `AudioManager`(stream volume/mute) | 通话音量、铃声静音、麦克风静音 |
| **Setting** | `CarAudioManager`(get/setGroupVolume) + `AudioFocusInfo` 焦点监听 | 分音源调音量 + 试音时被电话抢占要停 |

**关键结论**：项目是系统级应用（`android:sharedUserId="android.uid.system"`），可直接访问 `CarAudioManager` 等系统 API。判断音源状态最权威的机制是 **`CarAudioManager.registerCarFocusCallback`（车载音频焦点）**，而非 MediaSession。MediaSession 只负责蓝牙音乐这一音源的精细化状态。

---

## 三、最终实现方案

### 3.1 架构：两层监听 + 状态聚合

| 监听层 | API | 拿到的信息 |
|---|---|---|
| **焦点层** | `CarAudioManager.registerCarFocusCallback` | 哪个音源持有音频焦点（音源身份 + 会话存活） |
| **播放层** | `AudioManager.registerAudioPlaybackCallback` + `getActivePlaybackConfigurations()` | 当前是否有真实出声 |

Car 实例通过 `component:Carlib` 的进程单例 `CarConnectionManager.getCar()` 获取，并复用其 `CarServiceLifecycleListener` 在 Car 就绪后注册焦点回调。

### 3.2 三个状态如何监听（核心规则）

```
焦点持有 + 出声     → PLAYING     （播放开始/播放中）
焦点持有 + 不出声   → PAUSED      （暂停：会话仍存活，只是不出音）
焦点释放 + 被抢占   → INTERRUPTED （电话/导航打断音乐）
焦点释放 + 正常退出 → STOPPED     （结束）
```

**核心洞察**：音频焦点在「暂停」时通常仍被保留（蓝牙音乐暂停时 A2DP 链路仍在），所以单靠焦点变化无法区分「暂停」和「结束」；而 `AudioPlaybackCallback` 对蓝牙源暂停时又常报 STOPPED 而非 PAUSED。「焦点在但无声 = 暂停」这条规则恰好同时解决了两个问题，无需引入需要 NotificationListener 组件的 MediaSession 层。

### 3.3 新增文件

| 文件 | 职责 |
|---|---|
| `AudioSourceType.kt` | 音源类型枚举 + usage 归类映射 + 优先级 |
| `AudioSourceState.kt` | 状态枚举（PLAYING/PAUSED/STOPPED/INTERRUPTED） |
| `AudioSourceListener.kt` | 事件数据类 + 监听接口（主线程派发） |
| `AudioSourceMonitor.kt` | 核心聚合单例 |

唯一侵入点：`Myapplication.onCreate()` 加一行 `AudioSourceMonitor.getInstance(this).start()`。

## 四、关键坑：@hide API

### 4.1 PLAYER_STATE 常量值差异（重要）

`AudioPlaybackConfiguration.PLAYER_STATE_*` 是 **@hide API**，只存在于项目自定义 `framework.jar`，不在 SDK `android.jar` 公开 API 中。且**本项目 framework.jar 的取值与标准 AOSP 不同**：

| 常量 | 标准 AOSP | 本项目 framework.jar |
|---|---|---|
| `PLAYER_STATE_STARTED` | 1 | **2** |
| `PLAYER_STATE_PAUSED` | 2 | 3 |
| `PLAYER_STATE_STOPPED` | 3 | 4 |

（中间插入了 `PLAYER_STATE_IDLE = 1`，导致后续全部 +1）

**若按标准 AOSP 值硬编码会导致判断错误**，必须与本项目 framework.jar 取值对齐。

### 4.2 SDK 公开 API 可用性核查（android-34）

| 符号 | SDK 公开 API | 结论 |
|---|---|---|
| `AudioPlaybackConfiguration.getPlayerState()` | ❌ | @hide |
| `AudioPlaybackConfiguration.PLAYER_STATE_STARTED` | ❌ | @hide |
| `AudioPlaybackConfiguration.getAudioAttributes()` | ✅ | public |
| `AudioManager.getActivePlaybackConfigurations()` | ✅ | public |
| `AudioManager.registerAudioPlaybackCallback()` | ✅ | public |
| `android.media.AudioFocusInfo` | ❌ class not found | 整个类 @hide |
| `CarAudioManager.CarFocusCallback` | ❌ | @hide |
| `registerCarFocusCallback` / `getCarFocusForZoneId` / `PRIMARY_AUDIO_ZONE` | ❌ | 全部 @hide |
| `android.car.Car` | ❌（在 optional/android.car.jar） | @SystemApi |

**结论**：焦点层整套 API 无公开替代（Android 公开 SDK 不提供音频焦点监听），与 SystemUI 的 `CarAudioVolumeController` 用的是完全相同的一套 @hide API。

### 4.3 解决方式

1. **播放层**：改用公开 API `getActivePlaybackConfigurations()`（返回的就是「正在播放」的活跃配置），`AudioPlaybackCallback` 回调仅作触发信号，回调参数被忽略（因为其 `getPlayerState()` 是 @hide）。
2. **焦点层**：保留 @hide API（与 SystemUI 一致），命令行编译为准。
3. **IDE 标红**：属项目级现状，可配置 IDE 用 `component/frameworkLibs/libs/framework.jar` + `android.car.jar` 前置替代默认 `android.jar`。
