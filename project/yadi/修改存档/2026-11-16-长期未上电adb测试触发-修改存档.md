## 1. 背景与约束

- 测试同事需要 adb 直接模拟触发**长期未上电（长期未登录，SRS_007，动作码 11）**动作。
- 用户三条硬约束：①不与既有调试注入体系（`PetDebugInjector`/`pet_debug_event`）耦合；②测试不得借该入口触发其他动作；③仅测试使用。
- 方案：独立 manifest 广播接收器，单一 action、**零 extra 解析**（结构上无法触发其他事件）、独立开关门控。

### 3.1 新增 `application/Launcher/src/main/java/com/yadea/launcher/pet/debug/PetLongPowerOffTestReceiver.kt`（62 行，最终版全文）

```kotlin
package com.yadea.launcher.pet.debug

import android.content.BroadcastReceiver
import android.content.Context
import android.content.Intent
import android.os.Binder
import android.os.Process
import android.util.Log
import com.yadea.launcher.pet.PetConfig
import com.yadea.launcher.pet.PetCore
import com.yadea.launcher.pet.core.PetEvent

/**
 * 测试专用：长期未上电动作的单一 adb 触发入口（独立通道，与 PetDebugInjector 互不耦合）。
 *
 * 命令：
 * ```
 * adb shell am broadcast \
 *   -n com.yadea.launcher/.pet.debug.PetLongPowerOffTestReceiver \
 *   -a com.yadea.debug.pet.LONG_POWER_OFF
 * ```
 *
 * 约束（保证"仅测试、仅此一条动作"）：
 * - 只认 [ACTION] 一个 action，无任何 extra 解析——除 [PetEvent.LongPowerOffSignal]
 *   外结构上不可能注入其他事件，与 pet_debug_event 全量注入通道无关。
 * - 只响应 adb 下发（调用方 uid 白名单＝system/shell/root；`am broadcast` 由 system_server 代发，
 *   真机实测 onReceive 侧 `Binder.getCallingUid()`＝1000，故必须放行 system）。三方 App 广播直接忽略。
 * - [PetConfig.LONG_POWER_OFF_ADB_TRIGGER_ENABLED]=false 时收到广播直接忽略（交付前回 false）。
 *
 * 触发后走 PetCore 统一事件入口，仲裁照常：开场中/开场前到达会排队待开场完成补播，
 * 充电、舞动、常驻在播等场景按竞合表拒绝，开关关闭时忽略——均为正式产品行为。
 */
class PetLongPowerOffTestReceiver : BroadcastReceiver() {

    override fun onReceive(context: Context, intent: Intent) {
        if (intent.action != ACTION) return
        if (!PetConfig.LONG_POWER_OFF_ADB_TRIGGER_ENABLED) {
            Log.i(TAG, "adb trigger ignored: test flag off")
            return
        }
        val uid = Binder.getCallingUid()
        // am broadcast 经 system_server 代发（真机实测 getCallingUid()=1000），白名单＝system/shell/root；
        // 三方 App（uid>=10000）广播一律忽略
        if (uid != Process.SYSTEM_UID && uid != Process.SHELL_UID && uid != Process.ROOT_UID) {
            Log.i(TAG, "adb trigger ignored: caller uid=$uid not system/shell/root")
            return
        }
        if (!PetCore.isInitialized()) {
            Log.i(TAG, "adb trigger ignored: pet not initialized")
            return
        }
        Log.i(TAG, "adb trigger -> LongPowerOffSignal")
        PetCore.onEvent(PetEvent.LongPowerOffSignal)
    }

    companion object {
        private const val TAG = "Pet_LongPowerOffTest"

        /** 测试专用 action；勿复用本动作族承载其他事件 */
        const val ACTION = "com.yadea.debug.pet.LONG_POWER_OFF"
    }
}
```

## 4. 踩坑备忘（真机实证，勿再犯）

1. **`am broadcast` 的 uid 陷阱**：shell 只是把命令交给 `am`，真正 sendBroadcast 的是 system_server——接收器里 `Binder.getCallingUid()` 恒为 **1000（system）**，不是 shell(2000)。首发版本白名单只写 shell/root，真机两次广播全被拒（日志 `caller uid=1000 not shell/root`）。修正：白名单加入 `SYSTEM_UID`。Android 13 无 `getSentFromUid()`（API 34+），uid 白名单是当前唯一手段。
2. 广播送达、action 匹配、manifest 注册、开关在首发版本即已工作正常（拒绝日志本身就是证明），修正后真机可用。
3. Launcher 进程未运行时，广播先拉起进程（`Application.onCreate` 同步 `PetCore.init`）再投递，事件先后顺序不受影响。
